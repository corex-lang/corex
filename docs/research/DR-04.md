# Strong Static Type System, Constrained Type Groups, and Linear-Time Bidirectional Inference for CoreX (.cx)

CoreX (`.cx`) achieves C-level execution speed, compile-time memory safety under Strict Mutable Value Semantics (MVS), and interactive Language Server (`corex lsp`) responsiveness by pairing a **Spine-Local Dunfield–Krishnaswami Bidirectional Type Checker** with **Zero-Cost Constrained Type Groups** and a **Data-Oriented `InternPool` Type Arena**[cite: 1, 2, 3]. Rather than relying on Hindley–Milner global unification or C++/Swift-style constraint disjunction solvers—which can degrade to $\mathcal{O}(c^n)$ exponential time complexity on chained operators and unannotated closures—CoreX bifurcates type checking into bottom-up **Synthesis ($\Rightarrow$)** and top-down **Checking ($\Leftarrow$)**[cite: 3]. Function signatures act as mandatory type firewalls, numeric literals (`untyped_int`, `untyped_float`) adapt cleanly to expected target types in checking mode before defaulting to `i64` or `f64` at lexical commit points, and generic calls resolve type arguments in a single spine-first pass[cite: 3]. On a single 3.6 GHz core, where a throughput target of 500,000 lines of code per second (LOC/sec) grants a budget of 2,000 ns per line (1,600 CPU cycles per AST node at 4.5 nodes/LOC), CoreX's pointer-free Struct-of-Arrays (`MultiArrayList`) type representation requires an estimated 65–95 cycles per node—supporting a projected single-core throughput well above 500,000 LOC/sec (up to ~5.5 million LOC/sec in synthetic cycle modeling)[cite: 2, 3].

To make generic programming effortless without sacrificing static monomorphization, CoreX introduces **Constrained Type Groups** (such as `Number`, `Integer`, `Signed`, `Unsigned`, `Float`, `Comparable`, `Equatable`, `Bytes`, `Scalar`, `Numeric`, and `Copy`) that can be used both as explicit square-bracket bounds (`fn clamp[T: Number](val: T, low: T, high: T) -> T`) and as inline parameter types (`fn clamp(val: Number, low: Number, high: Number) -> Number`)[cite: 1]. Resolving a classic design tension between Nim's implicit generics and C++20's abbreviated function templates, CoreX enforces **Bind-Once Unification by Default** for bare Type Group names within a signature (unifying all occurrences of `Number` in `clamp` to a single synthetic type parameter `__G0: Number`), while providing the `any` modifier (`fn scale(val: Number, factor: any Float) -> f64`) for **Bind-Many Independent Polymorphism**. Furthermore, by pre-encoding the 19 built-in primitive types and internal literal sentinels into a 32-bit bitmask (`TypeGroupMask`), the compiler evaluates primitive Type Group membership and subset inclusion in a single $\mathcal{O}(1)$ bitwise `AND` instruction[cite: 1].

At the representation layer, every type in the Stage-0 Zig compiler (`stage0/corex`) and Stage-1 self-hosted compiler (`src/sema/type_arena.cx`) is canonicalized into a 32-bit `TypeId` handle (`enum(u32)` with `0xFFFFFFFF` as `none`) backed by a 14-byte, zero-padding Struct-of-Arrays (`MultiArrayList`) `InternPool` and an append-only `extra_data: []u32` trail allocated inside a deterministic, zero-initialized `BumpArena`[cite: 2]. This unified representation directly powers CoreX's algebraic and data-oriented type primitives: postfix `T?` (`Option[T]`) sum types with multi-layer bit-pattern niche stacking, range-refined pattern types (`u32 is 0..4096` or `u8 is 1..=12`), nominal `distinct` newtypes with Go-inspired `~T` underlying-type approximation, `#soa[]T` columnar slices with lvalue-equivalent field addressing, and Least-Significant-Bit (LSB) `bit_field` integers projected by value across `inout` boundaries[cite: 1, 3].

## 1. Deliverable 1: Formal Type System & Bidirectional Inference Specification

### 1.1 Architectural Motivation: Avoiding Exponential Overload Disjunctions

A primary failure mode in modern static type checkers is the interaction between implicit ad-hoc function overloading, untyped literals, and unannotated closures[cite: 3]. As documented by Matt Gallagher (*Cocoa with Love*) and Chris Lattner regarding Swift's constraint solver (`CSSolver.cpp`), when integer literals are modeled as untyped protocol constraints (`ExpressibleByIntegerLiteral`) and arithmetic operators like `+` have up to 28 overloads in the standard library, evaluating an expression with $n$ operators and unannotated closure parameters constructs a Cartesian product of overload disjunctions that reduces to an NP-complete Boolean Satisfiability (SAT) problem—requiring up to 1,190 solver guesses on `let a: Double = 0 + 1 + -(2)` and taking 20 seconds in Swift 3.1 to compile `let g: Double = -(1 + 2) + -(3 + 4) + 5` (or 6.2 seconds in Swift 6 on a single-line `+` type mismatch)[cite: 3]. Conversely, full Hindley–Milner (HM) unification (as in OCaml, Haskell, or Koka) requires maintaining mutable unification graphs across entire module groups and can produce distant, non-local type error messages when a single expression is mistyped during interactive IDE editing[cite: 3].

CoreX guarantees strict $\mathcal{O}(N)$ linear-time type checking and crisp IDE error localization by combining **Dunfield–Krishnaswami Mode-Correct Bidirectional Typing** with **Spine-Local Generic Instantiation**[cite: 3].

### 1.2 Syntax of Types, Modes, and Contexts

In CoreX's formal type system, every expression is checked under a lexical typing environment $\Gamma$ (mapping value bindings `IDENT` and `CONST_IDENT` to their parameter/binding mode and canonical `TypeId`) and a local generic constraint environment $\Theta$ (mapping in-scope generic type parameters and call-site instantiation variables $\alpha_i$ to their bound constraints and solved concrete types)[cite: 1, 3]:

$$\begin{aligned}
\text{Binding Mode } m &::= \mathsf{let} \mid \mathsf{var} \mid \mathsf{inout} \mid \mathsf{sink} \mid \mathsf{set} \mid \mathsf{const} \\
\text{Primitive Type } \tau_{\text{prim}} &::= \mathsf{unit} \mid \mathsf{never} \mid \mathsf{bool} \mid \mathsf{char} \mid \mathsf{str} \mid \mathsf{i8} \mid \mathsf{i16} \mid \mathsf{i32} \mid \mathsf{i64} \mid \mathsf{i128} \mid \mathsf{isize} \\
&\quad \mid \mathsf{u8} \mid \mathsf{u16} \mid \mathsf{u32} \mid \mathsf{u64} \mid \mathsf{u128} \mid \mathsf{usize} \mid \mathsf{f32} \mid \mathsf{f64} \\
\text{Internal Sentinel } \tau_{\text{sent}} &::= \mathsf{untyped\_int}(v \in \mathbb{Z}) \mid \mathsf{untyped\_float}(v \in \mathbb{R}) \mid \tau_{\text{err}} \\
\text{Monotype } \tau, \sigma &::= \tau_{\text{prim}} \mid \tau_{\text{sent}} \mid \alpha \mid T_{\text{nom}}[\bar{\tau}] \mid \mathsf{distinct}\; T_{\text{nom}}(\tau) \mid (\tau \;\mathsf{is}\; P) \\
&\quad \mid \tau? \mid E!\tau \mid [\tau; N] \mid [\tau] \mid \mathsf{\#soa}[\tau; N] \mid \mathsf{\#soa}[\tau] \mid \mathsf{bit\_field}\; \tau_{\text{int}}\{\overline{f_i : \tau_i \mid w_i}\} \\
&\quad \mid (\tau_1, \dots, \tau_n) \mid \mathsf{fn}(\overline{m_i\; \tau_i}) \rightarrow \tau_{\text{ret}} \mid \mathsf{\&let}\; \tau \mid \mathsf{\&inout}\; \tau \mid \mathsf{own}\; \tau \mid \mathsf{dyn}\; B \\
\text{Constraint Bound } B &::= G_{\text{builtin}} \mid G_{\text{union}}(\tau_1 \mid \dots \mid \tau_k) \mid \sim\!\tau \mid \text{Trait}[\bar{\tau}] \mid B_1 + B_2 \\
\text{Polytype Scheme } \forall [\overline{\alpha_k : B_k}].\; \tau_{\text{fn}} &::= \forall [\alpha_1 : B_1, \dots, \alpha_k : B_k].\; \mathsf{fn}(m_1 \tau_1, \dots, m_n \tau_n) \rightarrow \tau_{\text{ret}} \\
\text{Typing Context } \Gamma &::= \cdot \mid \Gamma, x :_m \tau \qquad \text{Constraint Context } \Theta ::= \cdot \mid \Theta, \alpha : B \mapsto \tau^?
\end{aligned}$$

Following Dunfield and Krishnaswami's polarity discipline, the judgment forms explicitly separate inputs ($+$) from outputs ($-$)[cite: 3]:
1. **Type Synthesis ($\Gamma^+; \Theta^+ \vdash e^+ \Rightarrow \tau^- \dashv \Theta'^-$):** Given typing context $\Gamma$, constraint context $\Theta$, and expression $e$, the compiler deterministically synthesizes output type $\tau$ and updated local constraint assignments $\Theta'$ bottom-up[cite: 3].
2. **Type Checking ($\Gamma^+; \Theta^+ \vdash e^+ \Leftarrow \tau^+ \dashv \Theta'^-$):** Given typing context $\Gamma$, constraint context $\Theta$, expression $e$, and a known target type $\tau$, the compiler verifies top-down that $e$ conforms to $\tau$ and records any bound generic parameters in $\Theta'$[cite: 3].
3. **Mode-Correct Subtyping & Coercion ($\Theta^+ \vdash \tau_1^+ \le_{\text{coerce}} \tau_2^+ \dashv \Theta'^-$):** Verifies whether synthesized type $\tau_1$ is equal to or safely coercible to checked type $\tau_2$ without runtime overhead or precision loss[cite: 3].

### 1.3 Complete Typing Judgments for CoreX v1.0

#### A. Variables, Explicit Annotations, and the Subsumption Switch
Local variables, constants, and named functions synthesize their declared or inferred types in $\mathcal{O}(1)$ time via symbol table lookup; an explicit type annotation or `as` cast switches into checking mode or validates a primitive cast, while the subsumption rule $(\text{Sub}\Leftarrow)$ bridges synthesis to checking[cite: 1, 3]:

$$\frac{(x :_m \tau) \in \Gamma}{\Gamma; \Theta \vdash x \Rightarrow \tau \dashv \Theta} \;(\text{Var}\Rightarrow) \qquad \frac{\Gamma; \Theta \vdash e \Leftarrow \tau \dashv \Theta'}{\Gamma; \Theta \vdash (e : \tau) \Rightarrow \tau \dashv \Theta'} \;(\text{Anno}\Rightarrow)$$

$$\frac{\Gamma; \Theta \vdash e \Rightarrow \tau_1 \dashv \Theta_1 \quad \Theta_1 \vdash \tau_1 \le_{\text{coerce}} \tau_2 \dashv \Theta_2}{\Gamma; \Theta \vdash e \Leftarrow \tau_2 \dashv \Theta_2} \;(\text{Sub}\Leftarrow)$$

#### B. Polymorphic Numeric Literals and Contextual `.Variant` Shorthand
Rather than creating type variables or constraint disjunctions for integer and floating-point literals, CoreX synthesizes an immediate internal sentinel $\mathsf{untyped\_int}(v)$ or $\mathsf{untyped\_float}(v)$ carrying the exact 128-bit parsed value $v$[cite: 3]. When checked against a concrete numeric type $\tau \in \mathsf{Integer} \cup \mathsf{Float}$ (or an instantiated type parameter $\alpha : B$ where $B \subseteq \mathsf{Number}$), the compiler verifies compile-time representability $\text{in\_range}(v, \tau)$ in $\mathcal{O}(1)$ time[cite: 3]. If an untyped literal reaches a variable binding commit point (`let x = 42;`) without an external expected type, the **Commit Defaulting Rule ($\text{default}(\tau)$)** maps $\mathsf{untyped\_int}(v) \mapsto \mathsf{i64}$ and $\mathsf{untyped\_float}(v) \mapsto \mathsf{f64}$[cite: 3]:

$$\frac{\text{val}(L_{\text{int}}) = v}{\Gamma; \Theta \vdash L_{\text{int}} \Rightarrow \mathsf{untyped\_int}(v) \dashv \Theta} \;(\text{IntLit}\Rightarrow) \qquad \frac{\text{val}(L_{\text{int}}) = v \quad \tau \in \mathsf{Integer} \quad \min(\tau) \le v \le \max(\tau)}{\Gamma; \Theta \vdash L_{\text{int}} \Leftarrow \tau \dashv \Theta} \;(\text{IntLit}\Leftarrow)$$

$$\frac{\Gamma; \Theta \vdash e \Rightarrow \tau_e \dashv \Theta' \quad \tau_c = \text{default}(\tau_e) \quad \text{valid\_range}(e, \tau_c)}{\Gamma; \Theta \vdash \mathsf{let}\; x = e; \;\text{commits}\; x :_{\mathsf{let}} \tau_c} \;(\text{Let-Infer}\Rightarrow)$$

Similarly, contextual enum variant constructors (`.Some(x)`, `.None`, `.Admin`, `.SpaceBetween`) operate directly in Checking Mode ($\Leftarrow$) by looking up the variant identifier inside the expected `enum` or `T?` (`Option[T]`) target type[cite: 1, 3]:

$$\frac{\tau = \text{Enum}[\bar{\sigma}] \quad (\mathsf{.Variant}(\bar{\tau}_p) \in \text{variants}(\tau)) \quad \forall i.\; \Gamma; \Theta_{i-1} \vdash e_i \Leftarrow \tau_{p,i}[\bar{\sigma}] \dashv \Theta_i}{\Gamma; \Theta_0 \vdash \mathsf{.Variant}(e_1, \dots, e_k) \Leftarrow \tau \dashv \Theta_k} \;(\text{DotVariant}\Leftarrow)$$

#### C. Spine-Local Generic Function Application and Parameter Conventions
When checking a call $f(a_1, \dots, a_n)$ where $f$ synthesizes a polymorphic scheme $\forall [\overline{\alpha_k : B_k}].\; \mathsf{fn}(\overline{m_i\; \tau_i}) \rightarrow \tau_{\text{ret}}$, CoreX allocates $k$ fresh local instantiation slots $\hat{\alpha}_1, \dots, \hat{\alpha}_k$ on an arena stack frame[cite: 2, 3]. For each argument $a_i$ from left to right, if parameter type $\tau_i$ is concrete or all type parameters occurring in $\tau_i$ have already been bound in $\Theta$ (or if $a_i$ is an unannotated closure or contextual `.Variant`), $a_i$ is **checked** ($\Leftarrow$) against $\text{apply}(\Theta, \tau_i)$[cite: 1, 3]. Conversely, if $\tau_i$ contains unbound local type variables $\hat{\alpha}$ and $a_i$ is a synthesizable expression, $a_i$ **synthesizes** ($\Rightarrow$) its type $\sigma_i$, and $\text{unify\_local}(\Theta, \tau_i, \sigma_i)$ binds $\hat{\alpha}$ immediately and verifies its Type Group or trait bound $B_k$ in $\mathcal{O}(1)$ time[cite: 3]. Parameter passing modes (`let`, `inout`, `sink`, `set`) simultaneously enforce CoreX's call-site syntactic markers: passing to an `inout` parameter requires `&e` where $e$ is a mutable place expression rooted at a `var` or `inout` binding; passing to a `sink` parameter requires `own e` (for non-`Copy` types); and passing to a `set` parameter requires `&set e` on an uninitialized binding[cite: 1, 3].

$$\frac{\begin{array}{c} \Gamma; \Theta \vdash f \Rightarrow \forall [\overline{\alpha_k : B_k}].\; \mathsf{fn}(\overline{m_i\; \tau_i}) \rightarrow \tau_{\text{ret}} \dashv \Theta_0 \quad \Theta_{\text{call}} = \Theta_0 \cup \{\hat{\alpha}_k : B_k \mapsto \mathsf{none}\} \\ \forall i \in 1..n.\; \Gamma; \Theta_{\text{call}, i-1} \vdash_{\text{arg}} (a_i, m_i, \tau_i) \dashv \Theta_{\text{call}, i} \quad \forall k.\; \text{check\_bound}(\Theta_{\text{call}, n}(\hat{\alpha}_k), B_k) \end{array}}{\Gamma; \Theta \vdash f(a_1, \dots, a_n) \Rightarrow \text{subst}(\Theta_{\text{call}, n}, \tau_{\text{ret}}) \dashv \Theta_{\text{call}, n} \setminus \{\hat{\alpha}_k\}} \;(\text{App-Poly}\Rightarrow)$$

#### D. Closures, Branching (`if` / `match`), and Divergence (`never`)
Unannotated closures `|x, y| body` are checked top-down against an expected function or closure type $\mathsf{fn}(\tau_1, \dots, \tau_n) \rightarrow \tau_{\text{ret}}$, pushing $x_1 :_{\mathsf{let}} \tau_1, \dots, x_n :_{\mathsf{let}} \tau_n$ into $\Gamma$ before checking `body` $\Leftarrow \tau_{\text{ret}}$[cite: 1, 3]. If a closure provides explicit parameter annotations `|x: i32| -> i32 { x + 1 }`, it can also synthesize ($\Rightarrow$) its type directly[cite: 1]. In multi-way branching (`if` / `else` and `match`), if an expected type $\tau$ is pushed down ($\Leftarrow$), every arm is checked against $\tau$; if synthesized bottom-up ($\Rightarrow$), the first non-diverging arm synthesizes $\tau_1$ (committing any untyped literals if later arms require a concrete type) and all subsequent arms are checked against $\tau_1$[cite: 3]. Because control-transfer expressions (`return`, `break`, `continue`, `unreachable`) synthesize the bottom type $\mathsf{never}$, and $\mathsf{never} \le_{\text{coerce}} \tau$ holds for every type $\tau$, diverging arms unify seamlessly with value-producing arms (including `let .Some(x) = opt else { return err; };` guards)[cite: 1, 3]:

$$\frac{\Gamma, x_1 :_{\mathsf{let}} \tau_1, \dots, x_n :_{\mathsf{let}} \tau_n; \Theta \vdash e \Leftarrow \tau_{\text{ret}} \dashv \Theta'}{\Gamma; \Theta \vdash (|x_1, \dots, x_n|\; e) \Leftarrow \mathsf{fn}(\tau_1, \dots, \tau_n) \rightarrow \tau_{\text{ret}} \dashv \Theta'} \;(\text{Closure}\Leftarrow)$$

$$\frac{\Gamma; \Theta \vdash e_{\text{cond}} \Leftarrow \mathsf{bool} \dashv \Theta_1 \quad \Gamma; \Theta_1 \vdash b_{\text{then}} \Leftarrow \tau \dashv \Theta_2 \quad \Gamma; \Theta_2 \vdash b_{\text{else}} \Leftarrow \tau \dashv \Theta_3}{\Gamma; \Theta \vdash \mathsf{if}\; e_{\text{cond}}\; b_{\text{then}}\; \mathsf{else}\; b_{\text{else}} \Leftarrow \tau \dashv \Theta_3} \;(\text{If}\Leftarrow)$$

#### E. Postfix Propagation (`?`) and Error Unions (`E!T` / `Result[T, E]` / `T?`)
CoreX supports postfix `?` propagation across optional types (`T?`), standard library `Result[T, E]`, and native value error unions (`E!T`)[cite: 1, 3]:

$$\frac{\Gamma; \Theta \vdash e \Rightarrow \tau? \dashv \Theta' \quad \text{ret\_type}(\Gamma) = \sigma?}{\Gamma; \Theta \vdash e? \Rightarrow \tau \dashv \Theta'} \;(\text{Try-Opt}\Rightarrow) \qquad \frac{\Gamma; \Theta \vdash e \Rightarrow E_1!\tau \dashv \Theta' \quad \text{ret\_type}(\Gamma) = E_2!\sigma \quad E_1 \subseteq E_2}{\Gamma; \Theta \vdash e? \Rightarrow \tau \dashv \Theta'} \;(\text{Try-ErrUnion}\Rightarrow)$$

### 1.4 Spine-Local Constraint Propagation Algorithm & Poison Error Recovery

To guarantee that `corex lsp` provides instant autocompletion and pinpoint diagnostics on half-typed source files without cascading bogus errors, the type checker uses **Poison Token Propagation (`TypeId.err`)** combined with a five-step spine-local unification algorithm[cite: 2, 3]:

1. **Two-Phase Module Header Collection:** Before checking any function bodies, `Sema` scans top-level item headers (`struct`, `enum`, `union`, `trait`, `type`, `const`, `fn` signatures) and interns all nominal types and function schemes into the `InternPool`[cite: 1, 2, 3]. Because `DR-02` mandates explicit types at function boundaries, function bodies are completely independent of one another and can be type-checked in any order (or on-demand per edited function in `corex lsp`)[cite: 3].
2. **Spine-First Call Resolution:** On a call `foo(arg1, arg2)`, the checker resolves `foo` first. If `foo` is generic with $k \le 8$ type parameters, it initializes a stack-allocated `SubstitutionMap` of size $k$. Arguments whose parameter types do not depend on unresolved type variables—or whose expressions can synthesize a concrete type—are processed first, binding $\hat{\alpha}_j \mapsto \tau_{\text{concrete}}$. If a parameter $\hat{\alpha}_j$ receives only an `untyped_int` or `untyped_float` literal across all arguments, $\hat{\alpha}_j$ defaults to `i64` (if `i64` satisfies $B_j$) or `f64` (if $B_j \subseteq \mathsf{Float}$) before checking remaining closure or contextual-variant arguments[cite: 3].
3. **O(1) Bitmask Constraint Verification:** When binding $\hat{\alpha}_j \mapsto \tau_{\text{concrete}}$ under bound $B_j$, if $B_j$ is a built-in or union Type Group, the checker tests `(group_mask(B_j) & type_bit(underlying(\tau_{\text{concrete}}))) != 0` in a single CPU instruction.
4. **Poison Type (`TypeId.err`) Absorption:** Whenever a syntax error node (`invalid_parse_subtree` from `DR-01`), an undefined identifier, or a type mismatch occurs, the checker emits **one** primary diagnostic at the exact AST span and assigns `TypeId.err` to that AST node[cite: 2]. By defining $\tau_{\text{err}} \le_{\text{coerce}} \tau$ and $\tau \le_{\text{coerce}} \tau_{\text{err}}$ for all $\tau$, and by returning `TypeId.err` silently from field access (`err_val.field`), indexing (`err_val[i]`), and calls (`err_val(x)`) without emitting secondary diagnostics, a single typo never triggers a wall of cascading errors[cite: 2].
5. **Incomplete Dot-Completion Recovery in `corex lsp`:** When a user types `user.` at the end of a line, the fault-tolerant parser emits a postfix dot node with an empty member `StringId.empty` while still synthesizing the receiver type `user => User`[cite: 1, 2]. `corex lsp` reads the synthesized `TypeId` directly from the side-table (`node_types[receiver_node]`) in $\mathcal{O}(1)$ time to populate field and method completions[cite: 2].

### 1.5 Proof of Linear-Time $\mathcal{O}(N)$ Complexity Bounds

Let $N$ be the number of AST nodes in a function body, $D$ be the maximum nesting depth of the AST, and $P_{\max}$ be the maximum number of generic type parameters on a single function declaration (bounded by a small constant in practice, typically $1 \le P_{\max} \le 4$).

Every AST node $e$ is visited **at most once**—either in Synthesis mode ($\Rightarrow$) or in Checking mode ($\Leftarrow$). The subsumption rule $(\text{Sub}\Leftarrow)$ performs an $\mathcal{O}(1)$ `TypeId` equality or bitmask check on the already-synthesized type $\tau_1$ without re-traversing $e$'s subtree[cite: 3]. Because all composite types are canonically interned in `InternPool` upon construction (`Wyhash(0)` over child `TypeId`s), checking whether two arbitrarily deep structural types $\tau_1$ and $\tau_2$ are identical is a single 32-bit integer comparison (`id1 == id2`), taking $\mathcal{O}(1)$ time[cite: 2]. Furthermore, because CoreX bans implicit ad-hoc function overloading and binds binary operators (`+`, `-`, `*`, `<`, `==`) to canonical traits keyed on the left-hand operand's concrete type, there is zero branching search ($c = 1$) at operator nodes[cite: 3].

Consequently, for an AST of $N$ nodes, total time complexity is strictly $\mathcal{O}(N \cdot P_{\max}) = \mathcal{O}(N)$, and transient scratch memory in `BumpArena` is $\mathcal{O}(D \cdot P_{\max})$ (reclaimed in $\mathcal{O}(1)$ via `arena.restore(checkpoint)` at the end of each function)[cite: 2]. At an estimated 65–95 CPU cycles per AST node on a 3.6 GHz processor (4.5 AST nodes/LOC, where a 500,000 LOC/sec target provides a 2,000 ns/LOC or 1,600 cycles/node budget), CoreX's single-core type-checking architecture models at roughly 25 million AST nodes/sec (~5.5 million LOC/sec)—comfortably exceeding the `>= 500,000 LOC/sec` design target.

## 2. Deliverable 2: Constrained Type Groups & Ergonomic Generics Specification

### 2.1 Built-in Constrained Type Groups Hierarchy & 32-Bit Lattice Encoding

In systems programming, writing generic numerical, serialization, or container algorithms often requires verbose trait bounds. CoreX eliminates this ceremony by providing **11 Built-in Constrained Type Groups** as first-class `TYPE_IDENT` constraints in the predeclared prelude[cite: 1].

By assigning all 19 primitive types and 3 internal inference sentinels to static `TypeId`s in the range `0..21`, CoreX encodes every built-in Type Group as a 32-bit bitmask (`TypeGroupMask = u32`)[cite: 1]. Testing whether a concrete primitive type `t` belongs to a Type Group `G` is a single bit-test `((G.mask >> @intFromEnum(t)) & 1) != 0`, and testing whether Type Group $G_1$ is a subset of $G_2$ ($G_1 \subseteq G_2$) is `(G1.mask & ~G2.mask) == 0`.

### 2.2 User-Defined Type Groups & Underlying-Type (`~T`) Approximation

Beyond built-in groups, CoreX allows developers to define custom **Type Groups** using `DR-03`'s `type` alias syntax with the pipe union operator (`|`), intersection (`+`), and Go-inspired underlying-type approximation (`~T`)[cite: 1]:

```rust
// 1. Exact Nominal / Primitive Type Union Group:
pub type Int32Or64 = i32 | i64 | u32 | u64;

// 2. Underlying-Type Approximation Group (~T):
// Matches i64, u64, f64 AND any `distinct` newtype or range-refined type
// whose underlying representation is i64, u64, or f64 (e.g., `type Duration = distinct i64;`)
pub type Word64Number = ~i64 | ~u64 | ~f64;

// 3. Structural Slice / Container Type Group:
pub type ByteBuffer[E: ~u8] = [E] | Vec[E] | str;

// 4. Combined Type Group + Trait Capability Intersection:
pub type PrintableNumber = Number + Display + Hash;

// 5. Closed Structural / Sum-Type Group:
pub type JsonScalar = str | i64 | f64 | bool;
```

#### Formal Semantics of `~T` (Underlying-Type Approximation)
As demonstrated by Go 1.18+ generics (`constraints.Signed`, `cmp.Ordered`), a type constraint `i64 | f64` that admits *only* exact primitives rejects domain-specific types like `type Duration = distinct i64;` or `type Celsius = distinct f64;`, forcing callers to litter code with casts before calling `min(d1, d2)` or `clamp(temp, min_t, max_t)`. Conversely, if `distinct` types always matched `i64` implicitly everywhere, `distinct` would lose its type-safety barrier on non-generic functions (`fn transfer(uid: UserId, amount: Dollars)`)[cite: 2].

CoreX resolves this cleanly with two rules. First, all built-in mathematical and ordering groups (`Signed`, `Unsigned`, `Integer`, `Float`, `Number`, `Comparable`, `Equatable`, `Scalar`) include implicit `~T` underlying approximation over `distinct` numeric types that have opted into arithmetic (`@derive(Number)`) and over range-refined pattern types (`u32 is 1..=100`). Thus, passing two `Duration` values (`@derive(Number) type Duration = distinct i64;`) to `clamp(d, min_d, max_d)` instantiates `clamp[Duration](...) -> Duration` directly while preserving the `Duration` return type and preventing mixing `Duration` with `UserId` (`type UserId = distinct i64;`). Second, in a user-defined Type Group `type FastInt = i32 | i64;`, only exact `i32` and `i64` match; writing `type FastInt = ~i32 | ~i64;` explicitly admits any `distinct` or refined type whose terminal underlying type $\text{underlying}^*(U) \in \{\mathsf{i32}, \mathsf{i64}\}$.

> **Visual — Bit-Vector Type Groups and Bind-Once Default Unification Combine Ergonomic Signatures with O(1) Constraint Checking:** Top: Every primitive TypeId (0..20) occupies a dedicated bit position in a 32-bit word, enabling the compiler to test whether a type satisfies `Signed`, `Unsigned`, `Integer`, `Float`, `Number`, `Comparable`, `Equatable`, or `Scalar` in a single bitwise AND operation. Bottom: Writing a Type Group name directly as a parameter type (`val: Number, low: Number, high: Number`) defaults to Bind-Once unification (all parameters unify to a single concrete type `__G0`), whereas prefixing `any` (`a: any Number, b: any Number`) explicitly opts into Bind-Many independent type parameters.

### 2.3 Same-Type ("Bind-Once") vs. Independent-Type ("Bind-Many") Unification Semantics

A critical ergonomic design question occurs when a developer writes a Type Group directly in a function signature without an explicit `[T: Group]` bracket list:
```rust
pub fn clamp(val: Number, low: Number, high: Number) -> Number
```
In **C++20 Abbreviated Function Templates** (`auto min(Number auto a, Number auto b)`), every occurrence of a constrained `auto` parameter introduces an *independent* template parameter (`T1`, `T2`), meaning `min(5, 3.14)` deduces `T1 = int, T2 = double` and either fails inside the body or performs an unintended implicit conversion, and C++20 cannot constrain the return type to match the parameters without reverting to a full `template<Number T>` header. Conversely, in **Nim's Implicit Generics**, type classes default to **bind once** (`proc p(a: SomeNumber, b: SomeNumber): SomeNumber` binds `a`, `b`, and the return type to the *exact same* concrete type `T`), while prefixing `distinct` (`proc p(a: SomeNumber, b: distinct SomeNumber)`) opts into **bind many**.

CoreX adopts and formalizes the **Bind-Once by Default / `any` for Bind-Many** rule, giving developers effortless, bug-free signatures for both homogeneous and heterogeneous generics:

1. **Rule 1 — Bare Type Group Name (`G`) is Bind-Once Across the Signature:**
   When a Type Group identifier `G` (where `G` is a built-in Type Group or a user-defined `type G = A | B;` union group, and *not* a `dyn Trait` object) appears directly as a parameter type, nested parameter type (`&[Number]`, `Vec[Number]`), or return type in a function signature, the compiler synthesizes a **single shared generic type parameter `__G_G: G`** for that Group name across the entire function signature:
   ```rust
   // Surface Syntax written by developer:
   pub fn clamp(val: Number, low: Number, high: Number) -> Number {
       if val < low { low } else if val > high { high } else { val }
   }

   // Exact Compiler AST Desugaring (Bind-Once):
   pub fn clamp[__G0: Number](val: __G0, low: __G0, high: __G0) -> __G0 {
       if val < low { low } else if val > high { high } else { val }
   }
   ```
   Under this rule, calling `clamp(50i32, 0, 100)` synthesizes `val => i32`, binds `__G0 = i32`, and checks the untyped literals `0 <= i32` and `100 <= i32` with zero casts[cite: 3]. Calling `clamp(50i32, 0.0f64, 100.0f64)` is immediately caught at the second argument as a compile-time type mismatch (`expected i32 (bound from parameter 'val' via Type Group 'Number'), found f64`).
2. **Rule 2 — Prefix `any G` (or Explicit `[T: G, U: G]`) is Bind-Many (Independent Types):**
   When a function intentionally accepts *independent* concrete types from the same Type Group (for example, multiplying a value by an arbitrary float precision factor, or converting between two arbitrary integer widths), the developer either prefixes the inline Type Group with `any` (introduced as a contextual modifier before a Type Group in parameter position) or writes explicit type parameters `[T: Number, U: Number]`[cite: 1]:
   ```rust
   // Surface Syntax (Bind-Many via `any` prefix):
   pub fn dot_convert(a: any Integer, b: any Integer) -> i64 {
       (a as i64) * (b as i64)
   }

   // Exact Compiler AST Desugaring (Bind-Many):
   pub fn dot_convert[__G0: Integer, __G1: Integer](a: __G0, b: __G1) -> i64 {
       (a as i64) * (b as i64)
   }
   ```
   CoreX uses `any Integer` rather than Nim's `distinct Integer` for Bind-Many parameters because `distinct` is already reserved in CoreX for nominal newtype declarations (`type UserId = distinct u64;`); `any Integer` reads naturally in English ("accepts *any* `Integer` independently for each parameter") while keeping `distinct` unambiguous[cite: 1, 2]. Furthermore, `any G` is forbidden in return-type position because an unbound independent return type cannot be uniquely determined from the parameters unless written explicitly as `[T: G, R: G](x: T) -> R`.
3. **Rule 3 — Explicit Square-Bracket Generics `[T: G, U: G]` for Multi-Group Coupling:**
   Whenever a function needs two distinct type variables that are each referenced multiple times (e.g., `fn zip[T: Copy, U: Copy](a: &[T], b: &[U]) -> Vec[(T, U)]`), standard `DR-03` square-bracket generic parameters `[T: Copy, U: Copy]` are used directly[cite: 1].

| Signature Pattern | CoreX Surface Syntax (`.cx`) | Desugared Polymorphic Scheme | `f(10i32, 20i32)` | `f(10i32, 20)` (`20` untyped) | `f(10i32, 20i64)` |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Inline Bind-Once (Default)** | `fn max(a: Number, b: Number) -> Number` | `∀[T: Number]. fn(T, T) -> T` | Valid (`T = i32`) | Valid (`20 <= i32`, `T = i32`) | **Compile Error** (`E0402`: `b` expected `i32`, found `i64`) |
| **Explicit Same-Type** | `fn max[T: Number](a: T, b: T) -> T` | `∀[T: Number]. fn(T, T) -> T` | Valid (`T = i32`) | Valid (`20 <= i32`, `T = i32`) | **Compile Error** (`E0402`: `b` expected `i32`, found `i64`) |
| **Inline Bind-Many (`any`)** | `fn cmp_wide(a: any Integer, b: any Integer) -> bool` | `∀[T1: Integer, T2: Integer]. fn(T1, T2) -> bool` | Valid (`T1=i32, T2=i32`) | Valid (`T1=i32, T2=i64` default) | Valid (`T1 = i32, T2 = i64`) |
| **Explicit Independent** | `fn cmp_wide[T: Integer, U: Integer](a: T, b: U) -> bool` | `∀[T: Integer, U: Integer]. fn(T, U) -> bool` | Valid (`T=i32, U=i32`) | Valid (`T=i32, U=i64` default) | Valid (`T = i32, U = i64`) |

### 2.4 Definition-Site Checking & Monomorphization Lowering

Unlike C++ templates or Zig `anytype` functions—which defer body type checking until a call site instantiates the template—CoreX type-checks every generic function body **once at its definition site** against the exact capability contract of its Type Group or Trait bounds[cite: 2, 3].

When type-checking `fn clamp[T: Number](val: T, low: T, high: T) -> T`, the type parameter `T` has a known `TypeGroupMask` (`0x001FFFE0`). Any operation invoked on `T` inside the body (such as `val < low`, `val + low`, or `0` literal coercion) is checked against the **intersection of capabilities** of all members of `Number`. If the developer attempts `val << 2` inside a function constrained by `Number` (which includes `f32` and `f64`), the compiler immediately rejects `val << 2` at the definition of `clamp` (`error[E0415]: bitwise shift '<<' is not supported by all members of Type Group 'Number' (missing for 'f32', 'f64'); restrict bound to 'Integer'`), even if `clamp` is never called.

During HIR-to-MIR lowering (`DR-01` / `DR-02`), every concrete call site `clamp[i32]` or `clamp[f64]` is recorded in a deduplicated `MonoCollector` keyed by `MonoInstanceKey = (FnDefId, TypeIdSlice)`[cite: 2, 3]. Because Type Groups are strictly compile-time constraints and **cannot** be used as dynamically boxed runtime values (there is no heap-boxed `Number` value at runtime unless explicitly wrapped in `&let dyn Trait` for a dyn-compatible trait), `clamp[i32]` lowers to a direct scalar machine function taking and returning 32-bit registers with **zero boxing, zero vtable pointers, and full inlining eligibility**[cite: 3]. Furthermore, following `DR-02`, when a generic container function (such as `Vec[T]::len(&self)` or `SlotMap[K, V]::get(&self, k)`) is instantiated across distinct nominal pointer or scalar types that share identical byte size, alignment, and trivial move/drop semantics without invoking type-specific trait methods, the MIR monomorphizer applies Pointer-Shape Identical Code Folding (ICF) to share a single canonical machine-code body across layout-identical instantiations[cite: 3].

## 3. Numeric Hierarchy, Literal Polymorphism & Overflow Safety

### 3.1 Explicit Bit-Width Numeric Hierarchy & Zero Implicit Promotion

C and C++ suffer from subtle bugs caused by *usual arithmetic conversions* and *integer promotion rules*—where adding or comparing a signed and unsigned integer silently converts values or depends on compiler-specific `int` widths.

CoreX eliminates implicit integer/float widening and signedness conversions entirely. The language provides six signed two's-complement integers (`i8`, `i16`, `i32`, `i64`, `i128`, `isize`), six unsigned integers (`u8`, `u16`, `u32`, `u64`, `u128`, `usize`), and two IEEE-754 binary floating-point types (`f32`, `f64`)[cite: 1]. Only `isize` and `usize` vary with target pointer width (32-bit on `wasm32`, 64-bit on `x86_64`, `aarch64`, and `riscv64`); all other widths are platform-invariant[cite: 2]. Given `let a: i32 = 10;` and `let b: i64 = 20;`, the expression `a + b` is a compile-time type error (`expected i32, found i64`). Even converting between `i8` and `u8` (same bit width, since `u8` cannot represent negative values) or `i32` and `i64` requires an explicit `as` cast (`(a as i64) + b`)[cite: 1].

Because concrete-to-concrete conversions are forbidden, forcing developers to suffix every literal (`x_u16 + 1u16`, `idx + 4usize`) would create unnecessary syntactic friction. CoreX's bidirectional literal rules (`IntLit<=` and `FloatLit<=`) solve this cleanly: in `let offset: usize = base_idx + 4;`, `base_idx` synthesizes `usize`, the `+` operator on `usize` switches its right-hand operand into Checking Mode ($\Leftarrow \mathsf{usize}$), and the untyped literal `4` (`untyped_int(4)`) verifies $0 \le 4 \le \text{usize::MAX}$ at compile time and becomes `4usize` with **zero `as` casts and zero type suffixes**[cite: 3]. Similarly, in `let ratio: f64 = count_f64 * 2;`, an `untyped_int(2)` checked against an expected `f64` or `f32` type coerces at compile time provided its integer magnitude is losslessly representable in the target IEEE-754 mantissa ($|v| \le 2^{24}$ for `f32`, $|v| \le 2^{53}$ for `f64`). Conversely, a float literal (`2.0`) never coerces to an integer type. Arithmetic expressions composed exclusively of literals and `const` declarations (`1 << 40`, `64 * 1024 * 1024`) are evaluated at compile time in exact 128-bit arithmetic before checking whether the final result fits into the target type:
```rust
let bad_byte: u8 = 200 + 100; // Compile Error E0301: literal value '300' overflows target type 'u8' (valid range: 0..=255)
```

### 3.2 Compile-Time vs. Runtime Integer Overflow Semantics

Integer overflow in C is undefined behavior for signed integers and silent modular wraparound for unsigned integers—a combination that both hides arithmetic bugs in unsigned quantities (such as `a - b` when `b > a`) and permits unexpected compiler optimizations on signed checks. Synthesizing the explicit operator design of **Zig (`+%`, `+|`, `@addWithOverflow`)** and **Carbon's build modes**, CoreX enforces explicit, unambiguous overflow semantics:

| Arithmetic Form | CoreX Syntax / Intrinsics | Compile-Time (`const`) Behavior | Debug & Safe Builds (`-O0`, `-OSafe`) | ReleaseFast Builds (`-OReleaseFast`) | Intended Engineering Domain |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **1. Default Checked Arithmetic** | `a + b`, `a - b`, `a * b`, `a / b`, `-a`, `a += b` | **Compile Error** (`E0301`) on overflow or division by zero | **Deterministic Trap / Panic** at exact source line | **Defined Two's-Complement Wrap** (or configurable abort via `--hardened`; **never** C-style UB that deletes safety branches) | General quantities, array sizes, financial counters, loop bounds where overflow indicates a bug. |
| **2. Explicit Wrapping (Modular)** | `a +% b`, `a -% b`, `a *% b`, `-%a`, `a +%= b`, `a -%= b`, `a *%= b` | Evaluates modular $2^W$ two's-complement wrap at compile time | **Two's-Complement Modular Wrap** ($2^W$) with zero trap instructions | **Two's-Complement Modular Wrap** ($2^W$) | Cryptographic hashes (`Wyhash`), PRNGs, checksums, ring buffer indices, sequence numbers[cite: 2]. |
| **3. Explicit Saturating (Clamped)** | `a +\| b`, `a -\| b`, `a *\| b`, `a +\|= b`, `a -\|= b`, `a *\|= b` | Evaluates clamped to `[T::MIN, T::MAX]` at compile time | **Clamps to `T::MIN` or `T::MAX`** | **Clamps to `T::MIN` or `T::MAX`** | DSP audio mixing, pixel/color arithmetic, gain controls, progress counters, brightness. |
| **4. Tuple Overflow Intrinsics & Checked Methods** | `@add_with_overflow(a, b) -> (T, bool)`, `a.checked_add(b) -> T?` | Evaluates exact `(wrapped, overflowed)` or `.Some`/`.None` | Returns `(wrapped_val, did_overflow)` using hardware carry/overflow flag | Returns `(wrapped_val, did_overflow)` using hardware carry/overflow flag | Untrusted network/file parsing boundaries, multi-word arithmetic carry propagation. |

In bitwise shift operations (`a << b` and `a >> b`), the left-hand operand `a` must satisfy `Integer` and the shift count `b` may be any `Unsigned` type (or an `untyped_int` checked against `0..bit_width(a) - 1`). Shifting by a count $\ge \text{bit\_width}(a)$ is a compile-time error for constants and traps in Debug/Safe builds (use `a.wrapping_shl(b)` when hardware mask-modulo shifting is desired).

## 4. Algebraic Types, Null Safety & Refinement/Newtype Ergonomics

### 4.1 Null Safety (`T?`) and Recursive Multi-Layer Niche Optimization

CoreX has **no `null` or `nil` value** in its safe type grammar[cite: 1, 3]. Absence of a value is represented exclusively by `Option[T]`, written ergonomically via postfix `T?` (`UserRole?`, `OwnPtr[AvlNode[K, V]]?`, `(&let User)?`)[cite: 1].

To guarantee that `T?` and general algebraic `enum` types incur zero memory bloat, the CoreX layout engine tracks a **Niche Interval Summary (`NicheRange { start: u128, end: u128 }`)** for every `TypeId` in `InternPool`[cite: 3]. All safe second-class projections (`&let T`, `&inout T`), owned heap pointers (`OwnPtr[T]`, `Box[T]`), and function pointers (`fn(...) -> R`) are statically non-null, leaving bit pattern `0x0` as a niche[cite: 1, 3]. Consequently, `sizeof((&let T)?) == 8` bytes and `sizeof(OwnPtr[Node]?) == 8` bytes, and `.None` is represented at the machine level by the zero value (`0x0`)[cite: 1, 3]. Similarly, `bool` occupies 1 byte (`0x00` = `false`, `0x01` = `true`), leaving 254 niches (`0x02..=0xFF`), while Unicode scalar `char` leaves unused bit ranges above `0x10FFFF`[cite: 3].

When computing the layout of a `struct`, the compiler sorts fields by alignment and selects the field with the largest available niche count as the primary niche carrier[cite: 3]. Wrapping a type in an `enum` consumes only the exact number of niche bit-patterns required by its unit variants and propagates the remaining niche interval upward (*niche stacking*): `bool` (1 byte, 254 niches) $\rightarrow$ `bool?` (1 byte, consumes `2`, 253 niches left) $\rightarrow$ `bool??` (1 byte, consumes `3`, 252 niches left), fitting up to 254 unit variants wrapping a `bool` inside a single byte[cite: 3]. Additionally, per `DR-02`, whenever the largest variant of an `enum` exceeds the second-largest variant by more than 64 bytes (one cache line), `corexc` emits a `@warn(variant_size_skew)` layout diagnostic recommending cold-path boxing (`OwnPtr[DiagnosticPayload]`) so a single 512-byte cold variant never inflates a 1,000,000-element hot array from 16 MB to 520 MB[cite: 1, 3].

### 4.2 Zero-Cost Range & Pattern Refinements (`T is Pattern`)

Historically, languages like Rust had to define special-case wrapper structs (`NonZeroU8`, `NonZeroUsize`, `NonZeroI8`) to inform the compiler that `0` (or `-128` for balanced signed integers) is an unoccupied niche. Building on Ada range subtypes and the Rust **Pattern Types RFC (`type is pattern`)**, CoreX integrates **Zero-Cost Pattern-Refined Types (`T is Pattern`)** directly into the type grammar:

```rust
// 1. Standard library NonZero types are pure 1-line range refinements in CoreX:
pub type NonZeroU32   = u32 is 1..=u32::MAX;
pub type NonZeroUsize = usize is 1..=usize::MAX;
pub type BalancedI8   = i8 is -127..=127;       // Leaves -128 (0x80) as niche for BalancedI8? (1 byte!)

// 2. Domain-specific bounded integer & enum refinements:
pub type Errno        = u32 is 0..4096;         // 4096..=u32::MAX are niches!
pub type Month        = u8 is 1..=12;           // sizeof(Month?) == 1 byte (0 represents .None)!
pub type HttpSuccess  = u16 is 200..=299;

// 3. Structural slice refinements (compile-time non-empty slice guarantee):
pub type NonEmptySlice[T] = [T] is [_, ..];

pub fn minimum[T: Comparable](items: &[T] is [_, ..]) -> T {
    // Compiler statically knows `items.len() >= 1`; bounds check on `items[0]` is elided!
    var min_val = items[0];
    for item in items[1..] {
        if item < min_val { min_val = item; }
    }
    min_val
}
```

#### Subtyping, Flow-Sensitive Narrowing, and Layout Variance Rules
As noted in the Rust internals analysis of pattern types and subtyping, if `(usize is 1..) <: usize` were treated as covariant inside `Option[T]` (`Option[usize is 1..] <: Option[usize]`), the compiler could *not* niche-optimize `Option[usize is 1..]` to 8 bytes because `Option[usize]` requires 16 bytes and subtype coercion requires identical memory layout. CoreX resolves this dilemma cleanly with three rules:
1. **Value-Level Widening Coercion ($\tau \;\mathsf{is}\; P \le_{\text{coerce}} \tau$), Invariant Container Layout:** A value of type `T is P` implicitly widens (coerces by value in registers) to its base type `T` (or a wider pattern `T is P_wide` where $P \subseteq P_{\text{wide}}$) in $\mathcal{O}(1)$ time. However, container type constructors (`Option[T]`, `Vec[T]`, `&inout T`) are **layout-invariant** with respect to refinements (or wrapped in a zero-cost `struct` newtype when covariance is not needed): `Option[u8 is 1..=12]` (`Month?`) has a distinct 1-byte layout from 2-byte `Option[u8]`, so `Month?` and `NonZeroUsize?` always achieve full niche optimization (`sizeof(Month?) == 1`, `sizeof(NonZeroUsize?) == 8`).
2. **Compile-Time Literal Verification:** In Checking Mode ($\Leftarrow \tau \;\mathsf{is}\; P$), a constant or literal expression (`let m: Month = 12;`, `minimum(&[0, 1, 2, 3])`) is verified against pattern $P$ at compile time with zero runtime instructions.
3. **Flow-Sensitive Narrowing via `let ... else` and `match`:** To construct a refined type from a dynamic runtime value `input: u8`, the developer uses either a refutable pattern binding (`let month @ 1..=12 = input else { return .Err(.InvalidMonth); };` or `match slice { s @ [_, ..] => minimum(s), [] => ... }`) or the synthesized constructor `Month::try_from(input) -> Month?`[cite: 1].

### 4.3 Nominal `distinct` Newtypes, `#soa` Slices, and `bit_field` Typing

#### 1. `distinct` Nominal Newtypes
Following `DR-01` and Odin, `type Name = distinct BaseType;` creates a brand-new nominal `TypeId` with the exact size, alignment, ABI register class, and niche summary of `BaseType`, but with zero implicit conversions to or from `BaseType`[cite: 2, 3]:
```rust
pub type UserId   = distinct u64;
pub type TenantId = distinct u64;

// Zero-cost explicit conversion via `as`:
let uid = 42 as UserId;
let raw_u64 = uid as u64;
// let bad: TenantId = uid; // Compile Error E0400: expected 'TenantId', found 'distinct' type 'UserId'
```
A `distinct` type can define its own `impl UserId { ... }` methods and traits[cite: 1]. By default, a `distinct` type over a primitive does not inherit raw `+` or `*` operators (preventing `uid1 + uid2` on `UserId`), *unless* the declaration includes `@derive(Number)` or `@derive(Add, Sub, Comparable)` (e.g., `@derive(Number) pub type Meters = distinct f64;`), which enables arithmetic and admits `Meters` into `~f64` and `Number` Type Groups[cite: 1].

#### 2. First-Class `#soa` Slice, Array, and Vector Typing
Given `pub struct Particle { pub pos: Vec3, pub vel: Vec3, pub hp: u32 }`, the type constructor `#soa[Particle; N]`, `#soa[Particle]`, or `#soa Vec[Particle]` transforms the physical layout from an Array-of-Structs into parallel field arrays while preserving unified typing rules[cite: 1, 3]. If `s` has type `#soa[T]` (or `#soa Vec[T]`) and `field: F` is a field of `T`, then `s.field` synthesizes a contiguous column slice `[F]` (`&[F]` or `&mut [F]`) with zero stride overhead[cite: 3]. Indexing `s[i]` yields a virtual projection `#soa_elem T`, where accessing `s[i].field` in `let`, `inout` (`&s[i].field += 10`), `sink`, or `set` mode rewrites directly in `Sema` to `s.field[i]`—synthesizing type `F` and computing the exact same pointer address `&s.field[i]` without gathering unused fields of `T` onto the stack[cite: 3].

#### 3. LSB `bit_field` Typing & Synthesized Value Projections
Given `pub type FrameHeader = bit_field u16 { pub fin: bool | 1, pub opcode: Opcode | 4, pub delta: i16 | 6, pub rsv: u8 | 5 };` (where $\sum w_i = 1 + 4 + 6 + 5 = 16 \le \text{bit\_width}(\mathsf{u16})$ is verified at compile time)[cite: 3], reading `header.delta` synthesizes the declared field type `i16` and automatically sign-extends the 6-bit signed field to 16 bits[cite: 3]. Taking a raw pointer `*i16` to a bit-field is a static type error (avoiding Zig's unaligned bit-pointer complexity)[cite: 3]. However, passing `&header.delta` to an `inout i16` parameter is legal and type-safe: following `DR-02`'s Hylo/Ada subscript-synthesis model, the type checker marks the argument node with `CoercionKind.BitFieldInoutProject`, which extracts `header.delta` into a temporary register `var __tmp: i16`, passes `&__tmp` to the callee, and bit-masks `__tmp` back into bits `5..=10` of `header` immediately upon return[cite: 3].

> **Visual — Niche-Stacked Refinements and the 14-Byte SoA TypeArena Maximize Cache Density in Both Runtime Data and the Compiler:** Top: Range refinements (`type Month = u8 is 1..=12;`, `type NonZeroU64 = u64 is 1..=MAX;`) expose unoccupied bit patterns directly to the enum layout engine, packing `Month?` and `bool??` into 1 byte and `NonZeroU64?` into 8 bytes with zero tag overhead, while `@warn(variant_size_skew)` guides cold-path boxing to shrink a 1M-element event buffer from 520 MB to 16 MB. Bottom: Inside `corexc`, every type is a 32-bit `TypeId` handle indexing into a 14-byte-per-type Struct-of-Arrays (`MultiArrayList`) `InternPool` with zero alignment padding.

## 5. Deliverable 3: Compiler Data Structures (`TypeArena`, `TypeId`, `InternPool`, `SubstitutionMap`)

To satisfy `DR-01`'s Data-Oriented Design mandate and guarantee a mechanical 1-to-1 translation from the Zig Stage-0 compiler (`stage0/corex`) to the self-hosted Stage-1 CoreX compiler (`src/sema/type_arena.cx`), the type representation avoids heap-allocated pointer trees (`Type*`) entirely[cite: 2].

### 5.1 Architectural Overview of `TypeId`, `InternPool`, and `SubstitutionMap`

Indices `0..18` of `TypeId(u32)` are permanently pre-assigned to CoreX's 19 primitive types (`unit` through `f64`), indices `19..21` are reserved for compiler inference sentinels (`untyped_int`, `untyped_float`, `err`), and indices `32..42` are reserved for the 11 built-in Constrained Type Groups (`Signed` through `Copy`)[cite: 1]. Because their indices are compile-time constants, checking `ty == .i32_ty`, `ty == .err_ty`, or testing a `TypeGroupMask` requires **zero memory dereferences**.

Dynamic composite, nominal, generic, and refinement types (`TypeId >= 64`) are stored in a Struct-of-Arrays (`MultiArrayList(TypeNode)`) decomposed into four dense parallel arrays: `tags: [*]TypeTag` (1 byte), `flags: [*]TypeFlags` (1 byte), `hashes: [*]u32` (4 bytes), and `datas: [*]TypeData` (8 bytes: `lhs: u32, rhs: u32`), totaling **14 bytes per interned type with 0 bytes of alignment padding**[cite: 2]. Variable-length payloads (such as function parameter lists, struct field lists, union Type Group members, or range refinement bounds `min_lo, min_hi, max_lo, max_hi`) are appended to a contiguous `extra_data: []u32` trail, and deduplicated via an open-addressed power-of-two `Wyhash(0)` hash table[cite: 2].

Every interned type carries a 1-byte bitfield `TypeFlags` that accelerates tree queries to $\mathcal{O}(1)$ time: `has_type_vars (1 << 0)` is set if the type is a `type_param` or transitively contains any generic `type_param` (allowing `SubstitutionMap.subst()` to return concrete types immediately in $\mathcal{O}(1)$ time without inspecting child nodes); `has_error (1 << 1)` is set if the type is `.err_ty` or transitively contains `.err_ty` (enabling $\mathcal{O}(1)$ poison suppression); `is_copy (1 << 2)` marks bitwise `Copy` types; and `is_distinct (1 << 3)` and `has_niche (1 << 4)` support `~T` approximation and niche layout queries[cite: 3]. Furthermore, because `InternPool` hashes canonical structural representations with `Wyhash(0)` and inserts types in deterministic file/AST order, every `TypeId` and function signature has a stable 64-bit structural fingerprint (`SemanticHash = u64`). In `corex lsp`, if a user edits inside a function body, the module's top-level signature fingerprint remains unchanged, invalidating only that single function's local type-check query while reusing 100% of the module's `InternPool`[cite: 2, 3].

### 5.2 Stage-0 Zig Implementation (`stage0/src/type_system.zig`)

The following Zig implementation builds directly on `stage0/src/mem_foundation.zig` from `DR-01`, enforcing `comptime` layout assertions, zero-padding SoA arrays, $\mathcal{O}(1)$ 32-bit `TypeGroupMask` evaluation, and fast `SubstitutionMap` instantiation[cite: 2]:

```zig
//! CoreX Stage-0 Compiler (`stage0/corex`)
//! Module: `stage0/src/type_system.zig`
//! Implements `TypeId`, `TypeGroupMask`, `InternPool` (`TypeArena`), and `SubstitutionMap`.
//! Aligns with DR-01 (`BumpArena`, `StringId`, `NodeIndex`, `Wyhash(0)`) and DR-03 surface syntax.

const std = @import("std");
const assert = std.debug.assert;
const Allocator = std.mem.Allocator;
const mem = @import("mem_foundation.zig");
const BumpArena = mem.BumpArena;
const StringId = mem.StringId;
const NodeIndex = mem.NodeIndex;

// ============================================================================
// 1. CANONICAL TypeId(u32) & 32-BIT TypeGroupMask ENCODING
// ============================================================================

pub const TypeId = enum(u32) {
    // --- 0..18: The 19 Reserved CoreX Primitive Types (DR-03) ---
    unit_ty = 0,
    never_ty = 1,
    bool_ty = 2,
    char_ty = 3,
    str_ty = 4,
    i8_ty = 5,
    i16_ty = 6,
    i32_ty = 7,
    i64_ty = 8,
    i128_ty = 9,
    isize_ty = 10,
    u8_ty = 11,
    u16_ty = 12,
    u32_ty = 13,
    u64_ty = 14,
    u128_ty = 15,
    usize_ty = 16,
    f32_ty = 17,
    f64_ty = 18,

    // --- 19..21: Internal Inference & Error Sentinels ---
    untyped_int_ty = 19,
    untyped_float_ty = 20,
    err_ty = 21,

    // --- 32..42: Reserved Built-in Constrained Type Groups ---
    group_signed = 32,
    group_unsigned = 33,
    group_integer = 34,
    group_float = 35,
    group_number = 36,
    group_numeric = 37,
    group_comparable = 38,
    group_equatable = 39,
    group_bytes = 40,
    group_scalar = 41,
    group_copy = 42,

    // --- 64..0xFFFFFFFE: Dynamically Interned Types in InternPool ---
    first_dynamic = 64,
    none = std.math.maxInt(u32),
    _,

    pub inline fn isNone(self: TypeId) bool {
        return self == .none;
    }

    pub inline fn isError(self: TypeId) bool {
        return self == .err_ty;
    }

    pub inline fn isPrimitiveOrSentinel(self: TypeId) bool {
        return @intFromEnum(self) <= 21;
    }

    pub inline fn isBuiltinGroup(self: TypeId) bool {
        const raw = @intFromEnum(self);
        return raw >= 32 and raw <= 42;
    }

    pub inline fn toU32(self: TypeId) u32 {
        return @intFromEnum(self);
    }

    /// Returns the single-bit mask (1 << id) if `self` is in 0..31, else 0.
    pub inline fn primitiveBit(self: TypeId) u32 {
        const raw = @intFromEnum(self);
        return if (raw < 32) (@as(u32, 1) << @intCast(raw)) else 0;
    }
};

/// Precomputed 32-bit bitmasks for O(1) primitive Type Group membership & subtyping.
pub const TypeGroupMask = struct {
    pub const SIGNED: u32 = 0x000007E0; // i8..isize (bits 5..10)
    pub const UNSIGNED: u32 = 0x0001F800; // u8..usize (bits 11..16)
    pub const INTEGER: u32 = 0x0009FFE0; // SIGNED | UNSIGNED | untyped_int (bit 19)
    pub const FLOAT: u32 = 0x00160000; // f32 | f64 | untyped_float (bits 17..18, 20)
    pub const NUMBER: u32 = 0x001FFFE0; // INTEGER | FLOAT
    pub const COMPARABLE: u32 = 0x001FFFF8; // NUMBER | char(3) | str(4)
    pub const EQUATABLE: u32 = 0x001FFFFD; // COMPARABLE | bool(2) | unit(0)
    pub const SCALAR: u32 = 0x001FFFEC; // NUMBER | bool(2) | char(3)
    pub const COPY_PRIM: u32 = 0x001FFFED; // SCALAR | unit(0)

    pub inline fn forBuiltinGroup(group_id: TypeId) u32 {
        return switch (group_id) {
            .group_signed => SIGNED,
            .group_unsigned => UNSIGNED,
            .group_integer => INTEGER,
            .group_float => FLOAT,
            .group_number, .group_numeric => NUMBER,
            .group_comparable => COMPARABLE,
            .group_equatable => EQUATABLE,
            .group_scalar => SCALAR,
            .group_copy => COPY_PRIM,
            else => 0,
        };
    }

    /// O(1) bitwise check: does primitive type `candidate` belong to `mask`?
    pub inline fn containsPrimitive(mask: u32, candidate: TypeId) bool {
        return (mask & candidate.primitiveBit()) != 0;
    }

    /// O(1) subset check: is every primitive in `sub_mask` also in `super_mask`?
    pub inline fn isSubset(sub_mask: u32, super_mask: u32) bool {
        return (sub_mask & ~super_mask) == 0;
    }
};

// ============================================================================
// 2. TYPE NODE TAGS, FLAGS & EXTRA PAYLOAD STRUCTURES
// ============================================================================

pub const TypeTag = enum(u8) {
    primitive = 0,
    builtin_group = 1,
    /// `T?` (`Option[T]`): `lhs = inner_type`, `rhs = niche_kind`
    option_type = 2,
    /// `E!T` error union: `lhs = error_type`, `rhs = payload_type`
    error_union = 3,
    /// `[T]`: `lhs = elem_type`, `rhs = 0` (or `1` for `#soa[T]`)
    slice_type = 4,
    /// `[T; N]`: `lhs = elem_type`, `rhs = extra_index` (`ArrayExtra`)
    array_type = 5,
    /// Second-class projection or pointer (`&let T`, `&inout T`, `own T`, `*T`, `*mut T`)
    pointer_type = 6,
    /// Tuple `(T1, T2, ...)`: `lhs = extra_start`, `rhs = len`
    tuple_type = 7,
    /// Function `fn(m1 T1, ...) -> R`: `lhs = extra_start` (`FnTypeExtra`), `rhs = param_count`
    fn_type = 8,
    /// Nominal `struct`, `enum`, or `union`: `lhs = decl_node`, `rhs = extra_start` (`NominalInstExtra`)
    nominal_type = 9,
    /// `type Foo = distinct Bar`: `lhs = name_str_id`, `rhs = underlying_type_id`
    distinct_type = 10,
    /// `T is low..=high`: `lhs = base_type_id`, `rhs = extra_start` (`RangeRefinementExtra`)
    range_refined_type = 11,
    /// `bit_field BackingInt { ... }`: `lhs = backing_int_type`, `rhs = decl_node`
    bit_field_type = 12,
    /// Generic Type Parameter `T: Bound` (or inline `__G0: Number`):
    /// `lhs = name_str_id`, `rhs = bound_type_id`
    type_param = 13,
    /// User-defined Type Group union `type G = A | ~B | C`:
    /// `lhs = prim_bitmask`, `rhs = extra_start` (`UserGroupExtra`)
    user_type_group = 14,
};

pub const TypeFlags = packed struct(u8) {
    has_type_vars: bool = false,
    has_error: bool = false,
    is_copy: bool = false,
    is_distinct: bool = false,
    has_niche: bool = false,
    is_soa: bool = false,
    allow_underlying_approx: bool = false,
    _reserved: u1 = 0,
};

pub const ParamMode = enum(u8) {
    let_mode = 0,
    inout_mode = 1,
    sink_mode = 2,
    set_mode = 3,
};

/// 14-byte Struct-of-Arrays (SoA) element decomposed by `std.MultiArrayList(TypeNode)`.
/// Parallel arrays: `tags` (1B) + `flags` (1B) + `hashes` (4B) + `datas` (8B) = 14B, 0 padding!
pub const TypeNode = struct {
    tag: TypeTag,
    flags: TypeFlags,
    hash: u32,
    data: Data,

    pub const Data = extern struct {
        lhs: u32,
        rhs: u32,
    };

    pub const FnTypeExtra = extern struct {
        return_type: TypeId,
        /// Packed array of `param_count` `TypeId`s followed by packed `ParamMode` words in `extra_data`.
        params_start: u32,
        modes_start: u32,
    };

    pub const RangeRefinementExtra = extern struct {
        min_lo: u32,
        min_hi: u32,
        max_lo: u32,
        max_hi: u32,
    };

    pub const UserGroupExtra = extern struct {
        approx_prim_mask: u32,
        nominal_members_start: u32,
        nominal_members_len: u32,
    };
};

// ============================================================================
// 3. InternPool / TypeArena (CANONICAL O(1) TYPE INTERNER)
// ============================================================================

pub const InternPool = struct {
    pub const EMPTY_BUCKET: u32 = std.math.maxInt(u32);
    pub const STATIC_COUNT: u32 = 64;

    backing_allocator: Allocator,
    arena: *BumpArena,
    /// SoA storage: 14 bytes per interned type, 0 bytes padding.
    nodes: std.MultiArrayList(TypeNode) = .{},
    /// Contiguous 32-bit payload trail for variable-length type children.
    extra_data: std.ArrayListUnmanaged(u32) = .{},
    /// Open-addressed deduplication hash table (`hash & mask -> TypeId`).
    buckets: []u32 = &[_]u32{},

    pub fn init(backing_allocator: Allocator, arena: *BumpArena, initial_cap: u32) !InternPool {
        var self = InternPool{
            .backing_allocator = backing_allocator,
            .arena = arena,
        };
        const cap = std.math.ceilPowerOfTwoAssert(u32, @max(initial_cap, 256));
        self.buckets = try backing_allocator.alloc(u32, cap);
        @memset(self.buckets, EMPTY_BUCKET);

        try self.nodes.ensureTotalCapacity(backing_allocator, STATIC_COUNT);
        // Pre-populate static reserved slots 0..63 so `TypeId` indexes directly into `nodes`.
        var i: u32 = 0;
        while (i < STATIC_COUNT) : (i += 1) {
            const tid: TypeId = @enumFromInt(i);
            const is_group = tid.isBuiltinGroup();
            const mask = if (is_group) TypeGroupMask.forBuiltinGroup(tid) else tid.primitiveBit();
            const is_copy = (TypeGroupMask.COPY_PRIM & tid.primitiveBit()) != 0;
            const has_niche = (tid == .bool_ty or tid == .char_ty or tid == .never_ty);
            self.nodes.appendAssumeCapacity(.{
                .tag = if (is_group) .builtin_group else .primitive,
                .flags = .{
                    .has_error = (tid == .err_ty),
                    .is_copy = is_copy,
                    .has_niche = has_niche,
                },
                .hash = hashKey(.primitive, i, mask),
                .data = .{ .lhs = i, .rhs = mask },
            });
        }
        return self;
    }

    pub fn deinit(self: *InternPool) void {
        self.nodes.deinit(self.backing_allocator);
        self.extra_data.deinit(self.backing_allocator);
        if (self.buckets.len > 0) {
            self.backing_allocator.free(self.buckets);
        }
    }

    pub inline fn hashKey(tag: TypeTag, lhs: u32, rhs: u32) u32 {
        var buf: [9]u8 = undefined;
        buf[0] = @intFromEnum(tag);
        std.mem.writeInt(u32, buf[1..5], lhs, .little);
        std.mem.writeInt(u32, buf[5..9], rhs, .little);
        const h64 = std.hash.Wyhash.hash(0, &buf);
        return @truncate(h64 ^ (h64 >> 32));
    }

    pub inline fn getTag(self: *const InternPool, id: TypeId) TypeTag {
        return self.nodes.items(.tag)[id.toU32()];
    }

    pub inline fn getFlags(self: *const InternPool, id: TypeId) TypeFlags {
        return self.nodes.items(.flags)[id.toU32()];
    }

    pub inline fn getData(self: *const InternPool, id: TypeId) TypeNode.Data {
        return self.nodes.items(.data)[id.toU32()];
    }

    /// Resolves the terminal underlying type `~T` across `distinct` and range-refined types.
    pub fn underlyingType(self: *const InternPool, id: TypeId) TypeId {
        var curr = id;
        while (true) {
            const tag = self.getTag(curr);
            if (tag == .distinct_type) {
                curr = @enumFromInt(self.getData(curr).rhs);
            } else if (tag == .range_refined_type) {
                curr = @enumFromInt(self.getData(curr).lhs);
            } else {
                return curr;
            }
        }
    }

    /// Evaluates in O(1) time whether concrete `candidate` satisfies `group_or_bound`.
    pub fn satisfiesGroup(self: *const InternPool, candidate: TypeId, group_or_bound: TypeId) bool {
        if (candidate == group_or_bound or candidate == .err_ty or candidate == .never_ty) return true;
        if (group_or_bound.isBuiltinGroup()) {
            const mask = TypeGroupMask.forBuiltinGroup(group_or_bound);
            if (TypeGroupMask.containsPrimitive(mask, candidate)) return true;
            // Support `~T` underlying match for `distinct` (if arithmetic-enabled) and range refinements
            const base = self.underlyingType(candidate);
            if (base != candidate) {
                const flags = self.getFlags(candidate);
                if (self.getTag(candidate) == .range_refined_type or flags.allow_underlying_approx) {
                    return TypeGroupMask.containsPrimitive(mask, base);
                }
            }
            return false;
        }
        if (self.getTag(group_or_bound) == .user_type_group) {
            const data = self.getData(group_or_bound);
            if (TypeGroupMask.containsPrimitive(data.lhs, candidate)) return true;
            const extra = self.getExtra(TypeNode.UserGroupExtra, data.rhs);
            const base = self.underlyingType(candidate);
            if (TypeGroupMask.containsPrimitive(extra.approx_prim_mask, base)) return true;
            const members = self.extra_data.items[extra.nominal_members_start..][0..extra.nominal_members_len];
            for (members) |m_raw| {
                if (m_raw == candidate.toU32()) return true;
            }
        }
        return false;
    }

    /// Interns a `T?` (`Option[T]`) type, propagating niche flags from `inner`.
    pub fn internOption(self: *InternPool, inner: TypeId) !TypeId {
        const inner_flags = self.getFlags(inner);
        const flags = TypeFlags{
            .has_type_vars = inner_flags.has_type_vars,
            .has_error = inner_flags.has_error,
            .is_copy = inner_flags.is_copy,
            .has_niche = true,
        };
        return self.internSimple(.option_type, flags, inner.toU32(), @intFromBool(inner_flags.has_niche));
    }

    /// Interns a slice `[T]` or `#soa[T]`.
    pub fn internSlice(self: *InternPool, elem: TypeId, is_soa: bool) !TypeId {
        const ef = self.getFlags(elem);
        const flags = TypeFlags{
            .has_type_vars = ef.has_type_vars,
            .has_error = ef.has_error,
            .is_copy = false,
            .is_soa = is_soa,
        };
        return self.internSimple(.slice_type, flags, elem.toU32(), @intFromBool(is_soa));
    }

    /// Creates a `distinct` nominal newtype (always given a fresh identity per declaration).
    pub fn createDistinct(
        self: *InternPool,
        name: StringId,
        underlying: TypeId,
        allow_approx: bool,
    ) !TypeId {
        const uf = self.getFlags(underlying);
        const idx: u32 = @intCast(self.nodes.len);
        try self.nodes.append(self.backing_allocator, .{
            .tag = .distinct_type,
            .flags = .{
                .has_type_vars = uf.has_type_vars,
                .has_error = uf.has_error,
                .is_copy = uf.is_copy,
                .is_distinct = true,
                .has_niche = uf.has_niche,
                .allow_underlying_approx = allow_approx,
            },
            .hash = hashKey(.distinct_type, name.toIndex(), underlying.toU32()),
            .data = .{ .lhs = name.toIndex(), .rhs = underlying.toU32() },
        });
        return @enumFromInt(idx);
    }

    /// Interns a simple 2-operand `TypeNode` (`lhs`, `rhs`) with O(1) Wyhash deduplication.
    pub fn internSimple(self: *InternPool, tag: TypeTag, flags: TypeFlags, lhs: u32, rhs: u32) !TypeId {
        const h = hashKey(tag, lhs, rhs);
        if ((self.nodes.len + 1) * 10 >= self.buckets.len * 7) {
            try self.rehash(@intCast(self.buckets.len * 2));
        }
        const mask: u32 = @intCast(self.buckets.len - 1);
        var slot: u32 = h & mask;

        const tags = self.nodes.items(.tag);
        const hashes = self.nodes.items(.hash);
        const datas = self.nodes.items(.data);

        while (true) {
            const existing = self.buckets[slot];
            if (existing == EMPTY_BUCKET) break;
            if (hashes[existing] == h and tags[existing] == tag) {
                const d = datas[existing];
                if (d.lhs == lhs and d.rhs == rhs) {
                    return @enumFromInt(existing);
                }
            }
            slot = (slot + 1) & mask;
        }

        const new_id: u32 = @intCast(self.nodes.len);
        try self.nodes.append(self.backing_allocator, .{
            .tag = tag,
            .flags = flags,
            .hash = h,
            .data = .{ .lhs = lhs, .rhs = rhs },
        });
        self.buckets[slot] = new_id;
        return @enumFromInt(new_id);
    }

    pub inline fn getExtra(self: *const InternPool, comptime T: type, start_idx: u32) T {
        const word_count = @sizeOf(T) / @sizeOf(u32);
        const slice = self.extra_data.items[start_idx..][0..word_count];
        const ptr: *const T = @ptrCast(slice.ptr);
        return ptr.*;
    }

    fn rehash(self: *InternPool, new_cap: u32) !void {
        const new_buckets = try self.backing_allocator.alloc(u32, new_cap);
        @memset(new_buckets, EMPTY_BUCKET);
        const mask = new_cap - 1;
        const hashes = self.nodes.items(.hash);
        var idx: u32 = STATIC_COUNT;
        while (idx < self.nodes.len) : (idx += 1) {
            const tag = self.nodes.items(.tag)[idx];
            if (tag == .distinct_type or tag == .type_param) continue;
            var slot = hashes[idx] & mask;
            while (new_buckets[slot] != EMPTY_BUCKET) {
                slot = (slot + 1) & mask;
            }
            new_buckets[slot] = idx;
        }
        self.backing_allocator.free(self.buckets);
        self.buckets = new_buckets;
    }
};

// ============================================================================
// 4. SubstitutionMap (SPINE-LOCAL UNIFICATION & MONOMORPHIZATION)
// ============================================================================

/// Compact, arena-friendly SubstitutionMap for spine-local call instantiation
/// and MIR monomorphization. Uses an 8-slot inline buffer
/// for the common case where a generic function has <= 8 type parameters.
pub const SubstitutionMap = struct {
    pub const INLINE_CAP: usize = 8;

    pub const Entry = extern struct {
        param_id: TypeId,
        bound_id: TypeId,
        concrete_id: TypeId,
    };

    inline_entries: [INLINE_CAP]Entry = undefined,
    overflow_entries: []Entry = &[_]Entry{},
    len: u32 = 0,

    pub fn initEmpty() SubstitutionMap {
        return .{ .len = 0 };
    }

    pub inline fn entriesSlice(self: *SubstitutionMap) []Entry {
        return if (self.len <= INLINE_CAP)
            self.inline_entries[0..self.len]
        else
            self.overflow_entries[0..self.len];
    }

    pub inline fn entriesConst(self: *const SubstitutionMap) []const Entry {
        return if (self.len <= INLINE_CAP)
            self.inline_entries[0..self.len]
        else
            self.overflow_entries[0..self.len];
    }

    pub fn registerParam(self: *SubstitutionMap, arena: *BumpArena, param: TypeId, bound: TypeId) !void {
        const idx = self.len;
        if (idx < INLINE_CAP) {
            self.inline_entries[idx] = .{ .param_id = param, .bound_id = bound, .concrete_id = .none };
            self.len = idx + 1;
            return;
        }
        if (idx == INLINE_CAP) {
            const buf = try arena.allocSlice(Entry, 32);
            @memcpy(buf[0..INLINE_CAP], self.inline_entries[0..INLINE_CAP]);
            self.overflow_entries = buf;
        }
        self.overflow_entries[idx] = .{ .param_id = param, .bound_id = bound, .concrete_id = .none };
        self.len = idx + 1;
    }

    pub fn lookup(self: *const SubstitutionMap, param: TypeId) TypeId {
        for (self.entriesConst()) |entry| {
            if (entry.param_id == param) return entry.concrete_id;
        }
        return .none;
    }

    /// Spine-local unification: binds `param_or_pattern` against `arg_ty`, enforcing
    /// Bind-Once consistency and O(1) TypeGroupMask constraint checking.
    pub fn unifyLocal(
        self: *SubstitutionMap,
        pool: *InternPool,
        pattern_ty: TypeId,
        arg_ty: TypeId,
    ) !bool {
        if (pattern_ty == arg_ty or arg_ty == .err_ty or arg_ty == .never_ty) return true;

        // If `pattern_ty` is not dependent on any generic type parameter, check direct match
        const pat_flags = pool.getFlags(pattern_ty);
        if (!pat_flags.has_type_vars) {
            return pattern_ty == arg_ty;
        }

        const pat_tag = pool.getTag(pattern_ty);
        if (pat_tag == .type_param) {
            for (self.entriesSlice()) |*entry| {
                if (entry.param_id == pattern_ty) {
                    if (entry.concrete_id == .none) {
                        if (!pool.satisfiesGroup(arg_ty, entry.bound_id)) return false;
                        entry.concrete_id = arg_ty;
                        return true;
                    }
                    // Bind-Once invariant: if already bound to untyped literal, upgrade to concrete
                    if (entry.concrete_id == .untyped_int_ty and
                        TypeGroupMask.containsPrimitive(TypeGroupMask.INTEGER, arg_ty))
                    {
                        if (!pool.satisfiesGroup(arg_ty, entry.bound_id)) return false;
                        entry.concrete_id = arg_ty;
                        return true;
                    }
                    if (arg_ty == .untyped_int_ty and
                        TypeGroupMask.containsPrimitive(TypeGroupMask.INTEGER, entry.concrete_id))
                    {
                        return true;
                    }
                    return entry.concrete_id == arg_ty;
                }
            }
            return false;
        }

        // Structural peel for `[T]`, `T?`, etc.
        if (pat_tag == pool.getTag(arg_ty)) {
            const pat_data = pool.getData(pattern_ty);
            const arg_data = pool.getData(arg_ty);
            if (pat_tag == .option_type or pat_tag == .slice_type) {
                return self.unifyLocal(pool, @enumFromInt(pat_data.lhs), @enumFromInt(arg_data.lhs));
            }
        }
        return false;
    }

    /// Instantiates `ty` by substituting all bound type parameters.
    /// Fast path: if `!flags.has_type_vars`, returns `ty` in O(1) without recursion!
    pub fn subst(self: *const SubstitutionMap, pool: *InternPool, ty: TypeId) !TypeId {
        const flags = pool.getFlags(ty);
        if (!flags.has_type_vars) return ty;

        const tag = pool.getTag(ty);
        const data = pool.getData(ty);
        return switch (tag) {
            .type_param => {
                const resolved = self.lookup(ty);
                return if (resolved != .none) resolved else ty;
            },
            .option_type => {
                const inner = try self.subst(pool, @enumFromInt(data.lhs));
                return if (inner.toU32() == data.lhs) ty else pool.internOption(inner);
            },
            .slice_type => {
                const elem = try self.subst(pool, @enumFromInt(data.lhs));
                return if (elem.toU32() == data.lhs) ty else pool.internSlice(elem, data.rhs != 0);
            },
            else => ty,
        };
    }
};

    assert(@sizeOf(TypeTag) == 1);
    assert(@sizeOf(TypeFlags) == 1);
    assert(@sizeOf(TypeNode.Data) == 8);
```

### 5.3 Stage-1 Self-Hosted CoreX Implementation (`src/sema/type_arena.cx`)

The following self-hosted `.cx` module is the exact 1-to-1 Stage-1 counterpart of `stage0/src/type_system.zig`, written strictly in `DR-03` surface syntax (`[T]` generics, postfix `: Type`, `T?` option sugar, `let`/`var`/`const` bindings, `;` statement termination, `@snake_case` attributes, and canonical lexical casing) while leveraging `DR-02`'s `#soa Vec[TypeNode]`, `bit_field u8`, and `distinct u32` primitives[cite: 1, 2, 3]:

```rust
    RangeRefinedType = 11,

}

    pub has_error:               bool | 1,
    pub is_copy:                 bool | 1,
    pub is_distinct:             bool | 1,
    pub has_niche:               bool | 1,
    pub is_soa:                  bool | 1,
    pub allow_underlying_approx: bool | 1,

@repr(C)

    pub lhs: u32,
    pub rhs: u32,
}

pub struct TypeNode {
    pub tag:   TypeTag,   // Column 0: 1 byte
    pub flags: TypeFlags, // Column 1: 1 byte
    pub hash:  u32,       // Column 2: 4 bytes
    pub data:  TypeData,  // Column 3: 8 bytes (Total in #soa Vec = 14 bytes, 0 padding!)

// ============================================================================
// 3. InternPool (`TypeArena`) & SubstitutionMap IN SELF-HOSTED COREX
// ============================================================================

const EMPTY_BUCKET: u32 = 0xFFFF_FFFF;

pub struct InternPool {
    pub arena:      &mut BumpArena,
    pub nodes:      #soa Vec[TypeNode],
    pub extra_data: Vec[u32],
    pub buckets:    Vec[u32],
}

impl InternPool {
    @inline
    pub fn get_tag(&self, id: TypeId) -> TypeTag {
        self.nodes.tag[id as usize]
    }

    @inline
    pub fn get_flags(&self, id: TypeId) -> TypeFlags {
        self.nodes.flags[id as usize]
    }

    @inline
    pub fn get_data(&self, id: TypeId) -> TypeData {
        self.nodes.data[id as usize]
    }

    pub fn underlying_type(&self, id: TypeId) -> TypeId {
        var curr = id;
        loop {
            let tag = self.get_tag(curr);
            if tag == .DistinctType {
                curr = self.get_data(curr).rhs as TypeId;
            } else if tag == .RangeRefinedType {
                curr = self.get_data(curr).lhs as TypeId;
            } else {
                return curr;
            }
        }
    }

    pub fn satisfies_group(&self, candidate: TypeId, group_or_bound: TypeId) -> bool {
        if candidate == group_or_bound or candidate == TypeId::ERR or candidate == TypeId::NEVER {
            return true;
        }
        if group_or_bound.is_builtin_group() {
            let mask = builtin_group_mask(group_or_bound);
            if (mask & candidate.primitive_bit()) != 0 {
                return true;
            }
            let base = self.underlying_type(candidate);
            if base != candidate {
                let flags = self.get_flags(candidate);
                if self.get_tag(candidate) == .RangeRefinedType or flags.allow_underlying_approx {
                    return (mask & base.primitive_bit()) != 0;
                }
            }
            return false;
        }
        false
    }
}

@repr(C)
@derive(Copy)
pub struct SubstEntry {
    pub param_id:    TypeId,
    pub bound_id:    TypeId,
    pub concrete_id: TypeId,
}

pub struct SubstitutionMap {
    pub inline_entries: [SubstEntry; 8],
    pub len:            u32 = 0,
}

impl SubstitutionMap {
    pub fn lookup(&self, param: TypeId) -> TypeId {
        for i in 0..(self.len as usize) {
            if self.inline_entries[i].param_id == param {
                return self.inline_entries[i].concrete_id;
            }
        }
        TypeId::NONE
    }

    pub fn unify_local(
        &mut self,
        pool: &InternPool,
        pattern_ty: TypeId,
        arg_ty: TypeId,
    ) -> bool {
        if pattern_ty == arg_ty or arg_ty == TypeId::ERR or arg_ty == TypeId::NEVER {
            return true;
        }
        let pat_flags = pool.get_flags(pattern_ty);
        if not pat_flags.has_type_vars {
            return pattern_ty == arg_ty;
        }
        if pool.get_tag(pattern_ty) == .TypeParam {
            for i in 0..(self.len as usize) {
                if self.inline_entries[i].param_id == pattern_ty {
                    let existing = self.inline_entries[i].concrete_id;
                    if existing.is_none() {
                        if not pool.satisfies_group(arg_ty, self.inline_entries[i].bound_id) {
                            return false;
                        }
                        self.inline_entries[i].concrete_id = arg_ty;
                        return true;
                    }
                    return existing == arg_ty;
                }
            }
        }
        false
    }
}
```

## 6. End-to-End `.cx` Showcase: Constrained Type Groups, `#soa` Projections & Refinements

The following complete `.cx` module demonstrates how CoreX's inline **Bind-Once Type Groups** (`Number`), **Bind-Many Type Groups** (`any Float`), **`~T` underlying `distinct` types**, **range-refined types (`u8 is 1..=100`)**, **`#soa` slices**, and **explicit wrapping/saturating arithmetic (`+%`, `+|`)** work together seamlessly in `DR-03` syntax[cite: 1, 3]:

```rust
// File: src/telemetry_physics.cx
mod telemetry_physics;

// 1. Nominal `distinct` newtype opting into `Number` (~f32 approximation):
@derive(Copy, Number)
pub type MetersPerSec = distinct f32;

// 2. Zero-cost range-refined type (sizeof(HealthPct?) == 1 byte, 0 is niche!):
pub type HealthPct = u8 is 1..=100;

// 3. LSB bit_field packed into a single 16-bit integer register:
pub type EntityFlags = bit_field u16 {
    pub active:    bool | 1,
    pub shielded:  bool | 1,
    pub team_id:   u8   | 4,
    pub tick_seq:  u16  | 10,
};

pub struct Entity {
    pub pos_x:  MetersPerSec,
    pub vel_x:  MetersPerSec,
    pub health: HealthPct?,
    pub flags:  EntityFlags,
}

// 4. Inline Bind-Once Type Group: `val`, `low`, `high`, and return type
//    automatically unify to the SAME concrete type `__G0: Number`!
//    Works for `i32`, `f64`, AND `MetersPerSec` (via ~f32 underlying match) with zero boxing.
@inline
pub fn clamp(val: Number, low: Number, high: Number) -> Number {
    if val < low {
        low
    } else if val > high {
        high
    } else {
        val
    }
}

// 5. Inline Bind-Many (`any Float`): `val` and `dt` can be independent float types (`MetersPerSec` and `f64`).
@inline
pub fn integrate_step(pos: MetersPerSec, vel: MetersPerSec, dt: any Float, min_x: MetersPerSec, max_x: MetersPerSec) -> MetersPerSec {
    let next_pos = pos + ((vel as f32) * (dt as f32)) as MetersPerSec;
    clamp(next_pos, min_x, max_x)
}

// 6. Zero-copy `#soa` slice loop with `+|` saturating damage and `+%` wrapping tick sequence:
pub fn update_entities(
    entities: &mut #soa[Entity],
    dt_sec: f64,
    damage_burst: u8,
) {
    let min_bound = -1000.0 as MetersPerSec;
    let max_bound = 1000.0 as MetersPerSec;

    for i in 0..entities.len() {
        if not entities[i].flags.active {
            continue;
        }

        // `entities[i].pos_x` rewrites directly to `entities.pos_x[i]` (100% L1d cache utilization)
        entities[i].pos_x = integrate_step(
            entities[i].pos_x,
            entities[i].vel_x,
            dt_sec,
            min_bound,
            max_bound,
        );

        // Wrapping 10-bit sequence counter using `+%` (projected by value into bit_field)
        entities[i].flags.tick_seq = (entities[i].flags.tick_seq +% 1) & 0x03FF;

        // Niche-optimized 1-byte `HealthPct?` pattern match with saturating subtraction `-|`
        if let .Some(hp) = entities[i].health {
            let remaining = (hp as u8) -| damage_burst;
            entities[i].health = match remaining {
                alive_hp @ 1..=100 => .Some(alive_hp),
                _ => {
                    entities[i].flags.active = false;
                    .None
                }
            };
        }
    }
}
```
