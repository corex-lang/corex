# Fault-Tolerant Lossless CST, Incremental Query Engine, and Built-in Language Server Architecture for CoreX

To guarantee sub-5 ms interactive editor responses across 500,000-line codebases while sharing a single frontend across `corex build`, `corex check`, `corex fmt`, `corex upgrade`, and `corex lsp`, CoreX (`corex-lang/corex`) rejects pointer-heavy, reference-counted Red-Green syntax trees (`rowan`) in favor of a **Contiguous Struct-of-Arrays (SoA) Lossless Concrete Syntax Tree (`LosslessCstArena`)** paired with a **Salsa-inspired Demand-Driven Incremental Query Engine (`CompilerDb`)**. Based on quantitative layout modeling of a 500,000-line codebase (~1,250 files, 3.25 million syntactic tokens, 3.5 million CST nodes, and 1.5 million lowered AST nodes), decomposing syntax structures into 32-bit indexed parallel arrays (`12 bytes/token` in `TokenBuffer`, `8 bytes/record` in `TriviaTable`, `10 bytes/node` in `LosslessCstArena`, and `13 bytes/node` in `AstArena`) stores the entire workspace's lossless syntax and semantic trees in **95.46 MiB** – a **56.3% memory reduction** (2.29x smaller) compared to `rowan`-style Red-Green trees (**218.20 MiB**) while eliminating atomic reference counting and serial pointer-chasing cache misses.

This contiguous data foundation powers a four-stage resilience and incrementality pipeline designed from Phase 1 for broken, mid-keystroke code. First, a stateless maximal-munch lexer recognizes CoreX's `DR-03` `TokenKind` table and performs Carbon-style **lexical bracket balancing**, inserting zero-length virtual recovery tokens so `()`, `[]`, and `{}` are balanced before parsing begins. Second, an **Explicit-Stack Postorder Parser** (`MAX_PARSE_DEPTH = 512`) eliminates call-stack overflow risks and recovers from syntax errors using `FOLLOW`-set anchor synchronization (`;`, `{`, `}`, `,`, and item/statement introducers), bracketing malformed token ranges inside `InvalidParseSubtree` nodes without discarding a single byte of source trivia. Third, during CST-to-AST lowering, syntax errors and incomplete expressions (`user.` or `repo.find(`) lower into typed **Syntactic Hole Membranes** (`ExprHole`, `TypeHole`, `PatternHole`) that integrate with `DR-02`'s mode-correct bidirectional type checker ($\Rightarrow$ synthesis / $\Leftarrow$ checking) via Hazel-inspired gradual hole propagation (`Type::Error` / $?_\Rightarrow$), localizing type errors without cascading secondary diagnostics.

Finally, `CompilerDb` isolates edits at the granularity of individual top-level definitions (`DefId`) using **Position-Independent `ItemTree` Projections** and **128-bit `Wyhash(0)` / BLAKE3 Early Cutoff (Backdating)**. In our single-core throughput model, when a developer edits code inside a function body, `corex lsp` applies the in-memory `Vfs` overlay (`15 µs`), re-lexes and re-parses the 400-line active file in **81 µs** (`25 µs` lex + `56 µs` CST), lowers the AST and extracts the file's `ItemTree` in **54 µs** (`40 µs` AST + `14 µs` `ItemTree`), verifies that the file's exported signature fingerprint is unchanged (`2 µs` for downstream signature verification), and backdates the signature query's `changed_at` revision. Consequently, only the single modified `DefId` undergoes bidirectional type checking (**85 µs**) and path-sensitive Ghost-Instruction MIR verification (**65 µs**), delivering complete keystroke-to-LSP response turnaround (including `120 µs` for completions, MVS inlay hints, or delta semantic tokens) in **420 µs (0.42 ms)** – more than an order of magnitude inside the 5 ms real-time budget.

## 1. Lossless Contiguous CST (`LosslessCstArena`) and Typed AST (`AstArena`) Architecture

### 1.1 Architectural Trade-Off: Flat Postorder SoA Trees vs. Pointer-Heavy Red-Green Trees

Modern IDE-oriented compilers often rely on **Red-Green Trees** (pioneered by C#'s Roslyn and adopted by `rust-analyzer`'s `rowan` and `JuliaSyntax.jl`). In a Red-Green architecture, every token, whitespace run, comment, and interior syntax node is allocated on the heap as an immutable, reference-counted "Green" node storing variable-length child pointer arrays, overlaid during traversal by transient, heap-allocated "Red" parent-pointer cursor nodes. While Red-Green trees support structural node sharing across edits, empirical profiling from `rust-analyzer` (Issue `#17491`) and `countme` telemetry reveals three architectural costs for a systems compiler. First, benchmarking `rowan` against contiguous flat syntax trees (`syntree`) showed that Red-Green tree construction is **twice as slow** during workspace loading, while a medium Rust workspace allocates over **9.45 million `GreenNode` instances**, **4.71 million `GreenToken` instances**, and **72.12 million transient `SyntaxNode` cursors**. Second, walking a pointer-linked syntax tree forces the CPU into a serial dependent load chain where child addresses cannot be prefetched until the parent cache line resolves, collapsing hardware Memory-Level Parallelism (MLP) toward 1 and wasting over 90% of each 64-byte L1d cache line. Third, even in `rust-analyzer`, edited files are reparsed from scratch on keystrokes because lexing and parsing a single source file takes less than 100 µs; incremental reuse happens at the semantic query layer (`ItemTree` and `Salsa` memos), making sub-file Green-node pointer sharing an unnecessary source of memory bloat.

Building directly upon `DR-01` Section 2.2 and Carbon's `Lex::TokenizedBuffer` and `Parse::Tree` architecture, CoreX separates syntax representation into three contiguous, zero-pointer, 32-bit-indexed arena layers. The lexical layer (`TokenBuffer` + `TriviaTable`) uses a Struct-of-Arrays (SoA) token stream (`12 bytes/token`) paired with a side-band structured trivia table (`8 bytes/trivia piece`) that partitions 100% of the UTF-8 source buffer into alternating trivia gaps and token spans. The concrete syntax layer (`LosslessCstArena`) stores a flat postorder/bracketed SoA parse tree (`10 bytes/node`) constructed by a non-recursive explicit state-stack parser (`MAX_PARSE_DEPTH = 512`) that maintains a 1-to-1 correspondence with tokens on valid input and encloses malformed syntax inside `InvalidParseSubtree` brackets. The abstract syntax layer (`AstArena`) provides a lowered, trivia-free SoA abstract syntax tree (`13 bytes/node` + append-only `extra_data: []u32` trail, matching `DR-01`'s `AstStore`) where concrete punctuation is stripped and syntax errors are isolated inside typed hole nodes (`ExprHole`, `TypeHole`, `PatternHole`, `ItemHole`) for `DR-02` bidirectional type checking.

| Architectural Dimension | Red-Green Tree (`rowan` / Roslyn) | CoreX Contiguous SoA Arenas (`TokenBuffer` + `LosslessCstArena` + `AstArena`) | Engineering Impact for CoreX (`corex` / `corex lsp`) |
| :--- | :--- | :--- | :--- |
| **Memory Layout & Indirection** | Heap-allocated `Arc` nodes + 64-bit pointer arrays + transient Red cursors. | Contiguous `MultiArrayList` SoA slices indexed by `u32` handles (`TokenIndex`, `CstNodeIndex`, `NodeIndex`). | **Zero heap pointers, zero `Arc` atomic traffic**, and hardware-prefetched linear scans. |
| **Per-Node Memory Footprint** | `32–64+ bytes` per Green node + `48 bytes` per transient Red cursor. | **`12 B`** per token, **`8 B`** per trivia piece, **`10 B`** per CST node, **`13 B`** per AST node. | **95.46 MiB** vs. **218.20 MiB** modeled across a 500,000-line codebase (**56.3% smaller**). |
| **Parser Execution Model** | Recursive-descent call stack (vulnerable to stack overflow on deeply nested expressions). | **Explicit `ParseState` loop stack** (`MAX_PARSE_DEPTH = 512`, `8 bytes/entry` = 4 KiB fixed stack). | **Immunity** to 256 KiB thread stack overflows on deeply nested generated code. |
| **Lossless Source Fidelity** | Whitespace and comments stored as heap `GreenToken` leaves mixed with syntax tokens. | **Implicit Gap Invariant** (`prev_end..curr_start`) + indexed `TriviaPiece` table (`PackedTriviaSpan`). | **100% bit-for-bit source round-tripping** without polluting parser lookahead (`peek(k)`). |
| **Deallocation Cost** | Sequential `Arc` reference-count drop cascades across millions of nodes. | **O(1) slab reset** (`BumpArena.restore` or `deinit`). | Instantaneous reclamation when a file revision is superseded in `corex lsp`. |

### 1.2 Lossless Byte-for-Byte Source Reconstruction & Trivia Representation

A foundational requirement for `corex fmt`, `corex upgrade` (automated syntax migrations), and `corex lsp` refactorings is **100% lossless bit-for-bit round-tripping** of any `.cx` source file – including UTF-8 byte order marks, shebangs, regular comments (`//`), outer doc comments (`///`), module doc comments (`//!`), nested block comments (`/* ... */`), blank lines, arbitrary horizontal whitespace, and even illegal UTF-8 or malformed lexer bytes.

If a lexer emits whitespace and comments as ordinary tokens in the main token stream, the `LL(k)` parser (`DR-03` Section 2.2) can no longer index `peek(1)` or `peek(2)` in O(1) array offset time (`curr_tok + 1`), because an arbitrary number of comment tokens may sit between `ident` and `[` or `::`. Conversely, if the lexer discards whitespace and comments, `corex fmt` and `corex upgrade` cannot reconstruct the file.

CoreX resolves this tension with a **Dual-Representation Lossless Trivia Architecture** inspired by Carbon's `Lex::TokenizedBuffer` and Swift's `libSyntax` trivia ownership rules:

1.  **The Mathematical Partition Invariant (Implicit Byte Gaps):**
    Every real syntactic token $i \in [0, N-1]$ (where token $N-1$ is always `TokenKind.EOF` at `byte_offset = source.len` with `length = 0`) stores its exact start offset `byte_offsets[i]: u32` and byte length `lengths[i]: u16` (with sentinel `0xFFFF` overflowing to a side table for >64 KiB string literals). For any real token $i$, let $\text{End}(i-1)$ be `0` if $i = 0$, or `byte_offsets[i-1] + lengths[i-1]` if $i > 0$ (skipping zero-length virtual recovery tokens where `flags[k].is_injected_recovery == 1`). The inter-token trivia gap preceding token $i$ is **identically**:
    $$\text{Gap}(i) = \text{source}\big[\text{End}(i-1) \mathrel{..} \text{byte\_offsets}[i]\big]$$
    Because $\text{Gap}(0)$ starts at byte `0` and `EOF` sits at byte `source.len`, concatenating $\bigoplus_{i=0}^{N-1} \big(\text{Gap}(i) \mathbin{\Vert} \text{TokenBytes}(i)\big)$ reproduces `source[0..source.len]` **bit-for-bit in O(N) time with zero external storage**.
2.  **Fast-Path Whitespace Flags in `TokenFlags` (1 Byte per Token):**
    Most inter-token gaps in `.cx` code consist purely of single spaces (` `), standard newline-plus-4-space indentation, or empty adjacency (e.g., `foo(bar)`). Each token's 1-byte `TokenFlags` bitfield records `has_leading_space: u1`, `has_leading_newline: u1`, `blank_lines_before: u2` (`0`, `1`, `2+`), `is_malformed: u1`, `is_injected_recovery: u1`, `has_leading_trivia_pieces: u1`, and `has_trailing_trivia_pieces: u1`. When both `has_leading_trivia_pieces` and `has_trailing_trivia_pieces` are `0`, `corex fmt` and the lexer diagnostics printer know immediately that $\text{Gap}(i)$ contains only pure whitespace without touching the `TriviaTable`.
3.  **Structured `TriviaTable` (`8 Bytes` per Comment or Malformed Span) with Trailing/Leading Ownership:**
    Whenever the lexer encounters a comment (`//`, `///`, `//!`, `/*...*/`), a shebang (`#!`), or an unrecognized/malformed byte sequence (e.g., a stray ASCII character or invalid UTF-8 bytes) inside $\text{Gap}(i)$, it appends an 8-byte `TriviaPiece` to `TokenBuffer.trivia_pieces` and binds it to the adjacent token via `trivia_spans[tok]: PackedTriviaSpan` (`start_idx: u24`, `count: u8`). Under the **Trailing Trivia Rule**, any comment or malformed byte sequence starting on the **same line** after token $i-1$ (up to and including the line's terminating `\n` or `\r\n`) attaches as trailing trivia (`is_trailing = 1`) of token $i-1$ (e.g., `return a + b; // inline note`), whereas under the **Leading Trivia Rule**, any comment, doc comment (`///`, `//!`), blank line run, or malformed byte sequence appearing **after the first newline** following token $i-1$ attaches as leading trivia (`is_trailing = 0`) of token $i$.

### 1.3 Carbon-Style Flat Postorder CST (`LosslessCstArena`) with Explicit State Stack

Following `DR-01` Section 2.2 and Carbon's `Parse::Tree::Parse` design, CoreX's `LosslessCstArena` stores the concrete syntax tree in a **flat postorder array** (`CstNodeIndex(0 .. len)`), constructed by an iterative loop driven by a fixed-capacity array stack (`state_stack: [512]ParseState`, `MAX_PARSE_DEPTH = 512`).

In Carbon's postorder layout, children appear **before** their enclosing parent node in the contiguous array, and every composite construct is bracketed at its beginning by an introducer/start leaf node (such as `FnIntroducer` for `fn`, `ParamListStart` for `(`, `BlockStart` for `{`, or `IfIntroducer` for `if`) and closed at its end by the parent node (`FnDef`, `ParamList`, `Block`, `IfExpr`), which records `subtree_size: u32` – the exact total number of CST nodes in the subtree rooted at that parent.

This layout provides four major advantages for CoreX's compiler and IDE tools:
1.  **Zero-Allocation Tree Construction:** As the parser pops a `ParseState` from `state_stack`, it records `subtree_start = cst.len` when pushing the closing state for a construct, pushes child states in reverse execution order, and upon popping the closing state, computes `subtree_size = (cst.len + 1) - state.subtree_start` in O(1) arithmetic.
2.  **Bidirectional Traversal (Postorder Evaluation & Preorder Skipping):** Bottom-up passes (`lower_ast` and constant folding) iterate forward (`0 .. cst.len`) in natural postorder with sequential L1d cache access. Top-down passes (`corex fmt`, `corex lsp` cursor-offset-to-node lookup, and `ItemTree` signature extraction) iterate backward from the root (`cst.len - 1` down to `0`) or jump over an entire uninteresting function body in **O(1) time** by subtracting `subtree_size` (`prev_sibling_idx = idx - cst.subtree_sizes[idx]`). Note that while Carbon's documentation observes that `subtree_size` may be optional if only pure postorder walks are needed, CoreX explicitly retains `subtree_size` because O(1) top-down subtree skipping is essential for sub-millisecond LSP cursor-to-node resolution and `corex fmt` preorder traversal.
3.  **100% Lossless Round-Trip Printing (`corex fmt` & `corex upgrade`):** Every real token `TokenIndex(0 .. N-1)` is referenced by at least one leaf or bracket CST node in strict source order. Walking the CST leaves in order and emitting each token's leading trivia, token slice, and trailing trivia reconstructs the original source byte-for-bit.
4.  **Bounded Memory Stack:** If a malicious or machine-generated `.cx` file nests expressions deeper than `MAX_PARSE_DEPTH = 512`, the parser never overflows the OS call stack; instead, it emits a single `ParseDepthExceeded` diagnostic, transitions to `SkipPastLikelyEnd` recovery, wraps the excess tokens in a flat `InvalidParseSubtree` node, and continues parsing the rest of the file.

### 1.4 Deliverable 1: Byte-Exact Data Structure Blueprint for `TokenBuffer`, `LosslessCstArena`, and `AstArena`

The following implementations provide the complete, byte-accurate memory blueprints for **Stage 0 (Zig)** and **Stage 1 (self-hosted `.cx`)**, strictly adhering to `DR-01`'s `MultiArrayList` and `u32` handle invariants and `DR-03`'s unified **112-variant `TokenKind` table** (`0..111`, including `invalid_token` and `eof`, all fitting cleanly in a 1-byte `enum(u8)` and a 128-bit `u128` anchor bitset).

#### Stage-0 Zig Blueprint (`stage0/src/syntax_arenas.zig`)

```zig
//! CoreX Stage-0 Compiler (`stage0/corex`)
//! Module: Byte-Exact TokenBuffer, TriviaTable, LosslessCstArena, and AstArena
//! Aligns with DR-01 (MultiArrayList SoA, u32 handles) and DR-03 (112-token grammar).

const std = @import("std");
const assert = std.debug.assert;
const Allocator = std.mem.Allocator;
const mem = @import("mem_foundation.zig");

pub const FileId = mem.FileId;
pub const Span = mem.Span;
pub const StringId = mem.StringId;
pub const SymbolId = mem.SymbolId;
pub const TokenIndex = mem.TokenIndex;
pub const TokenId = mem.TokenId;
pub const CstNodeIndex = mem.CstNodeIndex;

// ============================================================================
// [1] AUTHORITATIVE TOKEN KIND TABLE (DR-03 SECTION 5.2 + DR-04/05/07)
// ============================================================================

pub const TokenKind = enum(u8) {
    // Visibility & Module Keywords (4)
    kw_pub = 0, kw_mod = 1, kw_use = 2, kw_as = 3,

    kw_bit_field = 14, kw_comptime = 15,
    // Memory, Async & Safety Keywords (11)

    // Control-Flow Keywords (11)

    at = 69, hash_soa = 70, question = 71, underscore = 72,

    bang = 95, tilde = 96, shl = 97, shr = 98,
    // Assignment Operators (11)
    eq = 99, plus_eq = 100, minus_eq = 101, star_eq = 102, slash_eq = 103,
    percent_eq = 104, amp_eq = 105, pipe_eq = 106, caret_eq = 107, shl_eq = 108, shr_eq = 109,

// ============================================================================
// [2] LOSSLESS TOKEN BUFFER & STRUCTURED TRIVIA TABLE (12 B/Tok + 8 B/Trivia)
// ============================================================================

/// 1-byte bit-packed flags per token for O(1) whitespace/recovery inspection.
pub const TokenFlags = packed struct(u8) {
    has_leading_space: bool = false,
    has_leading_newline: bool = false,
    /// Number of blank lines immediately preceding this token (0, 1, 2, or 3 = 3+).
    blank_lines_before: u2 = 0,
    /// True if the lexer synthesized this token for bracket recovery (`)`, `]`, `}`).
    /// Virtual recovery tokens have `byte_len == 0` so lossless source printing skips them.
    is_injected_recovery: bool = false,
    /// True if token is unclosed literal, invalid casing, or unknown byte span.
    is_malformed: bool = false,
    has_leading_trivia_pieces: bool = false,
    has_trailing_trivia_pieces: bool = false,
};

/// 4-byte handle linking a token to its slice of `TriviaPiece` records in `TriviaTable`.
pub const PackedTriviaSpan = packed struct(u32) {
    start_index: u24 = 0,
    count: u8 = 0,
};

pub const TriviaKind = enum(u4) {
    line_comment = 0,        // `// …`
    doc_line_comment = 1,    // `/// …`
    mod_doc_comment = 2,     // `//! …`
    block_comment = 3,       // `/* … */` (supports nesting)
    shebang = 4,             // `#!/usr/bin/env corex`
    malformed_bytes = 5,     // Unrecognized ASCII/UTF-8 bytes preserved losslessly
};

/// 8-byte structured trivia record for comments and malformed byte sequences.
pub const TriviaPiece = extern struct {
    pub const Meta = packed struct(u8) {
        kind: TriviaKind,
        /// 0 = attaches as leading trivia to token `i`; 1 = attaches as trailing trivia to token `i`.
        is_trailing: bool,
        blank_lines_before: u2 = 0,
        has_newline_after: bool = false,
    };

    meta: Meta,
    /// Column indentation depth (in spaces, saturating at 255) for `corex fmt` comment alignment.
    indent_cols: u8,
    /// Byte length of the trivia piece (`0xFFFF` = length stored in `TokenBuffer.large_lengths`).
    byte_len: u16,
    /// Exact start byte offset in `source`.
    byte_offset: u32,
};

/// Logical Token record decomposed by `std.MultiArrayList(TokenRecord)` into:
/// - `kinds: [*]TokenKind` (1 B)
/// - `flags: [*]TokenFlags` (1 B)
/// - `byte_lens: [*]u16` (2 B; 0xFFFF -> lookup in `large_lengths` or paired bracket index)
/// - `byte_offsets: [*]u32` (4 B)
/// - `trivia_spans: [*]PackedTriviaSpan` (4 B)
/// Total = 12 bytes per token, 0 padding bytes!
pub const TokenRecord = struct {
    kind: TokenKind,
    flags: TokenFlags,
    byte_len: u16,
    byte_offset: u32,
    trivia_span: PackedTriviaSpan,
};

/// 0-based line and column coordinates for terminal diagnostics and LSP 3.17 Position encoding.
pub const LineCol = extern struct {
    line: u32,
    col_utf8: u32,
    col_utf16: u32,
};

/// Binary-searchable line offset index supporting O(log L) byte-offset-to-(line, col) lookup.
pub const LineIndex = struct {
    line_starts: []const u32,

    /// Resolves `byte_offset` in `source` to 0-based `(line, col_utf8, col_utf16)` coordinates.
    pub fn resolveOffset(self: LineIndex, source: []const u8, byte_offset: u32) LineCol {
        var low: usize = 0;
        var high: usize = self.line_starts.len;
        while (low + 1 < high) {
            const mid = low + (high - low) / 2;
            if (self.line_starts[mid] <= byte_offset) {
                low = mid;
            } else {
                high = mid;
            }
        }
        const line_start = self.line_starts[low];
        const col_utf8 = byte_offset - line_start;
        var col_utf16: u32 = 0;
        var cursor: usize = line_start;
        const limit: usize = @min(byte_offset, @as(u32, @intCast(source.len)));
        while (cursor < limit) {
            const seq_len = std.unicode.utf8ByteSequenceLength(source[cursor]) catch 1;
            col_utf16 += if (seq_len == 4) 2 else 1;
            cursor += seq_len;
        }
        return .{ .line = @intCast(low), .col_utf8 = col_utf8, .col_utf16 = col_utf16 };
    }
};

pub const TokenBuffer = struct {
    allocator: Allocator,
    /// Complete immutable UTF-8 source buffer for this file.
    source: []const u8,
    /// SoA token arrays (12 bytes/token).
    tokens: std.MultiArrayList(TokenRecord) = .{},
    /// Structured trivia array (8 bytes/piece) for comments and invalid byte spans.
    trivia_pieces: std.ArrayListUnmanaged(TriviaPiece) = .{},
    /// Byte offsets of every `\n` character + start of file (`0`), enabling O(log L)
    /// binary search between byte offsets and LSP `(line, character)` coordinates.
    line_starts: std.ArrayListUnmanaged(u32) = .{},
    /// Side-table for tokens or comments whose byte length >= 65,535 (`0xFFFF`).
    large_lengths: std.AutoHashMapUnmanaged(u32, u32) = .{},
    has_lex_errors: bool = false,

    pub fn init(allocator: Allocator, source: []const u8) !TokenBuffer {
        var self = TokenBuffer{ .allocator = allocator, .source = source };
        try self.line_starts.append(allocator, 0);
        return self;
    }

    pub fn deinit(self: *TokenBuffer) void {
        self.tokens.deinit(self.allocator);
        self.trivia_pieces.deinit(self.allocator);
        self.line_starts.deinit(self.allocator);
        self.large_lengths.deinit(self.allocator);
    }

    /// Reconstructs the exact byte span of `tok` in `source` (returns empty slice for virtual recovery tokens).
    pub inline fn tokenSlice(self: *const TokenBuffer, tok: TokenIndex) []const u8 {
        const idx = tok.toU32();
        const flags = self.tokens.items(.flags)[idx];
        if (flags.is_injected_recovery) return self.source[0..0];
        const start = self.tokens.items(.byte_offsets)[idx];
        const raw_len = self.tokens.items(.byte_lens)[idx];
        const len: u32 = if (raw_len == 0xFFFF) self.large_lengths.get(idx).? else raw_len;
        return self.source[start .. start + len];
    }

    /// Returns the exact inter-token trivia gap preceding `tok` in O(1) time.
    /// Concatenating `leadingGapSlice(i) ++ tokenSlice(i)` for `i in 0..tokens.len`
    /// reproduces `source` 100% bit-for-bit!
    pub inline fn leadingGapSlice(self: *const TokenBuffer, tok: TokenIndex) []const u8 {
        const idx = tok.toU32();
        const curr_start = self.tokens.items(.byte_offsets)[idx];
        var prev_idx = idx;
        while (prev_idx > 0) {
            prev_idx -= 1;
            const p_flags = self.tokens.items(.flags)[prev_idx];
            if (!p_flags.is_injected_recovery) {
                const p_start = self.tokens.items(.byte_offsets)[prev_idx];
                const p_raw_len = self.tokens.items(.byte_lens)[prev_idx];
                const p_len: u32 = if (p_raw_len == 0xFFFF) self.large_lengths.get(prev_idx).? else p_raw_len;
                return self.source[p_start + p_len .. curr_start];
            }
        }
        return self.source[0..curr_start];
    }
};

                .child_arity_small = 0,
            },

            .subtree_size = 1,

    }

    pub inline fn finishSubtree(
        self: *LosslessCstArena,
        kind: CstNodeKind,
        tok: TokenIndex,
        subtree_start: u32,
        has_error: bool,
        arity: u5,
    ) !CstNodeIndex {
        const idx: u32 = @intCast(self.nodes.len);
        assert(idx >= subtree_start);
        if (has_error) self.has_parse_errors = true;

            .kind = kind,
            .flags = .{
                .has_error = has_error,
                .is_missing_or_injected = false,
                .is_bracketed = true,
                .child_arity_small = arity,
            },
            .token = tok,
            .subtree_size = size,
        });
        return @enumFromInt(idx);
    }
```

## 2. Fault-Tolerant Parsing and Bidirectional Type Recovery for Incomplete Code

During interactive editing in `corex lsp`, source code is syntactically or semantically incomplete on the majority of keystrokes (for example, right after typing `let x = user.` or `repo.find(id, `). If a syntax error aborts parsing or causes the type checker to discard the enclosing function body, autocomplete and signature help stop working precisely when the developer needs them most. CoreX achieves **total syntax and type recovery** across three coordinated phases: (1) Lexical Bracket Balancing, (2) Anchor-Synchronized Explicit-Stack CST Recovery, and (3) Bidirectional Hole-Membrane Type Checking.

> **Visual – Syntactic Hole Membranes Isolate Mid-Keystroke Errors for Total Bidirectional Type Recovery:** End-to-end fault recovery pipeline when a developer types `let name = user.` inside an unclosed function block. Stage 1 balances unmatched delimiters by injecting a zero-byte virtual closing brace. Stage 2 pops the explicit `ParseState` stack, recognizes the missing field identifier after the dot, and brackets the subtree without discarding subsequent statements. Stage 3 lowers the CST into an `AstArena` node tagged `IncompleteMemberAccess` wrapped in a non-empty Hole Membrane. Stage 4 synthesizes the receiver type (`User`) while assigning the unknown hole type to `name`, enabling instant field completion on `user.` with zero cascading errors on downstream uses of `name`.

### 2.1 Phase 1: Carbon-Style Lexical Bracket Balancing and Casing Recovery

Following Carbon's `Lex::TokenizedBuffer` mismatched-bracket recovery architecture, the CoreX lexer maintains an open-delimiter stack for `{` (`LBRACE`), `(` (`LPAREN`), and `[` (`LBRACKET`) during its single O(n) scan, recording each opening bracket's `TokenIndex` and column indentation depth.

When the lexer encounters a closing delimiter (`}`, `)`, `]`) that does not match the top of the open-delimiter stack – or reaches a line with strictly lesser indentation bearing a top-level item starter (`pub`, `fn`, `struct`, `enum`, `union`, `trait`, `impl`) while an inner `(` or `[` remains unclosed – it evaluates two repair candidates using indentation and line-break evidence. In the **Missing Closing Bracket** case, if an inner `(` or `[` was left open before a semicolon `;`, closing brace `}`, or newline followed by a statement/item starter, the lexer inserts a synthetic closing token (`RPAREN`, `RBRACKET`, or `RBRACE`) with `flags.is_injected_recovery = true`, `byte_offset = curr_offset`, and `byte_len = 0`. In the **Stray Closing Bracket** case, if an unmatched `)` or `]` appears with no corresponding opener on the stack, the lexer reclassifies that token's kind to `TokenKind.invalid_token` with `flags.is_malformed = true` so it never prematurely pops an outer `Block` or `Item` scope. As a result, **every `LBRACE`, `LPAREN`, and `LBRACKET` in `TokenBuffer` is guaranteed to have a matching closing token**, enabling the parser to bound any bracketed subtree in O(1) time.

For **Lexical Casing Recovery (`DR-03` Disjoint Casing Invariant)**, `TYPE_IDENT` (`PascalCase`), `IDENT` (`snake_case`), and `CONST_IDENT` (`SCREAMING_SNAKE_CASE`) are lexically disjoint in `DR-03`. If a developer writes a mixed-case typo such as `struct my_struct` (where `kw_struct` requires `TYPE_IDENT`, or vice versa `let MyVar = 1;`), the lexer still classifies `my_struct` as `IDENT` and `MyVar` as `TYPE_IDENT` based on its leading character (`[a-z_]` vs. `[A-Z]`), setting `flags.is_malformed = true` if internal casing rules are violated (e.g., `bad_Camel_Mix`). At the parser level, when a grammar slot expects `TYPE_IDENT` after `struct`, `enum`, `union`, `trait`, or `type` and sees `IDENT` (or expects `IDENT` after `fn`, `let`, `var`, `mod`, or `.` and sees `TYPE_IDENT`), the parser **accepts the wrong-cased identifier**, emits a targeted `CasingViolationDiagnostic` with a machine-applicable `CodeFix` rename action, and continues building a valid declaration node rather than aborting the item.

### 2.2 Phase 2: Explicit-Stack Synchronization Anchor Sets (`DR-03` Grammar)

Because `TokenKind` has 112 total enum values (`0..111`), any token set is represented as a **128-bit bitset (`TokenSet128 = u128`)** where membership testing `set.contains(tok_kind)` is a single bitwise shift-and-mask operation (`(mask >> @intFromEnum(kind)) & 1 != 0`).

When a `ParseState` handler encounters an unexpected token $t$, it executes a three-step recovery protocol:
1.  **Suppress Cascading Syntax Diagnostics (`state.has_error`):** If `state.has_error` is already `true` (because a child state called `returnErrorOnState()`), the parser suppresses emitting a second syntax diagnostic for the same construct. Otherwise, it emits a single diagnostic at $t$ and marks `state.has_error = true`.
2.  **Bracket Replacement & Progress Guarantee (`skipPastLikelyEnd`):** Following Carbon's 6-step recovery protocol, if the error occurs while matching an introducer/header, the parser replaces the placeholder node at `state.subtree_start` with `CstNodeKind.invalid_parse_start`. It then invokes `skipPastLikelyEnd(anchor_set, stop_before_set)`, which **always consumes at least one token** (wrapped as `CstNodeKind.invalid_parse_leaf` with `has_error = true`) unless the current token is an enclosing scope closer (`}`, `)`, `]`, `eof`), preventing infinite parser loops.
3.  **Close with `InvalidParseSubtree`:** Once the scanner reaches an anchor token in `anchor_set` or `stop_before_set`, it closes the broken construct by emitting `CstNodeKind.invalid_parse_subtree` with `subtree_size = (cst.len + 1) - state.subtree_start` and resumes the enclosing loop state (`file_loop`, `block_stmt_loop`, `struct_fields_loop`, etc.).

#### Special Mid-Keystroke IDE Recovery Rules (`expr.` and `callee(a, `)

Two syntax states occur constantly during live typing and receive dedicated CST-to-AST lowering rules. First, under **Trailing Dot Recovery (`expr.` followed by whitespace/newline/`;`/`}`/`)`)**, when the Pratt postfix parser consumes `TokenKind.dot` (`DOT`) and the next token is *not* `IDENT`, `TYPE_IDENT`, `INT_LIT`, or `KW_AWAIT` (for example, the user just typed `user.` on a line before `let next = 1;`), the parser does **not** consume the following line's `let` token. Instead, it inserts a zero-length synthetic missing identifier leaf (`CstNodeKind.invalid_parse_leaf`, `is_missing_or_injected = true`) and closes `CstNodeKind.field_or_method_expr` (`has_error = true`), which lowers into `AstNode.Tag.incomplete_member_access` holding `data.lhs = receiver_node_idx` and `data.rhs = dot_token_idx`. Second, under **Unclosed Call or Generic Argument List Recovery (`repo.find(user_id, `)**, when `call_args_loop` sees `,` followed immediately by `RPAREN` (potentially injected by the lexical bracket balancer at the end of the line) or a statement starter, it emits `AstNode.Tag.expr_hole` for the trailing argument slot and lowers the call as `AstNode.Tag.incomplete_call`, preserving the callee node and all completed arguments so `textDocument/signatureHelp` highlights the exact active parameter index (`activeParameter = 1`).

### 2.3 Phase 3: Deliverable 2B – Partial-AST Bidirectional Typing & MVS Recovery Rules

In `DR-02` (Deliverable 2, Section 1), CoreX's type checker is defined as a **linear-time, mode-correct Bidirectional Type System** with two primary judgments: **Synthesis ($\Delta^+ \vdash e^+ \Rightarrow \tau^-$)** and **Checking ($\Delta^+ \vdash e^+ \Leftarrow \tau^+$)**, followed by a single-pass **Ghost-Instruction Abstract Interpreter** over Block-Argument SSA MIR to verify Mutable Value Semantics (MVS) exclusivity (`let`, `inout`, `sink`, `set`).

To prevent syntax or type errors from halting semantic analysis or unleashing cascades of false positive errors, CoreX extends `DR-02`'s bidirectional calculus with **Hazel-style Marked Hole Membranes and Gradual Unknown Type Propagation** (based on Zhao, Maroof, Dukkipati, Blinn, Pan, and Omar, *Total Type Error Localization and Recovery with Holes*, POPL 2024).

#### 1. The Unknown / Error Type ($\tau_{\text{err}}$ / `?`) and Quiet Consistency ($\sim$)

We reserve `TypeId.err_ty` (denoted $\tau_{\text{err}}$ or $?$ in formal rules) in the compiler's `InternPool`. Unlike ordinary types that compare by strict structural equality ($\tau_1 = \tau_2$), compatibility in the bidirectional checker is governed by the **reflexive, symmetric consistency relation ($\tau_1 \sim \tau_2$)**:
-   $\tau_{\text{err}} \sim \tau$ and $\tau \sim \tau_{\text{err}}$ for **all** types $\tau$ (including primitive types, structs, enums, traits, and function types).
-   For composite types, consistency holds inductively: $[T_1] \sim [T_2] \iff T_1 \sim T_2$, and $\text{Result}[T_1, E_1] \sim \text{Result}[T_2, E_2] \iff (T_1 \sim T_2 \land E_1 \sim E_2)$.
-   **Silent Unification Rule (Zero Cascading Diagnostics):** Whenever a checking rule or operator constraint checks $\tau_{\text{actual}} \sim \tau_{\text{expected}}$ and either operand is $\tau_{\text{err}}$, the check **succeeds silently without emitting a secondary diagnostic**, because a primary diagnostic was already emitted at the AST hole or localized type mismatch that produced $\tau_{\text{err}}$.

#### 2. Formal Partial-AST Bidirectional Inference Rules for CoreX

Let `⦅e⦆` denote a non-empty **Error Membrane** wrapping an ill-typed sub-expression $e$, and let $\text{Hole}_{\text{expr}}$, $\text{Hole}_{\text{type}}$, and $\text{Hole}_{\text{pat}}$ denote AST hole nodes produced by fault-tolerant CST lowering:

$$\frac{}{\Delta \vdash \text{Hole}_{\text{expr}} \Rightarrow \tau_{\text{err}}} \;(\text{Hole-Syn}\Rightarrow) \qquad \frac{}{\Delta \vdash \text{Hole}_{\text{expr}} \Leftarrow \tau} \;(\text{Hole-Chk}\Leftarrow)$$

$$\frac{\Delta \vdash e \Rightarrow \tau}{\Delta \vdash e \Leftarrow \tau_{\text{err}}} \;(\text{SynSwitch-Err}\Leftarrow) \qquad \frac{\Delta \vdash p \Leftarrow \tau_{\text{err}} \dashv \Delta'}{\Delta \vdash \text{Hole}_{\text{pat}}(x) \Leftarrow \tau \dashv \Delta, x \Rightarrow \tau} \;(\text{Pat-Hole}\Leftarrow)$$

These foundational rules enable five concrete recovery behaviors across incomplete expressions:
1.  **Mode-Switching on Unknown Context (`SynSwitch-Err` $\Leftarrow$, adapted from Hazel `UASynSwitch`):** When an expression $e$ is checked against an unknown expected type $\tau_{\text{err}}$ (for example, `let x: MissingType = user.age;` where `: MissingType` resolved to $\tau_{\text{err}}$), the checker does **not** skip $e$; it switches $e$ into **Synthesis Mode** ($\Delta \vdash e \Rightarrow \tau$) so all identifiers, field accesses, and method calls inside $e$ still receive full type resolution and IDE hover/completion support.
2.  **Incomplete Member Access for Dot-Completion (`IncompleteMember` $\Rightarrow$):** When typing `user.` (`AstNode.Tag.incomplete_member_access`), the type checker synthesizes the receiver's type $\tau_{\text{recv}}$, records $\tau_{\text{recv}}$ in the per-body `TypeTable[receiver_node]`, attaches a completion obligation $\mathcal{O}_{\text{member}}(\tau_{\text{recv}})$ at the dot token offset, and yields $\tau_{\text{err}}$ for the overall expression so the enclosing statement remains well-typed:
    $$\frac{\Delta \vdash e_{\text{recv}} \Rightarrow \tau_{\text{recv}} \quad \text{record\_completion\_type}(e_{\text{recv}}, \tau_{\text{recv}})}{\Delta \vdash \text{IncompleteMemberAccess}(e_{\text{recv}}, \text{`.`}) \Rightarrow \tau_{\text{err}}} \;(\text{Dot-Complete}\Rightarrow)$$
3.  **Incomplete Call for Signature Help (`IncompleteCall` $\Rightarrow$):** When typing `repo.find(id, ` (`AstNode.Tag.incomplete_call`), the type checker synthesizes the callee signature $\text{fn}(\tau_1, \dots, \tau_n) \rightarrow \tau_{\text{ret}}$. Even if argument count $m \neq n$, it checks each present argument $a_i$ against parameter type $\tau_i$ for $1 \le i \le \min(m, n)$ (and synthesizes any extra arguments $i > n$ via `SynSwitch-Err`), binding the expected parameter type $\tau_{\text{active}}$ onto the trailing `expr_hole` at the cursor and returning the known return type $\tau_{\text{ret}}$:
    $$\frac{\Delta \vdash f \Rightarrow \text{fn}(\tau_1, \dots, \tau_n) \rightarrow \tau_{\text{ret}} \quad \forall i \le \min(m,n).\; \Delta \vdash a_i \Leftarrow \tau_i \quad \forall j > n.\; \Delta \vdash a_j \Rightarrow \tau'_j}{\Delta \vdash \text{IncompleteCall}(f, [a_1, \dots, a_m]) \Rightarrow \tau_{\text{ret}}} \;(\text{Call-Recover}\Rightarrow)$$
    Because `IncompleteCall` synthesizes the actual return type $\tau_{\text{ret}}$ (rather than $\tau_{\text{err}}$) whenever the callee $f$ is known, chaining a dot after an incomplete call (`repo.find(id, ).`) still knows the return type $\tau_{\text{ret}}$ and provides accurate method completions.
4.  **Branch Divergence Localization (`If-Mismatch` $\Rightarrow$, Hazel Neutral Branch Rule):** If an `if` or `match` expression in synthesis mode has conflicting branch types ($\Delta \vdash e_{\text{then}} \Rightarrow \tau_1$, $\Delta \vdash e_{\text{else}} \Rightarrow \tau_2$, and $\tau_1 \not\sim \tau_2$), guessing that $\tau_1$ is "correct" would trigger false type errors on downstream uses of the variable that expected $\tau_2$. Following Hazel's POPL 2024 localization rule, CoreX localizes a single `BranchTypeMismatch(τ1, τ2)` diagnostic to the `if`/`match` expression wrapped in a non-empty hole membrane `⦅if ec e1 else e2⦆` and synthesizes $\tau_{\text{err}}$ as the result of the conditional, isolating all downstream uses of the bound variable from cascading errors:
    $$\frac{\Delta \vdash e_c \Leftarrow \text{bool} \quad \Delta \vdash e_1 \Rightarrow \tau_1 \quad \Delta \vdash e_2 \Rightarrow \tau_2 \quad \tau_1 \not\sim \tau_2}{\Delta \vdash (\!\!(\text{if } e_c \; e_1 \text{ else } e_2)\!\!) \Rightarrow \tau_{\text{err}}} \;(\text{If-Mismatch}\Rightarrow)$$
5.  **Unannotated Closure Recovery (`Closure-Hole` $\Rightarrow$):** In `DR-02`, unannotated closures `|x| body` are checked in $\Leftarrow$ mode against a known function type $\tau_1 \rightarrow \tau_2$. If an unannotated closure appears in a broken context where the expected type is $\tau_{\text{err}}$ (or in bare synthesis mode), `Closure-Hole` binds each unannotated parameter $x_i \Rightarrow \tau_{\text{err}}$ in $\Delta$ and synthesizes the body $\Delta, x_1 \Rightarrow \tau_{\text{err}} \vdash \text{body} \Rightarrow \tau_{\text{ret}}$, allowing IDE features inside the closure body to operate normally without crashing.

#### 3. MVS Ghost-Instruction Verification Recovery on Partial MIR

When `typecheck_body(DefId)` lowers a partial AST containing holes or $\tau_{\text{err}}$ expressions into Block-Argument SSA MIR for `DR-02`'s Ghost-Instruction Abstract Interpreter (`verify_sast_mir(DefId)`), three rules prevent false-positive borrow/initialization errors:
1.  **Definite Initialization Recovery (`storage.init` on Holes):** If a local declaration `let x: Packet = Hole_expr;` or a `set` call `init_packet(&set out, Hole_expr)` contains an expression hole, the MIR builder still emits `storage.init %x` (or `storage.init %out`), transitioning the variable's abstract state to $\text{Initialized}$ so subsequent reads of `x` or `out` in the function body are not flagged as uninitialized reads.
2.  **Immediate Release of Incomplete Projections (`access.end`):** If an `inout` projection `&vec.push(Hole_expr)` is part of an `incomplete_call`, the MIR builder brackets the call with `%p = access.inout %vec` and an immediate post-call `access.end %p`, ensuring the mutable borrow does not leak across the remainder of the basic block.
3.  **Linear / Explicit-Deinit Suppression on Poisoned Paths:** In `DR-02` (Deliverable 1, Axis 5), resource types (`File`, `Socket`, `Arena`) require explicit `sink` consumption or `defer` cleanup before scope exit. If a basic block ends with an `InvalidParseSubtree` / `stmt_hole` (because the user is still typing the middle of the block and hasn't typed `defer file.close();` yet, or a syntax error truncated the block), any unconsumed linear binding whose scope contains a `stmt_hole` suppresses its missing-cleanup error on the truncated CFG edge until the block is syntactically closed.

## 3. Demand-Driven Incremental Query Engine (`CompilerDb`) with Early Cutoff

To achieve sub-5 ms incremental turnaround without re-checking untouched modules across a 500,000-line codebase, CoreX implements a **Salsa-inspired Demand-Driven Query Database (`CompilerDb`)** featuring **Durability Levels**, **Position-Independent `ItemTree` Projections**, and **128-bit `Wyhash(0)` / BLAKE3 Early Cutoff (Backdating)**.

> **Visual – ItemTree Early Cutoff Shields 99.99% of the Workspace from Function-Body Edits:** Architecture of CoreX's demand-driven `CompilerDb` and lock-free LSP scheduler. Top: Editing inside a function body bumps the global `Revision` counter (`R41` to `R42`) and marks `FileId(7)` dirty at `Durability::Low`. Recomputing `parse_cst`, `lower_ast`, and `item_tree` produces the exact same 128-bit signature fingerprint (`0x8F3A...9C12`), triggering **Early Cutoff (Backdating)**: `resolve_signatures(ModuleId)` retains `changed_at = R12`, pruning all 24,999 unmodified `DefId` bodies across the workspace and re-checking only `DefId(7, 3)`. Bottom: Cooperative cancellation unwinds any stale `R41` background check within microseconds when `didChange` arrives, immediately publishing Wave 1 syntax diagnostics before settling Wave 2 semantic diagnostics.

### 3.1 The Six-Stage Query Hierarchy and Position-Independent `ItemTree`

A naive incremental compiler keys semantic queries by raw AST node indices (`NodeIndex(u32)`). However, if a developer adds two lines of code or a new helper function at the top of `http_server.cx`, the byte offset and `NodeIndex` of every subsequent function in `http_server.cx` shifts downward – invalidating all downstream memos for every function in the file even though their source text did not change.

Following `rust-analyzer` (`hir_def::item_tree::ItemTree`) and `ry-lang`'s position-independent item architecture, CoreX decouples file-level syntax trees from semantic checking via two structural abstractions. First, **Content-Addressed `DefId` Identity (`64-bit` Packed Handle)** assigns every top-level item or member (`fn`, `struct`, `enum`, `union`, `trait`, `impl`, `const`, `type`, `mod`) a stable `DefId` interned from the tuple `(parent_scope: ModuleOrImplId, item_kind: ItemKind, name: StringId, disambiguator: u16)`. Because `DefId` depends on the item's lexical name (`StringId`) and enclosing module rather than its line number or `NodeIndex` ordinal, inserting or deleting lines above `fn scan_file` leaves `DefId(scan_file)` **100% unchanged**.

Second, **The `item_tree(FileId)` Firewall and Relative Body Windows** scans `AstArena` in O(N_items) time (skipping over function or method block bodies `{ ... }` in O(1) via CST `subtree_size`) and extracts two artifacts per file. The **Exported & Module-Local Signature Table (`ItemTreeSignatures`)** contains all item declarations, generic `TypeParams`, `WhereClause` predicates, `StructField` / `EnumVariant` layouts, and `FnSignature` parameter/return types normalized with **relative token/node indices** (`0 .. sig_len`) stripped of absolute byte offsets, along with its 128-bit `Wyhash(0)` / BLAKE3 content fingerprint `signature_hash: u128`. Alongside it, the **Per-Body Relative AST Window (`BodyAstWindow` per `DefId`)** extracts for each function, method, or constant body `DefId` in the file a position-independent window over the body's AST nodes where all internal `NodeIndex` links and token offsets are stored **relative to the start of that `DefId`** (`base_node_idx`, `base_byte_offset`), accompanied by a per-body 128-bit fingerprint `body_hash: u128`.

| Query Stage | Input Key | Output Value | Memo Fingerprint / Equality Basis | Modeled Execution Cost |
| :--- | :--- | :--- | :--- | :--- |
| **0. `source_text`** (Input) | `FileId(u32)` | `SourceInput { text: []const u8, durability: Durability }` | 128-bit `Wyhash(0)` / BLAKE3 of `text`. | O(1) on `didChange` (`15 µs`). |
| **1. `parse_cst`** | `FileId(u32)` | `*LosslessCstArena` + `*TokenBuffer` | Always runs if `source_text(FileId)` changed. | `81 µs` per 400-LOC file (`25 µs` lex + `56 µs` CST). |
| **2. `lower_ast`** | `FileId(u32)` | `*AstArena` + `[]SyntaxDiagnostic` | 128-bit hash of normalized trivia-free `AstArena`. | `40 µs` per 400-LOC file (**Early Cutoff on comment/whitespace edits!**). |
| **3. `item_tree`** | `FileId(u32)` | `*ItemTree { sig_hash: u128, body_hashes: Map[DefId, u128] }` | `sig_hash` for module queries; `body_hashes[DefId]` for body queries. | `14 µs` per 400-LOC file (**Early Cutoff Firewall!**). |
| **4. `resolve_signatures`** | `ModuleId(u32)` | `*ModuleDefMap` (Resolved symbol table, trait impls, struct layouts) | `sig_hash` of all `FileId`s belonging to `ModuleId` + imported symbols. | `2 µs` (O(1) verification hit when `sig_hash` is unchanged). |

| **6. `verify_sast_mir`** | `DefId(u64)` | `*MirVerificationResult` (Block-Arg SSA MIR + Ghost-Inst SAST diagnostics) | Depends solely on `typecheck_body(DefId)` fingerprint. | `65 µs` for the **single modified `DefId`**. |

#### Three Levels of Early Cutoff in `CompilerDb`

This six-stage pipeline provides **three distinct early-cutoff barriers**:
1.  **Barrier 1 – Comment & Formatting Cutoff (`lower_ast`):** Because `AstArena` strips comments and whitespace trivia, typing inside a doc comment `///` or reformatting whitespace with `corex fmt` produces an identical `lower_ast(FileId)` fingerprint (`AstArena` hash unchanged), backdating `lower_ast` and skipping `item_tree`, `resolve_signatures`, `typecheck_body`, and `verify_sast_mir` entirely.
2.  **Barrier 2 – Sibling Body Position Cutoff (`body_hashes[DefId]`):** Because each function body's `BodyAstWindow` uses offsets relative to the function's own `fn` keyword token, editing inside `fn alpha()` changes `body_hashes[alpha]` while leaving `body_hashes[beta]` (for every other function `beta` in the same file) **bit-for-bit identical**. Thus, sibling functions in the edited file are never re-typechecked.
3.  **Barrier 3 – Module Signature Firewall (`item_tree.sig_hash` → `resolve_signatures`):** Editing statements inside `fn alpha()` leaves the file's `ItemTree.sig_hash` unchanged. When `resolve_signatures(ModuleId)` verifies its dependencies, it sees that `item_tree(FileId).sig_hash` was backdated to its prior revision, terminating invalidation across all 1,249 other files in the workspace. Even when a public function's signature *does* change, fine-grained symbol dependency tracking (`def_signature(DefId)`) ensures only callers that actually reference that specific `DefId` are re-verified (*Blast Radius Indexing*).

### 3.2 Durability Optimization (`Durability::Low | Medium | High`)

In a 500,000-line workspace, walking the dependency graph down to the leaf `FileId` inputs on every query just to verify that standard library (`std::*`) or third-party package files (`corex.toml` dependencies) haven't changed would waste milliseconds of CPU time. Following Salsa's durability mechanism, every `SourceInput` is tagged with one of three durability levels: `Durability.low (0)` for actively open editor buffers in `corex lsp` (`textDocument/didOpen` / `didChange`), `Durability.medium (1)` for unopened workspace `.cx` files on disk, and `Durability.high (2)` for standard library modules (`std::*`), locked external dependencies, and `corex.toml` compiler target settings.

Every memoized query node records `durability: Durability = min(dep.durability for dep in dependencies)`. The database maintains a global array `last_changed_by_durability: [3]Revision`. When a user types a character in an open buffer (`Durability.low`), `current_revision` increments to $R$, and only `last_changed_by_durability[0]` is updated to $R$, while `last_changed_by_durability[1]` (Medium) and `[2]` (High) remain at their older revisions. Under the **Durability Fast-Path**, when verifying any memoized query whose recorded `memo.durability` is `Medium` or `High`, if `memo.verified_at >= last_changed_by_durability[memo.durability]`, `CompilerDb` immediately updates `memo.verified_at = current_revision` in **O(1) time (a single integer comparison)** without inspecting a single dependency edge.

### 3.3 Deliverable 3: Incremental Query Database (`CompilerDb`) & Early-Cutoff Invalidation Algorithm

The following implementation provides the complete, cycle-safe, thread-safe `CompilerDb` runtime, memo header layout, 128-bit `Fingerprint128` backdating comparator, and recursive `maybeChangedAfter` verification algorithm in Zig (Stage 0):

```zig
//! CoreX Stage-0 Compiler (`stage0/corex`)
//! Module: Demand-Driven Incremental Query Engine (`CompilerDb`) with Early Cutoff
//! Implements Salsa-style `verified_at` / `changed_at` backdating, Durability fast-paths,
//! and cooperative atomic cancellation for `corex lsp`.

const std = @import("std");
const assert = std.debug.assert;
const Allocator = std.mem.Allocator;

/// Monotonically increasing logical clock bumped on every input mutation.
pub const Revision = enum(u32) {
    initial = 1,
    _,

    pub inline fn raw(self: Revision) u32 {
        return @intFromEnum(self);
    }
    pub inline fn isAfter(self: Revision, other: Revision) bool {
        return self.raw() > other.raw();
    }
};

/// Classifies how frequently an input changes to skip dependency graph walks.
pub const Durability = enum(u2) {
    low = 0,    // Open editor buffers (`textDocument/didChange`)
    medium = 1, // Workspace files on disk (watched by file watcher)
    high = 2,   // Standard library (`std::*`) & locked external packages

    pub inline fn min(a: Durability, b: Durability) Durability {
        return if (@intFromEnum(a) < @intFromEnum(b)) a else b;
    }
};

/// 128-bit content fingerprint (computed via BLAKE3-128 or dual-seeded Wyhash64)
/// used for O(1) Early Cutoff (backdating) equality comparisons.
pub const Fingerprint128 = extern struct {
    lo: u64,
    hi: u64,

    pub inline fn eql(a: Fingerprint128, b: Fingerprint128) bool {
        return a.lo == b.lo and a.hi == b.hi;
    }

    pub fn fromBytes(bytes: []const u8) Fingerprint128 {
        var out: [16]u8 = undefined;
        std.crypto.hash.Blake3.hash(bytes, &out, .{});
        return .{
            .lo = std.mem.readInt(u64, out[0..8], .little),
            .hi = std.mem.readInt(u64, out[8..16], .little),
        };
    }
};

pub const QueryStage = enum(u8) {
    source_text = 0,          // Input: FileId -> SourceText
    parse_cst = 1,            // Derived: FileId -> (TokenBuffer, LosslessCstArena)
    lower_ast = 2,            // Derived: FileId -> AstArena
    item_tree = 3,            // Derived: FileId -> ItemTree (Signature & Body Windows)
    item_tree_sig_proj = 4,   // Firewall Projection: FileId -> ItemTree.sig_hash
    body_ast_proj = 5,        // Firewall Projection: DefId -> ItemTree.body_hashes[DefId]
    resolve_signatures = 6,   // Derived: ModuleId -> ModuleDefMap
    def_signature = 7,        // Fine-Grained Projection: DefId -> SymbolSignature
    typecheck_body = 8,       // Derived: DefId -> TypedBody
    verify_sast_mir = 9,      // Derived: DefId -> MirVerificationResult
};

/// Universal 8-byte Query Key identifying any node in the CompilerDb dependency DAG.
pub const QueryKey = extern struct {
    stage: QueryStage,
    _pad: u8 = 0,
    /// Disambiguator or sub-item index for DefId queries.
    sub_id: u16 = 0,
    /// Primary 32-bit ID (`FileId`, `ModuleId`, or `DefId` index).
    primary_id: u32,
};

/// Memoized metadata header stored for every executed query in `CompilerDb`.
pub const MemoHeader = struct {
    key: QueryKey,
    /// The revision in which this query's output value actually changed.
    /// Preserved in the past when Early Cutoff (Backdating) triggers!
    changed_at: Revision,
    /// The latest revision in which all dependencies of this memo were verified up-to-date.
    verified_at: std.atomic.Value(u32),
    /// Minimum durability across all transitive inputs read during the last execution.
    durability: Durability,
    /// Cycle-detection state during active verification/execution.
    in_flight: std.atomic.Value(bool) = std.atomic.Value(bool).init(false),
    /// 128-bit cryptographic/structural fingerprint of the query's output value.
    output_fingerprint: Fingerprint128,
    /// Slice of dependencies read during the most recent execution of this query.
    dependencies: []QueryKey = &[_]QueryKey{},
    /// Opaque pointer to the arena-allocated output artifact (`*AstArena`, `*TypedBody`, etc.).
    value_ptr: ?*anyopaque = null,
};

pub const QueryError = error{
    Cancelled,
    DependencyCycle,
    OutOfMemory,
};

/// Active query stack frame tracked per worker thread to automatically record dependencies.
pub const ActiveQueryFrame = struct {
    key: QueryKey,
    min_durability: Durability = .high,
    max_dep_changed_at: Revision = .initial,
    recorded_deps: std.ArrayListUnmanaged(QueryKey) = .{},
};

pub const CompilerDb = struct {
    allocator: Allocator,
    /// Global monotonically increasing revision counter.
    current_revision: std.atomic.Value(u32) = std.atomic.Value(u32).init(1),
    /// Cooperative cancellation counter bumped immediately on `textDocument/didChange`
    /// or `$/cancelRequest` before acquiring the database write lock.
    cancellation_epoch: std.atomic.Value(u32) = std.atomic.Value(u32).init(0),
    /// Tracks the latest Revision that mutated an input at each Durability level [Low, Medium, High].
    last_changed_by_durability: [3]Revision = .{ .initial, .initial, .initial },
    /// Memo table mapping `QueryKey` (bitcast as u64) -> `*MemoHeader`.
    memos: std.AutoHashMapUnmanaged(u64, *MemoHeader) = .{},
    /// Thread-local active query stack for automatic dependency tracking.
    active_stack: std.ArrayListUnmanaged(ActiveQueryFrame) = .{},

    pub inline fn keyToU64(k: QueryKey) u64 {
        return @bitCast(k);
    }

    /// Cooperative cancellation check invoked at the entry of every query,
    /// every parser loop iteration, and every MIR basic block verification step.
    pub inline fn unwindIfCancelled(self: *const CompilerDb, expected_epoch: u32) QueryError!void {
        if (self.cancellation_epoch.load(.acquire) != expected_epoch) {
            return error.Cancelled;
        }
    }

    /// Mutates an external input (`source_text(FileId)`) and bumps the global revision clock in O(1).
    /// Does NOT eagerly recompute any downstream queries (lazy pull evaluation).
    pub fn setInput(
        self: *CompilerDb,
        file_id: u32,
        new_text: []const u8,
        durability: Durability,
        value_ptr: *anyopaque,
    ) !Revision {
        const k = QueryKey{ .stage = .source_text, .primary_id = file_id };
        const new_fp = Fingerprint128.fromBytes(new_text);

        if (self.memos.get(keyToU64(k))) |existing| {
            // Same-value optimization: if content fingerprint is identical, no revision bump!
            if (Fingerprint128.eql(existing.output_fingerprint, new_fp) and existing.durability == durability) {
                return @enumFromInt(self.current_revision.load(.acquire));
            }
        }

        // Bump cancellation epoch first so any in-flight worker unwinds immediately
        _ = self.cancellation_epoch.fetchAdd(1, .seq_cst);
        const next_rev_raw = self.current_revision.fetchAdd(1, .seq_cst) + 1;
        const next_rev: Revision = @enumFromInt(next_rev_raw);
        self.last_changed_by_durability[@intFromEnum(durability)] = next_rev;

        const memo = try self.getOrCreateMemo(k);
        memo.changed_at = next_rev;
        memo.verified_at.store(next_rev_raw, .release);
        memo.durability = durability;
        memo.output_fingerprint = new_fp;
        memo.value_ptr = value_ptr;
        return next_rev;
    }

    /// Core Salsa-style demand-driven query fetch with Durability Fast-Path and Early Cutoff.
    pub fn fetchQuery(
        self: *CompilerDb,
        key: QueryKey,
        expected_epoch: u32,
        computeFn: *const fn (*CompilerDb, QueryKey, u32) QueryError!struct { ptr: *anyopaque, fp: Fingerprint128 },
    ) QueryError!*anyopaque {
        try self.unwindIfCancelled(expected_epoch);
        const curr_rev_raw = self.current_revision.load(.acquire);
        const curr_rev: Revision = @enumFromInt(curr_rev_raw);

        const memo = try self.getOrCreateMemo(key);

        // [1] Register dependency in parent query frame (if called inside another query)
        if (self.active_stack.items.len > 0) {
            var parent = &self.active_stack.items[self.active_stack.items.len - 1];
            try parent.recorded_deps.append(self.allocator, key);
        }

        // [2] Fast Path: Already verified in current revision!
        if (memo.verified_at.load(.acquire) == curr_rev_raw and memo.value_ptr != null) {
            self.propagateToParent(memo.durability, memo.changed_at);
            return memo.value_ptr.?;
        }

        // [3] Verify whether any transitive dependency changed after `memo.verified_at`
        if (memo.value_ptr != null) {
            const changed = try self.maybeChangedAfter(key, curr_rev, expected_epoch);
            if (!changed) {
                self.propagateToParent(memo.durability, memo.changed_at);
                return memo.value_ptr.?;
            }
        }

        // [4] Red Path: At least one dependency changed (or first run) -> Execute query!
        const result = try self.executeAndBackdate(memo, curr_rev, expected_epoch, computeFn);
        self.propagateToParent(memo.durability, memo.changed_at);
        return result;
    }

    /// Recursive verification algorithm (`maybe_changed_after`):
    /// Returns `false` (Green Path) if all dependencies are unchanged, updating `verified_at`.
    /// Returns `true` (Red Path) if the query must re-execute.
    pub fn maybeChangedAfter(
        self: *CompilerDb,
        key: QueryKey,
        after_rev: Revision,
        expected_epoch: u32,
    ) QueryError!bool {
        try self.unwindIfCancelled(expected_epoch);
        const curr_rev_raw = self.current_revision.load(.acquire);
        const curr_rev: Revision = @enumFromInt(curr_rev_raw);
        const memo = self.memos.get(keyToU64(key)) orelse return true;

        // Input queries (`source_text`) are always verified at the current revision
        if (key.stage == .source_text) {
            return memo.changed_at.isAfter(after_rev);
        }

        const last_verified: Revision = @enumFromInt(memo.verified_at.load(.acquire));
        if (last_verified == curr_rev) {
            return memo.changed_at.isAfter(after_rev);
        }

        // DURABILITY FAST-PATH: If no input of `memo.durability` (or lower) has changed
        // since `last_verified`, skip walking the entire dependency subtree in O(1)!
        const last_dur_change = self.last_changed_by_durability[@intFromEnum(memo.durability)];
        if (!last_dur_change.isAfter(last_verified)) {
            memo.verified_at.store(curr_rev_raw, .release);
            return memo.changed_at.isAfter(after_rev);
        }

        // Walk recorded dependencies in execution order (handles dynamic dependency branching)
        for (memo.dependencies) |dep_key| {
            if (try self.maybeChangedAfter(dep_key, last_verified, expected_epoch)) {
                // Dependency `dep_key` changed since `last_verified` -> Re-execute `memo`
                // to see if `memo` hits Early Cutoff (backdating) or produces a new output!
                return true;
            }
        }

        // All dependencies verified unchanged! Mark `memo.verified_at = curr_rev` (Green Path).
        memo.verified_at.store(curr_rev_raw, .release);
        return memo.changed_at.isAfter(after_rev);
    }

    fn executeAndBackdate(
        self: *CompilerDb,
        memo: *MemoHeader,
        curr_rev: Revision,
        expected_epoch: u32,
        computeFn: *const fn (*CompilerDb, QueryKey, u32) QueryError!struct { ptr: *anyopaque, fp: Fingerprint128 },
    ) QueryError!*anyopaque {
        if (memo.in_flight.swap(true, .acq_rel)) {
            return error.DependencyCycle;
        }
        defer memo.in_flight.store(false, .release);

        try self.active_stack.append(self.allocator, .{ .key = memo.key });
        errdefer {
            var popped = self.active_stack.pop();
            popped.recorded_deps.deinit(self.allocator);
        }

        const old_fp = memo.output_fingerprint;
        const had_old_value = (memo.value_ptr != null);

        const computed = try computeFn(self, memo.key, expected_epoch);

        var frame = self.active_stack.pop();
        if (memo.dependencies.len > 0) {
            self.allocator.free(memo.dependencies);
        }
        memo.dependencies = try frame.recorded_deps.toOwnedSlice(self.allocator);
        memo.durability = frame.min_durability;

        // EARLY CUTOFF (BACKDATING) CHECK:
        // If the recomputed 128-bit fingerprint equals the previous output fingerprint,
        // we KEEP `memo.changed_at` in the past! All downstream queries checking
        // `memo.changed_at > parent.verified_at` will evaluate to FALSE and skip execution!
        if (!had_old_value or !Fingerprint128.eql(old_fp, computed.fp)) {
            memo.changed_at = curr_rev;
            memo.output_fingerprint = computed.fp;
        }
        memo.value_ptr = computed.ptr;
        memo.verified_at.store(curr_rev.raw(), .release);
        return computed.ptr;
    }

    inline fn propagateToParent(self: *CompilerDb, dep_durability: Durability, dep_changed_at: Revision) void {
        if (self.active_stack.items.len > 0) {
            var parent = &self.active_stack.items[self.active_stack.items.len - 1];
            parent.min_durability = Durability.min(parent.min_durability, dep_durability);
            if (dep_changed_at.isAfter(parent.max_dep_changed_at)) {
                parent.max_dep_changed_at = dep_changed_at;
            }
        }
    }

    fn getOrCreateMemo(self: *CompilerDb, key: QueryKey) !*MemoHeader {
        const gop = try self.memos.getOrPut(self.allocator, keyToU64(key));
        if (!gop.found_existing) {
            const ptr = try self.allocator.create(MemoHeader);
            ptr.* = .{
                .key = key,
                .changed_at = .initial,
                .verified_at = std.atomic.Value(u32).init(0),
                .durability = .high,
                .output_fingerprint = .{ .lo = 0, .hi = 0 },
            };
            gop.value_ptr.* = ptr;
        }
        return gop.value_ptr.*;
    }
};
```

## 4. Built-in `corex lsp` Server Architecture

Because `corex lsp` is compiled directly into the `corex` binary and shares `TokenBuffer`, `LosslessCstArena`, `AstArena`, and `CompilerDb` with `corex build`, `corex check`, and `corex fmt`, there is zero protocol translation or out-of-process sidecar serialization overhead between the IDE host and the compiler's semantic engine.

### 4.1 JSON-RPC 2.0 Transport, Lock-Free Cancellation, and Two-Wave Diagnostics

`corex lsp` communicates over standard input/output (`stdin`/`stdout`) using LSP 3.17+ JSON-RPC 2.0 framing (`Content-Length: <bytes>\r\n\r\n<utf-8 JSON payload>`). Following the concurrency architectures of `rust-analyzer` and `ry-lang`, the server separates I/O routing from query execution across two core mechanisms:

1.  **Non-Blocking I/O Router & Priority Job Queue:**
    A dedicated I/O thread reads JSON-RPC messages from `stdin` and classifies each message into one of three priority classes. **Class 0 (State Mutations & Cancellations: `textDocument/didOpen`, `didChange`, `didClose`, `workspace/didChangeWatchedFiles`, `$/cancelRequest`)** is processed immediately: whenever an input mutation arrives, the I/O thread atomically increments `CompilerDb.cancellation_epoch` (`fetchAdd(1, .seq_cst)`) *before* acquiring the database write lock, so any in-flight query worker hits `unwindIfCancelled(expected_epoch)` within microseconds, drops its shared snapshot lock, and unwinds cleanly via `error.Cancelled`. **Class 1 (Interactive Foreground Queries: `textDocument/completion`, `signatureHelp`, `hover`, `definition`, `inlayHint`, `semanticTokens/full/delta`, `codeAction`, `formatting`, `rename`)** preempts any idle background checking; following `ry-lang`'s stability invariant, an interactive LSP request **never cancels another active interactive request**, and authoritative mutations like `textDocument/rename` return `CONTENT_MODIFIED` (`-32801`) if superseded by a concurrent document edit, whereas pull diagnostics return `SERVER_CANCELLED` (`-32802`) with `retriggerRequest: true`. **Class 2 (Idle Background Settled Workspace Checking)** runs across worker threads on cloned read-only snapshots of `CompilerDb` only when the Class 0 and Class 1 queues are empty, checking each file's cancellation flag before starting.
2.  **Two-Wave Diagnostic Publishing (`Wave 1` Immediate vs. `Wave 2` Settled):**
    For clients using push diagnostics (`textDocument/publishDiagnostics`), `corex lsp` publishes findings in two waves on every `didChange` sync. **Wave 1 (Immediate Syntax + Active-Body Diagnostics, `< 0.5 ms`)** immediately publishes lexer diagnostics, CST/AST syntax recovery errors, casing lints, and the active `DefId`'s semantic/SAST diagnostics tagged with the document `version`; during cold startup on a large repository, `corex lsp` can also load a persisted check record (`.corex_cache/check.json`, analogous to `ry check`'s `~0.2 s` restore on a 300,000-line package) to populate initial workspace diagnostics without waiting for full background warm-up. **Wave 2 (Settled Cross-Module Diagnostics at Idle)** runs once typing pauses and background workers verify any cross-module callers affected by signature edits, publishing the complete settled diagnostic set. For clients supporting LSP 3.17 Pull Diagnostics (`textDocument/diagnostic`), `corex lsp` omits push waves and returns content-hashed `resultId` strings (`RelatedFullDocumentDiagnosticReport` or `RelatedUnchangedDocumentDiagnosticReport`).

### 4.2 In-Memory `Vfs` Overlay Buffers and Fast UTF-8 ↔ UTF-16 `LineIndex`

Because open files in an editor contain unsaved modifications, `CompilerDb` never reads open files directly from the OS filesystem during analysis. Instead, all file reads pass through an in-memory **Virtual File System (`Vfs`)**. Disk files start in `VfsState.disk_backed` (`Durability.medium`). When `textDocument/didOpen` arrives, the `Vfs` promotes that `FileId` to `VfsState.memory_overlay` (`Durability.low`), shadowing the disk file with an in-memory UTF-8 byte buffer updated via `textDocument/didChange` incremental range replacements (`TextDocumentContentChangeEvent`). When `textDocument/didClose` arrives, the overlay is dropped and `FileId` reverts to the disk file at `Durability.medium`.

To provide a **Zero-Allocation UTF-8 ↔ UTF-16 `LineIndex`**, since LSP 3.17 defaults to UTF-16 code units for `Position { line, character }` unless the client negotiates `PositionEncodingKind.UTF8` (`"utf-8"`) during `initialize`, `TokenBuffer.line_starts` stores the `u32` byte offset of every line start alongside a compact bitset `non_ascii_lines` marking the lines that contain multi-byte UTF-8 scalars (`byte >= 0x80`). For pure ASCII lines (`non_ascii_lines.isSet(line) == false`), `utf16_col == utf8_byte_col` in **O(1) arithmetic**; only lines with `non_ascii_lines` set scan the line's UTF-8 bytes to translate UTF-16 surrogate pairs.

### 4.3 Semantic Tokens (`full` and `delta` 5-Integer Relative Encoding)

`corex lsp` implements `textDocument/semanticTokens/full`, `textDocument/semanticTokens/range`, and `textDocument/semanticTokens/full/delta`. Per the LSP 3.17 specification, semantic tokens are transmitted as a flat `[]u32` array where every token is encoded as **5 relative unsigned integers** `(deltaLine, deltaStartChar, length, tokenType, tokenModifiersBitset)`:
$$\text{deltaLine}_i = \text{line}_i - \text{line}_{i-1}, \qquad \text{deltaStartChar}_i = \begin{cases} \text{col}_i - \text{col}_{i-1} & \text{if } \text{deltaLine}_i = 0 \\ \text{col}_i & \text{if } \text{deltaLine}_i > 0 \end{cases}$$

Because `DR-03` already partitions `TYPE_IDENT`, `CONST_IDENT`, `PRIM_TYPE`, and `IDENT` in `TokenBuffer`, `corex lsp` combines `TokenBuffer` with `TypedBody` (`typecheck_body(DefId)`) and `MirVerificationResult` (`verify_sast_mir(DefId)`) to highlight **CoreX-specific semantic roles** – most notably mutability (`var`, `&mut`), MVS ownership consumption (`own` / `sink`), and contextual enum variants (`.Some`, `.Ok`):

| Index / Bit | `SemanticTokenTypes` Legend (`u32` index) | `SemanticTokenModifiers` Legend (`u32` bitmask) | CoreX Semantic Source (`DR-02` / `DR-03`) |
| :--- | :--- | :--- | :--- |
| **`0` (`1 << 0`)** | `namespace` (`mod http_server`) | `declaration` (Item / binding site) | `TokenKind.ident` in `ModItem` / `UseTree` |
| **`1` (`1 << 1`)** | `type` (`struct`, `union`, `type` alias) | `readonly` (`let` binding, `const`) | `TYPE_IDENT` resolved to struct/union/alias; `let` locals |
| **`2` (`1 << 2`)** | `enum` (`enum ApiError`) | `mutable` (`var` binding, `mut` param, `&mut` borrow) | `var` locals, `inout` / `&mut` arguments and fields |
| **`3` (`1 << 3`)** | `interface` (`trait Serialize`) | `consumedMove` (**MVS `sink` / `own` ownership transfer!**) | Highlights moved variables at `sink` / `own` call sites |
| **`4` (`1 << 4`)** | `typeParameter` (`[T, K: Ord]`) | `async` (`async fn`, `.await` suspension point) | Generic parameters in `TypeParams`; async calls |
| **`5` (`1 << 5`)** | `enumMember` (`V4`, `.Some`, `.Ok`) | `unsafe` (Operations inside `unsafe { ... }`) | `EnumVariant` and contextual `.Variant` selectors |
| **`6` (`1 << 6`)** | `function` / `method` (`fn scan_file`) | `attribute` (`@derive`, `@route`, `@component`) | Function/method `IDENT` and `@snake_case` attributes |
| **`7` (`1 << 7`)** | `variable` / `parameter` / `property` | `linearResource` (Explicit-deinit types requiring `defer`) | Types not implementing `ImplicitDrop` (`File`, `Arena`) |

For `textDocument/semanticTokens/full/delta`, `corex lsp` caches the previous `[]u32` array under `resultId` (formatted from the revision number). When the next delta request arrives, it computes the single contiguous diff span `[first_mismatch_idx .. last_mismatch_idx]` between the old and new `[]u32` arrays in O(N_tokens) time and returns a single `SemanticTokensEdit { start, deleteCount, data }` payload.

### 4.4 Inlay Hints (`textDocument/inlayHint`) for Types and MVS Parameter Modes

In `DR-03` Section 1.4, eye-tracking studies (Saarland University APA+26) showed that omitting redundant inline type annotations speeds up initial reading while 91% of developers value seeing static types when inspecting unfamiliar code. `corex lsp` bridges both needs via `textDocument/inlayHint(range)`:
1.  **Inferred Local Binding Types (`InlayHintKind.Type = 1`):** For any `LocalDeclStmt` (`let x = ...;` or `var count = ...;`) and any unannotated `ClosureParam` (`|e| ...`) that omits an explicit `: Type` annotation in `AstArena`, `corex lsp` queries `typecheck_body(DefId)` for the synthesized `TypeId`. If `TypeId != TypeId.err_ty`, it emits an interactive `InlayHint` right after the identifier (`label: ": CreateUserReq"`, `paddingLeft: false`) carrying a `textEdits` payload so clicking or double-clicking the hint inserts `: CreateUserReq` directly into the `.cx` source buffer.
2.  **Pipeline Stage Intermediate Types (`|>`):** On multiline pipeline chains (`body_bytes \n |> Json::parse[CreateUserReq]() \n |> Result::map_err(...)`), `corex lsp` emits end-of-line type hints showing the output type of each `|>` stage.
3.  **Parameter Names & Implicit MVS Mode Hints (`InlayHintKind.Parameter = 2`):** On positional function calls `f(arg1, arg2)` where the argument expression is not an identifier matching the parameter name, `corex lsp` emits parameter hints (`cap: `). Furthermore, when an argument or method receiver undergoes an implicit MVS convention projection or `Copy` vs. `sink` transfer (`DR-02` Axis 2), optional MVS mode hints (`inout self`, `sink`) make aliasing and ownership transfers transparent in the editor.

### 4.5 Machine-Applicable `CodeFix` Actions (`textDocument/codeAction`)

Following Go (`gopls`) and `rust-analyzer`'s structured diagnostic architecture, every compiler diagnostic emitted by the lexer, parser, bidirectional type checker, or Ghost-Instruction SAST verifier can attach one or more structured `SuggestedFix` records (`title`, `CodeActionKind`, `isPreferred: true`, and an array of `TextEdit { range, newText }`):

| Diagnostic / Cursor Context | `CodeActionKind` | Machine-Applicable `WorkspaceEdit` Transformation |
| :--- | :--- | :--- |
| **1. Casing Violation (`DR-03` Matrix)** (`struct my_user` or `let UserId = 5;`) | `quickfix` (`isPreferred: true`) | Converts `my_user` → `MyUser` (`PascalCase`) or `UserId` → `user_id` (`snake_case`) across declaration and local references. |
| **2. Missing Statement Semicolon (`;`)** (`DR-03` Section 3.2) | `quickfix` (`isPreferred: true`) | Inserts `;` at the exact end offset of the preceding token (`prev_token.byte_offset + prev_token.byte_len`). |
| **3. Missing Call-Site `&mut` / `own` Marker** (`DR-02` MVS `inout` / `sink`) | `quickfix` (`isPreferred: true`) | Prepends `&mut ` or `own ` before the call argument expression (`scan_file(&mut arena, ...)` or `rotate_right(own node)`). |
| **4. Immutable Binding Mutation (`let` → `var`)** (`DR-02` Axis 1) | `quickfix` (`isPreferred: true`) | Rewrites the root declaration token `let` (`KW_LET`) to `var` (`KW_VAR`) at `decl_node.main_token` when a sub-path is mutated. |
| **5. Unhandled Linear Resource (`MissingDeferCleanup`)** (`DR-02` Axis 5) | `quickfix` | Inserts `\n    defer <ident>.<deinit_method>();` immediately after the variable's declaration statement (e.g., `defer file.close();`). |
| **6. Non-Exhaustive `match` (`Maranget` Missing Arms)** (`DR-02` Section 3) | `quickfix` / `refactor.rewrite` | Uses the Maranget decision tree's `NonExhaustiveError` leaf constructors to generate all missing `.Variant(...) => todo(),` arms. |
| **7. Enum Variant Size Skew (`> 64 Bytes`)** (`DR-02` `#[warn(variant_size_skew)]`) | `quickfix` | Wraps the oversized cold variant payload type `T` in `OwnPtr[T]` (`Error(OwnPtr[DiagnosticPayload])`) to shrink the enum stride. |

By unifying the **12-byte `TokenBuffer`**, **10-byte postorder `LosslessCstArena`**, **13-byte hole-enabled `AstArena`**, **Hazel-style bidirectional type recovery**, and **Salsa-style `CompilerDb` with `ItemTree` Early Cutoff**, CoreX achieves a single, zero-duplication compiler and IDE engine capable of delivering sub-millisecond interactive feedback on 500,000-line systems codebases.
