# High-Level IR, Mid-Level Block-Argument SSA IR, and Optimization Pipeline Specification for CoreX

To bridge CoreX's single-pass `LL(k)` / Pratt surface parser with its compile-time evaluator (`comptime`), path-sensitive static vulnerability and memory verifier (`SAST`), and three-tier code generation backends (`-ofmt=c` bootstrap, custom x86_64/AArch64 debug emitter, and LLVM/LLD release backend), the `corex` compiler lowers parsed syntax trees (`AstStore`) through two cache-dense, arena-allocated Intermediate Representations: **High-Level IR (`HIR`)** and **Mid-Level Block-Argument SSA IR (`MIR`)**. Rather than allocating pointer-chasing heap graphs that stall CPU memory-level parallelism (MLP) or threading pervasive lifetime parameters (`'tcx`) through every compiler pass, both `HIR` and `MIR` enforce Data-Oriented Design (DoD) invariants across Stage 0 (Zig) and Stage 1 (self-hosted `.cx`). Every node, instruction, basic block, type, and variable-length payload is stored in contiguous Struct-of-Arrays (`MultiArrayList`) tables indexed by strongly typed 32-bit handles (`HirIndex`, `MirBlockId`, `MirValueId`, `LocalId`, `PlaceId`, `TypeId`) with `0xFFFF_FFFF` (`none`) sentinel optionals and zero internal alignment padding.

In the first lowering phase (`AstStore` to `HirStore`), the compiler performs linear-time mode-correct bidirectional type checking ($\Delta \vdash e \Rightarrow \tau$ and $\Delta \vdash e \Leftarrow \tau$) while desugaring all high-level surface ergonomics into canonical, typed `HIR` nodes. Specifically, `HIR` construction rewrites infix `|>` pipelines using strict left-to-right argument sequencing and post-argument callee evaluation; expands postfix `?` option (`T?`) and error-union (`Result[T, E]`) propagation into explicit early-exit branches; lowers `for pat in iter` loops, `let ... else` guards, and inline `"{expr}"` string interpolations; rewrites `#soa` element field projections (`slice[i].field`) directly into contiguous columnar pointer offsets (`slice.field_ptr[i]`); and synthesizes value-projected `let`/`set` subscript bundles for non-byte-aligned LSB `bit_field` accesses.

In the second lowering phase (`HirStore` to `MirBody`), `corex` translates typed expression trees into a hybrid **Place and Block-Argument SSA `MIR`** modeled on MLIR's `cf` dialect, Cranelift CLIF, Swift SIL, and Hylo IR. Scalar bindings that are never address-projected lower immediately into pure SSA register values (`MirValueId`) using Matthias Braun et al.'s single-pass forward SSA construction algorithm without a prior dominance-frontier pass. Conversely, composite value trees (`struct`, `enum`, `[N]T`) and `inout`-projected bindings lower into rooted memory places (`Place { base: LocalId, proj_start: u24, proj_len: u8 }`) bracketed by **Ghost Lifetime Instructions** (`access.let`, `access.inout`, `access.end`, `storage.init`, `storage.move`, `storage.deinit`). This dual representation allows Phase 6 SAST and the exclusivity abstract interpreter to verify field-level path disjointness (`&r.pos.x` vs. `&r.dim.y`), move-reinitialization inside `inout` parameters, and deterministic `defer`/`errdefer` resource cleanup before erasing all ghost instructions and promoting non-escaped places into pure SSA registers via Scalar Replacement of Aggregates (SROA).

## Deliverable 1: HIR and Block-Argument SSA MIR Instruction, Place, and Terminator Catalog

### 1.1 Architectural Division of Labor Across AST, HIR, and MIR

Separating `HIR` from `MIR` prevents semantic responsibilities from bleeding across compiler phases while keeping per-node memory footprints compact. As noted in compiler microarchitecture analyses (`hiraditya.github.io`), a conventional object-oriented compiler allocates AST nodes individually on the heap and links them via 64-bit pointers – for example, a `BinaryExpr` holding two 8-byte child pointers (`Expr* lhs`, `Expr* rhs`), an 8-to-16-byte `SourceRange`, a `QualType` pointer, and a 1-byte `Opcode` plus alignment padding consumes 40 to 48 bytes on 64-bit architectures and forces dependent pointer loads that degrade hardware cache prefetching. By decomposing `HIR` and `MIR` into parallel Struct-of-Arrays slices inside deterministic 64 KiB zero-filled `BumpArena` slabs, CoreX eliminates struct padding bytes (which reduced parser node memory by 37.5% in Mitchell Hashimoto's analysis of Zig's `MultiArrayList` parser and contributed to a 22% faster wall-clock execution time reported by Andrew Kelley) and ensures that every pass streams sequentially through L1d cache lines.

| IR Layer | Primary Representation | Granularity & Control Flow | Core Compiler Responsibilities | SoA Element Stride (Zero Padding) |
| :--- | :--- | :--- | :--- | :--- |
| **`AstStore`** (`DR-01` / `DR-03`) | Untyped postorder Concrete/Abstract Syntax Tree | Surface `.cx` grammar (`\|>`, `?`, `"{x}"`, `for`, `let...else`, `@attr`) | Stateless `LL(k)` / Pratt parsing, fault-tolerant `invalid_parse_subtree` recovery, `corex fmt`, and casing lints. | **13 bytes/node** (`Tag`: 1B, `TokenIndex`: 4B, `Data`: 8B) + `extra_data: []u32`. |
| **`HirStore`** (Phase 4–5) | Explicitly typed, name-resolved, desugared expression tree | Structured expression-oriented blocks (`if`, `match`, `loop`, `defer`, `return`) | Bidirectional type checking ($\Rightarrow / \Leftarrow$), trait/method bundle resolution, `#soa` and `bit_field` rewriting, and declaration-level `comptime` evaluation. | **18 bytes/node** (`HirTag`: 1B, `HirFlags`: 1B, `TypeId`: 4B, `TokenIndex`: 4B, `HirData`: 8B). |
| **`MirBody`** (Phase 6–7) | Control-Flow Graph (CFG) of Basic Blocks with Block Arguments, Places, and Ghost Instructions | Flat `BasicBlock` array; all control transfer localized to block-ending `MirTerminator`s | Braun forward SSA, Maranget decision trees, Ghost-Instruction SAST & exclusivity checking, `defer` edge elaboration, SROA, inlining, and pointer-shape deduplication. | **16 bytes/inst** (`MirOp`: 1B, `InstFlags`: 1B, `AuxU16`: 2B, `TypeId`: 4B, `Lhs`: 4B, `Rhs`: 4B); **8 bytes/place**; **8 bytes/proj**. |

### 1.3 Coexistence of Memory Places, Ghost Instructions, and Pure Block-Argument SSA Values in MIR

A central design challenge in a Mutable Value Semantics (MVS) compiler is reconciling **alias-free SSA register optimization** with **fine-grained path-wise mutation and exclusivity checking** (`&r.pos.x += 1` while reading `r.dim.y`). If a compiler immediately converts all struct mutations into functional whole-struct SSA reconstructions (`%r1 = insertvalue %r0, ...`), it obscures in-place field access paths from the borrow/exclusivity checker and risks generating stack copies for large aggregates. Conversely, if it keeps all variables in stack slots (`alloca`) without SSA values, dataflow optimizations stall.

CoreX's `MIR` solves this cleanly via a **two-tier value and storage model** that transitions seamlessly across the compilation pipeline:

1.  **Pure SSA Register Values (`MirValueId`) via Block Arguments:** Every `MirInst` that computes a value (and every incoming parameter of a `MirBasicBlock`) defines a unique, immutable `MirValueId`. Local scalar bindings (`let x: i32 = ...` or `var count: usize = 0`) that are never sub-element projected (`&count.field`) bypass memory places entirely: during `HIR` to `MIR` lowering, Braun's forward SSA algorithm maps reads and writes of `count` directly to `MirValueId` registers and threads loop-carried dependencies through `MirBasicBlock` arguments (`^loop_head(%count_phi: usize):`).
2.  **Rooted Memory Places (`PlaceId` -> `Place` + `Projection` Slice):** Any variable representing a composite value tree (`struct`, `enum`, `[N]T`), an `inout`/`set` parameter, or a local variable whose address is projected via `inout` is allocated a `LocalDecl` (`LocalId`) in `MirBody.locals`. Access to an interior part of that tree is represented by an 8-byte `Place { base: LocalId, proj_start: u24, proj_len: u8 }` slicing into `MirBody.projections: []Projection`. For example, given `var r: Rect`, the access path `r.pos.x` is represented by `Place { base: LocalId(r), proj_start: k, proj_len: 2 }` where `projections[k..k+2]` contains `[Projection.Field(0 /* pos */), Projection.Field(0 /* x */)]`.
3.  **Ghost Lifetime Instructions (`access.*` and `storage.*`):** Before any `Place` is read, mutated, or passed by reference, `MIR` lowering brackets the access with zero-cost Ghost Instructions (`DR-02`). Specifically, `%tok = access.let %place_id` begins a scoped shared projection of `%place_id` and returns an `AccessTokenId` (`MirValueId`), while `%tok = access.inout %place_id` begins a scoped exclusive mutable projection. The paired `access.end %tok` instruction terminates the borrow immediately after the **last dominating SSA use** of `%tok` (enabling early last-use projection termination so subsequent statements in the same block can immediately mutate the root variable). Simultaneously, `storage.init %place_id`, `storage.move %place_id`, and `storage.deinit %place_id` record definite initialization, `sink` ownership consumption, and scope cleanup.
4.  **Post-Verification Erasure & SROA Promotion:** Once Phase 6 SAST and the Ghost-Instruction Abstract Interpreter verify that all access brackets obey the Law of Exclusivity and linear resource rules, Pass D3/R2 **erases all `access.*` and `storage.*` ghost instructions in linear time**. In `--release` builds (and for small aggregates), Pass R2 (SROA / `mem2reg`) decomposes non-escaped composite `LocalId`s into leaf scalar variables and invokes Braun's SSA algorithm to promote every remaining `place_load` and `place_store` into pure Block-Argument SSA registers.

| `0: br` | `target: MirBlockId`, `args: Slice[MirValueId]` | Unconditional jump `br ^target(%v_0, ..., %v_{k-1})`. Outgoing `args` bind 1-to-1 to `target`'s block parameters. |
| `1: cond_br` | `cond: MirValueId`, `then_bb: MirBlockId` (`then_args`), `else_bb: MirBlockId` (`else_args`) | Two-way branch `cond_br %cond, ^then(%t_args), ^else(%e_args)`. |
| `2: switch_int` | `discr: MirValueId`, `cases: Slice[(u64, MirBlockId, Slice[MirValueId])]`, `default_bb: MirBlockId` (`def_args`) | Multi-way integer/discriminant jump table emitted by Maranget decision-tree compilation. |
| `3: call` | `callee: MirValueId`, `call_args: Slice[MirValueId]`, `normal_bb: MirBlockId` (receives `%ret_val` as 1st block arg), `err_unwind_bb: MirBlockId` | Invokes function `callee`. On completion, jumps to `normal_bb(%ret_val)` (or `err_unwind_bb` if panicking/unwinding in tests). |
| `4: subscript_yield` | `yielded_place: PlaceId`, `resume_bb: MirBlockId`, `cleanup_bb: MirBlockId` | Coroutine subscript suspension (`yield &storage[idx]`); inlined during Pass R1 into direct pointer/bitfield operations. |
| `5: ret` | `ret_val: MirValueId` (or `MirValueId.none` for `unit`) | Returns `ret_val` to caller. Verifier requires all `inout` and `set` parameters to be in `Initialized` state and all linear resources cleaned up. |
| `6: assert_check` | `cond: MirValueId`, `msg_id: StringId`, `pass_bb: MirBlockId`, `fail_bb: MirBlockId` | Bounds-check, division-by-zero, or integer-overflow guard. Eliminated by Pass R3 whenever SAST value-range analysis proves `cond == true`. |
| `7: unreachable` | None (`0` outgoing edges) | Inhabits bottom type `never`; emitted on impossible enum niche branches or after diverging calls. |

## Deliverable 2: AST to HIR to MIR Lowering Algorithms

### 2.1 Phase 4–5: AST to HIR Desugaring and Type-Directed Rewriting

During `AST` to `HIR` lowering, the compiler runs mode-correct bidirectional type checking ($\Delta \vdash e \Rightarrow \tau$ for synthesis and $\Delta \vdash e \Leftarrow \tau$ for checking) while simultaneously eliminating all syntactic sugar so `MIR` construction only handles canonical primitives. Below are the seven deterministic `AST` to `HIR` desugaring transformations:

#### 1. Infix Pipeline (`|>`) Desugaring with Post-Argument Callee Sequencing

In `DR-03`, the pipeline operator `lhs |> fn_call(arg_1, ..., arg_k)` has precedence level 1 (`(l_bp=2, r_bp=3)`) and passes `lhs` as the **first argument** to `fn_call`. Under `DR-02`'s Formal Evaluation Sequencing Invariant, all arguments of a call must evaluate strictly from left to right *before* the callee/receiver projection. Given `E_pipe = E_lhs |> Path[T](A_1, ..., A_k)` – such as `DR-03` Showcase 2's `body_bytes |> Json::parse[CreateUserReq]() |> Result::map_err(|e| ApiError::InvalidJson(e.message()))?` – the type checker first synthesizes $\Delta \vdash E_{\text{lhs}} \Rightarrow \tau_0$, resolves the target function signature `Path[T]: (p_0: Mode_0 \tau_0, p_1: Mode_1 \tau_1, ..., p_k: Mode_k \tau_k) -> \tau_{\text{ret}}`, checks each trailing argument $\Delta \vdash A_i \Leftarrow \tau_i$ for $i \in 1..k$, and emits a single `hir_call` node whose argument list in `extra_data` is `[hir_project_arg(Mode_0, E_lhs), hir_project_arg(Mode_1, A_1), ..., hir_project_arg(Mode_k, A_k)]`. Because `E_lhs` is placed at index `0` of the call's argument array, left-to-right evaluation sequences `E_lhs` first, followed by `A_1..A_k`, followed by `Path[T]`.

#### 2. Postfix `?` Error-Union (`Result[T, E]`) and Option (`T?`) Propagation

When the postfix `?` operator is applied to an expression `E_inner` inside a function returning `Result[U, E_fn]` (or `U?`), `AST` to `HIR` lowers `E_inner?` into a canonical `hir_match` over a synthesized temporary `LocalId` (`%tmp_try`):

```rust
// Surface (`DR-03`): let file = File::open(opts.file_path)?;
// Lowered HIR equivalent:
{
    let %tmp_try: Result[File, IoError] = File::open(opts.file_path);
    match %tmp_try {
        .Ok(%val)  => %val,
        .Err(%err) => return_err .Err(From::from(%err)), // sets is_err_return = 1 on hir_return!
    }
}
```

Setting `is_err_return = 1` on the synthesized `hir_return` node instructs the `MIR` `defer` elaborator to execute both active `errdefer |err|` and `defer` cleanups along the early-return CFG edge, whereas normal `.Ok` returns only execute `defer` cleanups.

#### 3. `for pat in iter` Loops (Slices, Ranges, `#soa`, and `soa_zip` Views)

CoreX replaces C's error-prone three-clause `for` loop with `for pat in expr { body }`. During `HIR` lowering, the compiler dispatches on the synthesized type $\tau_{\text{iter}}$ of `expr`. First, for an **integer range** (`start..end` or `start..=end`), `HIR` lowers the loop directly to a mutable cursor `var %idx = start`, a bound `let %end = end`, and a `hir_loop` whose body checks `if %idx < %end` (or `<=`), binds `pat = %idx`, executes `{ body }`, and increments `&%idx += 1` inside the continue block. Second, for a **contiguous slice (`[]T`) or `#soa[]T` / `soa_zip(a: xs, b: ys)`**, `for &elem, i in slice` binds `%len = slice.len`, loops `%i` from `0` to `%len`, and binds `elem` via an `inout` subscript projection `&slice[%i]`. When iterating over a `soa_zip` view (`let view = soa_zip(a: xs, b: ys)`), `HIR` lowering **never materializes a temporary AoS struct on the stack**; instead, `view` is recorded as a virtual tuple of slices `(%xs_slice, %ys_slice)` in the symbol table, and every access `v.a` or `&v.b` inside the loop body is rewritten directly into `hir_index_proj(%xs_slice, %i)` or `hir_index_proj(%ys_slice, %i)`. Third, for any **general `Iterator` trait conformance**, `HIR` lowers the construct to `var %iter = IntoIterator::into_iter(expr)` followed by `hir_loop { match Iterator::next(&mut %iter) { .Some(pat) => body, .None => break } }`.

#### 4. `let Pat = expr else { diverge }` Guard Desugaring

To preserve top-to-bottom reading linearity (`DR-03` Showcase 3: `let .Some(mut x) = y.left.take() else { return y; };`), a refutable `let ... else` statement is desugared into a binding of the outer pattern variables initialized by a `hir_match`. The type checker verifies that the `else` block has synthesized type `never` (`HirFlags.diverges == true`, meaning all paths end in `return`, `break`, `continue`, or `unreachable`). If `Pat` binds $k$ variables $(v_1, \dots, v_k)$, `HIR` lowers the statement into:

```rust
let (v_1, ..., v_k) = match expr {
    Pat => (v_1, ..., v_k),
    _   => { else_block }, // Type is `never`, unifying with any tuple type!
};
```

#### 5. Inline String Interpolation (`"Node: {node_name}:{line}"`) Desugaring

In `DR-03`, double-quoted strings support inline `{expr}` interpolation without macro ceremony. During `AST` to `HIR` lowering, the lexer and parser segment `"prefix {e_1} mid {e_2} suffix"` into alternating literal slices and expressions. When an interpolated string is passed directly to an I/O or formatter method such as `out.write_fmt("{opts.file_path}:{stats.lines_scanned}: {line}\n")` (`DR-03` Showcase 1), `HIR` rewrites the call into a zero-allocation sequence of `Formatter::write_str(out, ...)` and `Display::fmt(&e_i, out)` calls. When used as a standalone `str` value expression, `HIR` allocates a buffer from the implicit `context.temp_allocator` (or request `Arena` in `context.allocator`, `DR-02`), pre-calculates literal byte lengths, appends each segment via `Display::fmt`, and returns the resulting `str` slice.

#### 6. `#soa` Element Projection Rewriting (`slice[i].field` -> `slice.field_ptr[i]`)

In `DR-02`, `#soa[N]T`, `#soa[]T`, and `#soa Vec[T]` physically transpose struct fields into contiguous column arrays in a single aligned buffer while preserving natural AoS syntax `items[i].x`. Whenever the `HIR` lowerer encounters a field projection `AstTag.field_access(AstTag.index_expr(base, idx), field_name)` where `base` has a `#soa` type, it intercepts the AST pair *before* emitting an AoS element index node. It resolves `field_name` to its column index `field_idx` and emits a single `HirTag.hir_soa_field_ptr` node with `HirSoaExtra { field_index: field_idx, elem_index_hir: lowerExpr(idx) }`. Conversely, if `base.field_name[idx]` (columnar syntax) is written in source, it lowers to the **exact same `hir_soa_field_ptr` node**, guaranteeing `&p[i].hp == &p.hp[i]` by construction.

#### 7. LSB `bit_field` Subscript Synthesis (`let` and `inout`/`set` Bundles)

In `DR-02`, a `bit_field u16` packs fields from Least-Significant-Bit (LSB) upward and forbids raw bit-pointers (`*align(...) u9`), projecting bitfields by value instead. In a read (`let`) context (`let d: i16 = header.delta`), `HIR` emits `hir_bitfield_read(base_hir, bit_spec)` with `bit_offset = 5, bit_width = 6, is_signed = 1`, which lowers in `MIR` to an arithmetic shift-left plus arithmetic shift-right (`sbfm` on AArch64, or `shl 5` + `ashr 10` on a 16-bit integer) that sign-extends the 6-bit value into a native `i16` register. In a mutable projection (`inout`) context (`mutate_delta(&mut header.delta)` or `&header.delta += 1`), `HIR` synthesizes a `hir_bitfield_rmw` node (equivalent to an inline `let`/`set` subscript bundle) that begins an exclusive `access.inout` on `header`, extracts `header.delta` via `bitfield_extract` into a temporary native `var %tmp_bf: i16`, passes `&mut %tmp_bf` (`inout i16`) to `mutate_delta` (or executes the compound assignment on `%tmp_bf`), executes `bitfield_insert` to mask `(1 << 6) - 1` at bit offset `5` and write the updated bits back into `header`, and finally ends the `access.inout` on `header`.

### 2.2 Phase 5–6: HIR to MIR Lowering Algorithms

> **Visual – Forward Block-Argument SSA Construction, Maranget Decision Trees, and Ghost Exclusivity Tries:** CoreX's three core HIR-to-MIR lowering and verification mechanisms. Panel A: **Jacobs' clause-frequency heuristic** scores pattern matrix columns by active constructor tests (4/4 on column o0 vs 2/4 on column o1), selecting o0 first to produce a zero-duplication switch_int decision tree. Panel B: **Braun's forward SSA algorithm** lowers acyclic if/match joins directly into block arguments and resolves cyclic loop variables via unsealed proxy arguments upon sealBlock. Panel C: The **Ghost-Instruction Abstract Interpreter** tracks initialization and borrow states across a field-path trie, permitting simultaneous inout access to disjoint sibling subtrees (&r.pos.x and &r.dim.y) while rejecting overlapping ancestor/descendant mutations.

#### Algorithm 1: Braun et al. Single-Pass Forward Block-Argument SSA Construction

When lowering `HIR` into `MIR` (and again during Pass R2 SROA when promoting composite places into registers), CoreX constructs Block-Argument SSA directly in a single forward walk using Matthias Braun et al.'s algorithm adapted from $\phi$-nodes to **Basic Block Arguments**.

Instead of computing dominance trees and iterated dominance frontiers upfront, the `MirSsaBuilder` maintains two dense maps indexed by `(LocalId, MirBlockId)`: `current_def[var][block] -> MirValueId`, which maps variable `var` in `block` to its most recent dominating SSA `MirValueId` definition in that block, and `incomplete_params[block] -> List[(LocalId, MirValueId)]`, which stores proxy `block_param` `MirValueId`s added on demand for any block whose CFG predecessors are not yet fully known (an **unsealed** block, such as a `loop` header before its back-edge is emitted).

A block is marked **sealed** (`block.is_sealed = 1`) as soon as no further incoming predecessor edges can ever be added to it. In structured `HIR` lowering, `if` and `match` branch blocks (`^then`, `^else`, `^arm_i`) are sealed immediately upon creation because their sole predecessor is the branching header block, and join blocks (`^if_join`, `^match_join`) are sealed immediately after all non-diverging arm blocks emit their outgoing `br ^join(...)` edges. Conversely, a `loop` header block (`^loop_head`) remains **unsealed** while lowering the loop body, and is sealed via `sealBlock(^loop_head)` once all `continue` edges and the body fallthrough back-edge have been wired.

Below is the complete Zig implementation of the Braun Block-Argument SSA builder (`stage0/src/ssa_braun.zig`):

```zig
//! CoreX Stage-0 Compiler: Braun et al. Forward Block-Argument SSA Builder
//! Adapts "Simple and Efficient Construction of Static Single Assignment Form" (CC 2013)
//! directly to MLIR/Cranelift-style Basic Block Arguments (`^bb(%arg0, %arg1)`).

const std = @import("std");
const assert = std.debug.assert;
const ir = @import("ir_catalog.zig");

pub const MirSsaBuilder = struct {
    body: *ir.MirBody,
    /// `current_def[local_id * max_blocks + block_id]` -> `MirValueId` (`.none` if not defined locally)
    current_def: std.AutoHashMapUnmanaged(u64, ir.MirValueId) = .{},
    /// Incomplete block parameters waiting for `sealBlock(block_id)`
    incomplete_params: std.AutoHashMapUnmanaged(ir.MirBlockId, std.ArrayListUnmanaged(IncompleteParam)) = .{},

    pub const IncompleteParam = struct {
        var_id: ir.LocalId,
        param_val: ir.MirValueId,
        type_id: ir.TypeId,
    };

    inline fn defKey(v: ir.LocalId, b: ir.MirBlockId) u64 {
        return (@as(u64, @intFromEnum(v)) << 32) | @as(u64, @intFromEnum(b));
    }

    /// 1. Local Value Numbering: Record a new definition of `v` in `block`.
    pub fn writeVariable(self: *MirSsaBuilder, v: ir.LocalId, block: ir.MirBlockId, val: ir.MirValueId) !void {
        try self.current_def.put(self.body.allocator, defKey(v, block), val);
    }

    /// 2. Read Variable: O(1) if defined in `block`, otherwise recurses over CFG predecessors.
    pub fn readVariable(self: *MirSsaBuilder, v: ir.LocalId, ty: ir.TypeId, block: ir.MirBlockId) !ir.MirValueId {
        if (self.current_def.get(defKey(v, block))) |local_val| {
            return local_val;
        }
        return self.readVariableRecursive(v, ty, block);
    }

    fn readVariableRecursive(self: *MirSsaBuilder, v: ir.LocalId, ty: ir.TypeId, block: ir.MirBlockId) anyerror!ir.MirValueId {
        const bb = &self.body.blocks.items[@intFromEnum(block)];
        var val: ir.MirValueId = .none;

        if (bb.is_sealed == 0) {
            // Unsealed loop header: append a proxy Block Parameter to `block` and record in `incomplete_params`
            val = try self.appendBlockParam(block, ty);
            const gop = try self.incomplete_params.getOrPut(self.body.allocator, block);
            if (!gop.found_existing) gop.value_ptr.* = .{};
            try gop.value_ptr.append(self.body.allocator, .{ .var_id = v, .param_val = val, .type_id = ty });
        } else if (bb.pred_len == 1) {
            // Optimize common single-predecessor case: no block parameter needed!
            const single_pred = self.body.block_lists.items[bb.pred_start];
            val = try self.readVariable(v, ty, single_pred);
        } else {
            // Break potential cyclic loop recursion by inserting a Block Parameter first,
            // writing it as `current_def` in `block`, and then populating predecessor edge arguments.
            val = try self.appendBlockParam(block, ty);
            try self.writeVariable(v, block, val);
            val = try self.addBlockParamOperands(v, ty, block, val);
        }

        try self.writeVariable(v, block, val);
        return val;
    }

    /// 3. Wire incoming edge arguments on all predecessor terminators of `block` for `param_val`,
    ///    and eliminate trivial block parameters where all non-self predecessors pass the same `same_val`.
    fn addBlockParamOperands(
        self: *MirSsaBuilder,
        v: ir.LocalId,
        ty: ir.TypeId,
        block: ir.MirBlockId,
        param_val: ir.MirValueId,
    ) anyerror!ir.MirValueId {
        const bb = self.body.blocks.items[@intFromEnum(block)];
        const preds = self.body.block_lists.items[bb.pred_start .. bb.pred_start + bb.pred_len];

        var same_val: ir.MirValueId = .none;
        var is_trivial = true;

        for (preds) |pred_bb| {
            const incoming_val = try self.readVariable(v, ty, pred_bb);
            try self.appendEdgeArgToTerminator(pred_bb, block, incoming_val);

            if (incoming_val == param_val) continue; // Self-reference in loop back-edge
            if (same_val != .none and incoming_val != same_val) {
                is_trivial = false;
            } else {
                same_val = incoming_val;
            }
        }

        if (is_trivial and same_val != .none) {
            // Trivial Block Argument (`%p = phi(%x, %x)` or `%p = phi(%x, %p)`):
            // Mark block param slot for removal and forward uses of `param_val` to `same_val`.
            self.markTrivialBlockParamRedirect(param_val, same_val);
            return same_val;
        }
        return param_val;
    }

    /// 4. Seal Block: Invoked once all CFG predecessors of `block` have been connected.
    pub fn sealBlock(self: *MirSsaBuilder, block: ir.MirBlockId) !void {
        if (self.incomplete_params.fetchRemove(block)) |kv| {
            var list = kv.value;
            defer list.deinit(self.body.allocator);
            for (list.items) |inc| {
                _ = try self.addBlockParamOperands(inc.var_id, inc.type_id, block, inc.param_val);
            }
        }
        self.body.blocks.items[@intFromEnum(block)].is_sealed = 1;
    }

    fn appendBlockParam(self: *MirSsaBuilder, block: ir.MirBlockId, ty: ir.TypeId) !ir.MirValueId {
        const val_idx: u32 = @intCast(self.body.instructions.len);
        try self.body.instructions.append(self.body.allocator, .{
            .op = .block_param,
            .flags = 0,
            .aux_u16 = @intCast(self.body.blocks.items[@intFromEnum(block)].param_len),
            .type_id = ty,
            .operands = .{ .lhs = @intFromEnum(block), .rhs = 0 },
        });
        const val_id: ir.MirValueId = @enumFromInt(val_idx);
        try self.body.value_lists.append(self.body.allocator, val_id);
        self.body.blocks.items[@intFromEnum(block)].param_len += 1;
        return val_id;
    }

    fn appendEdgeArgToTerminator(self: *MirSsaBuilder, pred: ir.MirBlockId, target: ir.MirBlockId, arg: ir.MirValueId) !void {
        _ = pred; _ = target;
        try self.body.extra_data.append(self.body.allocator, @intFromEnum(arg));
    }

    fn markTrivialBlockParamRedirect(self: *MirSsaBuilder, param_val: ir.MirValueId, replacement: ir.MirValueId) void {
        self.body.instructions.items(.flags)[@intFromEnum(param_val)] |= 0x80; // Flag bit 7 = trivial redirect
        self.body.instructions.items(.operands)[@intFromEnum(param_val)].rhs = @intFromEnum(replacement);
    }
};
```

#### Algorithm 2: Maranget Pattern Matrix Decision Trees with Jacobs' Clause-Frequency Heuristic

To compile `hir_match` expressions (`match scrutinee { Pat_1 if g_1 => e_1, ..., Pat_m => e_m }`) into optimal `MIR` jump tables while checking exhaustiveness and reachability in a single pass, CoreX combines **Luc Maranget's Pattern Matrix Specialization** with **Jules Jacobs' Clause-Frequency Branching Heuristic**.

1.  **Pattern Matrix & Occurrence Vector Representation:** A `match` problem is represented as a matrix $\mathcal{M}$ of $m$ rows (clauses) and $n$ columns corresponding to an **occurrence vector** $\vec{o} = (o_1, \dots, o_n)$, where each $o_j$ is a `PlaceId` representing a sub-scrutinee access path (initially $\vec{o} = (\text{scrutinee\_place})$). Each row $i$ holds a vector of patterns $(p_{i,1}, \dots, p_{i,n})$, an optional guard `HirIndex` $g_i$, and an action target block `^arm_i`.
2.  **Flatten Product Types & Push Variable Bindings:** Product patterns (`struct` and tuple patterns `(P_1, ..., P_k)`) are irrefutable structural containers: whenever column $o_j$ has a product type, it is immediately replaced in-place by its component columns $(o_j.\text{Field}(0), \dots, o_j.\text{Field}(k-1))$. Any bare variable binding pattern `x` (`mut x`, `ref x`, `own x`) at cell $(i, j)$ is normalized into a wildcard `_` after appending a binding action `let x = o_j` to row $i$'s action header.
3.  **Evaluate Base Cases (Empty Matrix vs. Irrefutable First Row):** If the matrix $\mathcal{M}$ is empty ($m = 0$), matching has failed on the current path; the compiler records the missing constructor path in `missing_witnesses` (emitting a compile-time `NonExhaustiveMatchError` diagnostic with the exact counterexample pattern) and emits `MirTerminator.unreachable_term`. Conversely, if row $0$ contains only wildcards ($\forall j \in 1..n,\; p_{0,j} = \_$) and has no guard ($g_0 = \text{none}$), row $0$ unconditionally succeeds, marking `arm_reached[0] = true` and emitting `br ^arm_0(bound_vars)`. If row $0$ is all wildcards but carries a pattern guard (`if g_0`), the compiler evaluates $g_0$ in the current block and terminates with `cond_br %g_0_val, ^arm_0(bound_vars), ^guard_fail`, where `^guard_fail` recursively compiles the residual matrix $\mathcal{M}[1..m]$ (rows $1$ through $m-1$).
4.  **Jacobs' Clause-Frequency Heuristic for Column Selection:** When row $0$ contains one or more active constructor tests $p_{0,j} = C_k(q_1, \dots, q_a)$, choosing a suboptimal column $j$ to branch on causes **Case (c) clause duplication**: any subsequent row $i > 0$ that has a wildcard `_` in column $j$ must be duplicated into both the matching sub-problem $\mathcal{S}(C_k, \mathcal{M})$ and the fallback sub-problem $\mathcal{D}(\mathcal{M})$. Among all columns $j$ where the first row $p_{0,j}$ is a non-wildcard constructor test, CoreX computes the **Clause-Frequency Score**:
    $$\text{Score}(j) = \sum_{i=0}^{m-1} \mathbb{I}(p_{i,j} \neq \_)$$
    and selects the column $j^*$ that **maximizes $\text{Score}(j^*)$** (breaking ties by choosing the column with the smallest branching factor $|\text{Constructors}(j)|$ and leftmost position). For example, when matching `(Result[Option[i32], ApiError], bool)` against four arms – Row 0: `(.Ok(.Some(x)), true)`, Row 1: `(.Ok(.None), _)`, Row 2: `(.Ok(.Some(y)), false)`, and Row 3: `(.Err(e), _)` – testing column $o_1$ (`bool`) yields $\text{Score}(o_1) = 2/4$ and duplicates Rows 1 and 3 across both branches, whereas testing column $o_0$ (`Result`) yields $\text{Score}(o_0) = 4/4$ and inside `.Ok` tests $o_{0\_\text{payload}} = \text{Downcast}(o_0, \text{.Ok}).\text{Field}(0)$ with score $3/3$, producing **zero clause duplication**.
5.  **Matrix Specialization $\mathcal{S}(C_k, \mathcal{M})$, Switch Fusion, and Exhaustiveness Check:** For the selected column $j^*$ with sum type $\tau_{j^*}$ having total constructor set $\Sigma(\tau_{j^*})$, the compiler collects every distinct constructor $C_k$ appearing in column $j^*$ across $\mathcal{M}$ and builds a Specialized Matrix $\mathcal{S}(C_k, \mathcal{M})$ by replacing column $o_{j^*}$ with its downcast payload fields $\text{Downcast}(o_{j^*}, C_k).\text{Field}(0..a-1)$. Rows with $p_{i,j^*} = C_k(q_1, \dots, q_a)$ expand $(q_1, \dots, q_a)$ into the new columns, rows with $p_{i,j^*} = \_$ expand $a$ wildcards $(\_, \dots, \_)$, and rows with $p_{i,j^*} = C_{k'} \neq C_k$ are dropped. If the tested constructors cover all of $\Sigma(\tau_{j^*})$, the default matrix $\mathcal{D}(\mathcal{M})$ is omitted as unreachable; otherwise, $\mathcal{D}(\mathcal{M})$ retains only rows where $p_{i,j^*} = \_$. The compiler emits `%tag = place_discriminant(o_{j^*})` and a fused `MirTerminator.switch_int` jumping to each specialized child block. Once tree construction completes, if `missing_witnesses` is empty, the `match` is **exhaustive**, and any original arm $i$ with `arm_reached[i] == false` is flagged as an **Unreachable Pattern**.

#### Algorithm 3: Lexical `defer` and `errdefer |err|` CFG Edge Elaboration

CoreX achieves deterministic resource cleanup without C++ unwinding tables (`eh_frame`) or hidden RAII destructor calls at every brace by maintaining an explicit **Lexical Scope Cleanup Stack** during `MIR` construction and elaborating cleanup blocks strictly along exiting CFG edges.

```zig
pub const ScopeCleanupEntry = struct {
    scope_id: u32,
    loop_id: u32,         // 0xFFFF_FFFF if function/block scope; >= 0 if inside a loop
    is_errdefer: bool,    // false = `defer`, true = `errdefer |err|`
    err_local: LocalId,   // Bound to the error payload on `return_err` paths
    cleanup_hir: HirIndex,
};
```

When a statement registers `defer expr;` or `errdefer |err| expr;` inside lexical scope $S$, it pushes a `ScopeCleanupEntry` onto `active_cleanups`. Because `defer` executes in **Last-In, First-Out (LIFO)** order, exiting one or more scopes walks `active_cleanups` backward from `top` down to the target boundary scope $S_{\text{target}}$:

| Control-Flow Exit Construct | Target Boundary Scope $S_{\text{target}}$ | Executed Cleanup Entries (LIFO Order) |
| :--- | :--- | :--- |
| **Normal Block Fallthrough (`}`)** | Current block scope $S_{\text{curr}}$ | All entries in $S_{\text{curr}}$ where **`is_errdefer == false`** (`defer` only). |
| **`break` / `continue` in Loop $L$** | Loop scope $S_{\text{loop}(L)}$ | All entries from `top` down to $S_{\text{loop}(L)}$ where **`is_errdefer == false`**. |
| **Normal `return val;` (or `.Ok` return)** | Function root scope $S_{\text{fn}}$ | All entries from `top` down to $S_{\text{fn}}$ where **`is_errdefer == false`**. |
| **Error Return (`?` or `return .Err(e)`)** | Function root scope $S_{\text{fn}}$ | **All entries** from `top` down to $S_{\text{fn}}$ (**both `errdefer \|err\|` and `defer`** in exact LIFO interleaving order). |

To uphold `DR-02`'s zero-cost happy-path guarantee when multiple `?` operators appear in the same scope $S$ after `errdefer tx.rollback();`, the compiler does **not** inline duplicate copies of `tx.rollback()` at every `?` call site. Instead, it creates a single shared cold cleanup basic block `^errdefer_pad_S(%err_val: ErrType)` for scope $S$, lowers `tx.rollback()` inside `^errdefer_pad_S`, and chains `^errdefer_pad_S` to the parent scope's cleanup pad `^defer_pad_parent(%err_val)` before reaching the function's error return block. Consequently, every `?` operator in scope $S$ simply emits `switch_int %is_ok [1: ^happy_next, 0: ^errdefer_pad_S(%err)]`, adding **zero instructions** to the happy path beyond the branch check.

### 3.1 Dual-Mode MIR Optimization Pipeline (`--dev` vs. `--release`)

### 3.2 Formal MIR Well-Formedness Verifier Invariants (Checked After Every Pass)

In debug builds of `corex` (and always at Pass D1), the `MirVerifier` validates six formal invariants in a linear walk over `MirBody`. Any violation halts compilation with an internal compiler diagnostic pinpointing the offending `MirLocation { block, statement_index }`:

1.  **Invariant V1 – Strict SSA Single-Definition and Dominance:** Every `MirValueId` $v$ in `MirBody` is defined at most once (either in `bb.param_start..param_len` with `op == .block_param`, or at a unique position in `bb.inst_start..inst_len` with `op != .block_param`). For every instruction or terminator in block $B_{\text{use}}$ that reads operand $v$ defined in $B_{\text{def}}$, $B_{\text{def}}$ must strictly dominate $B_{\text{use}}$ ($B_{\text{def}} \text{ dom } B_{\text{use}}$), or $B_{\text{def}} = B_{\text{use}}$ and the definition of $v$ precedes its use in `inst_order`.
2.  **Invariant V2 – Block-Argument Arity and Type Unification:** For every CFG edge $e = (B_{\text{src}} \rightarrow B_{\text{dst}})$ encoded in $B_{\text{src}}$'s `MirTerminator` with outgoing argument list $(a_0, \dots, a_{k-1})$, the argument count must equal $B_{\text{dst}}$'s incoming parameter count ($k = B_{\text{dst}}.\text{param\_len}$), and for all $i \in [0, k)$, $\text{Type}(a_i) == \text{Type}(B_{\text{dst}}.\text{param}[i])$. Furthermore, $B_{\text{src}}$ appears in $B_{\text{dst}}.\text{preds}$ if and only if $B_{\text{dst}}$ appears in $B_{\text{src}}.\text{terminator.successors}$, and the entry block `MirBlockId.entry` (`0`) must have `pred_len == 0`.
3.  **Invariant V3 – Place Projection Type Well-Formedness:** For every `MirPlace { base, proj_start, proj_len }`, walking $p_0, \dots, p_{\text{len}-1}$ starting from $\tau_0 = \text{locals}[base].\text{type\_id}$ must be type-valid at each step. Specifically, `Field(idx)` requires $\tau_{\text{curr}}$ to be a `struct`, `union`, tuple, or `Downcast` enum variant with `idx < num_fields`; `Downcast(variant_idx)` requires $\tau_{\text{curr}}$ to be an `enum` with `variant_idx < num_variants`; `SoaFieldPtr(field_idx, elem_val)` requires $\tau_{\text{curr}}$ to be `#soa[N]T`, `#soa[]T`, or `#soa Vec[T]` and $\text{Type}(elem\_val) == \text{usize}$; and `BitFieldExtract(bit_offset, bit_width)` requires $\tau_{\text{curr}}$ to be a `bit_field` backing integer where $\text{bit\_offset} + \text{bit\_width} \le \text{bit\_size}(\tau_{\text{curr}})$.
4.  **Invariant V4 – Ghost Lifetime Bracket Balance & Mode Exclusivity (Pre-D3):** While `body.has_ghost_instructions == true`, every `place_load`, `place_store`, and `place_addr` must reference a dominating, not-yet-ended `ghost_access_let`, `ghost_access_inout`, or `ghost_access_set` token `%tok` on the same `PlaceId`. Along every CFG path from `entry` to `ret`, every `%tok = ghost_access_*` must be paired with a unique `ghost_access_end %tok` along all reachable paths, and `ghost_access_end` may never execute on an already-ended token. Once Pass D3 completes, `body.has_ghost_instructions == false` and **zero** `MirInst` records in `inst_order` may have `op` in `.ghost_access_let .. .ghost_storage_deinit`.
5.  **Invariant V5 – Definite Initialization, `inout` Reinitialization & Linear Resource Completeness:** At every `MirTerminator.ret`, `LocalId.return_slot` (`0`) and every `LocalId` with `param_mode == .mode_inout` or `param_mode == .mode_set` must be in the **fully `Initialized`** trie state (`PartiallyMoved` or `Moved` on an `inout` parameter at `ret` is a compile-time error). Simultaneously, every local variable with `LocalFlags.is_linear_resource == true` (`~ImplicitDrop`, such as `File`, `Socket`, `OwnPtr`) must be in state `Moved` (via `sink` call) or explicitly cleaned up via `storage.deinit` / `defer` on all paths reaching `ret`.
6.  **Invariant V6 – ABI Context & Escape Invariants:** If `body.is_contextless == true`, no instruction in `MirBody` may read the implicit `Context` pointer or call a target function where `callee.is_contextless == false`. Any closure value marked `@local` (holding `let` or `inout` captures) may never be passed to a `sink` parameter, stored into a global or heap place, or returned via `ret`.

### 3.3 Polymorphic Code-Bloat Mitigation: Pointer-Shape Analysis and Structural MIR ICF

As highlighted in `DR-02` and `rustc` monomorphization analyses, naive static monomorphization duplicates an entire generic function body for every distinct type argument – even when `Vec[OwnPtr[User]]::push` and `Vec[OwnPtr[Order]]::push` (or `Slice[usize]::len` and `Slice[u64]::len` on 64-bit targets) compile to the exact same machine instructions. Conversely, Go 1.18+'s GCShape stenciling collapses all pointer types into `*uint8` by passing a runtime dictionary in the `AX` register, which shifts argument registers and forces indirect vtable (`itab`) calls that block inlining. Similarly, relying on LLVM's late `mergefunc` pass wastes 85%–98% of compile time because LLVM must still generate, optimize, and register-allocate all duplicated copies before attempting to merge them.

CoreX mitigates polymorphic code bloat **at the `MIR` level prior to LLVM codegen** without introducing runtime dictionary pointers, using a two-stage pipeline in Pass D5 and Pass R6:

#### Stage A: Definition-Site Polymorphization & Layout-Shape Keying (Pass D5)

When the monomorphizer in Pass D5 inspects a generic function `fn foo[T_1, ..., T_k](...)`, it runs a fast **Type-Parameter Dependency Analysis** over `foo`'s `HIR`/`MIR` body:

1.  **Unused or Phantom Type Parameters:** If a type parameter `T_i` is used only in phantom markers (`PhantomData[T_i]`) or pointer casts that do not depend on `T_i`'s size or trait implementations, `T_i` is immediately erased to `unit` (`TypeId.void_ty`).
2.  **Pointer-Shape & Value-Shape Equivalence Classes (`LayoutShapeKey`):** If a generic function body (and its transitive non-inlined callees) never invokes a type-specific trait method on `T_i` – operating on `T_i` solely through moves, bitwise copies, pointer offsets, or `Option` niche checks – then `T_i`'s semantic behavior in `MIR` depends **exclusively on its physical `LayoutShape`**:

    ```zig
    /// 16-byte canonical layout shape descriptor for `DR-02` Pointer-Shape Deduplication.
    pub const LayoutShapeKey = extern struct {
        byte_size: u32,
        alignment_log2: u8,
        abi_pass_class: AbiPassClass, // 0=IntReg, 1=FloatReg, 2=SimdVec, 3=TwoIntRegs, 4=IndirectNoAliasPtr
        niche_kind: NicheKind,        // 0=None, 1=NonZeroPointer(0x0), 2=BoolRange(2..255), …
        has_non_trivial_drop: u8,     // 0 if trivially movable/droppable (no type-specific drop fn)
        drop_fn_symbol_id: u32,       // 0 if trivial
        _pad: u32 = 0,
    };
    ```

    Under this rule, every non-null pointer type (`OwnPtr[A]`, `OwnPtr[B]`, `&let A`, `&inout B`, `*A`, `*B`) and 64-bit integer handle (`u64`, `usize`, `UserId`, `SlotKey[Widget]`) with trivial drop shares the exact same `LayoutShapeKey { byte_size: 8, alignment_log2: 3, abi_pass_class: .IntReg, niche_kind: .NonZeroPointer, has_non_trivial_drop: 0 }`. Consequently, `Vec[OwnPtr[User]]::len`, `Vec[OwnPtr[Order]]::len`, and `Vec[&let Config]::len` map to a **single shared `MirBody` instantiation** during Pass D5 – requiring **zero runtime dictionary arguments** and **zero duplicate `MIR` optimization passes**.

#### Stage B: Post-Optimization Structural MIR Hashing & Identical Code Folding (Pass R6)

Even when two generic instantiations invoke distinct trait methods at the surface level (for example, `Ord::cmp` on `u64` vs. `Ord::cmp` on `usize` or `distinct u64`), after Pass R1 (Inlining), Pass R2 (SROA), and Pass R5 (CFG Canonicalization), their optimized `MirBody` graphs frequently become structurally identical.

Pass R6 runs a deterministic **Structural MIR Hash (`Wyhash(0)`)** over every optimized `MirBody`:
1.  **Canonical Alpha-Normalized Hashing:** Because `MirValueId`, `MirBlockId`, and `LocalId` are assigned sequentially from `0` inside each `MirBody`, hashing the contiguous SoA slices (`blocks`, `instructions.items(.op)`, `instructions.items(.aux_u16)`, `LayoutShapeKey(instructions.items(.type_id))`, `instructions.items(.operands)`, `places`, `projections`, and `extra_data`) using `std.hash.Wyhash.hash(0, ...)` produces a deterministic 64-bit structural fingerprint in linear time.
2.  **Exact Structural Equality Check & Symbol Aliasing:** If two monomorphized functions `F_1` and `F_2` collide on their 64-bit structural hash, Pass R6 performs a byte-for-byte comparison of their normalized `MirBody` arrays. When equal, `F_2`'s `MirBody` is marked `is_folded_alias_of = F_1` and **skipped completely during LLVM IR codegen**; in the `corex_llvm.cpp` bridge (or `-ofmt=c` backend), `F_2` is emitted as a zero-cost `LLVMAddAlias2` symbol alias pointing to `F_1` (or redirected at all internal direct call sites).

#### Concrete Walkthrough: `Vec[OwnPtr[User]]::push` vs. `Vec[OwnPtr[Order]]::push`

Consider how a container method `Vec[T]::push(self: &mut Vec[T], elem: own T)` is compiled when called with `OwnPtr[User]` (`sizeof(User) = 128`) and `OwnPtr[Order]` (`sizeof(Order) = 256`):
1.  **Inner Non-Generic Allocation Helper (`Polymorphization`):** `Vec[T]::reserve_bytes(self: &mut RawVec, elem_size: usize, elem_align: usize)` does not depend on `T` beyond integer constants, so only one `reserve_bytes` exists in `std`.
2.  **Pointer-Shape Equivalence in `Vec[T]::push`:** Inside `Vec[T]::push`, `T` is `OwnPtr[User]` and `OwnPtr[Order]`. Both types have `byte_size = 8`, `alignment_log2 = 3`, `abi_pass_class = .IntReg`, and move via a single 64-bit register store (`*(self.ptr + self.len * 8) = elem; self.len += 1`) without calling any `User`- or `Order`-specific methods.
3.  **Single Instantiation Outcome:** Pass D5 computes identical `LayoutShapeKey`s for `OwnPtr[User]` and `OwnPtr[Order]` and instantiates a single canonical `Vec[ @shape(8B_align8_ptr) ]::push` `MirBody`. In `--release` builds, small calls to `push` are inlined directly into the caller by Pass R1, while any non-inlined calls share the single machine-code body with zero `AX`-register dictionary overhead and zero LLVM codegen duplication.
