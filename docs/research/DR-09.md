# Dual-Mode Compiler Backend Architecture and MIR Lowering Specification for CoreX (.cx)

To simultaneously deliver **instantaneous development feedback (targeting `>= 500,000` LOC/sec clean throughput and sub-50ms incremental rebuilds in `--dev` mode)** and **Ahead-of-Time production executables that match or outperform `clang -O3` and `rustc -O` (`--release` mode)**, the CoreX compiler (`corex`) implements a **Unified Three-Tier Backend Architecture** operating directly on verified **Block-Argument Static Single Assignment Mid-Level IR (`MirBody`)**. As compiler authors Christoffer Lernö (C3) and Ginger Bill (Odin) have independently reported, lexing, parsing, and semantic analysis account for only 1% to 2% of total build time in their compilers, whereas LLVM IR construction, multi-pass analysis, and linking consume **85% to 98%+ of total compilation time** – even in unoptimized `-O0` single-threaded builds. CoreX eliminates this bottleneck in development builds while maximizing hardware exploitation in release builds by routing a single, canonical `MirBody` representation through three specialized backends governed by a shared `CodegenBackend` interface and a deterministic `TypeLayoutResolver`:

1.  **Tier C – Fast Direct Machine-Code Emitter & In-Place Binary Patcher (`corex run`, `corex build --dev`):** Bypasses LLVM entirely during development. Consuming the 5-pass `--dev` `MIR` pipeline (`Passes D1–D5`), Tier C adapts the single-pass **TPDE** compilation paradigm (which academic benchmarks at TU Munich show compiles SSA IR **8x to 24x faster than `LLVM -O0`** on SPECint 2017) directly to CoreX's Block-Argument `MIR`. After a linear backward liveness and loop-extent scan, a single forward pass executes instruction selection, chordal SSA / eviction-based register allocation via a compact **16-byte `ValueAssignment` table**, and direct binary encoding for `x86_64`, `aarch64`, and `wasm32`. Paired with CoreX's in-tree incremental linker (`Atom` slot management with `padToIdeal` slack padding and Global Offset Table `GOT` indirection), modifying a function patches machine code and DWARF debug tables **in place** inside the executable without re-linking unchanged declarations.
2.  **Tier A – Self-Hosted Deterministic C99 Emitter (`-ofmt=c`):** Translates verified `MirBody` graphs into portable, target-exact ISO C99 source code. Built first in Stage 0 (Zig) and ported first to Stage 1 (`.cx`), Tier A powers CoreX's `wasm32-wasi` self-hosting bootstrap seed (`stage1/corex1.wasm.zst`, ~500–650 KB compressed) without requiring LLVM during bootstrapping.
3.  **Tier B – Optimizing Production AOT Backend (`corex build --release`):** Consumes the 11-pass `--release` `MIR` pipeline (`Passes D1–D5` + `R1–R6`) through a single isolated C++20 translation unit (`src/corex_llvm.cpp` + `src/corex_llvm.h`) linked against static **LLVM 20–23** and embedded **`lld::lldMain`** archives. Crucially, Tier B translates CoreX's compile-time semantic proofs – strict Mutable Value Semantics (`MVS`) disjoint parameter trees (`DR-02`), interprocedural `FnRegionSummary` escape bitmasks (`DR-06`), Pentagon (`Intv × Sub`) integer bounds proofs (`DR-06`), and `#soa` contiguous column pointers (`DR-02`, `DR-13`) – directly into LLVM 20–23 parameter attributes (`noalias`, `nonnull`, `noundef`, `readonly`, `nocapture`, `dereferenceable`), scoped alias metadata (`!alias.scope`, `!noalias`), `SROA`-surviving range assumptions (`!range`, `@llvm.assume` operand bundles), and loop vectorization metadata (`!llvm.access.group`, `!llvm.loop.parallel_accesses`). This enables LLVM to auto-vectorize, scalarize, and hoist `.cx` code in scenarios where C and C++ compilers are constrained by conservative pointer-aliasing assumptions.

To guarantee **zero semantic or layout divergence** between `--dev`, `-ofmt=c`, and `--release` builds, no backend is permitted to independently compute struct field offsets, alignment padding, enum niche encodings, or calling convention register assignments. Instead, a frontend-owned **`TypeLayoutResolver` and `AbiClassifier`** computes canonical byte layouts and `cx` ABI lowering recipes inside the shared `InternPool` prior to codegen, ensuring bit-identical memory layouts and cross-linking compatibility across all three tiers.

## 1. Deliverable 1: Unified CodegenBackend Interface and Three-Tier MIR Lowering Specification

### 1.1 Zero Dev/Prod Divergence: The Shared TypeLayoutResolver and AbiClassifier

A classic failure mode in dual-backend compilers occurs when a fast debug backend and an LLVM release backend disagree on subtle ABI or memory layout corner cases – such as struct field reordering, alignment padding holes, nested enum niche bit-patterns, or multi-register struct passing – causing FFI crashes or bugs that only manifest in `--release` builds. CoreX prevents this class of bugs structurally: **all type layout, niche computation, `#soa` column offset calculation, and `cx` ABI classification execute once in the middle-end `InternPool` (`TypeLayoutResolver`)** and are stored in an immutable, arena-allocated `ResolvedTypeLayout` and `AbiFnRecipe` table consumed read-only by all three backends.

> **Visual – Shared Layout and ABI Lowering Eliminates Divergence Across All Three Backends:** CoreX computes all struct layouts, recursive enum niches, Structure-of-Arrays column offsets, and register calling conventions once in the middle-end InternPool before dispatching through the **CodegenBackend** interface to the single-pass direct emitter, the C99 bootstrap emitter, or the isolated LLVM 20-23 bridge.

For every concrete `TypeId` in `InternPool`, `TypeLayoutResolver` deterministically computes a 32-byte `ResolvedTypeLayout` record across four layout categories:

First, for **default versus `@repr(C)` product types (`struct`)**, `@repr(C)` structs lay out fields sequentially in source declaration order with standard target ABI alignment padding. For native `.cx` structs (without `@repr(C)`), `TypeLayoutResolver` sorts fields by **descending alignment requirement, then descending niche capacity, then source index**. This deterministic sort eliminates internal alignment holes while keeping field order 100% reproducible across platforms. Furthermore, if the total `byte_size` of a `@repr(C)` struct is not a multiple of its alignment or contains internal alignment holes, `TypeLayoutResolver` records the exact byte intervals of all padding holes so `-ofmt=c` and `--dev` explicitly zero-fill padding during initialization.

Second, for **recursive niche computation (`enum` and `Option[T]` / `T?` / `Result[T, E]`)**, following `DR-02` and `DR-06`, `TypeLayoutResolver` tracks a canonical `NicheRange { byte_offset: u32, scalar_size: u8, start_val: u64, end_val: u64 }` for every type. Non-null pointers (`&T`, `&mut T`, `OwnPtr[T]`) and `NonZero*` integers register `NicheRange { byte_offset: 0, scalar_size: ptr_bytes, start_val: 0, end_val: 0 }`; `bool` registers `{ byte_offset: 0, scalar_size: 1, start_val: 2, end_val: 255 }`; `SlotKey[T]` registers `{ byte_offset: 0, scalar_size: 4, start_val: 0xFFFF_FFFF, end_val: 0xFFFF_FFFF }`; and `char` registers `{ byte_offset: 0, scalar_size: 4, start_val: 0x0011_0000, end_val: 0xFFFF_FFFF }`. A `struct` inherits the largest `NicheRange` of its fields (offset by the field's byte position in the struct). When laying out an `enum` with one data-carrying variant $V_{\text{data}}$ and $K$ unit variants $V_1, \dots, V_K$, if $V_{\text{data}}$ exposes a `NicheRange` where $\text{end\_val} - \text{start\_val} + 1 \ge K$, the enum's discriminant tag is **completely elided** (`tag_encoding = .niche_embedded`), mapping unit variant $V_i$ to $\text{start\_val} + (i - 1)$ at `byte_offset`. Consequently, `OwnPtr[T]?`, `(&T)?`, and `SlotKey[T]?` occupy 8 bytes across `--dev`, `-ofmt=c`, and `--release`.

Third, for **`#soa` contiguous buffer partitioning**, across fixed `#soa[N]T`, dynamic `#soa Vec[T]`, and `#soa[]T` slices (`DR-02`, `DR-13`), `TypeLayoutResolver` computes the column base offset for field $f \in [0, F)$ inside a capacity-$C$ allocation as:
$$\text{ColOffset}(f, C) = \text{alignForward}\!\left(\sum_{j=0}^{f-1} \text{alignForward}(C \cdot \text{sizeof}(\tau_j),\; \text{align}_{\text{SIMD}}),\; \max(\text{alignof}(\tau_f), \text{align}_{\text{SIMD}})\right)$$
where $\text{align}_{\text{SIMD}}$ is 32 bytes on `x86_64` (64 bytes when targeting `AVX-512`) and 16 bytes on `aarch64` and `wasm32`. This ensures that every column pointer `base_ptr + ColOffset(f, C)` is hardware-vector aligned across all three backends.

Fourth, for **LSB `bit_field` bitmasks** (`bit_field BackingInt { ... }`), `TypeLayoutResolver` assigns each field $f$ its exact `bit_offset: u8` (counting upward from bit 0 LSB), `bit_width: u8`, and `is_signed: bool`, ensuring identical shift/mask extraction in `--dev`, `-ofmt=c`, and `--release`.

#### Canonical `cx` ABI Classification (`AbiClassifier`)

Every function signature in `MirBody` is classified by `AbiClassifier` into a target-specific `AbiFnRecipe` that dictates exact physical register and stack-slot assignments prior to backend invocation:

| Parameter / Return Category | Size & Mode Predicate | Canonical `cx` ABI Lowering Rule (`x86_64` SysV / Win64, `aarch64` AAPCS64, `wasm32`) | Alias & Safety Invariant Guaranteed Across All Backends |
| :--- | :--- | :--- | :--- |
| **Implicit `Context*`** | `MirBody.is_contextless == false` | Passed in a dedicated argument register (`r10` or 1st GP reg on `x86_64`, `x8`/`x0` on `aarch64`, 1st `i32` local on `wasm32`). **Omitted completely** when Pass D5 proves `is_contextless == true`. | Non-null, valid for the duration of the call (`nonnull noundef align(8) dereferenceable(32)`). |
| **`let` Mode (`T` / `&T`) Small** | `byte_size <= 16` (`Copy` or `~Copy`) | Coerced into 1 or 2 eightbyte scalars (`i64`, `f64`, or `<2 x f32>` vector) passed directly in GP/XMM/NEON registers (`rdi..r9` / `xmm0..7` on SysV `x86_64`; `x0..x7` / `v0..v7` on `aarch64`). | Pure SSA register value (`noundef`); zero stack traffic. |
| **`let` Mode (`T` / `&T`) Large** | `byte_size > 16` | **Promoted to `const T* noalias nonnull`** pointing directly to caller's existing storage (`MirOp.place_addr`). Callee never copies the struct onto its stack frame, preserving `&v == &v` pointer identity. | `noalias nonnull noundef readonly align(A) dereferenceable(S)` + `nocapture` (when `FnRegionSummary` proves non-escaping). |
| **`inout` Mode (`&mut T`) Scalar** | `byte_size <= 8` & non-address-taken | Promoted by Pass R2 in `--release` to **register-in / register-out (`T -> T`)** (merged into return tuple). In `--dev` (or if address-taken), passed as `T* noalias nonnull` in 1 GP register. | Exclusive mutation; zero aliasing with any other parameter or global. |
| **`inout` (`&mut T`) & `set` (`ref mut T`) Composite** | Composite or address-taken `inout` / any `set` | Passed as `T* noalias nonnull` in 1 GP register pointing to caller's target `MirPlace`. For `set`, caller storage enters uninitialized and exits fully initialized. | `inout`: `noalias nonnull noundef align(A) dereferenceable(S)`.<br>`set`: `noalias nonnull noundef writeonly align(A) dereferenceable(S)`. |
| **`sink` Mode (`own T`)** | `byte_size <= 16` vs `> 16` | **≤16 B:** Passed in 1–2 registers.<br>**>16 B:** Passed via caller-allocated slot pointer (`T* noalias nonnull`) transferring ownership without `memcpy`. | Source binding ends lifetime at call site (`storage.move`); callee owns slot exclusively. |
| **Return Value (`ret`)** | `byte_size <= 16` vs `> 16` | **≤16 B:** Returned in `rax:rdx` / `xmm0:xmm1` (`x86_64`) or `x0:x1` / `v0:v1` (`aarch64`).<br>**>16 B:** Caller passes hidden 1st pointer `sret(T) noalias nonnull align(A) dereferenceable(S)`; callee constructs result directly in caller's destination `PlaceId.return_place` (Guaranteed RVO). | Eliminates return-value `memcpy` for large structs and `Result[T, E]` unions. |

### 1.2 Complete CodegenBackend Interface in Zig (Stage 0) and CoreX (Stage 1)

#### Stage-0 Zig Interface (`stage0/src/codegen_backend.zig`)

The following Zig module defines the canonical layout descriptors, ABI classification records, and `CodegenBackend` VTable consumed by `stage0/corex` (`DR-01`, `DR-13`):

```zig
//! CoreX Stage-0 Compiler (`stage0/corex`)
//! Module: Unified `CodegenBackend` Interface, `TypeLayoutResolver`, and `AbiClassifier`
//! Consumes verified `MirBody` (DR-13) and `FnRegionSummary` / Pentagon Ranges (DR-06).

const std = @import("std");
const assert = std.debug.assert;
const mem = @import("mem_foundation.zig");
const ir = @import("ir_catalog.zig");

pub const StringId = mem.StringId;
pub const TypeId = mem.TypeId;
pub const MirBlockId = mem.MirBlockId;
pub const MirValueId = mem.MirValueId;
pub const BumpArena = mem.BumpArena;

// ============================================================================
// [1] CANONICAL TYPE LAYOUT & NICHE DESCRIPTORS (SHARED ACROSS ALL 3 BACKENDS)
// ============================================================================

pub const TagEncoding = enum(u8) {
    none_product = 0,     // struct, tuple, array, primitive
    explicit_tag = 1,     // discriminant stored at `tag_byte_offset`
    niche_embedded = 2,   // discriminant encoded inside payload niche range
    untagged_union = 3,   // @repr(C) union
};

pub const NicheSpec = extern struct {
    byte_offset: u32 = 0,
    scalar_byte_size: u8 = 0, // 0 = no niche, 1 = u8/bool, 4 = u32/char/SlotKey, 8 = ptr/NonZeroU64
    tag_encoding: TagEncoding = .none_product,
    tag_scalar_size: u8 = 0,
    _pad: u8 = 0,
    niche_start: u64 = 0,     // Inclusive start of invalid bit-pattern range
    niche_end: u64 = 0,       // Inclusive end of invalid bit-pattern range
};

/// 32-byte canonical layout record computed once per `TypeId` in `InternPool`.
pub const ResolvedTypeLayout = extern struct {
    byte_size: u32,
    alignment_log2: u8,
    abi_eightbyte_class_lo: AbiRegClass, // Classification of bytes 0..7
    abi_eightbyte_class_hi: AbiRegClass, // Classification of bytes 8..15
    is_zst: u8,                          // 1 if byte_size == 0 (`unit`, phantom types)
    /// Slice in `LayoutPool.field_offsets[fields_start .. fields_start + fields_len]`
    /// Sorted by physical offset; maps logical `field_idx` -> physical `byte_offset`.
    fields_start: u32,
    fields_len: u16,
    soa_simd_align_log2: u16,
    niche: NicheSpec,
};

// ============================================================================
// [2] CANONICAL `cx` ABI CLASSIFICATION RECIPE (`AbiFnRecipe`)
// ============================================================================

pub const AbiRegClass = enum(u8) {
    no_class = 0,     // ZST or unused high eightbyte
    integer_gp = 1,   // 64-bit General Purpose register (`rax`, `rdi`, `x0`)
    sse_float = 2,    // 64-bit / 128-bit FP/Vector register (`xmm0`, `v0`)
    memory_indirect = 3,
};

pub const AbiPassKind = enum(u8) {
    zst_elided = 0,           // Zero-sized type (`unit`): 0 registers
    direct_one_reg = 1,       // <= 8B passed/returned in 1 GP or FP register
    direct_two_regs = 2,      // 9..16B passed/returned in 2 GP/FP registers
    indirect_const_noalias = 3, // `let` > 16B: `const T* noalias nonnull readonly`
    indirect_mut_noalias = 4,   // `inout` / `set` / `sink` > 16B: `T* noalias nonnull`
    indirect_sret = 5,          // Return > 16B via hidden 1st `sret(T) noalias nonnull` pointer
};

/// 16-byte per-parameter or return lowering recipe.
pub const AbiParamRecipe = extern struct {
    pass_kind: AbiPassKind,
    reg_class_lo: AbiRegClass,
    reg_class_hi: AbiRegClass,
    phys_reg_lo: u8,          // Target physical register ID (e.g., RDI=7, X0=0, 0xFF=stack)
    phys_reg_hi: u8,
    pointee_align_log2: u8,
    /// Bit 0: `noalias`, Bit 1: `nonnull`, Bit 2: `noundef`, Bit 3: `readonly`,
    /// Bit 4: `writeonly`, Bit 5: `nocapture` (from DR-06 FnRegionSummary)
    llvm_attr_mask: u16,
    pointee_deref_bytes: u32, // `dereferenceable(N)` byte count for indirect pointers
    stack_byte_offset: u32,   // Offset in caller/callee argument area if spilled
};

pub const AbiFnRecipe = extern struct {
    ret_recipe: AbiParamRecipe,
    params_start: u32,        // Slice in `LayoutPool.abi_params`
    params_len: u16,
    passes_context_reg: u8,   // 1 if implicit `Context*` passed in dedicated register, 0 if `contextless`
    calling_conv: u8,         // 0 = `cx_native`, 1 = `c_system`, 2 = `wasm_mvp`
};

// ============================================================================
// [3] SAST METADATA SIDE-TABLES FOR CODEGEN (`DR-06` PENTAGON & REGION PROOFS)
// ============================================================================

/// Proven integer interval `[inf, sup]` from DR-06 Pass 4 Pentagon analysis for a `MirValueId`.
pub const ProvenValueRange = extern struct {
    inf: i64,
    sup: i64,
    has_range: u8,            // 1 if non-top interval proven
    is_nuw: u8,               // 1 if unsigned overflow proven impossible
    is_nsw: u8,               // 1 if signed overflow proven impossible
    survived_sroa_load: u8,   // 1 if promoted from a Place load (emit `@llvm.assume` in Tier B!)
    _pad: u32 = 0,
};

/// Compilation unit / symbol handle across all three backends.
pub const SymbolId = enum(u32) { none = std.math.maxInt(u32), _ };

pub const CompileMode = enum(u8) {
    dev_fast = 0,             // Tier C: Direct machine-code emitter + In-place binary patcher
    bootstrap_c99 = 1,        // Tier A: Deterministic C99 source emitter (`-ofmt=c`)
    release_llvm_o2 = 2,      // Tier B: LLVM 20-23 `-O2` + Embedded LLD
    release_llvm_o3 = 3,      // Tier B: LLVM 20-23 `-O3` + Embedded LLD
    release_llvm_oz = 4,      // Tier B: LLVM 20-23 `-Oz` (compact native / wasm32)
};

// ============================================================================
// [4] UNIFIED `CodegenBackend` INTERFACE (VTABLE)
// ============================================================================

pub const CodegenBackend = struct {
    ctx: *anyopaque,
    vtable: *const VTable,

    pub const VTable = struct {
        /// Initializes target module/binary state and registers canonical layouts.
        beginModule: *const fn (
            ctx: *anyopaque,
            module_name: StringId,
            target_triple: [:0]const u8,
            mode: CompileMode,
        ) anyerror!void,

        /// Declares or updates a global symbol (function prototype or static constant).
        declareSymbol: *const fn (
            ctx: *anyopaque,
            sym_id: SymbolId,
            name: [:0]const u8,
            ty: TypeId,
            layout: *const ResolvedTypeLayout,
            abi: *const AbiFnRecipe,
            is_external: bool,
        ) anyerror!void,

        /// Compiles a verified, ghost-erased `MirBody` into the backend's representation.
        /// In `--dev` incremental mode, patches only the dirty `Atom` for `sym_id` in place!
        emitFunction: *const fn (
            ctx: *anyopaque,
            sym_id: SymbolId,
            body: *const ir.MirBody,
            abi: *const AbiFnRecipe,
            value_ranges: []const ProvenValueRange,
            scratch_arena: *BumpArena,
        ) anyerror!void,

        /// Emits a zero-cost symbol alias for Pass R6 Structural MIR Identical Code Folding (ICF).
        emitFoldedAlias: *const fn (
            ctx: *anyopaque,
            alias_sym: SymbolId,
            canonical_target_sym: SymbolId,
        ) anyerror!void,

        /// Finalizes codegen and invokes either the in-place incremental patcher (Tier C),
        /// C99 file flush (Tier A), or LLVM PassBuilder + `lld::lldMain` (Tier B).
        finishAndLink: *const fn (
            ctx: *anyopaque,
            output_path: [:0]const u8,
        ) anyerror!void,
    };

    pub inline fn emitFunction(
        self: CodegenBackend,
        sym_id: SymbolId,
        body: *const ir.MirBody,
        abi: *const AbiFnRecipe,
        value_ranges: []const ProvenValueRange,
        scratch_arena: *BumpArena,
    ) !void {
        return self.vtable.emitFunction(self.ctx, sym_id, body, abi, value_ranges, scratch_arena);
    }
};

comptime {
    assert(@sizeOf(NicheSpec) == 24);
    assert(@sizeOf(ResolvedTypeLayout) == 32);
    assert(@sizeOf(AbiParamRecipe) == 16);
    assert(@sizeOf(ProvenValueRange) == 24);
}
```

### 1.3 Complete MIR-to-Backend Lowering Matrix (Tier C, Tier A, and Tier B)

Because Pass D3 erases all `ghost_access_*` and `ghost_storage_*` verification instructions prior to codegen (`DR-13`), every backend consumes only executable `MirOp` instructions, `MirPlace`/`MirProjection` paths, and `MirTerminator` edges. The table below specifies the exact lowering of every `MIR` construct across all three backend tiers:

| `MIR` Construct (`DR-13`) | Tier C: Fast Direct Emitter (`x86_64` / `aarch64` / `wasm32`) | Tier A: Deterministic C99 Emitter (`-ofmt=c`) | Tier B: Production LLVM 20–23 Bridge (`corex_llvm.cpp`) |
| :--- | :--- | :--- | :--- |
| **`MirOp.block_param`** (`^bb(%p0: T)`) | Assigned a pinned physical register (single-pred) or deterministic stack/reg slot populated by incoming edge parallel moves. | Declared as function-scope C local `T_c bbN_p0;`; assigned prior to `goto bbN;` in every predecessor block. | Lowered to `LLVMBuildPhi(B, ty, "p0")`; incoming `(val, pred_bb)` pairs wired after block emission. |
| **`MirOp.const_scalar`** | Materialized lazily on demand (`mov r, imm` / `movz`+`movk` / `i64.const`) or folded directly into instruction immediate operand. | Emitted as typed C99 constant literal (`INT64_C(42)`, `UINT32_C(0xFF)`) or static constant array reference. | `LLVMConstInt` / `LLVMConstReal` / `LLVMConstNull` cached in module constant table. |
| **`MirOp.bin_op` / `unary_op`** | Single machine instruction (`add`, `sub`, `imul`, `shl`, `cmp`+`setcc`). If `flags.checked_overflow == 1` in `--dev`, emits `jo`/`jc ^panic_ovf`. | Explicit C99 unsigned cast for defined wrap (`(int32_t)((uint32_t)a + (uint32_t)b)`) to avoid signed C UB. | `LLVMBuildAdd` / `Sub` / `Mul` with **`nuw` / `nsw`** flags attached whenever `ProvenValueRange.is_nuw / is_nsw == 1`. |

### 1.4 Tier A (-ofmt=c) Deterministic C99 Emitter Specification

The `-ofmt=c` backend (`src/codegen/c_backend.zig` in Stage 0, `src/compiler/c_backend.cx` in Stage 1) has two strict architectural mandates from `DR-01`: (1) it must compile the entire self-hosted `.cx` compiler into `wasm32-wasi` (`corex1.wasm.zst`) and transpile `corex1` into `corex2.c` using **zero LLVM dependencies**, and (2) its generated C99 output must be **100% deterministic and free of C Undefined Behavior (UB)**.

To ensure byte-for-byte identical C99 output across runs and prevent host C compilers (`gcc`, `clang`, `cl.exe`) from miscompiling `.cx` semantics due to C's strict aliasing or signed integer overflow rules, Tier A enforces five emission invariants:
1.  **Explicit Byte-Array Struct Layout Emission:** Rather than trusting the host C compiler's struct packing pragmas, Tier A emits every composite `TypeId` using the exact physical byte offsets computed by `TypeLayoutResolver`. Every struct `cx_type_42` is emitted with explicit `uint8_t _pad_K[N];` fields filling every alignment hole recorded by `TypeLayoutResolver`, and local struct initializations always zero-initialize padding bytes (`= {0}`), satisfying `DR-01` Entropy Vector 3.
2.  **Block-Argument SSA to C99 Parallel-Assignment Lowering:** For every `MirBasicBlock` $B_j$ with incoming parameters $(\%p_0: \tau_0, \dots, \%p_{m-1}: \tau_{m-1})$, Tier A declares function-scoped variables `tau_0 bbJ_p0; ... tau_m bbJ_pm;` at the top of the C function. When predecessor block $B_i$ terminates with `br ^B_j(%v_0, ..., %v_{m-1})` (and $B_i$ could equal $B_j$ in a loop back-edge where `%v_1` reads `%p_0`), Tier A first evaluates all outgoing arguments into temporary C locals `_edge_0 = v_0; ... _edge_m = v_m;`, assigns `bbJ_p0 = _edge_0; ... bbJ_pm = _edge_m;`, and emits `goto bb_J;`.
3.  **Elimination of C Signed Overflow and Shift UB:** In C99, signed integer overflow (`int32_t + int32_t`) and shifting by `>= bit_width` are Undefined Behavior. Tier A lowers all wrapping or range-proven arithmetic (`MirOp.bin_op` on `i8`..`i64`) by casting operands to their unsigned C99 counterparts (`uint8_t`..`uint64_t`), performing the operation in unsigned arithmetic, and casting back to the signed type, while masking shift counts with `& (bit_width - 1)`.
4.  **Portable 128-Bit Integers (`i128` / `u128`):** On 64-bit GCC/Clang targets, `i128`/`u128` map to `__int128` / `unsigned __int128`; on strict C99 / 32-bit / MSVC bootstrap targets without `__int128`, Tier A lowers 128-bit values to `typedef struct { uint64_t lo; uint64_t hi; } cx_u128_t;` backed by inline helpers in `stage1/compiler_rt.c`.
5.  **`restrict` Qualification from MVS Proofs:** Even in `-ofmt=c` builds, Tier A emits C99 `restrict` on all pointer parameters where `AbiParamRecipe.llvm_attr_mask` has the `noalias` bit set (`const T * restrict param_0`, `T * restrict param_1`), allowing the host C compiler (`cc -O2` during Step 6 of `bootstrap.c` in `DR-01`) to optimize `corex2` aggressively.

## 2. Deliverable 2: Fast Direct Machine-Code Emitter (--dev) and Sub-50ms In-Place Incremental Binary Patching Blueprint

### 2.1 Single-Pass TPDE-Style Direct Lowering Architecture (x86_64, aarch64, wasm32)

To achieve its **`>= 500,000` LOC/sec** compilation throughput target in `corex run` and `corex build --dev`, Tier C (`src/codegen/direct_emitter.zig` -> `src/compiler/direct_emitter.cx`) eliminates intermediate Machine IR (`MIR` -> `MachineIR` -> `MCInst`) translation and multi-pass graph-coloring register allocation. Drawing directly on the **TPDE** single-pass compiler backend architecture (Schwarz, Kamm, and Engelke, TU Munich, 2025/2026) and Zig 0.15's self-hosted `x86_64` backend, Tier C compiles each verified `MirBody` in **one lightweight analysis scan followed by a single combined lowering, register-allocation, and binary-encoding pass**.

> **Visual – Single-Pass Direct Lowering Achieves 8x to 24x Faster Codegen Than LLVM -O0:** Bypassing LLVM in development builds eliminates the 85% to 98% codegen and linking bottleneck observed in traditional systems compilers. CoreX's single-pass emitter tracks every live SSA value in a compact 16-byte **ValueAssignment** record indexed directly by MirValueId.

#### Step 1: Linear Liveness, Use-Count, and Loop-Extent Analysis Scan

Before emitting machine bytes for a `MirBody` with $V$ SSA instructions (`MirValueId` $0 \dots V-1$) and $B$ basic blocks (`MirBlockId` $0 \dots B-1$, already ordered in Reverse Postorder / dominator-respecting topological order by `MirSsaBuilder`), Tier C runs a fast linear analysis pass using scratch arrays allocated in `BumpArena`:
1.  **Loop Extent Detection:** By scanning each block's `MirTerminator` successor edges, any edge $B_{\text{src}} \to B_{\text{hdr}}$ where $\text{RPO}(B_{\text{hdr}}) \le \text{RPO}(B_{\text{src}})$ identifies a loop back-edge. The loop body encompasses blocks in the RPO interval $[B_{\text{hdr}}, B_{\text{src}}]$.
2.  **Exact Remaining Use Counts & Loop-Live Extension:** A single pass over all instructions and terminators increments `use_count[val]` for every operand `MirValueId`. Crucially, if a value $v$ is defined prior to a loop header ($\text{DefBlock}(v) < B_{\text{hdr}}$) and read inside the loop body ($B_{\text{use}} \in [B_{\text{hdr}}, B_{\text{src}}]$), keeping $v$ alive across the back-edge requires preventing its register or spill slot from being freed prematurely inside the loop body. Tier C therefore adds a synthetic loop-retention weight (`+0x4000`) to `use_count[v]` upon entering $B_{\text{hdr}}$ and decrements it only when the single-pass emitter steps past the loop exit $B_{\text{src}}$.

#### Step 2: The 16-Byte `ValueAssignment` Descriptor and Single-Pass Register Allocator

Because programs in Block-Argument SSA form have **chordal interference graphs**, a dominator-order walk over the blocks can assign registers greedily in $O(1)$ time per instruction without building an $O(V^2)$ interference matrix. Tier C maintains a flat array `assignments: []ValueAssignment` indexed directly by `MirValueId` (`0..V`), where each single-part entry occupies **exactly 16 bytes** (fitting 4 value assignments per 64-byte L1d cache line, with multi-part values larger than 16 bytes adding 2 bytes per extra part if needed):

```zig
/// 16-Byte TPDE-style ValueAssignment record indexed directly by `MirValueId` (`0..V`).
/// Supports 1-part (<=8B) and 2-part (9..16B `cx` ABI register pairs) values in 16 bytes.
pub const ValueAssignment = extern struct {
    /// Stack frame offset from frame pointer (`rbp` / `x29`) if spilled (0 = not yet allocated).
    frame_spill_offset: i32 = 0,
    /// Remaining SSA uses of this value; when decremented to 0, its physical register(s) and
    /// stack spill slot are immediately returned to the free pools!
    remaining_uses: u16 = 0,
    /// Current physical register holding bytes 0..7 (`0xFF` = not currently in a register).
    phys_reg_lo: u8 = 0xFF,
    /// Current physical register holding bytes 8..15 for 2-part values (`0xFF` = none).
    phys_reg_hi: u8 = 0xFF,
    /// Bits 0..3: log2 byte size; Bits 4..5: num_parts (1 or 2); Bits 6..7: reg_bank (GP vs FP/SIMD).
    size_and_parts: u8 = 0,
    flags: Flags = .{},
    /// Monotonic instruction tick of last register access (for LRU eviction victim selection).
    last_access_tick: u16 = 0,
    /// For `is_rematerializable == true`: encodes `LocalId` frame offset or 32-bit immediate.
    remat_payload: u32 = 0,

    pub const Flags = packed struct(u8) {
        /// Locked during current instruction selection so reloading operand 2 never evicts operand 1!
        is_locked: bool = false,
        /// True if `frame_spill_offset` already holds an up-to-date copy of the value (clean eviction).
        is_stack_valid: bool = false,
        /// True if value is a `place_addr` stack address (`lea r, [rbp - disp]`) or small immediate;
        /// on eviction, it is NEVER spilled to memory – it is simply recomputed on reload!
        is_rematerializable: bool = false,
        /// True if value is pinned to a fixed register (e.g., single-pred Block Argument).
        is_fixed_reg: bool = false,
        _pad: u4 = 0,
    };
};

comptime {
    std.debug.assert(@sizeOf(ValueAssignment) == 16);
}
```

Alongside `assignments`, the emitter maintains a register file state `RegState` consisting of bitmasks `free_gp_regs: u32`, `free_fp_regs: u32`, `locked_regs: u32`, `clobbered_callee_saved: u32`, and an array `reg_owner: [32]MirValueId` mapping each physical register back to the `MirValueId` currently occupying it. Allocating a physical register `allocReg(bank, hint_reg)` executes in four deterministic steps:
1.  **Free Register Fast Path:** Check `free_regs & ~locked_regs`. If `hint_reg` (e.g., an ABI return or argument register) is free, select `hint_reg`; otherwise select `@ctz(free_regs & ~locked_regs)` (preferring caller-saved scratch registers before untouched callee-saved registers, unless the value is live across an upcoming `MirTerminator.call`).
2.  **Victim Selection (When All Registers in `bank` Are Occupied):** Select the unlocked register $r \notin \text{locked\_regs}$ with the oldest `last_access_tick` (preferring registers whose owner `val = reg_owner[r]` has `is_rematerializable == true` or `is_stack_valid == true` so eviction requires zero memory writes).
3.  **Lazy Spill / Rematerialization Handling:** If the evicted owner `val` has `is_rematerializable == false` and `is_stack_valid == false`, allocate a stack slot `frame_spill_offset` from the size-segregated stack-slot free list (if `frame_spill_offset == 0`), emit a store instruction (`mov [rbp - disp], r` on `x86_64`; `str xN, [x29, #-disp]` on `aarch64`), and set `val.flags.is_stack_valid = true`. Clear `val.phys_reg_lo = 0xFF`.
4.  **Operand Locking & Use Decrement:** Whenever an instruction needs an existing operand `op_val` in a physical register, `ensureInReg(op_val)` sets `op_val.flags.is_locked = true`. If `op_val` was previously evicted, it either emits `lea r, [rbp - disp]` (if `is_rematerializable == true`) or loads from `frame_spill_offset`. Once the instruction is encoded into the output byte buffer, all operand locks are cleared and `remaining_uses` is decremented for each operand; if `remaining_uses == 0`, its physical register is immediately set in `free_regs` and its `frame_spill_offset` (if any) is returned to the stack-slot free list for reuse by subsequent locals.

#### Block-Argument SSA Edge Resolution Without $\phi$-Nodes

Because CoreX's `MIR` uses Basic Block Arguments (`^bb(%p_0, ..., %p_{k-1})`) rather than $\phi$-nodes (`DR-02`, `DR-13`), Tier C resolves control-flow data transfers directly at block headers and terminator edges using TPDE's two-case protocol:
-   **Case A: Single-Predecessor Target Block (`bb.pred_len == 1`):** No data merge occurs. When predecessor $B_{\text{pred}}$ finishes and jumps to $B_{\text{dst}}$, the outgoing argument `%arg_i` transfers its active `ValueAssignment` (physical register or stack slot) directly to `%p_i` with **zero move instructions**.
-   **Case B: Multi-Predecessor Join or Loop Header Block (`bb.pred_len > 1`):** Upon encountering a multi-predecessor block $B_{\text{dst}}$ for the first time (either when emitting $B_{\text{dst}}$ as a loop header or when emitting a forward jump to $B_{\text{dst}}$), Tier C assigns each block parameter `%p_i` a canonical **pinned location**: either a fixed register (when only a single incoming value is merged and not live across calls) or a dedicated stack frame slot `frame_spill_offset`. At the end of every predecessor block $B_{\text{pred}}$ targeting $B_{\text{dst}}$, the terminator emitter resolves the parallel copy $(\%p_0, \dots, \%p_{k-1}) \leftarrow (\%a_0, \dots, \%a_{k-1})$. Any cycle among physical registers is broken using a temporary scratch register released at the end of the instruction or edge.

#### Fixed-Space Prologue/Epilogue Reservation and In-Place Patching

In a single-pass emitter, neither the total stack frame size (`max_frame_bytes`) nor the bitmask of modified callee-saved registers (`clobbered_callee_saved`) is known when emitting the function entry prologue at byte offset `0`. Tier C resolves this without moving generated machine code by reserving sufficient space for saving all required callee-saved registers and patching the prologue and epilogue at the end of the function:
-   On **`x86_64`**, byte offset `0` sets up the frame pointer (`push rbp; mov rbp, rsp`), reserves space for `sub rsp, imm32`, and reserves sufficient bytes for saving all required callee-saved registers (`rbx`, `r12..r15`). All local `MirPlace` slots and spill slots are addressed relative to the frame pointer (`[rbp - offset]`) rather than `rsp` so stack offsets never shift when the total frame size is finalized. Once the single pass completes, Tier C patches the final stack frame size and the `push` instructions for the callee-saved registers actually used into the prologue, and pads the remaining reserved instruction space with architectural `NOP`s.
-   On **`aarch64`**, byte offset `0` sets up the frame pointer (`stp x29, x30, [sp, #-frame_size]!`, `mov x29, sp`) and reserves slots for saving the required callee-saved registers (`x19..x28`), patching the final frame size and used register saves at function completion while padding unused slots with `nop`.
-   On **`wasm32`**, because WebAssembly is a structured virtual stack machine (`block`, `loop`, `if`, `br`, `br_if`, `br_table`) with typed locals, Tier C maps each `MirValueId` and scalar `LocalId` directly to a Wasm local index (`local.get` / `local.set` / `local.tee`) while keeping composite `MirPlace` structs in the linear-memory shadow stack. Since CoreX's `HIR` (`hir_if`, `hir_match`, `hir_loop`) is strictly structured (`DR-13`), forward branches wrap target blocks in Wasm `block $B` scopes (`br $depth`) and loop headers wrap bodies in `loop $L` scopes (`br $L`), emitting compact Wasm bytecode in a single pass.

### 2.2 In-Place Incremental Binary Patching Blueprint (ELF, Mach-O, PE/COFF, Wasm)

Even when a single-pass emitter compiles a modified function in microseconds, invoking a traditional external linker (`ld`, `ld64`, `link.exe`, or even `lld`) to re-link a debug binary from scratch breaks the sub-50ms developer feedback budget. CoreX's `--dev` mode achieves **sub-50ms incremental rebuilds** by pairing a long-lived compiler daemon (`corex watch` / `IncrementalDebugServer`) with an in-tree **Atom- and GOT-based In-Place Binary Patcher** modeled on Zig's self-hosted incremental linker (`src/link/Elf.zig`, `src/link/MachO.zig`, `src/link/Coff.zig`, `src/link/Wasm.zig`).

#### 1. Fine-Grained Declaration Dependency Graph and Persistent `InternPool`

In `corex watch` or when `corex build --dev` communicates with the background `IncrementalDebugServer` over a socket, the compiler keeps the `InternPool`, `StringInterner`, and output binary state resident in memory across edits, sidestepping process startup cost. For every top-level declaration or monomorphized function (`SymbolId`), the compilation unit tracks three dependency sets:
-   **`src_hash_deps`:** Source hashes of the declaration's instructions/tokens (`Wyhash(0)`) and any files read by the declaration.
-   **`decl_deps` (`nav_val_deps` / `nav_ty_deps`):** References to other declarations (`SymbolId` and `TypeId` handles for callees, types used, and fields read).
-   **`comptime_deps` (`interned_deps`):** Captured `comptime` values and interned types read during Pass D4.

When the OS file watcher (`inotify` on Linux, `kqueue` on macOS/BSD, or Windows file watching) detects a file edit on `foo.cx`, `corex` regenerates the AST/HIR for `foo.cx`, walks the dependency graph to mark only transitive dependents as dirty, and re-runs semantic analysis (`Sema`), `MIR` verification (`Passes D1–D5`), and Tier C codegen **solely on those invalidated declarations**.

#### 2. Global Offset Table (`GOT`) Function Indirection and `padToIdeal` Atom Slack

If functions in `--dev` mode called each other via direct PC-relative displacements (`call rel32` on `x86_64` or `bl imm26` on `aarch64`), relocating a single function that outgrew its previous code slot would require scanning and patching every caller across the entire binary. CoreX avoids this completely by combining **GOT indirection for all `--dev` function calls** with **over-provisioned `Atom` slots (`padToIdeal`)**:

1.  **Stable GOT Indirection Slots:** Every function `SymbolId` is assigned a stable index `got_idx: u32` in the binary's `.got` (Global Offset Table) section. In Tier C `--dev` codegen, calling `SymbolId` routes through its `.got` entry rather than hardcoding the target function's `.text` address into the caller:
    -   On **`x86_64`**, the caller emits a RIP-relative indirect call through the GOT slot (`call qword ptr [rip + disp32_to_got_slot]`), where the `.got` section is placed at a fixed virtual address prior to `.text` so `disp32_to_got_slot` remains constant as long as the caller `Atom` itself does not move.
    -   On **`aarch64`**, the caller loads the target address from the GOT page (`adrp` + `ldr` + `blr`).
    -   On **`wasm32`**, `--dev` functions are indexed in the indirect function table at `got_idx` and invoked via `call_indirect`.
2.  **`padToIdeal` Slack Formula:** Following Zig's incremental linker formula (`fn padToIdeal(actual_size: anytype) @TypeOf(actual_size) { return actual_size +| (actual_size / ideal_factor); }`), every newly allocated code `Atom` (and DWARF `.debug_info` / `.debug_line` `Atom`) of size `actual_size` bytes is allocated a virtual address and file region padded with growth headroom (`ideal_factor`, such as 25% slack when `ideal_factor == 4`, subject to `minimum_atom_size` / `minimum_text_block_size`):
    $$\text{AllocatedCap}(\text{actual\_size}) = \text{alignForward}\!\left(\max\!\left(\text{minimum\_atom\_size},\; \text{actual\_size} + \left\lfloor\frac{\text{actual\_size}}{\text{ideal\_factor}}\right\rfloor\right),\; 16\right)$$
3.  **Scenario A – Fast-Path In-Place Overwrite (`new_size <= atom.allocated_cap`):** When the recompiled machine code `new_size` fits inside `atom.allocated_cap`, the linker patches the `Atom` **directly in place** inside the binary by overwriting the machine bytes at `atom.file_offset`, padding the remaining slack bytes up to `atom.allocated_cap` with architectural traps/NOPs, and leaving `atom.vaddr` and the `.got` slot completely unchanged.
4.  **Scenario B – Overflow Relocation Patch (`new_size > atom.allocated_cap`):** When a modified function outgrows its allocated `padToIdeal` capacity, the linker returns the old `Atom` slot to the section's free list, allocates a new slot of size `padToIdeal(new_size)` (from the free list or by bumping the section size), writes the expanded machine code there, and updates the function's **single pointer entry in the `.got` table (`got_section[sym.got_idx] = new_vaddr`)**. Because all callers invoke the function through its `.got` entry, **zero bytes are modified in any caller `Atom` across the binary**.

| Scenario / Patching Path | Trigger Condition | `.text` Section Action | `.got` Table Action | Caller `Atom` Relocations Required |
| :--- | :--- | :--- | :--- | :--- |
| **Scenario A: Fast-Path In-Place Overwrite** | `new_size <= atom.allocated_cap` (fits within `padToIdeal` slack) | Overwrite machine bytes in place at existing `atom.file_offset`; pad remaining slack. | **None** (`got[idx]` unchanged). | **Zero** (`0` caller bytes modified). |
| **Scenario B: Overflow Atom Relocation** | `new_size > atom.allocated_cap` (exceeds `padToIdeal` slack) | Return old `Atom` to free-list; allocate new `padToIdeal(new_size)` `Atom`. | **Single pointer write** (`got[idx] = new_vaddr`). | **Zero** (`0` caller bytes modified). |

To ensure that growing `.text`, `.rodata`, `.data`, or `.debug_*` sections never forces a full-file shift on disk, CoreX's incremental linker configures each executable format with segment headroom and per-declaration `Atom` tracking:

#### 4. Incremental DWARF Debug Info Patching

As noted by Loris Cro and Andrew Kelley, in-place function patching must also handle debug information, because adding or removing lines in a function modifies the debug metadata used to print stack traces and drive debuggers. Following Zig's `src/link/Dwarf.zig` and `src/link/Elf.zig` design, CoreX treats each declaration's `.debug_info` tag and `.debug_line` fragment as an **independent `Atom` allocated with `padToIdeal` slack**. The linker records the exact byte offset from the beginning of the section and the unpadded size of the `.debug_info` tag for each `Decl`. When a declaration is recompiled during an incremental rebuild, its updated DWARF debug info and line-number program are written in place into its pre-allocated `.debug_info` and `.debug_line` `Atom` slots (or relocated using `padToIdeal` if the debug tag outgrows its slack), keeping stack traces and source-line mappings accurate in sub-50ms rebuilds.

## 3. Deliverable 3: LLVM 20–23 Optimization Pass Pipeline and Alias/Range Metadata Lowering Specification (--release)

### 3.1 Exploiting CoreX Semantic Invariants to Beat C/C++ and Rust in --release Mode

In C and C++ (`clang -O3`), the LLVM optimizer is frequently forced to generate conservative scalar code or duplicate runtime-versioned loops because C's semantics permit unrestricted pointer aliasing: any two pointers of compatible type (`float *a, float *b`) or any `char*` / `uint8_t*` pointer may alias, structs passed by reference (`const T&`) may alias mutable pointers or globals accessed inside the function, and array indices carry no compile-time non-negative range guarantees. Even in Rust (`rustc -O`), while `&T` and `&mut T` emit `noalias`, three critical optimization bottlenecks remain: (1) standard Array-of-Structs (`Vec<Particle>`) layouts waste 93.75% (60 of 64 bytes) of every fetched 64-byte cache line on single-field `u32`/`f32` loops unless manually refactored into separate vectors; (2) Rust lacks compile-time Pentagon (`Intv × Sub`) relational bounds verification, leaving runtime bounds-check branches inside indexed loops when iterators are not used; and (3) as documented in LLVM RFC #91264, when LLVM's `SROA` / `mem2reg` promotes stack/aggregate loads to SSA values, `PromoteMemToReg` **silently deletes `!range`, `!align`, and `!dereferenceable` metadata attached to the load** (only salvaging `!nonnull` when paired with `!noundef`), causing downstream `InstCombine`, `SCEV`, `ValueTracking`, and `BasicAA` passes to lose value-range and alignment facts!

> **Visual – CoreX Semantic Proofs Unlock Aggressive LLVM Vectorization Blocked in C++ and Rust:** Unlike C and C++ (where pointer aliasing and signed index uncertainty force runtime loop versioning or scalar fallback) and Rust (where SROA drops load *!range* metadata and AoS layouts fragment cache lines), CoreX lowers compile-time MVS and SAST Pentagon proofs directly into LLVM 20-23 attributes, assumptions, and parallel loop access groups.

CoreX bridges all five semantic guarantees from `DR-02`, `DR-06`, and `DR-13` into `src/corex_llvm.cpp` using the following exact LLVM 20–23 metadata and attribute lowering rules:

#### Rule 1: Function Parameter & Return Attributes from `DR-02` MVS and `DR-06` `FnRegionSummary`

Every indirect parameter pointer (`let` `>16B`, `inout` `&mut T`, `sink` `own T` `>16B`, `set` `ref mut T`, and `sret` `>16B`) is guaranteed by `DR-02`'s Law of Exclusivity to point to a disjoint topological value tree. Furthermore, `DR-06` Pass 3 computes the 24-byte `FnRegionSummary` for every function in $O(V + E)$ Tarjan SCC time. `src/corex_llvm.cpp` combines `AbiParamRecipe` with `FnRegionSummary` to emit the full legal LLVM 20–23 attribute set on every parameter $i$:
-   **Universal Pointer Validity:** Every safe indirect parameter receives `noalias nonnull noundef align(A) dereferenceable(S)`, where $A = 2^{\text{alignment\_log2}}$ and $S = \text{byte\_size}$ from `ResolvedTypeLayout`.
-   **Escape & Capture Elision (`nocapture`):** If parameter $i$'s bit is `0` in `FnRegionSummary.global_escape_mask`, `0` in `FnRegionSummary.ret_provenance_mask` (meaning the return value does not borrow from parameter $i$), and `0` in all outgoing columns of `FnRegionSummary.param_flow_matrix`, `corex_llvm.cpp` attaches **`nocapture`**. This informs LLVM's alias analysis passes that calling the function never captures the pointer into a global or another object, keeping caller locals promoted in registers across opaque calls.
-   **Read/Write Directionality (`readonly`, `writeonly`):** Every `let` (`>16B`) parameter receives **`readonly`**. Every `set` (`ref mut T`) parameter enters uninitialized and is guaranteed by `DR-06` Pass 2 to be fully initialized without reading prior contents; it receives **`writeonly`**, allowing LLVM's Dead Store Elimination to delete redundant caller stores prior to the call.
-   **Returned Views (`nonnull noundef align(A)`):** When a function returns a non-null pointer (`OwnPtr[T]`, `&T`) or non-zero handle, its return slot receives `nonnull noundef align(A)` (and `noalias` if `FnRegionSummary.ret_provenance_mask == 0`, proving a fresh allocation from `OwnPtr` or `PoolAllocator` – noting that while C99's `restrict` is meaningless on function return values, LLVM's `noalias` return attribute is fully exploited by the optimizer).

#### Rule 2: Scoped Aliasing Metadata (`!alias.scope`, `!noalias`, and Loop-Safety Hoisting)

Parameter-level `noalias` attributes only apply across function call boundaries. When Pass R1 or LLVM's CGSCC Inliner inlines a callee – or when a single function simultaneously mutates two sibling sub-paths of the same struct (`swap(&mut r.pos.x, &mut r.dim.y)`) or two disjoint entries from `SlotMap::get_disjoint_mut([k1, k2])` – parameter attributes alone do not tell LLVM that the resulting pointers inside the same function body are non-aliasing.

CoreX preserves `DR-06`'s `MovePath` Trie disjointness proofs inside function bodies and across inlining by emitting **LLVM Scoped Alias Metadata**:
1.  For each function call inlined during Pass R1 and each pair of simultaneously active `access.inout` / `access.let` projections on disjoint `MovePathId` subtrees ($p_1 \notin \text{Conflict}(p_2)$), `corex_llvm.cpp` creates a unique `MDNode` alias domain `!dom` and a scope node `!scope_k = distinct !{!scope_k, !dom, !"cx_path_k"}`.
2.  It emits `call void @llvm.experimental.noalias.scope.decl(metadata !{!scope_k})` at the dominance birth of the projection, attaches `!alias.scope !{!scope_k}` to all loads/stores through path $p_k$, and attaches `!noalias !{!scope_other_1, ...}` listing all concurrently live disjoint scopes (ensuring each declared scope is referenced by both sets per `InstructionCombining.cpp`).
3.  **Mitigating the LLVM #79137 Loop-Vectorizer Hazard:** As documented in LLVM Issue #79137, placing `@llvm.experimental.noalias.scope.decl` *inside* a loop body for an iteration-local pointer (such as `prev.ptr` vs `curr.ptr` that are only `noalias` within a single iteration) can cause `LoopVectorize` to mistakenly assume the underlying objects do not alias *across* loop iterations and miscompile the loop. CoreX enforces a strict safety invariant in `corex_llvm.cpp`:
    -   If a disjoint pointer pair is **loop-invariant** (such as `#soa` column pointers `p.pos_x` vs `p.pos_y` or function-level `inout` parameters), `@llvm.experimental.noalias.scope.decl` is **hoisted to the function entry block (or loop preheader)** so `LoopVectorize` safely vectorizes across iterations.
    -   Conversely, if an `access.inout` projection is rebound on each loop iteration to an iteration-dependent address ($p(i)$), `@llvm.experimental.noalias.scope.decl` is never emitted inside the loop body unless `DR-06` Pass 4 proves the address stride is non-overlapping across iterations.

#### Rule 3: SAST Pentagon Range Proofs (`!range`, `!noundef`, `@llvm.assume` Salvaging, and `nuw`/`nsw`)

In `DR-06` Pass 4 and `DR-13` Pass R3, CoreX's Pentagon Abstract Interpreter ($\text{Pntg} = \text{Intv} \times \text{Sub}$) computes a closed 64-bit interval $b^*(v) = [\text{inf}(v), \text{sup}(v)]$ and strict symbolic upper bounds $s^*(v)$ for every integer `MirValueId`. `src/corex_llvm.cpp` lowers `ProvenValueRange` into four LLVM IR mechanisms that work in concert:
1.  **Arithmetic Overflow Flags (`nuw`, `nsw`) and `inbounds` GEPs:** Whenever `ProvenValueRange` proves that an addition, subtraction, multiplication, or left-shift cannot wrap unsigned (`is_nuw == 1`) or signed (`is_nsw == 1`) – such as loop induction increments `i + 1` bounded by `slice.len` – `corex_llvm.cpp` sets `nuw` and `nsw` on the binary operator, and emits `getelementptr inbounds` for every slice/array/struct indexing `place_addr` where `inf(idx) >= 0` and `idx < len`.
2.  **`!range` + `!noundef` on Memory Loads and Calls:** When a `place_load` or `call` produces an integer or enum tag with a proven non-top interval $[\text{inf}, \text{sup}]$ (or a `bool` `[0, 1]`, `char`, or `NonZero*` `[1, UINT_MAX]`):

    ```llvm
    %val = load i64, ptr %field_ptr, align 8, !noundef !0, !range !{i64 0, i64 1024}
    ```

    In LLVM IR, `!range !{i64 A, i64 B}` specifies the **half-open** interval $[A, B)$, so CoreX's closed Pentagon interval $[\text{inf}, \text{sup}]$ lowers to `!{i64 inf, i64 (sup + 1)}`. Crucially, CoreX **always attaches `!noundef !0` alongside `!range`, `!nonnull`, `!align`, and `!dereferenceable`**.
3.  **Solving LLVM's `SROA`/`mem2reg` Metadata Loss via `@llvm.assume` (LLVM RFC #91264):** When LLVM's `SROA` or `mem2reg` promotes a load instruction to an SSA register (or when CoreX's own Pass R2 `SROA` promotes a `MirPlace` load into a pure SSA `MirValueId`), deleting the load instruction deletes its `!range`, `!align`, and `!dereferenceable` metadata – and converting poison-generating metadata into UB-generating `@llvm.assume` is only legal when the value is guaranteed `!noundef` (which CoreX statically guarantees via `DR-06` Pass 2 definite-initialization checking). Because `!align` and `!dereferenceable` already have a natural representation via `@llvm.assume` operand bundles while `!range` requires boolean `icmp` conditions, `corex_llvm.cpp` emits:
    -   For pointer values (`#soa` column base pointers, slice data pointers, `OwnPtr[T]`) promoted to SSA registers by Pass R2:

        ```llvm
        call void @llvm.assume(i1 true) [ "nonnull"(ptr %col_ptr), "align"(ptr %col_ptr, i64 32), "dereferenceable"(ptr %col_ptr, i64 4096) ]
        ```

    -   For integer values with `ProvenValueRange.survived_sroa_load == 1` (or function parameters with sub-range invariants that feed branch/division/index expressions):

        ```llvm
        %in_bounds = icmp ult i64 %val, 1024 ; when inf == 0 and sup == 1023
        call void @llvm.assume(i1 %in_bounds)
        ```

    This ensures `InstCombine`, `ValueTracking`, `SCEV`, and `BasicAA` retain CoreX's SAST range and alignment facts even after full aggregate scalarization.

#### Rule 4: `#soa` Contiguous Column Slices and Guaranteed Loop Auto-Vectorization

When iterating over a `#soa[]T` slice, `#soa Vec[T]`, or `soa_zip` view (`DR-02`, `DR-13`), Pass D5/R1 lowers field accesses `particles[i].pos_x` directly into contiguous column pointer offsets `col_pos_x[i]` (`MirProjection.soa_field_ptr`), and Pass R3 elides all `assert_check` bounds branches inside `0..len` loops. To ensure LLVM's `LoopVectorize` and `SLPVectorizer` emit unversioned, full-width SIMD instructions (`AVX2`/`AVX-512`, ARM `NEON`, or `wasm32` `SIMD128`):
1.  Every memory load and store inside a loop whose index is proven bounds-safe by Pass R3 and whose target `PlaceId`s are proven iteration-independent by Pass D2 is tagged with a loop-specific **`!llvm.access.group !G`** metadata node.
2.  The loop latch's back-edge branch (`br i1 %exit_cond, label %loop.exit, label %loop.body, !llvm.loop !L`) is annotated with:

    ```llvm
    !G = distinct !{}
    !L = distinct !{!L, !1, !2, !3}
    !1 = !{!"llvm.loop.parallel_accesses", !G}
    !2 = !{!"llvm.loop.vectorize.enable", i1 true}
    !3 = !{!"llvm.loop.vectorize.predicate.enable", i1 true}
    ```

    As specified in the LLVM Language Reference, when all memory-accessing instructions in a loop carry `!llvm.access.group` metadata referenced by the loop's `!"llvm.loop.parallel_accesses"` metadata, the loop has **no loop-carried memory dependencies**, allowing the vectorizer to vectorize the loop without runtime alias-check fallback blocks.

#### Rule 5: Structural TBAA (`!tbaa` and `!tbaa.struct`)

To further assist alias analysis when `@extern` C FFI pointers (`*T`, `*mut T` inside `unsafe` blocks) interact with safe CoreX values, `corex_llvm.cpp` attaches **`!tbaa`** metadata to every load and store so LLVM's TBAA analysis can answer `NoAlias` queries that pointer analysis alone cannot resolve:
1.  **`!"CoreX MVS Disjoint Root"`:** Every distinct nominal CoreX `TypeId` (`struct`, `enum`, primitive) and every distinct field `(StructTypeId, field_idx)` forms a disjoint TBAA access tag `{!StructNode, !FieldNode, i64 field_byte_offset, i64 is_immutable_let}`. Unlike C/C++ – where `char*` (`uint8_t*`) aliases all memory – CoreX's safe `[u8]` and `u8` accesses do **not** alias non-`u8` structs, so `u8` is a distinct leaf node under `"CoreX MVS Disjoint Root"`, while only raw `*u8` / `*mut u8` pointers inside `unsafe` blocks attach to an omnipotent byte root.
2.  **`!tbaa.struct` on Aggregate Copies:** Whenever `llvm.memcpy` copies a composite struct with alignment padding holes, `corex_llvm.cpp` attaches `!tbaa.struct` listing the exact `(offset, size, field_tbaa_tag)` triples from `ResolvedTypeLayout`.

### 3.2 Custom LLVM 20–23 PassBuilder Pipeline Specification (`src/corex_llvm.cpp`)

Because CoreX's 11-pass `--release` `MIR` pipeline (`Passes D1–D5` + `R1–R6` in `DR-13`) already performs subscript inlining (Pass R1), `Place`-to-SSA SROA promotion (Pass R2), Pentagon bounds-check elimination (Pass R3), Maranget switch fusion (Pass R4), and pointer-shape / structural MIR Identical Code Folding (Pass R6) *before* LLVM IR is constructed, `src/corex_llvm.cpp` configures LLVM 20–23's `llvm::PassBuilder` (`buildPerModuleDefaultPipeline`) to focus on target-specific instruction combining, interprocedural SCC optimization (`IPSCCP`, `CalledValuePropagation`), loop unrolling (`LoopUnrollAndJam`, `LoopUnroll`), and vectorization:

```cpp
// Excerpt from `src/corex_llvm.cpp`: Configuring LLVM 20-23 `PassBuilder` for CoreX `--release`
#include "corex_llvm.h"
#include "llvm/Analysis/AliasAnalysis.h"
#include "llvm/Analysis/CGSCCPassManager.h"
#include "llvm/Analysis/LoopAnalysisManager.h"
#include "llvm/Analysis/ScopedNoAliasAA.h"
#include "llvm/Analysis/TypeBasedAliasAnalysis.h"
#include "llvm/IR/PassManager.h"
#include "llvm/MC/TargetRegistry.h"
#include "llvm/Passes/OptimizationLevel.h"
#include "llvm/Passes/PassBuilder.h"
#include "llvm/Target/TargetMachine.h"

static llvm::OptimizationLevel mapCxOptLevel(CxLlvmOptLevel lvl) {
    switch (lvl) {
        case CX_LLVM_OPT_O0: return llvm::OptimizationLevel::O0;
        case CX_LLVM_OPT_O1: return llvm::OptimizationLevel::O1;
        case CX_LLVM_OPT_O2: return llvm::OptimizationLevel::O2;
        case CX_LLVM_OPT_O3: return llvm::OptimizationLevel::O3;
        case CX_LLVM_OPT_OS: return llvm::OptimizationLevel::Os;
        case CX_LLVM_OPT_OZ: return llvm::OptimizationLevel::Oz;
    }
    return llvm::OptimizationLevel::O3;
}

bool cx_llvm_optimize_and_emit_object(
    CxLlvmModule *cx_mod,
    const char *output_obj_path,
    const char *emit_ir_debug_path,
    char *err_buf,
    size_t err_buf_cap
) {
    llvm::Module &M = *cx_mod->module;
    llvm::TargetMachine *TM = cx_mod->target_machine.get();

    // [1] Configure PipelineTuningOptions for aggressive SIMD & unrolling in -O2/-O3, or compact -Oz
    llvm::PipelineTuningOptions PTO;
    const bool is_size_opt = (cx_mod->opt_level == CX_LLVM_OPT_OS || cx_mod->opt_level == CX_LLVM_OPT_OZ);
    PTO.LoopUnrolling = !is_size_opt;
    PTO.LoopInterleaving = !is_size_opt;
    PTO.LoopVectorization = !is_size_opt || cx_mod->target_triple.isWasm(); // Keep SIMD128 active on wasm32!
    PTO.SLPVectorization = true;
    PTO.MergeFunctions = false; // Already executed at MIR level in Pass R6 (DR-13) with 0 LLVM overhead!

    llvm::LoopAnalysisManager LAM;
    llvm::FunctionAnalysisManager FAM;
    llvm::CGSCCAnalysisManager CGAM;
    llvm::ModuleAnalysisManager MAM;

    llvm::PassBuilder PB(TM, PTO);

    // [2] Register ScopedNoAliasAA and TypeBasedAA in the FunctionAnalysisManager AA pipeline
    FAM.registerPass([&] {
        llvm::AAManager AA;
        AA.registerFunctionAnalysis<llvm::ScopedNoAliasAA>();
        AA.registerFunctionAnalysis<llvm::TypeBasedAA>();
        PB.registerAAPipeline(AA);
        return AA;
    });

    // [3] RegisterPassBuilder Extension Point Callbacks (OptimizerEarlyEP, CGSCCOptimizerLateEP, etc.)
    //    PassBuilderPipelines.cpp invokes PipelineStartEP, OptimizerEarlyEP, CGSCCOptimizerLateEP,
    //    ScalarOptimizerLateEP, LateLoopOptimizationsEP, and OptimizerLastEP during the module pipeline.
    PB.registerModuleAnalyses(MAM);
    PB.registerCGSCCAnalyses(CGAM);
    PB.registerFunctionAnalyses(FAM);
    PB.registerLoopAnalyses(LAM);
    PB.crossRegisterProxies(LAM, FAM, CGAM, MAM);

    llvm::OptimizationLevel OptLvl = mapCxOptLevel(cx_mod->opt_level);
    llvm::ThinOrFullLTOPhase LTOPhase = cx_mod->enable_lto_bitcode
        ? llvm::ThinOrFullLTOPhase::ThinLTOPreLink
        : llvm::ThinOrFullLTOPhase::None;

    llvm::ModulePassManager MPM = PB.buildPerModuleDefaultPipeline(OptLvl, LTOPhase);
    MPM.run(M, MAM);

    // [4] Emit native object file (or ThinLTO bitcode for embedded `lld::lldMain`)
    return emitTargetObjectFile(M, *TM, output_obj_path, emit_ir_debug_path, err_buf, err_buf_cap);
}
```

#### Why This Emitted LLVM IR Outperforms Both `clang -O3` and `rustc -O`

1.  **100% Cache-Line Utilization vs. 6.25% per Field in AoS C++/Rust:** As analyzed in `DR-02`, when iterating over a single 4-byte field inside an Array-of-Structs (AoS) where each struct is 64 bytes (`std::vector<Particle>` in C++ or `Vec<Particle>` in Rust), the CPU fetches a 64-byte cache line per element and wastes 15/16ths (60 of 64 bytes, or 93.75%) of memory bandwidth on unused fields (6.25% utilization per 4-byte field, or 12.5% when reading two 4-byte fields). CoreX's `#soa[]Particle` transposes each field into a contiguous column array (16 active 4-byte floats per 64-byte cache line, achieving 100% cache-line utilization) while preserving `particles[i].pos_x` surface syntax.
2.  **Zero Runtime Alias-Check Versioning Stubs:** In C++, even if a developer manually passes separate pointers `float *pos_x, const float *vel_x, const WorldConfig &cfg`, unless every pointer is manually annotated with `__restrict`, `clang -O3` must emit a runtime pointer-bounds overlap check comparing `[pos_x, pos_x + len)` against `[vel_x, vel_x + len)` and `[&cfg, &cfg + 1)`, plus a scalar fallback loop. Because CoreX automatically emits `noalias` on `%particles` and `%cfg`, hoists `@llvm.experimental.noalias.scope.decl` for `!soa_col_pos_x` (`!1`) and `!soa_col_vel_x` (`!4`), and attaches `!llvm.loop.parallel_accesses`, LLVM emits **zero runtime alias checks**.
3.  **Zero Bounds Checks and 32-Byte Aligned Vector Loads:** Because `DR-06` Pass 4 Pentagon analysis statically proves `0 <= i < len`, Pass R3 deletes the bounds check before LLVM sees the IR, and `@llvm.assume` preserves the 32-byte alignment of `%col_pos_x` and `%col_vel_x` across `SROA`, enabling aligned SIMD vector instructions (`AVX2`/`AVX-512`, `NEON`, or `wasm32 SIMD128`).
