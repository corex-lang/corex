# Zero-GC Memory Model, Automatic Compile-Time Cleanup & Static Vulnerability Verifier (SAST) for CoreX (.cx)

CoreX (`.cx`) achieves deterministic C-level execution speed, compact binary footprints (1.5–10 KB freestanding `wasm32` modules in developer comparisons), and compile-time temporal and spatial memory safety without a runtime tracing garbage collector, hidden Atomic Reference Counting (ARC), or Rust-style lifetime annotation parameters (`<'a, 'b>`). This specification unifies the **Strict Mutable Value Semantics (MVS)** and second-class reference architecture established in `DR-02` (`let`, `inout`, `sink`, `set` parameter modes and `subscript` `yield` projections) with the authoritative `LL(k)` / Pratt surface syntax and EBNF grammar established in `DR-03` (`&`, `&mut`, `own`, `ref`, `let`/`var`, and `defer`). By partitioning types into three compile-time ownership tiers – **`Copy` primitives**, **`AutoDrop` standard value containers** (`Vec[T]`, `String`, `Map[K, V]`, `SlotMap[K, V]`), and **`@linear` explicit-control resources** (`Arena`, `PoolAllocator[T]`, `OwnPtr[T]`, `File`, `Socket`) – CoreX makes everyday application coding automatic by default while giving systems programmers deterministic manual control over memory layout and arena allocation.

To ensure that neither everyday value containers nor manual arena and pool allocations introduce C-style memory corruption or resource leaks, the CoreX compiler (`corex`, bootstrapped in Zig in `stage0/corex` and self-hosted in `.cx` prior to v1.0 per `DR-01`) embeds a four-pass **Static Application Security Testing (SAST) and Lifetime Verification Engine** operating directly on **Block-Argument Static Single Assignment Mid-Level IR (`MIR`)**. Rather than requiring programmers to write lifetime variance bounds, the `MIR` verifier executes four sequential compile-time passes:
1.  **Path-Sensitive `DenseBitSet` Typestate Dataflow Analysis** over an arena-allocated `MovePath` trie to detect Use-After-Free/Move (`E0301`), Double-Free (`E0302`), Uninitialized Reads (`E0303`), and Memory/Resource Leaks (`E0304`), while driving automatic branch-aware drop elaboration for `AutoDrop` containers.
2.  **Ghost-Instruction Abstract Interpretation** (`access.let`, `access.inout`, `access.set`, `access.end`) to enforce the MVS Law of Exclusivity (`E0305`) across disjoint struct sub-paths, coroutines, `@local` closures, and structured `async` tasks.
3.  **Bottom-Up Tarjan Strongly Connected Component (SCC) Escape & Region Summary Inference** to synthesize interprocedural provenance summaries (`FnRegionSummary`), allowing functions to return zero-copy views (`Span16`, `[T]`, `str`) and accept `&mut Arena` parameters without manual lifetime annotations while statically rejecting dangling stack or arena escapes (`E0306`).
4.  **Pentagon Abstract Interpretation (`Pntg = Intv × Sub`) paired with Sparse ABCD Demand Traversal** to statically validate slice and array bounds safety, eliding redundant runtime bounds checks and flagging provable out-of-bounds buffer overflows (`E0307`) at compile time.

## Deliverable 1: Unified CoreX Memory & Ownership Specification

### 1.1 Canonical Reconciliation of `DR-02` MVS Modes and `DR-03` Surface Syntax

A foundational requirement of the CoreX language specification is reconciling `DR-02`'s Hylo-inspired second-class reference parameter conventions (`let`, `inout`, `sink`, `set`) with `DR-03`'s authoritative EBNF surface tokens (`&`, `&mut`, `own`, `ref`, `let`, `var`, `defer`) so that the parser, bidirectional type checker, and `MIR` verifier operate as a single cohesive system.

In Rust, `&'a T` and `&'a mut T` are **first-class reference types**: they can be stored inside arbitrary `struct` fields, returned independently of coroutine lexical scopes, and nested (`&'a &'b mut T`), which requires propagating explicit lifetime parameters (`<'a>`), higher-ranked trait bounds (`for<'a>`), and lifetime subtyping variance across the language. CoreX eliminates lifetime annotations by enforcing a strict invariant: **safe references in CoreX are second-class lexical projections**. In `DR-03`'s EBNF grammar (`PrimaryType = ... | "&" [ "mut" ] Type | "own" Type | "ref" [ "mut" ] Type`), the surface tokens `&T`, `&mut T`, `own T`, and `ref mut T` do **not** construct first-class lifetime-parameterized pointer types; instead, they serve as the canonical surface syntax for `DR-02`'s four MVS parameter-passing modes and scoped coroutine projections. Across target workloads in `DR-02`, combining this zero-GC value model with unboxed 16-bit spans (`Span16` as evaluated in OxCaml's `httpz` benchmark, which reduced 35-byte HTTP/1.1 request parse latency from 300+ ns to 154 ns and increased throughput from 3M to 6.5M req/sec with zero minor-heap allocations) and niche-optimized or cold-boxed sum types (shrinking a 1-million-element event array with a 512-byte cold payload from 520 MB to 8 MB or 16 MB) eliminates runtime memory bloat.

#### Resolving the Four Surface-to-Semantic Unification Edge Cases

In `DR-03`'s code showcases, functions accept read-only composite types using `&Type` (e.g., `opts: &ScanOptions`, `pool: &PgPool`, `node: &AvlNode[K, V]`) and primitive or slice types by bare name (`node_name: str`, `cap: usize`). Under CoreX's unified semantics, `param: T` (when not prefixed by `own` or `mut` on a `~Copy` type) and `param: &T` are **semantically and operationally identical**: both declare a second-class MVS **`let` parameter**. At the call site, writing `scan_file(&mut arena, &opts, &mut stdout)` or `scan_file(&mut arena, opts, &mut stdout)` emits the exact same `%t = access.let %opts` ghost instruction and passes a `const ScanOptions* noalias` pointer under the `cx` ABI. Permitting `&T` in signatures and `&x` at call sites alongside bare `T` preserves `&` as a visual beacon for systems engineers distinguishing borrowed inspection from `own` consumption on move-only types (`OwnPtr`, `Arena`, `Vec`), while maintaining the guarantee that `&T` never requires a `<'a>` lifetime annotation.

A second surface nuance arises in `DR-03`'s `FnParam` grammar (`[ "mut" | "own" | "ref" ] IDENT ":" Type`), where `mut` can appear either inside the type (`node: &mut AvlNode[K, V]`) or before the parameter identifier (`fn rotate_right(mut y: OwnPtr[AvlNode[K, V]]) -> OwnPtr[AvlNode[K, V]]`). These two forms map to distinct MVS modes. `node: &mut AvlNode[K, V]` is an **MVS `inout` projection** (`access.inout`): the caller retains ownership of the root variable, passes `&mut node` at the call site, and observes in-place mutations after the call returns. Conversely, `mut y: OwnPtr[AvlNode[K, V]]` (where `OwnPtr` is a move-only `~Copy` type) is an **MVS `sink` parameter** (`storage.move`) where the callee takes full ownership of `y` and binds it as a **mutable local `var` root** inside the callee's stack frame, allowing `y.left = x.right.take();` and `Self::update_height(&mut y);` before transferring ownership out via `x.right = .Some(own y);`.

Furthermore, unlike Rust's `&mut T` – which forbids moving out of a mutable reference without `std::mem::replace` dummy values or `unsafe` pointer reads – CoreX's MVS `inout` mode (`&mut T`) is formally "move-in / move-out". Inside a function taking `state: &mut ConnState`, the callee may consume `*state` by value via `own *state` (transitioning `state` to `Moved` / `MaybeUninit = 1` in the `MIR` typestate bitset), provided every non-diverging CFG path reaching `return` executes a dominating re-initialization `*state = ConnState::Next(...)` (`storage.init`). Finally, when invoking a mutating method `vec.push(vec.len())` (where `push` takes `&mut self` and `len` takes `&self`), `DR-03` allows omitting the leading `&mut` on method receivers (`stats.lines_scanned += 1;`, `tx.commit().await?;`) while requiring explicit `&mut arg` on free-function arguments. Because `DR-02` mandates that the receiver projection `&mut vec` is sequenced **after** all argument expressions (`vec.len()`) are evaluated from left to right, the `access.let` loan on `vec` inside `vec.len()` ends before `access.inout` on `vec` begins for `.push(...)`, making nested calls like `vec.push(vec.len())` legal without temporary variables.

### 1.2 Synthesizing Automatic Scope Cleanup (`AutoDrop`) vs. Explicit `defer` (`@linear`)

To satisfy both Goal 2 (*"everyday coding must feel effortless – memory allocation and deallocation are handled automatically by the compiler by default"*) and Goal 3 (*"optional manual control over memory allocation, arenas, and raw layout"*) while upholding `DR-02`'s ban on hidden C++ RAII control flow for external resources, CoreX partitions all types into **three compile-time ownership tiers**.

#### Tier 1: `Copy` Value Types (Trivial Bitwise Duplication, Zero Drop Glue)

Types that fit within **16 bytes** (two 64-bit registers) and own no heap buffers or external OS handles implement the marker trait `Copy`. This tier includes all 19 primitive types (`i8`..`i128`, `u8`..`u128`, `isize`, `usize`, `f32`, `f64`, `bool`, `char`, `str`, `unit`, `never`), unboxed buffer spans (`Span16 = struct { off: u16, len: u16 }`), LSB `bit_field` integers, `bit_set` flags, non-owning borrowed slice views (`[T]`), and 64-bit generational keys (`SlotKey[T]`). Passing or assigning a `Copy` type duplicates its bits without invalidating the source variable (`storage.move` is not emitted) and requires zero scope-exit cleanup.

#### Tier 2: `AutoDrop` Value Containers (Automatic Deterministic Scope & Last-Use Cleanup)

Standard library value-semantic collections – specifically `Vec[T]`, `#soa Vec[T]`, `String`, `Map[K, V]`, `Set[T]`, and `SlotMap[K, V]` – are **move-only (`~Copy`) value trees** that implement the compiler-known trait **`AutoDrop`**:

```rust
pub trait AutoDrop {
    fn drop(&mut self);
}
```

For all `AutoDrop` types, memory management is **automatic by default**. When a developer writes `var items = Vec[u64]::with_capacity(64);` or constructs a dynamic `String`, the container automatically acquires its backing memory from the implicit scoped `context.allocator` (`DR-02`) and stores an allocator handle alongside its `(ptr, len, cap)` header. Assigning `let items2 = own items;` or passing `own items` transfers ownership in $O(1)$ register moves and marks `items` as `Moved` (`MaybeUninit = 1`), whereas duplicating the backing heap buffer requires an explicit `items.clone()` call (eliminating Swift's hidden Copy-on-Write atomic reference-count checks).

Crucially, the developer never writes `defer items.free();` for standard `AutoDrop` containers. During `MIR` construction, the **`ElaborateDrops`** pass inspects the `MaybeInit` and `MaybeUninit` dataflow bitsets at every scope exit (`storage.dead`), early `return`, `break`, `?` error-propagation edge, and variable reassignment. For any `AutoDrop` variable path $p$ that remains initialized on that path, the compiler automatically synthesizes a deterministic `storage.drop %p` instruction. Furthermore, if an `AutoDrop` container (`Vec[T]`, `String`, `Map[K, V]`) is allocated inside a lexical `Arena` scope (either via `Vec::in_arena(&mut arena)` or inside a `mem::with_arena(&mut arena) { ... }` block that binds `context.allocator`) and its element type `T` has no non-memory cleanup side effects (`T: TrivialDrop`), the `MIR` optimizer statically elides the per-container `storage.drop` loop, reclaiming all container buffers in $O(1)$ time when the arena resets or releases.

#### Tier 3: `@linear` Explicit-Control Resources (Verified `defer` / `errdefer` or `own` Consumption)

Power-user manual memory allocators, low-level pointer primitives, and external OS/transactional resources are marked **`@linear`** (they are `~Copy` and **`~AutoDrop`**). This tier includes `Arena` and `BumpArena` (`std::mem::Arena`, backed by page-aligned 64 KiB zeroed slabs as specified in `DR-01`), `PoolAllocator[T]` (pre-allocated typed slab pools for $O(1)$ node allocation, as used in `DR-03` Showcase 3's `AvlTree[K, V]`), `OwnPtr[T]` (unique non-null owning pointer to a single pool- or heap-allocated node `T`, where `OwnPtr[T]?` occupies 8 bytes via `0x0` niche optimization per `DR-02`), and external OS or transaction handles (`File`, `Socket`, `PgTx`, `MutexGuard`, as used in `DR-03` Showcases 1 and 2).

Tier 3 types are `@linear` rather than `AutoDrop` for two architectural reasons. First, an `OwnPtr[AvlNode[K, V]]` allocated from a `PoolAllocator[AvlNode[K, V]]` must be returned to its specific `pool.free(own node)` rather than a global heap `free`, or transferred into a parent tree link (`x.right = .Some(own y)`). Second, for external resources (`File::open`, `pool.begin_tx`, `Arena::with_capacity`), `DR-02` and `DR-03` mandate visible lexical cleanup via `defer` / `errdefer` or explicit consuming methods (`tx.commit().await?`) so systems engineers can inspect every I/O close, transaction rollback, and bulk arena release directly in the control flow.

To guarantee that manual control never causes a resource or memory leak, the `MIR` SAST verifier enforces the **Linear Consumption & `defer` Completeness Law**. Every `@linear` variable or struct field $p$ must reach `DefUninit` ($\text{MaybeInit}[p] == 0$) on **every** non-diverging CFG path before its `storage.dead` or `Return` terminator; if $\text{MaybeInit}[p] == 1$ at `storage.dead` or `Return`, the compiler halts with diagnostic **`E0304 (ResourceOrMemoryLeak)`**. In `DR-03`, `defer expr;` (e.g., `defer arena.release();`, `defer file.close();`) registers `expr` in the enclosing block's LIFO defer stack. During `MIR` lowering, the compiler clones the deferred cleanup block onto **all** outgoing edges of that lexical scope (normal fallthrough, `return`, `break`, `continue`, and `?` error propagation) immediately prior to `storage.dead`. Inside the lowered `defer` block, the `@linear` consumption method (`arena.release(own self)` or `file.close(own self)`) transitions `%arena` / `%file` to `DefUninit` (`MaybeInit = 0`), while the main block body is permitted to use `%arena` via `&` (`let`) and `&mut` (`inout`) projections right up until the `defer` execution point. Similarly, `errdefer expr;` (or `errdefer |err| { ... }` from `DR-02`) is emitted strictly along the cold `?` error-return CFG edges. When a developer allocates a linear resource inside a factory function (`var node = pool.alloc(AvlNode { ... }); errdefer pool.free(own node); ... return own node;`), `errdefer` consumes `node` on all early `?` error paths while `return own node;` consumes `node` on the success path – satisfying linear verification across all CFG branches with zero runtime drop-flag overhead.

### 1.3 Safe Cyclic Graphs (`SlotMap[K, V]`), Closures (`@local` vs. `own`), Async Tasks, and `unsafe` Raw Pointers

#### 1. Cyclic Graphs, Doubly-Linked Lists, and Retained UI Trees via `SlotMap[K, V]`

Because Strict MVS prohibits storing references inside structs, representing graphs with back-edges, doubly-linked lists, LRU caches, or retained GUI widget trees (`cx.ui` Masonry/Xilem architecture from `DR-02`) uses CoreX's standard library **`SlotMap[K, V]`**. Each key is a `Copy` 64-bit value struct (`SlotKey[V]`) packing a 32-bit slot index (`index: u32`, supporting up to $2^{32} - 2$ concurrent items with `0xFFFF_FFFF` reserved per `DR-01` as the `none` niche so `SlotKey[V]?` occupies 8 bytes) and a 32-bit version counter (`generation: NonZeroU32`, wrapping only after $2^{31}$ deletions and insertions to the exact same slot).

Every occupied slot has an odd generation counter ($2k + 1$); removing an element (`map.remove(key)`) increments the slot's generation to even ($2k + 2$), drops the value `V` if `V: AutoDrop`, and pushes the slot index onto an intrusive free-list. Attempting to access a freed or recycled slot with a stale `SlotKey[V]` fails the 32-bit generation equality check in a single array index and version comparison (`map.get(key)` returns `.None`), converting potential C-style Use-After-Free undefined behavior or ABA spurious references into a deterministic, memory-safe `Option` check. When mutating two connected graph nodes simultaneously (e.g., updating `prev_node.next` and `next_node.prev` in a doubly-linked list), `map.get_disjoint_mut([k1, k2])` verifies `k1.index != k2.index` in $O(1)$ time and yields a pair of disjoint MVS `inout` projections `(&mut V, &mut V)` – preserving the Law of Exclusivity without `unsafe` blocks.

#### 2. Closures: Default Non-Escaping `@local` vs. Escaping `own` Closures

CoreX eliminates lifetime annotations on closures by distinguishing **non-escaping `@local` closures** (the default) from **escaping `own` closures**. A standard closure expression (such as `Button(on_click: || { is_paused = not is_paused; })` in `DR-03` Showcase 4) is non-escaping (`@local` modal axis from OxCaml and Hylo in `DR-02`), and its environment frame is allocated purely on the stack. If the closure body only reads a captured outer variable `v`, the compiler emits `%c = access.let %v` at closure creation; if the body mutates `v` (`is_paused = not is_paused`), the compiler emits `%c = access.inout %v` at closure creation and holds that exclusive loan active until the **last dominating SSA use** of the closure. While `%c = access.inout %v` is live, any concurrent access to `v` outside the closure triggers compile-time error **`E0305 (ExclusivityViolation)`**. Conversely, if a closure is returned from a function, stored inside a heap/struct field, or sent to a detached thread, the interprocedural escape verifier requires it to be prefixed with `own` (`own |x| { ... }`). An `own` closure captures all referenced outer bindings by MVS **`sink` move** (or bitwise copy for `Copy` bindings like `u64` or `SlotKey[V]`), making its environment a self-contained disjoint value tree with zero dangling stack references.

#### 3. Zero-Annotation Structured `async` / `.await` Concurrency

In `DR-03` Showcase 2, `pub async fn create_user(req: &mut Request, pool: &PgPool)` borrows `req` (`inout`) and `pool` (`let`) across multiple `.await?` suspension points without lifetime parameters. This is statically sound under MVS because `.await` is **strictly structured and parent-scoped**: an unawaited `async fn` call produces a **`@local` non-escaping coroutine frame** whose `access.let` and `access.inout` loans on caller arguments remain active until the `.await` expression completes. Because a suspended caller coroutine frame remains pinned in its task stack/arena until the awaited child frame finishes, child frames cannot outlive their borrowed parent arguments. For concurrent child tasks within a handler, `async::scope(|s| { ... })` allows spawning parallel child tasks that capture disjoint `let` or `inout` paths ($\text{Path}(\text{task}_1) \cap \text{Path}(\text{task}_2) = \emptyset$), statically guaranteeing all child tasks join before `async::scope` exits.

#### 4. Raw Pointers (`*T`, `*mut T`) and `unsafe { ... }` SAST Verification

When implementing custom allocators, OS kernel interfaces, or C FFI (`@extern fn`), CoreX provides raw pointers `*T` (`const`) and `*mut T` (`DR-03` EBNF `PrimaryType = ... | "*" [ "mut" ] Type`). Constructing a raw pointer (`&raw x` or `slice.as_ptr()`) is safe, but dereferencing (`*ptr`), pointer offset arithmetic (`ptr.add(n)`), or calling an `@extern` / `unsafe fn` requires an explicit **`unsafe { ... }` block**. Crucially, entering an `unsafe { ... }` block **does not disable the `MIR` SAST verifier**: raw pointer allocations (`alloc`, `free`), provenance tracking, stack address escapes, and static buffer bounds continue to be analyzed by the SAST abstract interpreter inside `unsafe` blocks, catching C-style double-frees, UAF, and stack-pointer escapes at compile time.

## Deliverable 2: Formal `MIR` SAST & Lifetime Verification Algorithm

### 2.1 Block-Argument SSA `MIR` Schema and Ghost Instruction Set

Following `DR-01` and `DR-02`, the CoreX frontend lowers the typed AST into a per-function `MirBody` stored in contiguous `BumpArena`-backed Struct-of-Arrays (`MultiArrayList`) tables indexed by 32-bit handles (`MirBlockId = enum(u32)`, `MirValueId = enum(u32)`, `MovePathId = enum(u32)`, `RegionId = enum(u32)`, where `0xFFFF_FFFF` is the `none` sentinel). Every basic block `^bb_k(%phi_0: T_0, ..., %phi_m: T_m)` takes explicit **Block Arguments** instead of LLVM $\phi$-nodes and terminates with a single control-flow instruction (`br`, `cond_br`, `switch`, `ret`, `unwind`, or `unreachable`).

> **Visual – Four-Pass MIR Static Vulnerability Verifier and Lifetime Engine:** **Four linear-time verification passes** on Block-Argument SSA MIR replace exponential lifetime constraint solving with bitset dataflow, bottom-up SCC summaries, and Pentagon range analysis.

During AST-to-`MIR` lowering, the frontend inserts **11 zero-cost Ghost Verification Instructions** (which are verified during Passes 1–4 and erased prior to machine codegen):

| Ghost Instruction | Operands (`u32` Handles) | Semantic Role in `MIR` SAST Verifier |
| :--- | :--- | :--- |
| **`storage.live`** | `%p: MovePathId` | Marks the lexical birth of root variable `%p` on the stack (`MaybeUninit = 1, MaybeInit = 0`). |
| **`storage.dead`** | `%p: MovePathId` | Marks lexical scope exit of `%p`; triggers `AutoDrop` elaboration or `@linear` leak check (`E0304`). |
| **`storage.init`** | `%p: MovePathId` | Marks definite initialization of path `%p` (and its subtree) via assignment or `set` call. |
| **`storage.move`** | `%p: MovePathId, %kind: MoveKind` | Marks consumption of `%p` via `own` (`sink`) transfer; sets `EverMoved[%p] = 1`. |
| **`storage.free`** | `%p: MovePathId, %alloc: RegionId` | Marks explicit manual deallocation (`pool.free(own p)`, `arena.release()`, `unsafe free(ptr)`). |
| **`storage.drop`** | `%p: MovePathId` | Synthesized by `ElaborateDrops` for initialized `AutoDrop` containers at scope exit or overwrite. |
| **`access.let`** | `%p: MovePathId -> %loan: LoanId` | Begins an immutable MVS `let` projection (`&x` or read access) on `%p`. |
| **`access.inout`** | `%p: MovePathId -> %loan: LoanId` | Begins an exclusive mutable MVS `inout` projection (`&mut x`) on `%p`. |
| **`access.set`** | `%p: MovePathId -> %loan: LoanId` | Begins a definite out-initialization MVS `set` projection (`ref mut x`) on uninitialized `%p`. |
| **`access.end`** | `%loan: LoanId` | Terminates active projection `%loan` immediately after the **last dominating SSA use**. |
| **`bounds.check`** | `%idx: MirValueId, %len: MirValueId` | Marks slice/array indexing `a[idx]` for Pentagon (`Intv × Sub`) range verification. |

### 2.2 Pass 1 & Pass 2: `MovePath` Trie and `DenseBitSet` Typestate Dataflow Equations

#### 1. The `MovePath` Trie and Precomputed Bitmasks

To track field-level partial moves (`own x.left`), re-initializations (`x.left = .Some(own y)`), and disjoint sibling borrows (`swap(&mut r.pos, &mut r.dim)`) in $O(1)$ bitwise word operations, Pass 1 constructs a per-function **`MovePath` Trie** containing $M$ nodes ($p \in \{0, \dots, M-1\}$). Every root local variable and every statically projected field path (`x`, `x.left`, `x.right`) is assigned a dense `MovePathId(u32)`. Dynamic array/slice indices (`arr[i]`) collapse onto their parent array `MovePathId`, as individual elements of a dynamic slice cannot be moved out without `.swap_remove()` or `.take()` replacing the slot.

For each path $p \in \{0, \dots, M-1\}$, Pass 1 precomputes three immutable `DenseBitSet` masks (stored as contiguous `[]u64` slices of $\lceil M / 64 \rceil$ words in `BumpArena`):
$$\text{Subtree}(p) = \{ q \in [0, M) \mid p \sqsubseteq q \} \qquad \text{Ancestors}(p) = \{ q \in [0, M) \mid q \sqsubseteq p \} \qquad \text{StrictAnc}(p) = \text{Ancestors}(p) \setminus \{p\}$$
$$\text{Conflict}(p) = \text{Subtree}(p) \cup \text{Ancestors}(p)$$
Two access paths $p_1$ and $p_2$ are **statically disjoint** if and only if $p_1 \notin \text{Conflict}(p_2)$ (equivalently, $\text{Subtree}(p_1) \cap \text{Subtree}(p_2) = \emptyset$).

> **Visual – Bitset Typestate Evolution and Bounds-Check Elimination Efficacy:** **Subtree and StrictAncestor bitmasks** resolve partial struct moves in O(1) word operations, while Pentagon abstract interpretation validates 83% of array bounds statically.

#### 2. Monotone Forward Dataflow Equations for Initialization, Move, and Free Tracking

At every `MirLocation` $\ell = (\text{block}, \text{stmt\_idx})$, Pass 2 computes four bitvectors of length $M$ via a forward worklist fixpoint iteration over the CFG in reverse postorder (RPO):
-   **$\mathcal{I}(\ell) = \text{MaybeInit}(\ell) \in \{0,1\}^M$**: Path $p$ may be initialized on *some* path reaching $\ell$.
-   **$\mathcal{U}(\ell) = \text{MaybeUninit}(\ell) \in \{0,1\}^M$**: Path $p$ may be uninitialized, moved, or freed on *some* path reaching $\ell$.
-   **$\mathcal{M}(\ell) = \text{EverMoved}(\ell) \in \{0,1\}^M$**: Path $p$ was consumed by `storage.move` (`own`) and not subsequently re-initialized on *some* path reaching $\ell$.
-   **$\mathcal{F}(\ell) = \text{EverFreed}(\ell) \in \{0,1\}^M$**: Path $p$ was deallocated by `storage.free` (`pool.free`, `arena.release`, `unsafe free`) and not subsequently re-initialized on *some* path reaching $\ell$.

Because all four analyses are forward **May** analyses over the powerset lattice $(\mathcal{P}(\{0,\dots,M-1\}), \subseteq)$, the confluence (join $\sqcup$) operator at any basic block entry `^bb` with predecessor blocks $\text{Pred}(\text{bb})$ is bitwise OR (`|`) across each `u64` word:
$$\mathcal{I}_{\text{in}}(\text{bb}) = \bigcup_{q \in \text{Pred}(\text{bb})} \mathcal{I}_{\text{out}}(q), \quad \mathcal{U}_{\text{in}}(\text{bb}) = \bigcup_{q \in \text{Pred}(\text{bb})} \mathcal{U}_{\text{out}}(q), \quad \mathcal{M}_{\text{in}}(\text{bb}) = \bigcup_{q \in \text{Pred}(\text{bb})} \mathcal{M}_{\text{out}}(q), \quad \mathcal{F}_{\text{in}}(\text{bb}) = \bigcup_{q \in \text{Pred}(\text{bb})} \mathcal{F}_{\text{out}}(q)$$

Each ghost instruction updates the state tuple $(\mathcal{I}, \mathcal{U}, \mathcal{M}, \mathcal{F})$ according to the following transfer functions ($\text{out} = (\text{in} \setminus \text{Kill}) \cup \text{Gen}$):
-   **On `storage.live %p`** (Variable declared uninitialized, e.g., `var x: Pair;`):
    $$\mathcal{I}' = \mathcal{I} \setminus \text{Subtree}(p), \quad \mathcal{U}' = \mathcal{U} \cup \text{Subtree}(p), \quad \mathcal{M}' = \mathcal{M} \setminus \text{Subtree}(p), \quad \mathcal{F}' = \mathcal{F} \setminus \text{Subtree}(p)$$
-   **On `storage.init %p`** (Path $p$ assigned a value or initialized via `set` mode):
    $$\mathcal{I}' = \mathcal{I} \cup \text{Subtree}(p) \cup \{ a \in \text{StrictAnc}(p) \mid \forall c \in \text{Children}(a).\; c \in (\mathcal{I} \cup \text{Subtree}(p)) \}$$ $$\mathcal{U}' = \mathcal{U} \setminus \text{Subtree}(p) \setminus \{ a \in \text{StrictAnc}(p) \mid \forall c \in \text{Children}(a).\; c \notin (\mathcal{U} \setminus \text{Subtree}(p)) \}$$ $$\mathcal{M}' = \mathcal{M} \setminus \text{Subtree}(p), \qquad \mathcal{F}' = \mathcal{F} \setminus \text{Subtree}(p)$$
    Re-initializing a moved sub-field `x.a` automatically restores parent `x` to `DefInit` once all sibling fields `x.b` are also initialized.
-   **On `storage.move %p`** (Path $p$ consumed via `own` / `sink`):
    $$\text{Gen}_{\text{uninit}}(p) = \text{Subtree}(p) \cup \text{StrictAnc}(p)$$ $$\mathcal{I}' = \mathcal{I} \setminus \text{Gen}_{\text{uninit}}(p), \quad \mathcal{U}' = \mathcal{U} \cup \text{Gen}_{\text{uninit}}(p), \quad \mathcal{M}' = \mathcal{M} \cup \text{Subtree}(p)$$
-   **On `storage.free %p, %alloc`** (Explicit manual deallocation of `OwnPtr`, `Arena`, or raw pointer):
    $$\text{Gen}_{\text{uninit}}(p) = \text{Subtree}(p) \cup \text{StrictAnc}(p)$$ $$\mathcal{I}' = \mathcal{I} \setminus \text{Gen}_{\text{uninit}}(p), \quad \mathcal{U}' = \mathcal{U} \cup \text{Gen}_{\text{uninit}}(p), \quad \mathcal{F}' = \mathcal{F} \cup \text{Subtree}(p)$$

In a diamond CFG with a partial move (`p0 = x`, `p1 = x.a`, `p2 = x.b` where the `then` branch executes `own x.a` and the `else` branch does not), the exit of `then` yields $\mathcal{I}_{\text{then}} = \{2\}$, $\mathcal{U}_{\text{then}} = \{0, 1\}$, and $\mathcal{M}_{\text{then}} = \{1\}$, while the exit of `else` yields $\mathcal{I}_{\text{else}} = \{0, 1, 2\}$, $\mathcal{U}_{\text{else}} = \emptyset$, and $\mathcal{M}_{\text{else}} = \emptyset$. At the entry of `join`, bitwise OR produces $\mathcal{I}_{\text{join}} = \{0, 1, 2\}$, $\mathcal{U}_{\text{join}} = \{0, 1\}$, and $\text{DefInit}_{\text{join}} = \mathcal{I}_{\text{join}} \setminus \mathcal{U}_{\text{join}} = \{2\}$. When `x` reaches `storage.dead` at the end of `join`, `ElaborateDrops` sees that `p0` (`x`) is partially moved ($\mathcal{U}[0]=1 \land \mathcal{I}[2]=1$), recursively inspects children `p1` (`x.a`) and `p2` (`x.b`), emits an unconditional `storage.drop %x.b` at `join` (since $2 \in \text{DefInit}_{\text{join}}$), and emits `storage.drop %x.a` specifically on the outgoing edge of `else` (`^else -> ^join`) where $1 \in \text{DefInit}_{\text{else}}$ – preventing memory leaks and double-frees without runtime drop flags whenever branch edge splitting suffices.

#### 3. Law of Exclusivity Lattice (`access.let` / `access.inout` / `access.set`)

Simultaneously during Pass 2, the verifier maintains the active loan map $\mathcal{A}(\ell) : [0, M) \to (\text{let\_count}: \texttt{u16}, \text{inout\_active}: \texttt{bool})$ paired with two bitsets $\text{LetLoan}(\ell) \in \{0,1\}^M$ and $\text{InoutLoan}(\ell) \in \{0,1\}^M$. On `%loan = access.let %p`, the pass checks $\text{InoutLoan}(\ell) \cap \text{Conflict}(p) == \emptyset$; if non-empty, it emits **`E0305 (ExclusivityViolation)`**, and otherwise increments $\text{let\_count}[p]$ and sets bit $p$ in $\text{LetLoan}$. On `%loan = access.inout %p` (or `access.set %p`), it checks $(\text{InoutLoan}(\ell) \cup \text{LetLoan}(\ell)) \cap \text{Conflict}(p) == \emptyset$ and verifies that the root variable of $p$ was declared `var` (or `mut` / `&mut` / `ref mut`). If any bit in $\text{Conflict}(p)$ has an active loan, it emits **`E0305 (ExclusivityViolation)`**; otherwise it sets $\text{inout\_active}[p] = \text{true}$ and sets bit $p$ in $\text{InoutLoan}$. Finally, `access.end %loan` is inserted automatically by the `MIR` liveness pass immediately after the **last dominating SSA instruction** that reads or writes `%loan` (rather than waiting for lexical `}` brace exit), clearing the loan bit on $p$.

### 2.3 Pass 3: Interprocedural Escape & Region/Arena Aliasing Summary Inference

To allow functions to return borrowed views (`fn trim(s: str) -> str`, `fn find_user(arena: &Arena, id: u64) -> &User`) or allocate into arenas (`fn parse_req(arena: &mut Arena, buf: [u8]) -> HttpReq`) **without writing `<'a, 'b>` lifetime annotations** while catching dangling stack pointers or arena escapes at compile time, Pass 3 executes **Compositional Bottom-Up Region & Escape Summary Inference** over the call graph's Strongly Connected Components (SCCs), building on Tarjan's $O(V + E)$ SCC algorithm and compositional summary-based static analysis.

#### 1. Symbolic Region Taxonomy and Lexical Depth Ordering

Every memory-bearing value or projection in a function $f$ with $k$ parameters is tagged with a **64-bit `RegionMask` (`u64`)** representing a subset of symbolic regions:
-   **$\rho_0, \dots, \rho_{k-1}$ (Bit $0 \dots k-1$)**: The caller-provided storage region of parameter $i$ (whether passed by `&T`, `&mut T`, or containing an `Arena` / slice view).
-   **$\rho_{\text{ctx}}$ (Bit 60)**: The implicit `context.allocator` region passed to $f$.
-   **$\rho_{\text{static}}$ (Bit 61)**: Global static memory (`const` string literals and static tables; outlives all scopes).
-   **$\rho_{\text{heap}}$ (Bit 62)**: Unscoped owned heap / pool allocations transferred by `own` (`sink`) value (`OwnPtr[T]`, `Vec[T]` using default allocator).
-   **$\rho_{\text{local}}(f, d)$ (Bit 63 + Lexical Scope Depth $d \ge 1$)**: Stack-allocated variables (`let`/`var`) and scoped `Arena` instances created inside $f$ at lexical block nesting depth $d$.

Every active region in a function body has a strictly ordered **Lifetime Depth $\text{Depth}(\rho) \in \mathbb{N}$** (where smaller depth means *longer-lived*):
$$\text{Depth}(\rho_{\text{static}}) = 0 < \text{Depth}(\rho_i \text{ params}) = 1 < \text{Depth}(\rho_{\text{local}}(f, 1)) = 2 < \dots < \text{Depth}(\rho_{\text{local}}(f, d)) = d + 1$$

#### 2. The Interprocedural `FnRegionSummary` Schema

Using Tarjan's algorithm, `corex` partitions the module call graph into Strongly Connected Components (SCCs) in $O(V + E)$ linear time and processes SCCs **bottom-up** (callees before callers; mutual recursion within an SCC iterates over the finite 64-bit region lattice until fixed point). For each function $f$, Pass 3 computes and caches a compact **24-byte `FnRegionSummary`**:

```zig
/// Compact 24-byte Interprocedural Region & Escape Summary per function `f`.
/// Stored in InternPool / FunctionTable (`stage0/corex` and self-hosted `.cx`).
pub const FnRegionSummary = extern struct {
    /// Bitmask of input parameter regions {rho_0..rho_{k-1}, rho_ctx, rho_static}
    /// whose memory addresses/views may be aliased by the return value of `f`.
    ret_provenance_mask: u64,
    /// Bitmask of parameters whose addresses may escape to a global static or detached thread.
    global_escape_mask: u32,
    /// Bitmask of parameters that are @linear and consumed (`own` / `sink`) by `f`.
    consumed_param_mask: u32,
    /// Compact parameter-to-parameter flow summary:
    /// Bit `(src_param * 8 + dst_param)` is 1 iff a reference/allocation from `src_param`
    /// may be stored into mutable `dst_param` (`&mut T` or `&mut Arena`).
    param_flow_matrix: u64,
};
```

#### 3. Intra- and Inter-Procedural Region Verification Rules (`E0306`)

With `FnRegionSummary` computed automatically for every callee, Pass 3 enforces four region safety rules without requiring user annotations:
1.  **No Stack or Local Arena Return Escape (`E0306`)**: At every `ret %val` terminator in function $f$, the verifier checks $\text{RegionMask}(\%val) \cap \{ \rho_{\text{local}}(f, d) \mid d \ge 1 \} == \emptyset$. If non-empty – for example, returning a slice allocated from a local `var arena = Arena::with_capacity(...)` declared inside $f$ (as opposed to an `arena: &mut Arena` passed in by the caller as $\rho_0$) – the compiler emits **`E0306 (DanglingStackOrArenaEscape)`**.
2.  **No Inner-Arena to Outer-Container Store Escape (`E0306`)**: Whenever an assignment `*dst = src` or summarized call `callee(arg_0, ..., arg_k)` flows a reference or arena-backed container from source region $\rho_{\text{src}}$ into mutable destination $\rho_{\text{dst}}$ (via `param_flow_matrix`), the verifier checks that $\forall \rho_s \in \text{RegionMask}(\text{src}),\; \forall \rho_d \in \text{RegionMask}(\text{dst}): \text{Depth}(\rho_d) \ge \text{Depth}(\rho_s)$. A longer-lived outer variable or outer `Arena` ($\text{Depth} = 1$) can never store a pointer, slice, or view allocated inside a shorter-lived inner `Arena` or inner lexical block ($\text{Depth} = 3$). Violating $\text{Depth}(\rho_d) \ge \text{Depth}(\rho_s)$ triggers **`E0306 (DanglingArenaEscape)`**.
3.  **Automatic Call-Site Loan Extension for Returned Views**: When a caller invokes `let header_view = extract_header(&packet_buf);`, Pass 3 reads `extract_header`'s `ret_provenance_mask` (which has bit $0$ set, indicating the return value borrows from parameter $\rho_0$). The caller's `MIR` automatically attaches the `%loan = access.let %packet_buf` token to `%header_view`, keeping `packet_buf` locked against `&mut` mutation or `own` movement until the **last dominating SSA use** of `%header_view`.
4.  **Trait Object (`dyn Trait`) and Function Pointer Soundness**: When a call targets a dynamic `dyn Trait` method or `fn(...)` pointer where the concrete callee is unknown at compile time, an unannotated `fn(a: &T1, b: &T2) -> View` signature carries the conservative default summary $\text{ret\_provenance\_mask} = \{\rho_0, \rho_1\}$ (assuming the returned view may alias any reference-bearing input parameter) and $\text{param\_flow\_matrix} = 0$ (prohibiting cross-parameter stores unless an explicit `@flows_to(dst_param)` attribute is present).

### 2.4 Pass 4: Pentagon Abstract Interpretation (`Intv × Sub`) & Sparse ABCD Bounds Verification

To catch static buffer overflows at compile time (`E0307`) and eliminate redundant runtime bounds checks from hot loops without the compile-time cost of full Octagon ($\pm x \pm y \le c$) or Polyhedra domains, Pass 4 implements Logozzo and Fähndrich's **Pentagon Abstract Domain ($\text{Pntg} = \text{Intv} \times \text{Sub}$)** – which validated 83% of array bounds accesses across `.NET`'s `mscorlib.dll` in under 4 minutes in Microsoft Research's Clousot evaluation – combined with Bodík, Gupta, and Sarkar's **Extended SSA (e-SSA) Sparse Demand Graph (ABCD)**, which removed 45% of dynamic bounds check instructions on average in under 10 analysis steps per check.

#### 1. Formal Definition of the Pentagon Lattice ($\text{Pntg} = \text{Intv} \times \text{Sub}$)

An abstract state $p = \langle b, s \rangle \in \text{Pntg}$ over integer SSA values $V$ is the reduced Cartesian product of two domains:
-   **The Box / Interval Domain ($\text{Intv}$)**: Maps each SSA integer variable $x \in V$ to a closed 64-bit interval $b(x) = [\text{inf}(x), \text{sup}(x)]$ where $\text{inf}(x), \text{sup}(x) \in \mathbb{Z}_{64} \cup \{-\infty, +\infty\}$ (with $\bot_{\text{Intv}}$ when $\text{inf}(x) > \text{sup}(x)$):
    $$[l_1, u_1] \sqcup_{\text{Intv}} [l_2, u_2] = [\min(l_1, l_2), \max(u_1, u_2)], \qquad [l_1, u_1] \sqcap_{\text{Intv}} [l_2, u_2] = [\max(l_1, l_2), \min(u_1, u_2)]$$
-   **The Symbolic Strict Upper Bound Domain ($\text{Sub}$)**: Maps each variable $x \in V$ to a finite set of symbolic upper-bound variables $s(x) = \{ y_1, \dots, y_m \} \subseteq V$ (stored as a compact `u64` bitset over local integer SSA values), meaning that at this program point, $x < y_i$ holds on **all** execution paths:
    $$s_1 \sqcup_{\text{Sub}} s_2 = \lambda x.\; s_1(x) \cap s_2(x), \qquad s_1 \sqcap_{\text{Sub}} s_2 = \lambda x.\; s_1(x) \cup s_2(x)$$
    For $x < y$ to hold after a control-flow join $\sqcup$, $y$ must be a strict upper bound of $x$ in **both** incoming branches, which corresponds to set intersection $\cap$.

Whenever a branch guard (`if idx < slice.len`), loop condition (`for i in 0..slice.len`), or arithmetic instruction updates $\langle b, s \rangle$, Pass 4 exchanges information between $\text{Intv}$ and $\text{Sub}$ via the Pentagon closure operator $\text{Close}(\langle b, s \rangle) = \langle b^*, s^* \rangle$:
$$b^*(x) = b(x) \sqcap_{\text{Intv}} \bigcap_{y \in s(x)} [-\infty, \text{sup}(b(y)) - 1] \sqcap_{\text{Intv}} \bigcap_{\{z \mid x \in s(z)\}} [\text{inf}(b(z)) + 1, +\infty]$$
$$s^*(x) = s(x) \cup \bigcup_{z \in s(x)} s(z) \cup \{ y \in V \setminus \{x\} \mid \text{sup}(b^*(x)) < \text{inf}(b^*(y)) \}$$

#### 2. Key Transfer Functions and Widening ($\nabla$) for Zero-Overhead Slice Indexing

For any slice `s: [T]` or `Vec[T]`, `s.len()` initializes with $b(\text{len}) = [0, \text{USIZE\_MAX}]$, while for a fixed array `a: [T; N]`, $b(\text{len}) = [N, N]$. On an unsigned remainder instruction `%r = rem_u %x, %d` (such as `RingBuffer`'s `(self.head + idx) % self.buf.len` in `DR-02`), Logozzo and Fähndrich's Pentagon transfer rule specifies that if $\text{inf}(b(d)) > 0$, then $b'(r) = [0, \text{sup}(b(d)) - 1]$ and $s'(r) = \{ d \} \cup s(d)$. This single rule statically proves that `(self.head + idx) % self.buf.len` is non-negative and strictly less than `self.buf.len` (`self.buf.len` $\in s'(r)$), eliminating the bounds check on `self.buf[(self.head + idx) % self.buf.len]` in a single table lookup.

Similarly, at a range loop header block `^loop(%i: usize)` (`for i in 0..n` or `while i < n`) with entry value $b_0(i) = [0, 0]$ and back-edge increment `%i_next = add %i, 1`, applying standard interval widening $[l_1, u_1] \nabla [l_2, u_2] = [l_2 < l_1 ? -\infty : l_1,\; u_2 > u_1 ? +\infty : u_1]$ yields $b(i) = [0, +\infty]$ at the loop header. Immediately inside the loop body `^body` (dominated by the guard `cond_br (%i < %n), ^body, ^exit`), the true-branch filter adds $n \in s(i)$ and refines $b^*(i) = [0, \text{sup}(b(n)) - 1]$.

At every `bounds.check %idx, %len` instruction, Pass 4 makes a three-way decision:
1.  **Statically Validated Safe**: If $\text{inf}(b^*(\text{idx})) \ge 0$ **and** ($\text{len} \in s^*(\text{idx})$ **or** $\text{sup}(b^*(\text{idx})) < \text{inf}(b^*(\text{len}))$), the access cannot overflow or underflow on any execution path, and `bounds.check` is **erased completely**.
2.  **Statically Proven Out-of-Bounds (`E0307`)**: If $\text{sup}(b^*(\text{idx})) < 0$ **or** $\text{inf}(b^*(\text{idx})) \ge \text{sup}(b^*(\text{len}))$ (for example, indexing `arr[10]` on `arr: [u8; 8]`, or an off-by-one `slice[slice.len()]` where $b^*(\text{idx}) = [\text{len}, \text{len}]$), the compiler halts with error **`E0307 (StaticBufferOverflow)`**.
3.  **Dynamically Indeterminate**: If neither condition holds, the compiler lowers `bounds.check` to a 2-instruction hardware branch (`cmp %idx, %len` + `jae ^panic_oob`) and, when compiled with `--sast-strict`, emits warning **`W0308 (UnprovenBoundsAccess)`** showing the inferred interval $b^*(\text{idx})$.

| :--- | :--- | :--- | :--- |

    // let read_alias = counter;            // <-- ERROR E0305: Cannot read `counter` while mutably borrowed by `inc_closure`
    inc_closure();                          // Last SSA use of `inc_closure` -> `access.end` runs immediately after!

    // [E0306 Dangling Arena Escape]:
    var outer_slice: [u8] = [];

        var inner_arena = Arena::with_capacity(4096);

### 2.6 Implementation Data Structures in `stage0/corex` (`mir_sast.zig` -> `mir_sast.cx`)

To ensure 1-to-1 mechanical translation from the Zig Stage-0 compiler (`DR-01`) into self-hosted `.cx`, all four SAST passes allocate their worklists, `MovePath` tries, `DenseBitSet` matrices, and Pentagon abstract states inside the per-function `BumpArena` checkpoint (`const cp = arena.checkpoint(); defer arena.restore(cp);` from `DR-01`), reclaiming verification scratch memory in $O(1)$ time as soon as each function's `MIR` is verified. For a function with $M \le 64$ move paths and $B \le 32$ basic blocks, all four `DenseBitSet` typestate vectors ($\mathcal{I}, \mathcal{U}, \mathcal{M}, \mathcal{F}$) fit into **four single 64-bit CPU registers (`u64`) per basic block**, allowing Passes 1 through 4 to execute in a single lightweight pass per function while providing compile-time protection against Use-After-Free, Double-Free, Uninitialized Reads, Memory Leaks, Aliasing Exclusivity Violations, Dangling Arena Escapes, and Buffer Overflows.
