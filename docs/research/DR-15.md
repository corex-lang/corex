# Stage-2 Batteries-Included Standard Library (`std`), TUI/CLI Engine & Unified WebAssembly/Native App Architecture in CoreX (.cx)

CoreX (`.cx`) implements a **Two-Stage Standard Library Architecture** that pairs a minimal, freestanding compiler-bootstrap kernel (**Stage 1 `core`**) with a modular, 100% self-hosted **Stage-2 Standard Library (`std`)** spanning 15 zero-GC packages: `std::mem`, `std::col`, `std::str`, `std::io`, `std::fs`, `std::cli`, `std::tui`, `std::async`, `std::net`, `std::http`, `std::serde`, `std::crypto`, `std::ui`, `std::test`, and `std::bench`. By enforcing a strict **5-Tier Acyclic Dependency Directed Acyclic Graph (DAG)**, banning module-level runtime static constructors (`init()`), and coupling `DR-05`'s **Signature Firewall** with function-and-data-section dead-code elimination (DCE) and Pointer-Shape Identical Code Folding (ICF), importing any subset of `std` incurs **zero dead-code bloat and zero cold-start initialization overhead**. In developer comparisons, minimal zero-runtime `wasm32` binaries compile down to **1.5–10 KB** (avoiding the 2–10 MB+ runtime and garbage-collector payloads typical of standard Go WebAssembly builds) while native CLI tools start with near-zero cold-start delay. Across all Stage-2 containers (`Vec[T]`, `#soa Vec[T]`, `Map[K, V]`, `SlotMap[K, V]`, and `String`), memory management is unified under `DR-06`'s `AutoDrop` ownership tier via a 1-bit pointer-tagged **`AllocatorHandle`**: containers default transparently to the implicit thread/task `context.allocator` (`DR-02`) for effortless everyday coding, while accepting explicit `&mut Arena` or `&mut BumpArena` overrides that statically elide per-element destructor loops when `T: TrivialDrop`.

For terminal and command-line engineering, **`std::cli`** and **`std::tui`** replace macro-heavy parsers and flickering terminal redraws with compile-time reflection and synchronized frame presentation. Driven by `@cli_command`, `@arg`, and `@flag` attribute schemas (`@attribute_schema`), `std::cli` validates flag collisions inside the `MirVm` compile-time virtual machine (`DR-05`), slices OS `argv` spans in place with zero heap allocations, and generates structured ANSI help and diagnostic output using a **strictly monochrome Unicode geometric and box-drawing glyph vocabulary** (`╭`, `│`, `╰`, `▸`, `✓`, `✗`, `⚠`, `─`) with zero colored emojis. Building on this terminal foundation, `std::tui` implements an immediate-mode, double-buffered **16-byte `Cell` grid** (4 cells per 64-byte CPU cache line), a cached Cassowary/Flexbox constraint solver (which in `no_std` benchmarks scales layout refresh rates from ~10 FPS to **300–500 FPS**), progressive-enhancement **Kitty keyboard protocol** parsing (`CSI > 3 u`), and **DEC Private Mode 2026 (`ESC[?2026h` / `ESC[?2026l`) synchronized output** to guarantee tear-free 120 FPS rendering.

For network backends and cross-platform graphical applications, **`std::http`**, **`std::serde`**, and **`std::ui`** unify high-throughput server I/O with a zero-JavaScript-framework application engine. `std::http` combines `DR-08`'s thread-per-core completion reactor (`io_uring` / `IOCP` / `kqueue` / `wasm32` – which in February 2026 engineering benchmarks delivered **5.7x higher message throughput** and **81%–92% lower P9999 tail latency** than multi-threaded work-stealing runtimes) with `DR-02`'s unboxed 4-byte **`Span16` (`{ off: u16, len: u16 }`)** HTTP parser (which in `httpz` synthetic benchmarks achieved **154 ns parse latency** and **6.5 million req/sec** with zero minor-heap allocations), compile-time `@route` radix-trie dispatch, HPACK static/dynamic header compression, and SIMD-accelerated RFC 6455 WebSocket masking. Paired with `std::serde`'s two-stage **`simdjson` 64-bit contiguous tape** (reaching up to **2.2 GB/s** parsing throughput on `twitter.json`) and two-tier `comptime for` struct specialization, web handlers process requests entirely inside per-request 64 KiB `BumpArena` slabs. Finally, **`std::ui`** compiles a single declarative `.cx` component tree (`@component`, `@state`, `Signal[T]`, `Computed[T]`, and trailing view blocks `Card(padding: 16) { ... }`) backed by a central **`SlotMap[WidgetId, WidgetNode]`** and **`IdPath` + `Adapt` lens** `&mut AppState` event router to two interchangeable targets: (1) a surgical binary DOM/Canvas2D/WebGPU command buffer over a **`< 3 KB` `wasm32` host bridge** that decodes strings once per batch via a single `TextDecoder` call, and (2) hardware-accelerated native desktop windows via Metal, Vulkan, and Direct3D 12.

## 1. Deliverable 1: Modular, Tree-Shakeable `std` Package Hierarchy & Canonical `.cx` API Signatures

### 1.1 Stage-1 `core` vs. Stage-2 `std` Boundary and Zero-Dead-Code Guarantee

To ensure that importing a single standard library module never pulls in unused subsystems (such as linking HTTP or cryptography tables into a compact CLI utility) and never executes hidden pre-`main` static constructors, CoreX enforces a strict architectural boundary between **Stage 1 (`core`)** and **Stage 2 (`std`)**.

**Stage-1 Bootstrap Kernel (`core::*`)** is compiled directly into the bootstrap compiler (`stage0/corex`) with zero OS or heap dependencies. `core` defines the 19 primitive types (`i8`..`i128`, `u8`..`u128`, `isize`, `usize`, `f32`, `f64`, `bool`, `char`, `str`, `unit`, `never`), the 11 built-in Constrained Type Groups (`Signed`, `Unsigned`, `Integer`, `Float`, `Number`, `Numeric`, `Comparable`, `Equatable`, `Bytes`, `Scalar`, `Copy`), `@lang("option")` `Option[T]` (`T?`) and `@lang("result")` `Result[T, E]`, the implicit `Context` ABI register layout (`context.allocator`, `context.temp_allocator`, `context.logger`, `context.diagnostics`, `context.cancel_token`), SIMD vector intrinsics (`Simd[T, const N: usize]`), atomic operations, and thin `@extern` OS syscall/WASI bindings.

**Stage-2 Batteries-Included Standard Library (`std::*`)** is written **100% in safe, idiomatic CoreX (`.cx`)** (with localized `unsafe { ... }` blocks strictly verified by `DR-06`'s `MIR` SAST abstract interpreter) and organized into a **5-Tier Acyclic Dependency DAG**. Three compiler mechanisms guarantee zero cold-start overhead and complete tree-shakeability across all 15 modules:

1.  **Absolute Ban on Runtime Module Initializers:** Unlike C++ (`__attribute__((constructor))`), Go (`func init()`), or Rust (`ctor`), CoreX forbids runtime code execution prior to `fn main()`. All lookup tables – such as `std::str` Unicode width tables, `std::http` HPACK static tables, `std::cli` flag schemas, and `std::crypto` S-boxes – are evaluated inside `DR-05`'s deterministic **`MirVm` at compile time** (`comptime`) and frozen directly into the binary's read-only `.rodata` segment. Process startup executes zero dynamic allocations before entering `main()`.
2.  **Reachability-Driven Monomorphization & Per-Symbol Section Splitting:** During Phase 3 (`MIR` lowering and codegen), `corex` constructs a symbol reachability graph rooted exclusively at `main()` (or exported `@wasm_export` / `@extern` entrypoints). Unreferenced functions, struct methods, and `.rodata` tables inside an imported module (`use std::http;`) are never lowered past Phase 2 (`item_signature` firewall). Every emitted machine function and `.rodata` constant is placed in its own linker section (`-ffunction-sections -fdata-sections`) paired with linker garbage collection (`--gc-sections` on ELF/Wasm, `-dead_strip` on Mach-O, `/OPT:REF` on COFF).
3.  **Pointer-Shape Identical Code Folding (ICF):** Following `DR-02` and `DR-04`, when generic containers (`Vec[T]`, `SlotMap[K, V]`, `Map[K, V]`) are instantiated across distinct nominal types that share identical byte size, alignment, and trivial move/drop semantics without invoking type-specific trait methods, the `MIR` monomorphizer folds their machine bodies into a single canonical routine – preventing template bloat in both native and `wasm32` builds.

### 1.2 Dual-Mode Allocator Integration in `std` Containers (`context.allocator` vs. `&mut Arena`)

A central requirement of Objective 1 is specifying how CoreX's `AutoDrop` containers (`Vec[T]`, `#soa Vec[T]`, `Map[K, V]`, `SlotMap[K, V]`, and `String`) integrate `DR-02`'s implicit **`context.allocator`** with explicit **`&mut Arena` / `&mut BumpArena`** overrides while maintaining a compact 24-byte container header and zero-cost `MIR` drop elision.

In 64-bit and 32-bit architectures, every `Arena`, `BumpArena`, and general-purpose `Allocator` instance is aligned to at least 8 bytes (and typically 16 or 64 bytes per `DR-01` and `DR-08`), leaving the least-significant 3 bits (`bits[2:0]`) of its address permanently zero. CoreX exploits this alignment niche via a single-word **`AllocatorHandle`** (8 bytes on 64-bit, 4 bytes on `wasm32`) stored as the third word of every dynamic container:

$$\text{AllocatorHandle} = (\text{ptr\_bits} \ \& \ \sim 0\text{x7}) \mid \text{AllocTag}, \quad \text{where } \text{AllocTag} \in \{0 = \texttt{GeneralAllocator},\; 1 = \texttt{BumpArenaNoFree},\; 2 = \texttt{StaticRoData}\}$$

When a container is constructed via the **Default Implicit `context.allocator` Path** (`Vec[T]::new()`, `Vec[T]::with_capacity(cap)`, `Map[K, V]::new()`), it reads `context.allocator` from the implicit `Context` register (`DR-02`). If the caller has not overridden `context.allocator`, it points to the thread-local general allocator (`AllocTag = 0`). If the caller entered a lexical `mem::with_arena(&mut arena) { ... }` scope – such as an HTTP worker binding a 64 KiB `BumpArena` to `context.allocator` for the duration of a request (`DR-02`) – `context.allocator` carries `AllocTag = 1` (`BumpArenaNoFree`).

Conversely, when a function uses the **Explicit `&mut Arena` Override Path** (`Vec[T]::in_arena(&mut arena, cap)`, `Map[K, V]::in_arena(&mut arena, cap)`), it allocates inside a specific arena distinct from `context.allocator` (for instance, building a response array in `caller_arena: &mut Arena` while using a local `scratch: Arena` for temporary parsing, as in `DR-06` §2.5). Calling `Vec[T]::in_arena(&mut arena, cap)` encodes `(&mut arena as usize) | 0x1` (`AllocTag = 1`) directly into the container's `AllocatorHandle`.

This tagged representation enables both **Compile-Time Region Escape Safety (`DR-06` Pass 3)** and **`O(1)` Bulk Drop Elision (`DR-06` Pass 2)**. When `Vec[T]::in_arena(&mut arena, cap)` is called, `FnRegionSummary` (`DR-06` Pass 3) records `param_flow_matrix` bit `(0 -> ret)`, binding the returned `Vec[T]`'s symbolic region mask to `rho_arena`. If the user attempts to return that `Vec[T]` after `arena` goes out of scope, `MIR` Pass 3 halts compilation with **`E0306 (DanglingStackOrArenaEscape)`**. At scope exit, when `ElaborateDrops` lowers `AutoDrop::drop(&mut self)`, if `T` is a `TrivialDrop` type (primitives, structs of primitives/spans/keys) and the container was constructed via `in_arena` (statically known `AllocTag == 1`), the `MIR` optimizer deletes the `storage.drop` call at compile time – reducing container cleanup to 0 instructions because `defer arena.release();` or `defer arena.restore(cp);` reclaims the backing slab in bulk. When `AllocTag` is known only dynamically via `context.allocator`, `Vec::drop` checks `(self.alloc.raw_tagged_ptr & 1) == 0` in a single register bit-test (`test rdx, 1; jnz .Lskip_free`) before calling the allocator's `dealloc` function.

#### Module 2: `std::col` (Contiguous Vectors, SwissTable Maps & Generational `SlotMap`)

## 2. Deliverable 2: Technical Blueprint for `std::cli` and `std::tui`

### 2.1 `std::cli` Zero-Allocation `comptime` Argument Parser & Monochrome Unicode Design

#### 1. Compile-Time Schema Synthesis & DFA Flag Dispatch

When a developer annotates a configuration struct with `@cli_command` and its fields with `@arg` or `@flag` (as in `DR-03` Showcase 1's `ScanOptions`), `std::cli::parse_args[T](&mut arena)` executes a two-phase compile-time and runtime pipeline powered by `DR-05`'s `std::meta` reflection mirror:

1.  **`comptime` Validation in `MirVm`:** Before emitting a single machine instruction, `validate_cli_schema[T]()` iterates over `@type_info[T]().as_struct().fields` inside `MirVm` and verifies three static invariants via `@compile_assert`: (a) no two fields share the same `short` character (`-p`) or `long` string (`--pattern`); (b) `-h` / `--help` and `-V` / `--version` are not shadowed unless explicitly marked override; and (c) every `@flag` field has type `bool` or an integer counter (`u8`..`usize`), while every `@arg` field has a supported `FromCliStr` parser (`str`, `Integer`, `Float`, `Path`, `SocketAddr`, or an `enum` of unit variants).
2.  **Zero-Allocation In-Place `argv` Slicing:** At runtime, `std::env::raw_args_slice(arena)` reads the OS `argc`/`argv` vector (on Unix, contiguous null-terminated strings already resident in the top of the process stack; on Windows, converted once into `arena` from `GetCommandLineW`). Every `str` field in `ScanOptions` (such as `pub pattern: str` and `pub file_path: str`) borrows its UTF-8 slice **directly from the OS `argv` memory buffer (`rho_static`) or the passed `arena`** – performing **zero `malloc` calls and zero string copies**.
3.  **Combined Short-Flag Clustering, `=`, and `--` Terminator:** The state machine handles POSIX short-flag clusters (`-ivf file.txt` unrolls `-i`, `-v`, and `-f` with value `file.txt`), inline equals assignment (`--max-matches=500` or `-m=500`), environment variable fallbacks (`@arg(env = "CX_PATTERN")`), subcommand sum-type dispatch (`@cli_command pub enum SubCmd { Build(BuildOpts), Test(TestOpts) }`), and the `--` positional argument separator. If an unknown flag is passed (`--igore-case`), `std::cli` computes a stack-allocated Levenshtein edit distance (≤2 edits) against the `comptime` flag table and suggests `"did you mean '--ignore-case'?"`.

#### 2. Strict Monochrome Unicode Glyph Vocabulary & ANSI Help Generator (Zero Colored Emojis)

Colored emojis (`U+1F680`, `U+2705`, `U+274C`, `U+26A0 U+FE0F`) introduce severe rendering flaws in terminal tools: they exhibit inconsistent 1-column vs. 2-column cell widths across terminal emulators (corrupting table borders), clash with user color themes, and fail on minimal Linux virtual consoles or serial teletypes. ### 2.2 `std::tui` Architecture: 16-Byte `Cell` Grid, Cassowary/Flexbox Solver & `DECSET 2026`

> **Visual – 16-Byte Cache-Aligned Cells and DECSET 2026 Synchronization Power 120 FPS Tear-Free TUIs:** **Top:** Each *std::tui::Cell* occupies exactly 16 bytes with an 8-byte inline UTF-8 grapheme buffer, fitting 4 cells per 64-byte L1d cache line with zero heap allocations. **Middle:** The presenter diffs the front and back buffers using 64-bit word comparisons and brackets the emitted ANSI run inside *DECSET 2026* (*ESC[?2026h* to *ESC[?2026l]*) so the terminal rasterizer commits the frame atomically. **Bottom:** Caching Cassowary/Flexbox layout splits increases embedded/constrained refresh rates from ~10 FPS to 300–500 FPS.

#### 1. Double-Buffered 16-Byte `Cell` Grid and Grapheme Cluster Storage

In many TUI libraries, each terminal cell stores a heap-capable string (`String` or `CompactString`, 24 bytes plus potential heap indirection), inflating a 240×80 terminal buffer (19,200 cells) across two buffers and scattering multi-codepoint graphemes across the heap.

CoreX's `std::tui::Cell` is an exact **16-byte `Copy` struct (`@repr(C)`)**, packing **4 complete cells into a single 64-byte CPU L1d cache line**. Through its **Inline 8-Byte Grapheme Storage (`glyph_utf8: [u8; 8]` + `flags.glyph_len: u4`)**, every ASCII character (1 byte), box-drawing/geometric glyph (`╭`, `│`, `▸`, `✓`, `█`, `⠋` – 3 bytes in UTF-8), and 2-column CJK ideograph (3–4 bytes in UTF-8) fits **100% inline** inside `glyph_utf8[0..8]` when `flags.glyph_len <= 8`. In the rare case where a cell contains a combining grapheme cluster exceeding 8 UTF-8 bytes (`flags.glyph_len == 15`), `glyph_utf8` stores a `(u32 offset, u32 len)` slice into a per-frame `BumpArena` overflow buffer.

For **Variable-Width CJK & Tab Handling (`wide_spacer`)**, when a glyph has `display_width(g) == 2` (East Asian Wide), `Buffer::set_str` writes the glyph into cell `(x, y)` and marks cell `(x + 1, y)` with `flags.wide_spacer = true`. If a subsequent widget overwrites `(x + 1, y)` with a 1-column character, the buffer automatically resets `(x, y)` to a space (`' '`) to prevent wide-character border bleeding. Finally, because each `Cell` is a flat 16-byte value with zero padding, **SIMD 64-Bit/128-Bit Diffing (`Buffer::diff`)** compares `back_buf.cells[i]` against `front_buf.cells[i]` (unless `flags.always_update` is set, matching Ratatui's `CellDiffOption::AlwaysUpdate`) via two 64-bit integer comparisons (`u64`) or a single 128-bit `Simd[u64, 2]` equality check across contiguous cache lines.

#### 2. Hybrid Cassowary / One-Pass Flexbox Layout Solver with LRU Layout Cache

Re-solving linear layout constraints from scratch on every frame can consume the majority of CPU time on constrained hardware, capping frame rates at ~10 FPS, whereas enabling a compact layout cache increases refresh rates to **300–500 FPS**.

`std::tui::Layout` combines a **Deterministic Single-Pass Priority Solver** for standard constraints (`Length`, `Percentage`, `Ratio`, `Min`, `Max`, `Fill`) with a **64-Entry `Wyhash(0)` LRU Layout Cache** stored inside `Terminal`:
1.  **O(1) Cache Lookup:** Given an input `area: Rect` and a slice `constraints: &[Constraint]` with `gap: u16`, the solver hashes `(area, direction, gap, constraints)` into a 64-bit key. On a cache hit (all steady-state frames between window resizes), `Layout::split` returns the cached `[Rect]` slice immediately without re-running the solver.
2.  **Fixed and Clamped Constraint Pass:** On a cache miss (first frame or terminal resize), the solver deducts total inter-cell gaps $G = \text{gap} \times \max(0, N - 1)$ from available span $L = \text{area.span} - G$ and allocates `Length(k)`, `Percentage(p)` ($\lfloor L \cdot p / 100 \rfloor$), and `Ratio(a, b)` ($\lfloor L \cdot a / b \rfloor$), clamping against `Min(m)` and `Max(M)`.
3.  **Proportional `Fill(w)` Distribution with Remainder Rounding:** The solver distributes remaining space $R = L - \sum_{\text{fixed}} s_i$ across all `Fill(w_i)` and unbounded `Min(m_i)` slots proportionally to weight $w_i$:
    $$s_i = \left\lfloor \frac{R \cdot w_i}{\sum_j w_j} \right\rfloor + \mathbb{I}\!\left(\text{rem}_i > \text{threshold}\right)$$
    distributing integer division remainders one column at a time so $\sum_{i=0}^{N-1} s_i + G == \text{area.span}$ with zero lost trailing columns.

#### 3. Tear-Free 120 FPS Synchronized Output (`DECSET 2026`) & Resize Ordering Invariant

When a terminal application emits cursor moves, clears, and SGR color changes over a PTY or SSH socket, the terminal emulator's render timer (60 Hz or 120 Hz) can fire mid-update, painting a partially drawn or blank screen ("tearing/flickering"). CoreX's `std::tui::Terminal` eliminates tearing by implementing **DEC Private Mode 2026 (Synchronized Output)** through four strict protocol rules:

1.  **Startup Feature Probe (`DECRQM 2026` Once on Init):** Querying `ESC[?2026$p` on *every* redraw spams warning messages on minimalist terminals like `st`. `std::tui::Terminal::enter_raw_alternate()` queries **`\x1b[?2026$p` (`DECRQM`) exactly once at initialization** (and checks for `tmux 3.7+` / `xterm.js` / `kitty` / `wezterm` / `alacritty` / `ghostty` support).
2.  **Atomic Frame Bracket (`\x1b[?2026h` … `\x1b[?2026l`):** On every `terminal.draw(...)` call, the presenter stages all output into a contiguous thread-local `ByteWriter` buffer, prepending the 8-byte Begin Synchronized Update sequence **`\x1b[?2026h`** (`1B 5B 3F 32 30 32 36 68`) and hiding the cursor (`\x1b[?25l` if cursor is hidden). It then iterates over diffed `(x, y, &Cell)` runs: if the next changed cell is at `(last_x + 1, last_y)`, the presenter omits the `CSI row;col H` cursor-move sequence, tracks active `(fg, bg, flags)` state so SGR codes (`\x1b[...m`) are emitted *only* on style transitions, and avoids the `Bold`/`Dim` double-emission bug when resetting intensity (`\x1b[22m`). Finally, it appends the 8-byte End Synchronized Update sequence **`\x1b[?2026l`** (`1B 5B 3F 32 30 32 36 6C`) and flushes the entire frame in a **single OS `write` syscall** (preserving the single-writer atomicity invariant).
3.  **Preventing the Resize Blank-Flash Bug:** Emitting a full screen clear (`\x1b[2J\x1b[3J\x1b[H`) *outside* the `DECSET 2026` bracket during a terminal height/width resize causes terminals to flash a blank screen before the next synchronized repaint arrives. In `std::tui`, whenever a resize event occurs, the full-clear and reflow sequences are emitted **strictly inside the next frame's `\x1b[?2026h` … `\x1b[?2026l` bracket** immediately prior to the repainted cells.
4.  **Progressive Kitty Keyboard (`CSI > 3 u`) & SGR-Pixel Mouse Input:** Upon entering raw mode, `Terminal` enables SGR 1006 mouse tracking (`\x1b[?1000;1002;1006h`), bracketed paste (`\x1b[?2004h`), and requests **Kitty Keyboard Protocol progressive enhancement flags `3` (`1 = DisambiguateEscapeCodes | 2 = ReportEventTypes`)** via `\x1b[>3u` (restored via `\x1b[<u` in `defer term.restore_and_close()`). This allows `std::tui` to distinguish a standalone `Esc` key press from an `Alt+Key` sequence without waiting for an escape timeout.

```rust
// File: src/bin/cx_top.cx
mod cx_top;

use std::cli::{self, CliError};
use std::tui::{Terminal, Frame, Layout, Constraint, Rect, Buffer, Color, StyleFlags, TuiEvent};
use std::tui::widgets::{Block, Table, Sparkline, Gauge, Paragraph};

use std::mem::Arena;
use std::io::{Stdout, IoError};

@cli_command(name = "cx-top", version = "1.0.0", about = "Zero-GC 120 FPS system telemetry monitor")
pub struct MonitorOpts {
    @arg(short = 'i', long = "interval-ms", help = "Refresh interval in milliseconds")
    pub interval_ms: u64 = 8, // 8 ms = ~120 FPS
    @arg(short = 'f', long = "filter", help = "Filter process names by substring")
    pub filter: str = "",
    @flag(short = 'm', long = "monochrome", help = "Force strict 1-bit monochrome high-contrast mode")
    pub monochrome: bool = false,
}

pub fn render_dashboard(frame: &mut Frame, opts: &MonitorOpts, cpu_history: &[u64], tick: u64) {
    let chunks = Layout::vertical(&[
        .Length(3),       // Top header bar
        .Percentage(50),  // Middle Braille sparkline + 1/8th-block gauges
        .Fill(1),         // Bottom process table
    ]).split(frame.buf.area);

    // [1] Monochrome Unicode Rounded Header (`╭─ … ─╮`)
    Block::rounded(title: " ▸ cx-top v1.0.0 │ tick: {tick} │ filter: '{opts.filter}' ")
        .render(chunks[0], frame.buf);

    // [2] Split middle section into CPU Sparkline and Memory 1/8th-cell Gauge
    let mid_chunks = Layout::horizontal(&[.Percentage(65), .Fill(1)]).split(chunks[1]);
    Sparkline::new(title: " ╭─ CPU Load (%) ", data: cpu_history)
        .render(mid_chunks[0], frame.buf);
    Gauge::eighths(title: " ╭─ Memory Used ", ratio: 0.734, label: "23.5 / 32.0 GiB ✓")
        .render(mid_chunks[1], frame.buf);

    // [3] Process Table with `─`, `│`, `├`, `┤` box-drawing borders
    Table::new(
        headers: &["PID", "PROCESS", "CPU%", "MEM", "STATUS"],
        widths: &[.Length(8), .Fill(1), .Length(8), .Length(10), .Length(10)],
    ).render(chunks[2], frame.buf);
}

pub fn main() -> i32 {
    var arena = Arena::with_capacity(262_144);
    defer arena.release();

    let opts = cli::parse_args[MonitorOpts](&mut arena) catch |err| {
        var out = Stdout::locked();
        let _ = cli::write_diagnostic(&mut out, &err) catch {};
        return match err { .HelpRequested(_) | .VersionRequested(_) => 0, _ => 2 };
    };

    var term = Terminal::enter_raw_alternate() catch |err| {
        std::io::stderr().write_fmt("✗ terminal init failed: {err}\n") catch {};
        return 1;
    };
    defer { let _ = term.restore_and_close() catch {}; };

    let history: [u64; 8] = [42, 48, 51, 63, 59, 44, 38, 45];
    var tick: u64 = 0;

    loop {
        tick +%= 1;
        // Wrapped automatically in DECSET 2026 (`\x1b[?2026h` … `\x1b[?2026l`)
        term.draw(|frame| {
            render_dashboard(frame, &opts, &history, tick);

        if let .Ok(.Some(ev)) = term.poll_event(Duration::from_millis(opts.interval_ms)) {
            if let .Key(k) = ev {
                if k.is_char('q') or k.is_ctrl('c') {
                    break;
                }
            }
        }
    }
    0
}
```

## 3. Deliverable 3: Technical Blueprint for `std::http` / `std::serde` & the Unified `std::ui` (`wasm32` + Native) Engine

### 3.1 `std::http` & `std::serde` High-Throughput Zero-Copy Architecture

> **Visual – Unboxed 32-Bit Spans and 64-Bit Contiguous JSON Tapes Eliminate Per-Request Heap Churn:** **Top:** Replacing 4-word boxed slices with unboxed 4-byte *Span16* offsets (*off: u16, len: u16*) cuts 35-byte HTTP request parsing latency from 300+ ns to 154 ns (and 439-byte requests from 2,000+ ns to 1,150 ns), more than doubling throughput from 3.0M to 6.5M req/sec with zero heap allocations. **Middle:** *std::serde*'s two-stage SIMD parser writes a contiguous 64-bit tape where opening braces store the exact tape index of their matching closing brace for *O(1)* subtree skipping. **Bottom:** Vectorized 64-byte block classification reaches 2.2 GB/s on *twitter.json*.

#### 1. Unboxed `Span16` HTTP/1.1 Parser, HTTP/2 HPACK & SIMD WebSockets

In `std::http`, every worker thread runs a share-nothing `DR-08` completion reactor (`io_uring` with `IORING_SETUP_SINGLE_ISSUER | IORING_SETUP_DEFER_TASKRUN` and multishot `IORING_REGISTER_PBUF_RING`, Windows `IOCP`, or macOS `kqueue`). When a kernel `ProvidedBuf` (up to 64 KiB) arrives on a socket, `std::http` processes the stream through four specialized subsystems:

First, the **HTTP/1.1 Unboxed `Span16` Vectorized Scanner** avoids allocating heap `String`s or 16-byte pointer slices for headers. It scans 32 or 64 bytes at a time using `Simd[u8, 32]` to locate `\r\n` and `:` delimiters and populates an inline array of `HeaderSpan = { name: Span16, value: Span16 }` (8 bytes per header) inside `Request`. As shown in Anil Madhavapeddy's February 2026 synthetic `Core_bench` evaluation of `httpz` (`DR-02`), indexing into a `< 64 KiB` request buffer via unboxed 4-byte `Span16` (`{ off: u16, len: u16 }`) cuts 35-byte request parsing latency from **300+ ns to 154 ns** (and 439-byte requests from **2,000+ ns to 1,150 ns**), increases throughput from **3.0 million to 6.5 million req/sec**, and reduces minor-heap allocations from 100–800 words to **zero**.

Second, for **HTTP/2 Multiplexing & RFC 7541 HPACK Compression**, `std::http::h2` maintains per-stream state inside a `SlotMap[StreamId, H2Stream]` and implements RFC 7541 **HPACK** header compression. The **61-entry Static Table** (Appendix A of RFC 7541, where index 2 is `:method: GET`, index 8 is `:status: 200`, etc.) is compiled into a `.rodata` constant lookup table and perfect hash map at `comptime`. The **Dynamic Table** (indices `62..61 + k` in FIFO eviction order, strictly bounded by `SETTINGS_HEADER_TABLE_SIZE`, default 4,096 bytes) is implemented as a zero-allocation `RingBuf[HeaderSpan]` backed by a fixed 4 KiB circular byte buffer per connection.

Third, **RFC 6455 & RFC 8441 WebSockets with SIMD 32-Byte XOR Unmasking** (`std::http::ws`) supports both HTTP/1.1 `Upgrade: websocket` and HTTP/2 Extended `CONNECT` (multiplexed WebSocket streams over a single TCP connection, configurable from 16 KiB up to 16 MiB frame limits). Because RFC 6455 mandates that all client-to-server frames are XOR-masked with a 32-bit `masking_key: u32`, `std::http::ws` broadcasts the 4-byte key into a 256-bit `Simd[u32, 8]` register (`AVX2` or two 128-bit `NEON` / `wasm32 SIMD128` registers) and unmasks the payload **in place inside the `ProvidedBuf` / `IoBuf`** before validating UTF-8 via `validate_utf8_simd`.

Fourth, the **Compile-Time `@route` Radix-Trie Router & Per-Request `BumpArena` Reset** (`std::http::Server::register_routes[Handlers]()`) inspects all `@route(method = "...", path = "...")` attributes (`DR-03` Showcase 2) inside `MirVm` (`DR-05`), verifies there are no ambiguous route collisions, and emits a static compressed radix-trie in `.rodata`. At runtime, before invoking the matched `async fn` handler, the worker takes a checkpoint `let cp = conn_arena.checkpoint(); defer conn_arena.restore(cp);` on its core-local 64 KiB `BumpArena` and binds it to `context.allocator` – reclaiming all request allocations in bulk upon response completion.

#### 2. `std::serde` Two-Stage `simdjson` 64-Bit Tape & Direct Struct Deserialization

Following `DR-02` and Langdale & Lemire's `simdjson` architecture, `std::serde::json` operates in two stages over 64-byte input blocks (requiring `SIMDJSON_PADDING = 32` bytes of safe tail padding, naturally satisfied by `IoBuf` / `ProvidedBuf` slab alignment).

In **Stage 1 (Branchless 64-Byte SIMD Structural Indexing)**, the parser loads 64 bytes into two `Simd[u8, 32]` registers (`vpcmpeqb` + `vpmovmskb` on `x86_64`, `vtbl` on `aarch64`, `i8x16.swizzle` on `wasm32`). In a branchless pipeline, Stage 1 computes 64-bit bitmasks for odd backslash escape runs (`\\`), string quote regions (`"`), whitespace (`' '`, `'\t'`, `'\n'`, `'\r'`), and structural characters (`{`, `}`, `[`, `]`, `:`, `,`), extracting their byte offsets into a structural index array while simultaneously validating UTF-8 encoding.

In **Stage 2 (64-Bit Contiguous Tape Construction & `comptime for` Direct Struct Mapping)**, the parser walks the structural indices and writes a contiguous array of 64-bit **`TapeWord`** values inside `context.allocator` (`BumpArena`):

$$\text{TapeWord} = (\text{u64}(\text{tag\_ascii}) \ll 56) \mid (\text{payload} \ \& \ 0\text{x00FF\_FFFF\_FFFF\_FFFF})$$

where `tag_ascii` is one of `'r'`, `'{'`, `'}'`, `'['`, `']'`, `'"'`, `'l'`, `'u'`, `'d'`, `'t'`, `'f'`, or `'n'`. On every opening `'{'` or `'['` word at tape index `i_open`, the 56-bit payload stores `i_close + 1` (the exact tape index immediately after the matching `'}'` or `']'`), and the closing word stores `i_open`. When deserializing a `.cx` struct `@derive(Deserialize)` that ignores an unknown nested JSON object or array, calling `cursor.skip_value()` simply sets `cursor.idx = word.payload()` – skipping an arbitrarily large nested JSON subtree in O(1) time without reading its contents. Furthermore, if Stage 1's backslash bitmask for a string token is `0` (meaning the JSON string contains no `\"` or `\uXXXX` escapes), `std::serde` performs **Zero-Copy Unescaped String Slicing**: the `str` field in the deserialized `.cx` struct (`CreateUserReq.username`) points directly into the immutable `raw_utf8` request buffer, while only strings containing backslash escapes are normalized into the `BumpArena` string buffer. Finally, per `DR-05`'s **Two-Tier `comptime` Struct Specialization**, structs with ≤8 fields unroll a SWAR 8-byte integer-packed key matcher (`u64` comparison of `"username"`) via `comptime for`, whereas structs with >8 fields generate a `.rodata` field-offset schema table (`Tier 2` in `DR-05`) to prevent instruction-cache bloat.

### 3.2 Unified `std::ui` Architecture (`wasm32` + Native Desktop, Zero JS Framework)

To enable developers to build snappy, visually polished web applications (`wasm32`) and native desktop applications in 100% CoreX without touching TypeScript, React, HTML/CSS templates, or a multi-megabyte Electron bundle, `std::ui` unifies **Fine-Grained Reactive Signals (`@component`, `@state`, `Signal[T]`, `Computed[T]`)** from `DR-03` Showcase 4 with the **Xilem / Masonry `SlotMap` + `IdPath` + `Adapt` Lens Architecture** from `DR-02`.

> **Visual – Unified Reactive View Tree Drives Both a Sub-3 KB Wasm32 Binary Bridge and Native GPU Windows:** **Top & Middle:** Declarative *@component* functions construct a lightweight value View tree inside a scratch *BumpArena* and reconcile against a central *SlotMap* widget arena. User events travel up with an *IdPath* and route back down through *Adapt* lenses as exclusive *&mut AppState* projections. **Bottom Left:** On *wasm32*, mutations serialize into a contiguous binary opcode stream with a single concatenated UTF-8 string table decoded once per frame by a tiny host shim. **Bottom Right:** On desktop, the same widget tree feeds a Flexbox/Grid layout engine and a native GPU command queue.

#### 1. Compiler Desugaring of `@component`, `@state`, `Signal[T]`, and Trailing View Blocks

In `DR-03` Showcase 4 (`telemetry_dashboard`), a UI component is written using pure `.cx` syntax with `@component`, `@state var`, `Signal[T]`, `Computed::new`, and trailing declarative view blocks (`Card(padding: 16) { Row(...) { ... } }`). Under the hood, `corex` and `std::ui` lower these constructs with **zero garbage collection, zero `Rc<RefCell<T>>` interior mutability, and zero global Elm message enums**:

1.  **Trailing Declarative View Blocks (`Card(padding: 16) { ... }`):** In `DR-03`'s `PathOrConstructExpr` EBNF rule (`PathExpr [ TypeArgs ] [ StructLiteral | CallArgs [ Block ] | Block ]`), a trailing `{ ... }` block after a view constructor call is passed as a non-escaping **`@local` builder closure** (`children: || -> View`) that appends child `ViewNode` descriptors into the current frame's `BumpArena` view tape. Because the `View` tree is allocated inside a scratch 64 KiB `BumpArena` (`AllocTag = 1`) and reconciled immediately, constructing a 1,000-node `View` tree costs **zero general-heap allocations** and reclaims its scratch memory in 1 instruction at the end of the frame.
2.  **`@component` & `@state` Persistent Slot Lowering:** During `DR-05` Phase 2/3 lowering, `@component` transforms each `@state var is_paused: bool = false;` declaration inside a component into a persistent typed slot inside the corresponding **`WidgetNode`** in the framework's central **`SlotMap[WidgetId, WidgetNode]`**. On the initial mount of that component at structural `IdPath`, the slot is initialized to `false`; on subsequent re-renders, `@state var is_paused` projects an MVS **`inout` (`&mut bool`)** reference directly to the `WidgetNode`'s retained state slot.
3.  **Fine-Grained `Signal[T]` & `Computed[T]` Dependency Graph inside `SlotMap`:** `Signal[T]` and `Computed[T]` are 8-byte `Copy` handles (`{ signal_id: u32, generation: u32 }`) indexing into a reactive graph arena owned by `std::ui::UiRuntime`. When a component or `Computed::new(|| ...)` reads `samples.get()`, the runtime records an edge `(signal_id -> current_widget_id)` in a compact bitset. When an event callback mutates `threshold_pct += 5.0;` or calls `signal.set(next)`, only the specific `WidgetId` subtrees subscribed to that signal or `@state` slot are marked dirty in the `DirtyWidgetBitSet` – skipping reconciliation of clean sibling subtrees in O(1) time.
4.  **`IdPath` Event Routing & `Adapt` Lens `&mut AppState` Projection (`DR-02`):** To allow `Button(on_click: || { is_paused = not is_paused; })` to mutate state safely under Strict MVS without storing closures that hold aliased `&mut` references across frames, `std::ui` implements Raph Levien's Xilem/Masonry architecture specified in `DR-02`. Every retained widget in `SlotMap[WidgetId, WidgetNode]` stores its **`IdPath`** (a compact `[u32; 8]` path of structural view indices from the root component down to the leaf `Button`). When the user clicks the `Button` (either via a browser DOM click event on `wasm32` or a native mouse-up event on desktop), the platform passes `(target_widget_id, EventPayload)` to `UiRuntime::dispatch_event(&mut app_state, event)`. `UiRuntime` traverses the active component spine along `IdPath` while threading an **exclusive MVS `inout` projection (`&mut AppState` / `&mut ComponentState`)**. Whenever the path crosses a sub-component boundary wrapped in `std::ui::adapt(child_view, |parent: &mut ParentState| -> &mut ChildState { &mut parent.telemetry })`, the `Adapt` lens narrows `&mut ParentState` to `&mut ChildState` (`DR-02` subscript projection) and invokes the leaf `on_click` handler directly in place.

#### 2. Dual-Target Rendering Backend A: Surgical Binary Opcode Buffer & `< 3 KB` `wasm32` Bridge

In traditional Rust WebAssembly frameworks (`wasm-bindgen`), every DOM manipulation (`createElement`, `setAttribute`, `setTextContent`) crosses the Wasm-to-JS FFI boundary individually and invokes JavaScript's `TextDecoder.decode()` on every single string – creating FFI call overhead and UTF-8 decoding bottlenecks.

Inspired by Dioxus's **Sledgehammer** binary batching architecture, CoreX's `std::ui` `wasm32` backend eliminates `wasm-bindgen` entirely and communicates with the browser through a **single batched binary command buffer** in Wasm linear memory paired with a **`< 3 KB` zero-dependency JavaScript host bridge (`cx_ui_host.js`)**. During the reconciliation pass of dirty `WidgetId` nodes in `SlotMap`, `std::ui` appends 4-byte-aligned binary instructions into a `BumpArena` `OpcodeBuffer` alongside a **single concatenated UTF-8 `StringBatch` buffer**:

| Opcode Byte | Opcode Name | Binary Payload Layout in Wasm Linear Memory | Surgical Browser Action Executed by `< 3 KB` Bridge |
| :---: | :--- | :--- | :--- |
| **`0x01`** | `OP_CREATE_EL` | `tag_id: u8`, `widget_id: u32`, `parent_id: u32` | `nodes[widget_id] = document.createElement(TAGS[tag_id])` (using a pre-populated array of 32 HTML/SVG tags) and appends to `nodes[parent_id]`. |
| **`0x02`** | `OP_SET_TEXT` | `widget_id: u32`, `str_idx: u16`, `str_len: u16` | Sets `nodes[widget_id].textContent = batchStr.slice(str_idx, str_idx + str_len)`. |
| **`0x03`** | `OP_SET_STYLE` | `widget_id: u32`, `prop_id: u8`, `val_packed: u32` | Mutates inline CSS property (`padding`, `gap`, `backgroundColor`, `borderColor`, `width`) directly on `nodes[widget_id].style` without CSS parser overhead. |
| **`0x04`** | `OP_ADD_LISTENER` | `widget_id: u32`, `event_kind: u8` | Attaches a shared delegated event listener (`data-cx-id = widget_id`) on the root container (zero per-node JS closure allocations). |
| **`0x05`** | `OP_REMOVE_EL` | `widget_id: u32` | Removes `nodes[widget_id]` from the DOM and frees its slot in the JS `nodes` array. |
| **`0x06`** | `OP_CANVAS_2D` | `widget_id: u32`, `cmd_count: u16`, `[f32; N]` | Executes batched 2D path/fill/stroke primitives for high-density charts and sparklines. |
| **`0x07`** | `OP_WEBGPU_SUBMIT`| `widget_id: u32`, `vbo_off: u32`, `vbo_len: u32` | Uploads zero-copy `Uint8Array(wasm.memory.buffer, vbo_off, vbo_len)` directly to `GPUQueue.writeBuffer` for 120 FPS custom shaders/canvases. |

At the end of the reconciliation pass, CoreX makes **one** FFI call: `cx_host_flush_batch(opcode_ptr, opcode_byte_len, str_table_ptr, str_table_byte_len)`. The `< 3 KB` JS bridge calls `const batchStr = decoder.decode(new Uint8Array(mem.buffer, strPtr, strLen))` **once per frame batch** and slices individual strings via `batchStr.slice(start, end)` while reading opcodes from a `DataView` over Wasm linear memory. Instead of allocating a JavaScript `Closure` per button (`Button(on_click: ...)`), the host bridge attaches **one** delegated event listener per event type (`click`, `input`, `pointerdown`, `keydown`) on the root mount node. When clicked, it reads `event.target.closest('[data-cx-id]').dataset.cxId` (the 32-bit `SlotMap` index) and calls exported Wasm function `cx_ui_on_event(widget_idx: u32, event_kind: u8, arg0: f64, arg1: f64)`, which routes down `IdPath` inside `.cx`.

#### 3. Dual-Target Rendering Backend B: Native Desktop OS Windowing & Hardware GPU Rasterizer

When the exact same `.cx` application is compiled for a native desktop target (`x86_64-linux`, `aarch64-macos`, `x86_64-windows`), `std::ui` swaps out the `wasm32` binary opcode emitter for the **Native Masonry/WebGPU Backend** with **zero changes to application `.cx` source code**:

1.  **Native OS Windowing & Completion Event Loop Integration:** `std::ui::native` opens a native platform window (`Wayland`/`X11` on Linux, `Cocoa`/`CAMetalLayer` on macOS, `Win32`/`DXGI` on Windows) and registers the window's file descriptor or message handle directly with the current thread's `DR-08` `std::io::Reactor` (`io_uring` / `kqueue` / `IOCP`). Background `async` HTTP requests (`std::http::Client`), file I/O (`std::fs::File`), and VSync UI frame ticks run cooperatively on the **same single-threaded core reactor** without cross-thread mutexes or `Arc` wrappers.
2.  **Flexbox/Grid Layout & Subpixel Glyph Atlas Shaping:** Dirty `WidgetNode` subtrees in `SlotMap[WidgetId, WidgetNode]` run through a native two-pass Flexbox/CSS-Grid constraint solver (computing exact `(x: f32, y: f32, width: f32, height: f32)` bounding boxes stored inline in `WidgetNode.layout_box`) and shape text runs via the platform font engine (`CoreText` on macOS, `DirectWrite` on Windows, `FreeType`/`HarfBuzz` on Linux) into a shelf-packed GPU glyph texture atlas.
3.  **Single-Pass Instanced SDF GPU Scene Graph (Vulkan / Metal / Direct3D 12):** Every UI primitive (`Card` rounded rectangle with drop shadow and border, `ProgressBar`, `Badge`, `Button`, and textured glyph quad) is encoded as a compact **64-byte `GpuUiInstance`** inside a `#soa Vec[GpuUiInstance]` buffer (`DR-02`) and rendered in a **single instanced Signed-Distance-Field (SDF) uber-shader draw call** per z-layer.
4.  **Native Accessibility Tree (`AccessKit` Semantics):** Because `SlotMap[WidgetId, WidgetNode]` retains the semantic role (`Role::Button`, `Role::ProgressBar`, `Role::Region`), label, and bounding rect of every widget, `std::ui` exposes the tree directly to macOS `NSAccessibility`, Windows `UIAutomation`, and Linux `AT-SPI2` without requiring a hidden browser webview.

### 3.3 End-to-End `.cx` Showcase: Full-Stack HTTP/WebSocket Backend + Shared `std::ui` App

The following modules share a single `common/telemetry_schema.cx` definition (`@derive(Serialize, Deserialize)`), demonstrating how `std::http`, `std::serde`, and `std::ui` (`DR-03` Showcases 2 & 4) form a unified full-stack CoreX application with zero JavaScript frameworks:

```rust
// ============================================================================
// [1] SHARED SCHEMA (`src/common/telemetry_schema.cx`)
// ============================================================================
mod telemetry_schema;

use std::serde::{Serialize, Deserialize};

@derive(Copy, Equatable, Serialize, Deserialize)
pub struct MetricSample {
    pub timestamp_ms: u64,
    pub cpu_load: f32,
    pub mem_used_mb: u32,
}

@derive(Serialize, Deserialize)
pub struct IngestBatchReq {
    @serde(rename = "node")
    pub node_name: str,
    pub samples: Vec[MetricSample],
}

@derive(Copy, Serialize, Deserialize)
pub struct IngestBatchResp {
    pub accepted_count: u32,
    pub peak_cpu: f32,
}
```

```rust
// ============================================================================
// [2] ZERO-COPY BACKEND (`src/server/telemetry_api.cx`)
// ============================================================================
mod telemetry_api;

use std::http::{Request, Response, StatusCode, Json};
use std::serde::{from_json};
use common::telemetry_schema::{IngestBatchReq, IngestBatchResp};

const MAX_BATCH_BYTES: usize = 65_536;

pub enum ApiError {
    PayloadTooLarge,
    InvalidJson(str),
    EmptyBatch,
}

@route(method = "POST", path = "/v1/telemetry/ingest")
pub async fn ingest_metrics(
    req: &mut Request,
) -> Result[Json[IngestBatchResp], ApiError] {
    // [1] Reads from io_uring ProvidedBuf ring with zero heap allocation
    let body_bytes = req.read_body_bounded(MAX_BATCH_BYTES).await catch {
        return .Err(.PayloadTooLarge);
    };

    // [2] Parses via 2-stage simdjson 64-bit tape inside `req.arena` (BumpArena);
    //    `payload.node_name` slices directly into `body_bytes` with 0 string copies!
    let payload = from_json[IngestBatchReq](req.arena, body_bytes)
        |> Result::map_err(|e| ApiError::InvalidJson(e.message()))?;

    if payload.samples.is_empty() {
        return .Err(.EmptyBatch);
    }

    var peak: f32 = 0.0;
    for sample in payload.samples.as_slice() {
        if sample.cpu_load > peak {
            peak = sample.cpu_load;
        }
    }

    .Ok(Json::from(IngestBatchResp {
        accepted_count: payload.samples.len() as u32,
        peak_cpu: peak,
    }))
}
```

```rust
// ============================================================================
// [3] UNIFIED `wasm32` + NATIVE DESKTOP FRONTEND (`src/app/dashboard_ui.cx`)
//    Compiles unchanged to:
//    (a) `corex build --target=wasm32-unknown-unknown` (Wasm + < 3 KB bridge)
//    (b) `corex build --target=native` (Vulkan/Metal/DX12 native window)
// ============================================================================
mod dashboard_ui;

use std::ui::{View, Signal, Computed, Theme, Color, Justify, Align, FontWeight};
use std::ui::{Card, Row, Column, Text, Badge, ProgressBar, Button};
use std::col::Vec;
use common::telemetry_schema::MetricSample;

@component
pub fn telemetry_dashboard(
    node_name: str,
    samples: &Signal[Vec[MetricSample]],
    theme: &Theme,
) -> View {
    @state var is_paused: bool = false;
    @state var threshold_pct: f32 = 80.0;

    let latest_cpu = Computed::new(|| -> f32 {
        match samples.get().as_slice().last() {
            .Some(sample) => sample.cpu_load,
            .None => 0.0,
        }
    });

    let is_critical = Computed::new(|| latest_cpu.get() >= threshold_pct);

    Card(padding: 16, border_color: theme.border_subtle) {
        Row(justify: .SpaceBetween, align: .Center) {
            Text(value: "Node: {node_name}", weight: .Bold, size: 18);
            if is_critical.get() {
                Badge(label: "CRITICAL", color: Color::Red);
            } else {
                Badge(label: "HEALTHY", color: Color::Emerald);
            }
        }

        Column(gap: 12) {
            ProgressBar(
                value: latest_cpu.get(),
                max: 100.0,
                tint: if is_critical.get() { Color::Red } else { Color::Cyan },
            );

            Row(gap: 8) {
                Button(
                    label: if is_paused { "Resume Stream" } else { "Pause Stream" },
                    on_click: || { is_paused = not is_paused; },
                );
                Button(
                    label: "Reset Alert (+5%)",
                    on_click: || { threshold_pct += 5.0; },
                );
            }
        }
    }
}
```
