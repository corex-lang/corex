### Detailed Technical Designs for Discoveries D-01 Through D-11

#### D-01 – Zero-Unsafe Wire Transmute and Padding-Leak Prevention

Systems code routinely reinterprets mmap'd compiler caches, `io_uring` packet buffers, and IPC frames as typed structs. In C/C++, raw pointer casts risk strict-aliasing undefined behavior, alignment faults, and kernel or network information leaks from uninitialized struct padding bytes. In Rust, the `zerocopy` crate requires procedural-macro `#[derive]` attributes, `unsafe` marker traits, and ongoing language-level workarounds regarding union and enum padding bit validity (`unsafe-code-guidelines#533`). CoreX can make safe zero-copy transmutation a zero-boilerplate primitive by allocating 2 spare bits inside `DR-04`'s existing 32-bit Constrained Type Group bitmask on the 14-byte SoA `InternPool`, computed bottom-up during layout finalization: `FromBytes` (`1` iff every bit pattern of `sizeof(T)` is valid, admitting fixed-width integers, IEEE floats, and aggregates thereof while rejecting `bool`, `char`, pointers, niche-optimized `enum`s, and range-refined types like `u32 is 0..4096`) and `IntoBytes` (`1` iff `T` contains no pointers/capabilities and zero uninitialized padding bytes, or carries `@zero_pad`, which instructs `MIR` initialization and moves to zero-fill and preserve padding slots). Exposing `std::mem::view_bytes[T: FromBytes](buf: []u8) -> Result[&T, LayoutErr]` and `std::mem::as_bytes[T: IntoBytes](val: &T) -> []u8` costs ~160 LOC per stage (**Bucket A, Phase 6**), compiles to a zero-instruction pointer cast whenever `DR-06` Pentagon SAST proves length and alignment, and allows `compiler/*.cx` itself to mmap `CompilerDb` incremental disk caches via single `readv`/`writev` syscalls without `unsafe` code.

#### D-02 – Static Worst-Case Stack and Inline Async Frame Budget Verifier

Embedded kernels, interrupt handlers, and thread-per-core `io_uring` workers require hard stack ceilings without OS virtual-memory overcommit. Ada/SPARK relies on an external post-link binary tool (`GNATstack`) to compute stack usage, Zig's `io_uring` evented I/O hit sizing obstacles when VM overcommit is disabled, and Rust had to add `clippy::large_futures` plus implicit Tokio 1.41+ heap-boxing (`> 16 KiB` in release, `> 2 KiB` in debug) after nested stackless `async` futures (`20,003 bytes` in a 2-level call) overflowed default `2 MiB` thread stacks. CoreX can verify both synchronous stack depth and caller-inlined `DR-08` coroutine frames in a single `O(V + E)` pass by extending `DR-06`'s 24-byte `FnRegionSummary` (already computed bottom-up over the `MIR` call graph via Tarjan SCC) by 8 bytes (`own_frame_bytes: u32`, `max_subtree_bytes: u32`):

$$\text{MaxStack}(f) = \text{OwnFrame}(f) + \max_{(f \to g) \in E} \text{MaxStack}(g)$$

Any SCC with size > 1 or a self-edge marks `MAX_UNBOUNDED`, triggering a compile-time error inside `@max_stack(N)` functions and rejecting unbounded recursive `async` state machines at compile time (~140 LOC per stage, **Bucket A, Phases 6 & 8**, zero runtime instructions).

#### D-03 – Zero-Bloat Binary Resource Inclusion via RawBlob MIR Constants

GCC 15 and Clang 19's implementations of C23 `#embed` demonstrated that expanding binary files into AST integer-literal arrays or per-byte `.byte` assembly directives causes severe compiler memory blowup and slow assembly on multi-megabyte assets, requiring a dedicated raw-buffer constant node (`RAW_DATA_CST` in GCC). Adding `@embed_bytes("relative/path") -> []u8` to CoreX (~150 LOC per stage, **Bucket A, Phases 7 & 8**) hashes the target file in `CompilerDb` via BLAKE3 for Early Cutoff, enforces via `DR-17` that the canonicalized path remains strictly inside the owning package root, and lowers directly to a 24-byte `MirConst::RawBlob(FileId, u64, u64)` handle in RAM. Codegen emits raw `.rodata` section bytes in Tier B/C and chunked string literals in Tier A `-ofmt=c`, immediately paying back its LOC cost in Phase 8 by embedding CoreX's `~2.95 MB` zstd sysroot and C builtin headers cleanly into the unified `corex` binary.

#### D-04 – Static Scratch-Arena Aliasing Exclusivity

Odin's `context.temp_allocator` and Ryan Fleury's C/Zig two-scratch-arena ping-pong pattern (`GetScratch(Arena **conflicts, count)`) make temporary allocations nearly as cheap as stack pushes, yet silently corrupt persistent return structures if a callee rewinds a scratch arena that aliases the caller's destination `BumpArena`. Pairing CoreX's `Context` with a 2-slot thread-local scratch ring (`Context.scratch[0..2]`) and recording a 2-bit `ScratchEffect` inside `DR-06`'s `FnRegionSummary` + Ghost exclusivity pass allows `MIR` SAST to statically select the non-conflicting scratch slot `1 - i` whenever a caller passes `&mut Context.scratch[i]` as an output `BumpArena` (or reject unguarded double-rewinds at compile time). At ~120 LOC per stage (**Bucket A, Phase 6**), this eliminates runtime `conflicts` array checks while protecting `compiler/*.cx`'s heavy arena usage during Phase 12 self-hosting.

#### D-05 – Compiler-Verified Constant-Time Secret Taint and LLVM 21+ Lowering

ETH Zürich's *Breaking Bad* study across 8 production cryptographic libraries and `CVE-2025-66442` in Mbed TLS / TF-PSA-Crypto (March 2026, where Clang 18 with LLVM `select-optimize` enabled on 64-bit RISC-V introduced RSA PKCS#1 v1.5 and CBC/ECB timing leaks) show that source-level constant-time bit-twiddling is routinely rewritten into variable-time branches by optimizing backends. Trail of Bits upstreamed `llvm.ct.select.*` optimization barriers and dedicated SelectionDAG lowering into LLVM 21+ (late 2025) across x86-64, AArch64, RISC-V, and WebAssembly, explicitly inviting language frontends to pair secret data types with the new intrinsics. Notably, LLVM's `llvm.ct.select.*` scopes itself strictly to branching timing leaks and does not prevent cache-timing memory indexing or hardware microarchitectural attacks like Spectre. CoreX can close both the branch and cache-timing gaps by reserving a 20-LOC `TypeFlags.is_secret` bit on `distinct` newtypes (`@secret type Scalar = ~[4]u64`) in Phase 6, and implementing a ~260-LOC `MIR` SAST + `corex_llvm.cpp` pass in **Phase 13.1 (`Bucket B`)** that (1) rejects `@secret`-tainted SSA values in `Branch`/`Switch` conditions, (2) rejects `@secret` slice/pointer offsets (closing cache-line index leaks), (3) rejects variable-latency `Div`/`Rem` on secrets, (4) lowers conditional `Select` to `llvm.ct.select.*`, and (5) emits a dead-store-proof zeroization barrier in `AutoDrop`.

#### D-06 – Zero-Unwind Post-Mortem Diagnostics and Lock-Free FlightRecorder

Systems languages face a sharp binary-size vs. observability trade-off. A `bloaty` inspection of a `109 MiB` Go binary (`pilot-agent`) shows `.gopclntab` alone consumes **`25.8 MiB` (`23.8%` of file size and `34.6%` of resident VM size)** so stack traces survive symbol stripping, while EuroLLVM 2026 measurements on `libLLVM.so` (`135,848 kiB` at `-O3`) show standard DWARF `.eh_frame` + `.eh_frame_hdr` consumes **`7,153 kiB` (`5.2%` of binary size)** with slow bytecode unwinding. Conversely, omitting *all* unwind metadata breaks Windows x64 ABI rules (which mandate PE `.pdata`/`.xdata` for every non-leaf function that adjusts `rsp` or saves non-volatile registers) and degrades Linux/macOS profiling if frame pointers are omitted. Recent toolchain advances resolve this tension: EuroLLVM 2026's **Async Compact Unwind** (64-bit descriptors + dictionary `.eh_frame_hdr` v2, currently implemented for x86-64 ELF in LLVM-MC) encodes `>99.93%` of `-O3` functions with an **`86%` size reduction** (`0.73%` binary overhead), outperforming SFrame (merged in Binutils 2.45 / Glibc 2.42 / Linux 6.17 for kernel/profiler stack tracing without callee-saved register state, though less compact than dictionary descriptors); Zig demand-maps non-`SHF_ALLOC` `.debug_line` (`0%` resident VM cost) only on panic alongside lightweight Error Return Traces; and Go 1.25 introduced `FlightRecorder` ring-buffer execution tracing. CoreX should emit mandatory minimal `.pdata`/`.xdata` on Windows plus zstd-compressed non-resident `.debug_line` (`lld --compress-debug-sections=zstd`) and a 16-slot `--dev` `ErrorReturnTrace` in **Phases 7 & 8 (`Bucket A`, ~180 LOC)**, while reserving a 15-LOC `Context.trace_sink` pointer today to power a `< 5 ns` lock-free `std::FlightRecorder` ring and SFrame / Async Compact Unwind emission in **Phase 13.2 (`Bucket B`, ~550 LOC)**.

> **▸ Architectural Summary – Compact Unwind & Non-Resident Line Tables Deliver Stack Traces at Under 1% VM Cost**
> Compared against Go's resident `.gopclntab` (`23.8%` file size / `34.6%` VM) and EuroLLVM 2026's DWARF `.eh_frame` measurements on `libLLVM.so` (`-O3`, `5.2%` size), omitting C++ LSDA personality tables, compressing non-allocated `.debug_line` with zstd, and enabling `lld --gc-sections --icf=safe` retains full post-mortem symbolication at near-zero resident RAM cost.

#### D-07 – Differential MirVm Oracle and Bounded SMT Translation Validation

Custom middle-end optimizers (`D1`–`D5`, `R1`–`R6`) and single-pass native backends (`Tier C`) are the leading source of miscompilation bugs in new compilers. Cranelift defends its pipeline with an UB-free IR and symbolic translation validation, while LLVM relies on Alive2 (`alive-tv`) over Z3 for intraprocedural bounded refinement checking. CoreX already possesses a deterministic 64-bit register `MirVm` (`Phase 5`), enabling an immediate two-step verification strategy: in **Phase 7 (`Bucket A`, ~180 LOC)**, add `corex test --diff-backends` to execute pure functions across unoptimized `MirVm`, post-optimization `MirVm`, Tier A (`-ofmt=c`), and Tier B (`LLVM`), catching ABI and optimizer divergences before self-hosting with zero external solver dependencies; then in **Phase 13.3 (`Bucket B`, ~600 LOC in `.cx`)**, add `corex verify-ir` to lower loop-bounded Block-Argument SSA `MIR` before and after `D1`–`D5`/`R1`–`R6` and Pentagon BCE into SMT-LIB2 bitvector queries checked by Z3/Bitwuzla in compiler CI.

#### D-08 – Built-In CompilerDb SemVer and Capability-Escalation Gate

Rust's `cargo-semver-checks` requires external Trustfall queries over unstable nightly `rustdoc` JSON and cannot detect silent supply-chain capability escalations or wire-layout padding breaks. By reserving a 30-LOC canonical `.cxi` public-interface digest in `Phase 9` (recording exported `InternPool` signatures, `LayoutShapeKey`, `FromBytes`/`IntoBytes` bits, `@no_alloc`/`@no_panic`, and `DR-17` `EffectCapabilityMask`), CoreX can ship `corex semver-check` (and automatic `corex publish` gating) in **Phase 13.1 (`Bucket B`, ~400 LOC in `.cx`)** that diffs `CompilerDb` summaries in `< 5 ms` and blocks minor/patch releases that silently introduce breaking signatures, padding shifts, or new `net`/`ffi`/`process` capabilities.

#### D-09 – Static MVS Drop-Allocation Fusion and FBIP Reuse Contracts

Koka's Perceus (`fbip`) and Lean 4's `reset/reuse` pass allow functional algebraic-data-type transformations (such as balanced tree insertions or AST rewrites) to mutate heap nodes in-place, yet both must store reference counts and emit dynamic `rc == 1` uniqueness branches at every node. Because CoreX's `own T` (`sink`) and `AutoDrop` values are **statically unique at compile time**, CoreX can add a ~350-LOC `MIR` pass `R7` in **Phase 13.2 (`Bucket B`, 0-LOC pre-`v0.0.1` seam)** that pairs an `AutoDrop` deallocation of `(AllocatorId, LayoutShapeKey)` with a dominated allocation of identical `(AllocatorId, LayoutShapeKey)` and fuses them into an in-place field overwrite with zero refcount headers and zero runtime branches, backed by an optional `@fbip` attribute asserting zero net allocations at compile time.

#### D-10 – Target-Aware Cache Alignment and Direct MVS GPU Kernel Lowering

Two hardware-utilization wins fall directly out of CoreX's Data-Oriented Design primitives. First, hardcoding `align(64)` on concurrent ring buffers causes silent 2-way false sharing on Apple Silicon (`aarch64-macos`), where hardware cache lines are **128 bytes** (`hw.cachelinesize: 128`, prompting LLVM `#208716` to raise Clang's Apple AArch64 `destructive_interference_size` to `128`); adding `@cache_aligned` / `std::target::cache_line_bytes` in **Phase 7 (`Bucket A`, ~30 LOC)** eliminates this trap for Phase 8/13 thread-per-core queues. Second, WebGPU's WGSL and Vulkan's SPIR-V forbid parameter pointer aliasing, recursion, and dynamic allocation, and mandate static uniformity analysis to prevent GPU hangs from barrier divergence. Whereas C/C++ developers often rewrite host math twice for WGSL and Mojo relies on the heavy MLIR compiler stack, CoreX functions using MVS (`let`/`inout` non-aliasing), `#soa[]T`, `@no_alloc @no_panic` (`DR-17`), and non-recursive `DR-06` Tarjan SCCs *already satisfy SPIR-V/TinyWGSL's structural invariants*. In **Phase 13.4 (`Bucket B`, ~2,400 LOC in `.cx`)**, a TinyWGSL-style uniformity check plus direct `MIR -> SPIR-V/WGSL` emission lets `.cx` compile both compute kernels and `std::ui` SDF shaders from pure `.cx` source without MLIR.

#### D-11 – Pentagon VRP Safe Narrowing and Linker Identical Code Folding

D's Value Range Propagation (VRP) proved that tracking expression bounds eliminates noisy narrowing casts on bit-masked arithmetic (`(x & 0xFF)` into `u8`), though D's C-inherited implicit signed/unsigned conversions caused subtle pitfalls. Allowing explicit `.narrow()` (or range-proven narrowing where `DR-04`/`DR-06` `Intv(e) ⊆ [Target::MIN, Target::MAX]`) gives CoreX zero-branch narrowing without C promotion hazards. Pairing this in **Phases 6 & 8 (`Bucket A`, ~90 LOC)** with `-ffunction-sections -fdata-sections`, `.llvm_addrsig` emission in `corex_llvm.cpp`, and `lld --gc-sections --icf=safe` (plus `--pack-dyn-relocs=relr` on ELF PIEs) compounds `Phase 5`'s `LayoutShapeKey` generic deduplication – a linker configuration reported in `llvm-project#117523` to cut `18–23%` (`200–400 MB`) on large Windows/Linux builds and `~13.3%` (`33,670 KB` down to `29,198 KB`) on stripped 32-bit ARM firmware.

## Pre-v0.0.1 Bottleneck, Soundness & Scope-Optimization Audit

### Audit 3.1 – Phase 7 Backend Triplication and the macOS Apple Silicon SIGKILL Trap

Scheduling three simultaneous backends (`Tier A` `-ofmt=c`, `Tier B` `corex_llvm.cpp` LLVM 20–23, and `Tier C` TPDE-style `x86_64` + `AArch64` native codegen with padded `Atom` + `GOT` ELF/Mach-O/PE in-place binary patching) prior to `v0.0.1` creates the largest schedule and duplication trap in `PLAN.md`. Even TPDE's C++ reference framework (`arXiv:2505.22610`, TUM, `10–20x` faster than LLVM `-O0`) took `< 8,000` LOC while supporting **ELF `Small-PIC` only** (`compile_to_elf`), omitting Mach-O, COFF/PE, complete DWARF debug info, and shared-instance multithreading. Likewise, Zig's `link.MappedFile` and `Elf/MachO` `Atom` binary patcher remains an active source of linker and `--watch -fincremental` regressions (`#37583`, `#37584`, `#37603`). Most importantly, Zig's own `zig1.wasm.zst` (`637 KB` zstd-compressed + `4,000-LOC` C `wasm2c` shim) **disables every backend except `-ofmt=c` during bootstrap stages 1 and 2**. Because `Tier A` (`-ofmt=c`) bootstraps `corex1.wasm.zst` and `corex_llvm.cpp` is C++ shared 1x across Stage-0 and Stage-1, writing Tier C + three OS binary patchers in Stage-0 Zig (~22,000 LOC estimated) is 100% throwaway work.

Furthermore, `Phase 7`'s plan to patch binaries in-place on disk hits a fatal OS soundness bug on `macos-arm64`: as documented in Apple's `updating_mac_software` guidance and `wild-linker/wild#2375`, XNU's Unified Buffer Cache (`ubc_subr.c`) caches code-signature timestamps (`cs_mtime`) per **vnode/inode** after an executable's first run. Overwriting or patching an existing Mach-O file in-place updates `mtime` while leaving the kernel's vnode `cs_mtime` stale (even after `MS_INVALIDATE` and even when `codesign --verify --strict` succeeds), causing macOS to immediately terminate the rebuilt binary with `SIGKILL (Code Signature Invalid, namespace CODESIGNING, code 2)`. **Recommendation:** Cut Tier C completely from Stage-0 Zig, build Tier C **1x in self-hosted `.cx` (`Phase 13.0`)**, use in-place `MappedFile` patching on Linux ELF, and mandate **`UnlinkAndReplace`** (writing/cloning to a fresh inode + ad-hoc linker `LC_CODE_SIGNATURE` + atomic replace) whenever emitting Mach-O on macOS.

### Audit 3.2 – DR-07 Carry-Flag Return ABI vs. Unmodified LLVM 20–23 and Windows SEH

`DR-07` specifies returning `Result[T, E]`'s discriminator in the CPU Carry Flag (`CF`) alongside 4 payload registers, while `Phase 7` links unmodified upstream LLVM 20–23 via `corex_llvm.cpp`. Unmodified LLVM IR provides no calling convention or attribute capable of returning an `i1` status flag in `EFLAGS.CF` / `NZCV.C` across function boundaries; implementing raw `CF` returns in Tier B would force CoreX to carry custom patches to LLVM's x86/AArch64 TableGen calling-convention definitions, breaking out-of-the-box linking against system LLVM 20–23 packages. CoreX can achieve the exact same zero-`sret`, 1-cycle branch performance on **100% unmodified LLVM 20–23** by lowering `cx_result_cc` onto LLVM's built-in `swiftcc` + `swifterror` convention: `swiftcc` provides 4 integer return registers (`RAX, RDX, RCX, R8` on x86-64; `X0–X3` on AArch64) plus 4 vector return registers (`XMM0–XMM3` / `V0–V3`), while an `alloca swifterror` parameter pins the error word exclusively to hardware register `R12` on x86-64, `X21` on Linux/macOS AArch64, and `X19` on Windows Arm64EC (`0` on `Ok`, `@cold_box` pointer or tagged `DiagId` on `Err`). On x86-64, `test r12, r12; jnz err_lbl` macro-fuses into a single 1-cycle micro-op (matching `jc`), and on AArch64 `cbnz x21, err_lbl` executes in 1 cycle without clobbering arithmetic condition flags. Simultaneously, `DR-07` must amend *"zero unwind tables"* on `windows-msvc`/`gnu`: Windows x64 requires `.pdata`/`.xdata` unwind descriptors for every non-leaf function so OS Structured Exception Handling (SEH), kernel callbacks, and crash dumpers can walk the stack.

### Audit 3.3 – Phase 6 Pentagon SAST Memory Cliff and MVS Projection Panic Soundness

In `DR-06`, Logozzo & Fähndrich's Pentagon domain (`Intv × Sub`) raises static bounds-check validation across `.NET` framework assemblies from `81.45%` (intervals alone) to `88.82%` while avoiding Octagons' 35 analysis timeouts. However, the authors explicitly report experiencing quadratic blowups unless relational closure is lazy, and eager relational closure costs $O(V^2)$ space and $O(V^3)$ time. Applying dense `Sub` bitsets across an unpartitioned `MIR` function with `V = 4,096` SSA variables and `B = V / 4 = 1,024` blocks allocates `V * ceil(V / 64) * 8 + 16 * V = 2,112 KiB` per block – totaling **`2,112 MB` of RAM for a single function** (`16,640 MB` at `V = 8,192, B = 2,048`) and `1,073,741,824` 64-bit word operations per eager closure! **Mandatory Phase 6 Fix:** Run `O(V)` `Intv` (`16 bytes/SSA value`) first to discharge ~81% of checks immediately; then run Sparse ABCD backwards solely from the remaining unproven slice/range checks to isolate the index/length subgraph $V_{\text{idx}}$ (hard-capped at `MAX_SUB_VARS = 256`), using Pentagon's lazy 1-hop join rule (`sup(b1(x)) < inf(b1(y))`). Peak CFG state drops below `1.5 MB` while keeping `--dev` rebuilds well under `50 ms`.

A second Phase 6 soundness corner case arises in Hylo-style `inout` `subscript`/`yield` projections (`DR-02` / `DR-06`). When an `inout` subscript computes a temporary transformation (e.g., `celsius` yielding `&c` and writing `c + 273` back to `self.kelvins` after the caller finishes, or temporarily moving out a non-`Copy` `AutoDrop`/`@linear` field), an early `?` error return or panic inside the caller's projection scope can bypass the post-`yield` writeback or expose an un-refilled slot to outer `AutoDrop` destructors. **Mandatory Phase 6 Fix:** Lower post-`yield` epilogues in `MIR` as mandatory `defer` cleanup blocks along *both* normal and `?` error-return edges, and require via `DR-17`'s `EffectCapabilityMask` that any projection window holding a temporarily vacated non-`Copy` slot either proves `may_panic == 0` (`@no_panic`) at the call site or forces immediate process `abort` on panic prior to running outer destructors.

> **▸ Architectural Summary – Demand-Driven Slicing & Frame Caps Eliminate Multi-Gigabyte SAST and Stack Cliffs**
> Unpartitioned Pentagon (`Intv × Sub`) bitsets across `B = V / 4` blocks explode to **2,112 MB** at `V = 4,096` SSA variables (`16,640 MB` at `V = 8,192`), whereas slicing `Sub` strictly to unresolved array-index variables (`MAX_SUB_VARS = 256`) caps memory below `2 MB` while retaining Pentagon's `88.82%` static bounds-check precision. Likewise, nested 2-way inline `async` joins (`1 KiB` leaf state) reach **1,040 KiB** at depth 10; enforcing a static `16 KiB` `FnRegionSummary` `TaskGroup` arena-spawn boundary prevents `2 MiB` stack overflows with zero hidden heap allocations.

### Audit 3.4 – Phase 8 Coroutine Frame Blowup, io_uring Halt Safety, and C23 Bitfield ABI Traps

In `DR-08`, caller-inlined stackless `async`/`await` avoids per-`.await` heap allocations, but nested concurrent fan-out combinators (e.g., 2-way inline `join` across depth `k` with `1,024-byte` leaf frames and `16-byte` state tags) compound as `2^k * 1,040 bytes` – reaching `260 KiB` at depth 8 and **`1,040 KiB` at depth 10**, half of a standard `2 MiB` OS thread stack. By computing exact unioned suspend-point frame sizes in `FnRegionSummary` (`D-02`) and enforcing a compile-time `16 KiB` caller-inline threshold (matching Clippy's `large_futures` and Tokio's release threshold), CoreX prevents stack overflows statically and directs oversized subtrees to explicit `TaskGroup.spawn(arena, …)` allocation without hidden `Box::pin` heap fallback. Additionally, while `DR-08`'s `@linear` DMA buffers prevent stack UAF before a CQE arrives, empirical findings across Rust `io_uring` runtimes (Monoio/Tonbo) show that cancelling an `accept` or `openat` SQE races with asynchronous kernel completion: if the kernel commits a valid descriptor (`cqe.res >= 0`) before cancellation takes effect, dropping the task without inspecting the CQE leaks live TCP sockets. Attaching a `CompletionReaper` action (`NoResource | CloseFd | ReleaseBuf`) to every `@linear` ring submission ensures the reactor's zombie-CQE drain closes orphaned descriptors deterministically.

In `DR-10` (Aro-inspired in-tree C11/C23 translator), construct-oriented fuzzing (`PROGnosticator`, FSE 2026) across seven transpilers including Zig `translate-c` `0.14.0`, C2Rust `0.19.0`, and CxGo `0.5.0` uncovered **77 bugs** (`64` previously unknown), driven by C integer promotions, bitwise negation of boolean comparisons (`~(5 > 3)`), comma-expression boolean-to-`c_int` mismatches, switch-scoped declarations, and nested conditional macros. Even more dangerously for cross-compilation, C bitfield layouts diverge sharply across platform ABIs: on System V / Itanium (Linux/macOS Clang & GCC), `struct S2 { int a:10; short b:10; }` packs into **4 bytes** and `struct [[gnu::packed]] P { int x:4, y:30, z:30; }` packs into **8 bytes**, whereas on `windows-msvc` x64 a type-size change forces a new storage unit and bitfields cannot straddle `int` units, inflating `S2` to **8 bytes** and `P` to **12 bytes**! **Mandatory Phase 8 Simplification:** Restrict Phase 8's C translator strictly to **C11/C23 declarations (`typedef`, `enum`, `struct`/`union`, `extern fn`, simple literal `#define` constants)**, defer full C function-body and macro AST transpilation to **Phase 13.3** (written 1x in `.cx`), and lower C bitfields into target-ABI-computed (`SysV` vs. `MSVC` vs. `AAPCS64`) byte arrays with generated `subscript` bit-mask projections rather than native `.cx` `bit_field`.

### Audit 3.5 – Phase 9 MaxSAT Deferral and DR-17 Supply-Chain Sandbox Hardening

In `Phase 9`, PubGrub (`uv`, SwiftPM, Hex, Bundler) already applies domain-specific conflict-driven clause learning over version ranges to derive human-readable incompatibility proof trees in milliseconds. By contrast, weighted Partial MaxSAT (`MSU3` / resolution-graph partitioning) requires iterative SAT solver invocations over unsatisfiable cores, and `DR-16`'s pre-verified counterfactual synthesis runs speculative `CompilerDb` checks across candidate manifest edits. Because a `v0.0.1` ecosystem has near-zero multi-major diamond conflicts, CoreX should ship **PubGrub + `corex.lock` + Bounded-MVS** in Phase 9, reserve a 35-LOC PubGrub `Incompatibility` DAG + lossless TOML CST span export seam, and move `DR-16` MCS/MaxSAT synthesis (~4,500 LOC x 2 = ~9,000 LOC pre-`v0.0.1` effort) to **Phase 13.2** (bounding speculative typechecks to the top-3 `.cxi` summaries from `D-08`). Meanwhile, `DR-17`'s compile-time capability sandbox should close three subtle bypass vectors in Phases 6 & 9 (~80 LOC): (1) keep `MirVm` `comptime` strictly hermetic (zero host syscalls) and path-jail `@embed_bytes` inside the package root; (2) taint any `extern` declaration, `@export`, `@link_name`, `@link_section` (blocking `.init_array`, `__mod_init_func`, `__interpose`, or `.CRT$XCU` pre-`main` constructors), or inline `asm` with `EffectCapabilityMask.ffi | EffectCapabilityMask.unsafe_op`; and (3) propagate `EffectCapabilityMask` across indirect `fn(…)` pointers and trait vtables so `@no_alloc`, `@no_panic`, and package permissions cannot be laundered through callbacks.

### Audit 3.7 – Stress-Testing RDG-18 and RDG-19

Stress-testing CoreX's `RDG-18` and `RDG-19` designs surfaces four targeted refinements:
1.  **Hash-Seed Determinism in `--sim` (`RDG-18`, Phase 11, ~40 LOC):** Ensure `std::col::HashMap`/`HashSet` draws its Wyhash seed strictly from `Context.rng` rather than OS entropy or stack addresses, and emit a `--sim` SAST warning on pointer-to-integer (`&x as usize`) casts so `--sim --seed` replays remain identical under ASLR.
2.  **Two-Phase Safety-to-Liveness Simulation (`RDG-18`/`DR-19`, Phase 13.3):** TigerBeetle's VOPR showed that uniform probabilistic fault injection and healing (*Safety Mode*) misses asymmetric partition livelocks and round-robin log-repair resonance bugs. Phase 13.3's multi-node simulator should implement VOPR's **Liveness Mode switch** (run uniform chaos -> select a quorum core -> heal core links while *permanently freezing* non-core asymmetric faults -> verify bounded transaction completion and physical byte-for-byte replica storage checksums).
3.  **`@must_vectorize` Constant-Trip Unroll & Early-Exit Loops (`RDG-19`, Phase 13.2):** On small constant-bound loops (e.g., `0..32`), LLVM's LoopUnroll pass often fully unrolls the loop before `LoopVectorize` runs, suppressing `loop-vectorize` remarks even when `SLPVectorizer` vectorizes the unrolled body (or leaving scalar adds if SLP misses). Furthermore, LLVM 21–23's early-exit vectorizer (`llvm-project#159697`) rejects `find`-style loops unless loads are provably non-faulting across the vector width. `corex_llvm.cpp` should delay full unrolling on `@must_vectorize` loops until after `LoopVectorize` (accepting either `loop-vectorize` or `slp-vectorizer` pass remarks) and emit `dereferenceable(N)` / `align(A)` slice metadata from `DR-06` Pentagon intervals to unlock early-exit SIMD.
4.  **Stateful Hot-Reload Invariants (`corex run --watch`, `RDG-19`, 35-LOC Seam in Phase 7):** Production experience with C++ Live++ and `cr.h` demonstrates that live code patching crashes if persistent state stores raw `.text` function addresses, if patches apply while stack frames borrow old layouts, or if struct layouts mutate without migration glue. Reserving indirect `GOT` thunk indices for `--dev` function pointers/vtables, storing `{TypeId, LayoutShapeKey, FieldHash64}` in `CompilerDb`, and exposing a quiescent `std::runtime::poll_reload()` frame-boundary hook (modeled on Zig `#20604`'s build-pipe protocol) makes Phase 13.0's stateful hot reload completely sound.
