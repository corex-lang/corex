# Definitive Surface Syntax Canonicalization, Micro-Ergonomic Polish, and Zero-Cost Language Advantages for CoreX (.cx)

CoreX (`corex-lang/corex`, `.cx`) executes a single pre-Phase-8 surface-syntax lock (**Phase 7.6**, `DR-22`) across the Stage-0 Zig compiler (`stage0/src/`) and the 12 Stage-1 kernel files (`core/**/*.cx`), resolving every duplicate operator, parameter-mode conflict, and half-wired construct on top of the green Phase 7.5 baseline (`384/384` tests and `117` `TokenKind`s `0..116`) before Phases 8–12 expand `.cx` source volume across async coroutines, C11/C23 FFI, `wasm32`, package management, `corex lsp`/`upgrade` tooling, the `cx.*` standard library, and the self-hosted `compiler/*.cx` rewrite. First, six Architectural Decision Records (**`ADR-22A`–`ADR-22F`**) establish strict **One Canonical Way** consistency: (`ADR-22A`) locking **`and`**, **`or`**, and **`not`** as the sole boolean operators and **`~x`** as the sole integer bitwise-not operator (retiring `&&`, infix `||`, and prefix `!x`); (`ADR-22B`) locking **`let`** and **`var`** as the sole local binding keywords and unifying all Mutable Value Semantics (MVS) borrows, moves, and out-parameters onto **`&T`**, **`&mut T`**, **`own T`**, and **`&out T`** (retiring `let mut`, `var mut`, `ref`, `inout`, `sink`, `set`, and fixing the `fn f(mut x: i32)` caller-mutation hazard via local-only `var x: T`); (`ADR-22C`) locking payload-first **`T!E`** as CoreX's canonical `Result` surface syntax symmetric with `T?` (`Option[T]`); (`ADR-22D`) standardizing `@attr(key: val)`, `bit_field Name: uN { … }`, `enum Name: Int { … }` with zero-cost `as` integer and boolean casts, `,`-only field separators, `.len()` methods, `Number`, and `@no_alloc`; (`ADR-22E`) adding **`pub(pkg)`** and **`pub(super)`** visibility with zero new tokens; and (`ADR-22F`) unifying raw pointers onto **`*T`**, **`*mut T`**, **`*opaque`**, safe **`&raw`** / **`&raw mut`** address-of, and postfix **`ptr.*`** dereferencing.

Second, CoreX adopts **fifteen orthogonal zero-cost surface elevations (`SE-09`–`SE-23`)** – while rejecting ten high-friction or redundant cross-language candidates under a strict pruning gate – that lower purely during `AST → HIR → MIR` with zero hidden heap allocations, zero runtime vtables, and zero parser backtracking. These elevations introduce Python PEP 695 inline union bounds (`[Data: str | &[u8]]`), PEP 696 generic type and const defaults, `@derive(From)` nominal error upcasting, and PEP 570 / PEP 3102 `/` and `*` parameter-zone separators (`SE-09`–`SE-11`); compile-time validated format specifiers (`"{mask:#010x}"`, `"{val:.2f}"`), Python/Rust self-debugging `"{x=}"`, `{{`/`}}` brace escaping, stack-resident zero-allocation `FmtArgs` usable inside `@no_alloc` code, closing-quote indent-stripped `"""…"""` multiline strings, `b'A'` / `b"…"` byte literals, and `_`-separated numeric suffixes (`42_u64`, `1.0_f32`) (`SE-12`–`SE-13`); mandatory struct initialization with MVS-sound functional spread (`..base` / `..own base`), `Config { .. }`, pattern field renaming, and parallel swap/destructuring assignment `(a, b) = (b, a);` (`SE-14`–`SE-15`); prose `test "…"` and `bench "…"` blocks with `DR-18` fuzz inputs and O(1) `CstNode.subtree_size` non-test skipping, zero-cloning `.rodata` `SourceLoc = @caller_location()` defaults, and native boolean `@cfg(expr)` (`SE-16`–`SE-18`); and complete Phase 8–13 seams for 3-tier closures, `async |g|` `task_group` nurseries, MVS `subscript`/`yield`, `@builder` `PascalCase` UI structs, and Zig-inspired labeled `match` finite-state machines (`continue :fsm next`) (`SE-19`–`SE-23`).

Across the compiler pipeline, `DR-22` preserves **100% stateless `LL(k)` + Pratt parsing**, **Signature Firewall Early Cutoff (`DR-04` / `DR-12`)**, and **Phase-6 `MIR` SAST + Pentagon (`Intv × Sub`) soundness (`DR-06`)**. Retiring `.kw_ref` and `.ampamp` (`-2` tokens) while adding `.kw_subscript`, `.kw_yield`, `.byte_lit`, `.byte_string_lit`, and `.dotdotdot` (`+5` tokens, with `"opaque"` mapped to existing `.prim_type`) moves `TokenKind` from `117` (`0..116`) to **`120` contiguous `enum(u8)` variants (`0..119`)** – leaving **8 spare bits (`120..127`)** inside `TokenSet128` (`u128`). Migrating Stage-1 kernel modules onto canonical `DR-22` syntax cuts `core/atomic.cx` by **30.0% LOC** (`100` to `70` lines, deleting all 30 lines of `ORDER_*` mapping boilerplate) and `core/mem.cx` by **26.7% LOC** (`60` to `44` lines, eliminating `unsafe` pointer swaps inside generic `swap[T]`).

### 1.1 ADR-22A: Word-Based Boolean Logic and Unambiguous Bitwise Complement

**Decision (`ADR-22A`):** CoreX locks **`and`** (`Pratt (4, 5)`), **`or`** (`Pratt (2, 3)`), and unary **`not`** (`Pratt (–, 28)`) as its **sole** boolean logical operators (requiring `bool` operands), and locks unary **`~x`** (`TokenKind.tilde`, `Pratt (–, 28)`) as its **sole** bitwise complement operator across `Integer`, `Simd[Int, N]`, and `bit_field` types. Symbolic aliases `&&`, infix `||`, and prefix `!x` are retired from the expression grammar.

Permitting both word-based (`and` / `or` / `not`) and C-punctuation (`&&` / `||` / `!`) boolean operators in Stage 0 (`DR-03` §1.1 & §5.2) split codebase style and created three concrete lexical and grammatical defects. First, because newlines are pure whitespace in CoreX (`DR-03` §3.2), retaining `||` as an infix operator caused a missing semicolon before a zero-argument closure statement (`compute_flag() \n || { log_event(); }`) to parse as `compute_flag() or { log_event(); }` instead of recovering cleanly at the statement boundary; restricting `TokenKind.pipepipe` (`||`) exclusively to zero-parameter closures (`|| expr` and `|| -> R`) eliminates this multiline ambiguity completely. Second, overloading `!x` for both `bool` logical negation and integer bitwise complement (`(addr + mask) & !mask`) forced readers to know the type of `x` to distinguish boolean logic from bit manipulation, conflicted stylistically with `SE-01`'s `is not` operator (`if role is not .Admin`), and competed visually with `T!E` (`ADR-22C`). Meanwhile, `~` (`TokenKind.tilde`) was already allocated in `TokenKind` (`DR-03` §5.2) yet unused in expressions because `~T` underlying-type approximation (`DR-04` §2.2) occurs exclusively inside `Type` and `ConstraintExpr` contexts, which are 100% syntactically disjoint from `PrefixExpr`.

Third, controlled human-factors studies by Stefik and Siebert (2013) found that languages using clear English logical words (`Quorum`, `Python`, `Ruby`) achieved higher novice syntactic accuracy than C-style punctuation syntaxes (though those trials evaluated small student cohorts rather than systems engineers), while Dorn's (2012) readability model across 360 snippets and over 5,000 participants identified lower operator-to-word visual density as a primary correlate of human scanning speed. Retiring `TokenKind.ampamp` (`&&`) directly reclaims 1 bit inside `TokenSet128` (emitting lexical error `E0113` with `SuggestedFix` `"&&"` → `"and"`), while infix `||` emits `E0219` (`SuggestedFix` → `"or"`) and prefix `!x` emits `E0220` (`SuggestedFix` → `"not "` on `bool` or `"~"` on `Integer`).

### 1.2 ADR-22B: Unified Local Mutability, Second-Class Borrow Tokens, and MVS Parameter Modes

**Decision (`ADR-22B`):** CoreX locks **`let`** (deeply immutable value root) and **`var`** (deeply mutable value root) as its sole local variable introducers, retires `TokenKind.kw_ref` (`ref`) across the entire language in favor of unified **`&`**, **`&mut`**, and **`&out`**, and maps every parameter onto `DR-02` / `DR-06`'s four second-class MVS `MIR` conventions (`let`, `inout`, `sink`, `set`) with **mandatory call-site mutation, out-initialization, and move visibility**.

In Stage 0, mixing Rust-style `let mut`, `ref`, `&T`, and `&mut T` with Hylo-style `inout`, `sink`, `set`, and `mut x: T` created 11 overlapping spellings and a severe semantic trap: writing `fn f(mut x: i32)` bound `x` as a caller-mutating `inout` parameter accepting bare `f(v)`, silently mutating the caller's variable without `&mut` at the call site (a pitfall also seen when Mojo's `mut` convention omits call-site markers, whereas Mojo separates callee-local mutation onto `var`). Under `ADR-22B`, `let mut`, `var mut`, and pattern `mut ident` are retired (`E0221`) in favor of `var x = …;`, `(var x := …)`, and `.Some(var x)`. Prefixing `var` on a function parameter (`fn popcount(var x: u64) -> u32` or `fn rebalance(var node: own OwnPtr[Node]) -> OwnPtr[Node]`) mutates **only the callee's local binding** and never mutates caller storage.

Simultaneously, retiring `ref` in patterns (`.Some(&n)` and `.Some(&mut n)` instead of `.Some(ref n)` and `.Some(ref mut n)`) is 100% unambiguous in CoreX while reclaiming 1 bit in `TokenSet128`. Rust requires both `&pat` and `ref ident` only because Rust references are first-class types stored in fields (`&pat` dereferences, `ref ident` borrows). Because CoreX references are strictly **second-class projections** (`DR-02`, `DR-06`), structs and enums never store `&T` fields; thus `&ident` and `&mut ident` inside any pattern or `for` loop (`if node is .Some(&n)`, `let Point { &x, &mut y } = p;`, `for &mut p, i in &mut particles`) uniformly mean *bind a second-class `access.let` or `access.inout` projection to the matched place*.

| Surface Parameter & Receiver | MVS `MIR` Mode | Mandatory Call-Site Form | Type & Mutability Contract | `MIR` SAST & `cx` ABI Lowering |
| :--- | :---: | :--- | :--- | :--- |
| **`[var] x: T`** / **`[var] self`** | `let` (by-value) | Bare `f(v)` | Requires `T: Copy` (or `Copy`-bounded generic `[T: Number]`); non-`Copy` bare `x: T` emits `E0421`. `var` mutates local copy only. | Passed in ≤2 GPR/SIMD registers (`≤16 B`). |
| **`x: &T`** / **`&self`** | `let` (borrow) | `f(&v)` *(or `v.m()`)* | Accepts any `T` (`Copy`, `AutoDrop`, `@linear`). Forbids `var x: &T` (second-class borrows cannot rebind). | `%t = access.let %v`; `≤16 B` in regs, `>16 B` as `const T* noalias nonnull`. |
| **`x: &mut T`** / **`&mut self`** | `inout` | `f(&mut v)` *(or `v.m()`)* | Requires `v` rooted at `var` or `&mut`. Callee may move out via `own x.*` if re-initialized before return. | `%t = access.inout %v` (method receiver sequenced *post-args*); `T* noalias nonnull`. |
| **`[var] x: own T`** / **`[var] own self`** | `sink` | `f(own v)` *(named `~Copy`)*; bare `f(rval)` / `f(copy_v)` | Transfers unique ownership. Omitting `own` on a named `~Copy` variable emits `E0420`; `Copy` args pass without `own`. | Active `ExprTag.own_move` emits `storage.move %v` (`E0302` on reuse). |
| **`x: &out T`** *(contextual `out`)* | `set` | `f(&out v)` | Requires uninitialized `var v: T;` (`E0422` if `v` holds live `AutoDrop`/`@linear` state). | `%t = access.set %v`; Pass 2 requires `storage.init` on all `.Ok`/normal exits. |

> **Visual – Unified MVS Parameter Conventions Enforce 100% Call-Site Visibility Across Five Surface Forms:** Every parameter declaration in CoreX maps deterministically to one of four second-class MVS modes in HIR/MIR without lifetime parameters. Prefixing `var` before a parameter identifier (`var x: T` or `var x: own T`) mutates only the callee's local binding, eliminating accidental caller mutation.

Note how `x: own T` handles unconstrained generic containers cleanly: in `impl[T] Vec[T] { pub fn push(&mut self, item: own T) }`, calling `vec_u32.push(42)` passes `Copy` integer `42` directly without requiring `own`, whereas calling `vec_nodes.push(own child)` on a named non-`Copy` variable requires explicit `own` at the call site (`E0420` if omitted).

### 1.3 ADR-22C: Payload-First Result Type Syntax and Unified Type-Operator Precedence

**Decision (`ADR-22C`):** CoreX locks payload-first **`T!E`** (`u64!IoError`, `unit!ScanError`, `WalHeader?!WalError`) as its **sole canonical surface `Result` type syntax**, symmetric with **`T?`** (`Option[T]`). Both `T!E` and nominal `Result[T, E]` (`@lang("result")` in `core/result.cx`) resolve to the exact same `TypeTag.error_union` (`result_ty`) `TypeId` in `InternPool`, and `corex fmt` / `corex upgrade` (`UR-22-03`) format `Result[T, E]` → `T!E` and `Option[T]` → `T?`.

Earlier in `DR-07` §1.1, Zig-style *error-first* `E!T` and inferred `!T` were rejected because prefix `!T` required whole-program cross-function error-set inference (violating `DR-04`'s Signature Firewall) and collided with prefix `!cond` boolean negation. Yet keeping `Result[T, E]` in user signatures while `Option[T]` used `T?` caused heavy bracket nesting (`Result[Option[OwnPtr[AvlNode[K, V]]], StorageError]`) and left `resolveTypeAst` out of sync with `DR-03` and `DR-21` showcases. Because `ADR-22A` retires prefix `!expr` in expressions and `T!E` places the success payload `T` *first* (matching `T?`, postfix `expr?`, and `Result[T, E]`'s parameter order) while keeping `E` mandatory (preserving 100% Signature Firewall Early Cutoff), `OwnPtr[AvlNode[K, V]]?!StorageError` removes two levels of brackets at `LL(1)` with zero `cx_result_cc` ABI changes.

To prevent precedence traps across `?`, `!`, `&`, and `*` (such as Zig's `?*T` vs. `*?T` confusion), CoreX locks a strict four-tier `Type` binding hierarchy:

| Type Tier | Grammar Production | Representative Surface Spellings | Exact Parsed Meaning & Niche Layout (`64-bit`) |
| :---: | :--- | :--- | :--- |
| **T4 (Tightest)** | `SliceType` & `* [mut] PrimaryType` | `&[u8]`, `&mut [f32]`, `*u8`, `*mut Sqlite3Db`, `*opaque` | Slice view (`16 B` fat ptr) or non-null raw pointer (`8 B` with `0x0` niche). |
| **T3** | `PostfixType = PrimaryType { "?" }` | `&[u8]?`, `*mut u8?`, `bool??` | `Option[&[u8]]` (`16 B`), `(*mut u8)?` (`8 B` nullable C ptr), `Option[Option[bool]]` (`1 B`). |
| **T2** | `& / &mut / &out / own PostfixType` | `&OwnPtr[Node]?`, `&out *mut Db?`, `(&V)?` | `&(OwnPtr[Node]?)` (borrows optional field), `&out ((*mut Db)?)`, vs. `Option[&V]`. |
| **T1 (Loosest)** | `PostfixType [ "!" PostfixType ] [ "is" Pat ]` | `T?!E`, `*mut u8?!AllocError` *(non-associative)* | `(T?)!E` (`Result[Option[T], E]`) and `((*mut u8)?)!AllocError`; chained `A!B!C` emits `E0222`. |

### 1.4 ADR-22D: Declarations, Attribute Punctuation, Slice .len(), and Built-in Deduplication

**Decision (`ADR-22D`):** CoreX locks seven declaration, formatting, and built-in surface rules so Stage-0 parsing, `core/*.cx`, and `corex fmt` align 100%:

First, **attribute key-value arguments** use colon `:` (`@route(method: "POST", path: "/v1/users")`, `@arg(short: 'p', long: "pattern")`), matching struct literals and `SE-07` named call arguments and retiring `=` inside `@attr(…)` (`E0223`, `SuggestedFix` `"="` → `":"`). Second, **`bit_field` declarations** use the single item header `[Vis] bit_field Name: BackingInt { [Vis] field: Type | INT_LIT, … }` (retiring `type Name = bit_field …`, `bit_field Name(u32)`, and trailing `;`), enforcing at compile time that `BackingInt` satisfies `Unsigned` (or `[u8; N]`) and that the sum of field bit widths equals the exact bit width of `BackingInt` (`E0423`, requiring explicit `_reserved` fields rather than hidden padding). Third, **integer-backed fieldless enums** use `[Vis] enum Name: BackingInt { Variant [= Expr], … }` where `BackingInt: Integer` (retiring `@repr(u8)` on enums, while keeping `@repr(C)` strictly for C-ABI struct/union/enum layouts). Casting an integer-backed `enum` to any `Integer` at least as wide as `BackingInt` (`order as u8`), casting a `bit_field` to its `BackingInt` (`flags as u32`), and casting **`bool as IntType`** (`false` → `0`, `true` → `1`, e.g., `weak as u8`) are safe, branchless zero-cost `MIR` operations – deleting all 30 lines of `ORDER_*` constants and `order_to_u8` match boilerplate in `core/atomic.cx`.

Fourth, all member lists in `struct`, `union`, `enum`, and `bit_field` use **`,` separators exclusively** (retiring `;` with `E0224`). Fifth, `corex fmt` **strips redundant `-> unit`** on functions, methods, and closure types, and formats parameterless marker attributes **inline on a single line** (`@inline @no_alloc @no_panic`) while stacking parameterized attributes (`@cfg(…)`, `@derive(…)`, `@route(…)`) on separate lines above. Sixth, slices (`&[T]`, `&mut [T]`), fixed arrays (`[T; N]`), `#soa` views, `str`, `String`, `Vec[T]`, `Map[K, V]`, and `SlotMap[K, V]` expose length uniformly via **`.len() -> usize`** and **`.is_empty() -> bool`** (retiring bare `.len` and `.ptr` field reads on slices with `E0424` in favor of `.len()`, `.as_ptr()`, and `.as_mut_ptr()`, since 24-byte `DR-15` containers store `len: u32` internally). Seventh, built-in Type Group `Numeric` (`TypeId 37`) is retired in favor of **`Number`** (`TypeId 36`), and `@noalloc` is retired (`E0225`) in favor of **`@no_alloc`**.

### 1.5 ADR-22E: Four-Tier Package and Module Visibility Hierarchy

**Decision (`ADR-22E`):** CoreX defines four strictly ordered visibility levels on items and struct fields using **zero new `TokenKind`s** (`"pkg"` and `"super"` are validated as contextual `IDENT` tokens inside `"pub" "(" IDENT ")"`):

$$\text{private (default)} \;\subset\; \texttt{pub(super)} \;\subset\; \texttt{pub(pkg)} \;\subset\; \texttt{pub}$$

Multi-file packages in Phases 9–12 (`stdlib/cx/*` and `compiler/*.cx`) must share internal data structures – such as `InternPool` tables across `compiler/sema.cx` and `compiler/mir.cx` or HPACK dynamic rings across `cx/http/h2.cx` and `cx/http/server.cx` – without leaking them into public `.cxi` SemVer contracts (`DR-20` `D-08` `corex semver-check`). Omitting `pub` restricts an item to its enclosing module and inline child `mod`s; **`pub(super)`** exposes it to the immediate parent module and its descendants; **`pub(pkg)`** (aligned with Swift 5.9 `SE-0386` `package` and Rust `pub(crate)`) exposes it across the entire `corex.toml` compilation unit while excluding it from `.cxi` interface hashes and keeping it eligible for whole-package Dead-Code Elimination; and **`pub`** exports it publicly when reachable from the package root. Arbitrary `pub(in path)` and redundant `pub(self)` are rejected.

### 1.6 ADR-22F: Raw Pointers, Opaque Targets, Safe &raw Address-Of, and Postfix ptr.* Dereferencing

**Decision (`ADR-22F`):** CoreX canonicalizes raw pointers onto **`*T`** (read-only), **`*mut T`** (mutable), and **`*opaque`** / **`*mut opaque`** (type-erased `void*`), constructs raw pointers safely via **`&raw place`** and **`&raw mut place`**, dereferences pointers exclusively via **postfix `ptr.*`**, and types C FFI callbacks and variadics via **`[unsafe] extern "C" fn(…, ...)`**.

Retiring `*const T` (`E0226`) in favor of `*T` makes immutability the unadorned default across every level of CoreX (`let x`, `&T`, `&[T]`, `*T`), while adding `"opaque"` to `KEYWORD_OR_PRIM_MAP` as the 20th `PRIM_TYPE` (`TypeId 22`, **0 new `TokenKind`s**) replaces the `struct c_void { _opaque: [u8; 0] }` workaround (`DR-10` §2.4, aliasing `cx.ffi.c_void = opaque`, analogous to Zig's `anyopaque`). `*mut T` coerces implicitly to `*T`, `*mut opaque`, and `*opaque`, and `*T` coerces implicitly to `*opaque`, whereas dereferencing `*opaque` or `*mut opaque` directly is rejected (`E0425`). Following Rust 2024's `&raw const` / `&raw mut` stabilization, `&raw place` (synthesizing `*T`) and `&raw mut place` (synthesizing `*mut T` on a mutable `place`, where `raw` is a contextual `IDENT` after `&`) are safe to evaluate without creating an intermediate MVS `&T` or `&mut T` loan, making them sound on `@repr(C, packed)` unaligned fields and uninitialized slots.

For pointer dereferencing, postfix **`ptr.*`** (`Pratt (30, –)`) replaces C-style prefix `*ptr` (`E0227`). Postfix `ptr.*` composes strictly left-to-right with field access, optional unwrapping, and parallel swap (`pp_db.*`, `node_ptr.*.next`, `opt_ptr?.*`, `(a.*, b.*) = (b.*, a.*);`) without parentheses and never collides with binary `*` multiplication across line breaks. On safe MVS borrows (`&T`, `&mut T`, `&out T`), `a.*` is safe (and `a.field` auto-dereferences); on raw pointers (`*T`, `*mut T`), **both `ptr.*` and field access `ptr.*.field` require an `unsafe { … }` block** (omitting implicit raw-pointer `ptr.field` auto-deref so every raw memory load is visually explicit). Finally, C FFI function types standardize on uppercase `"C"` (`extern "C" fn(…)` – automatically `contextless` per `DR-02` §4 & `DR-10` §2.4) and add `TokenKind.dotdotdot` (`"..."`) strictly as the trailing parameter of `extern "C" fn` items and types, applying target C variadic ABI lowering across `SysV64`, `Win64`, `AAPCS64`, `Apple ARM64`, and `wasm32` (`DR-10` §2.2).

### 2.1 Generics, Parameter Zones, and Error Composition (SE-09 through SE-11)

#### SE-09: PEP 695 Inline Ad-Hoc Union Bounds in Generic Brackets

Extending Python 3.12's PEP 695 bracket syntax onto `DR-04`'s Constrained Type Groups, `TypeParam` and `WherePred` accept inline union bounds `ConstraintExpr = IntersectBound { "|" IntersectBound }` (`IntersectBound = [ "~" ] Type { "+" [ "~" ] Type }`) directly inside `[…]` – e.g., `pub fn strip[Data: str | &[u8]](data: Data, /) -> Data` or `pub fn hash_word[W: ~u32 | ~u64](w: W, /) -> u64` – without requiring a separate `type` alias. Inline `|` unions are permitted **strictly inside `[…]` generic bounds and `type G = …;` Type Group aliases**, never as bare parameter types (`data: str | &[u8]` is a syntax error), preventing confusion between compile-time monomorphized Type Groups and runtime tagged enums. CoreX's three generic spellings thus have non-overlapping roles: bare `Group` (`fn clamp(v: Number, lo: Number, hi: Number) -> Number`) for Bind-Once named groups; `any Group` (`fn scale(v: Number, f: any Float)`) for Bind-Many independent parameters; and explicit `[T: Bound]` whenever writing inline `|` bounds, naming `T` inside the body, or coupling multiple type variables. `InternPool` interns `str | &[u8]` as an anonymous `TypeTag.user_type_group`, `Sema` checks the function body once at definition time against the **capability intersection** of all union members (`.as_bytes()`, `.len()`, `data[a..b] -> Data`), and `MonoCollector` monomorphizes each call site to `str` or `&[u8]` with zero boxing.

#### SE-10: PEP 696 Generic Type and Const Defaults and Nominal Error Composition

Following Python 3.13's PEP 696, both generic type parameters (`struct Map[K: Equatable, V, H: Hasher = WyHasher]`) and const parameters (`struct SmallVec[T, const N: usize = 8]`) accept `= Default` specifications. Defaulted parameters must trail non-defaulted parameters (`E0426`), may reference preceding parameters (`struct Pair[A, B = A]`), and validate their default against `: ConstraintExpr` or `: Type` at declaration time.

For error composition across `?` boundaries, `DR-22` evaluates `type AppErr = IoErr | ParseErr;` (partially parsed at `parser.zig:2048`) against `@derive(From)` on nominal `enum` types (`DR-07` §2.3). Overloading `type AppErr = IoErr | ParseErr;` to construct an anonymous runtime error sum type would collide directly with `DR-04`'s compile-time Type Group syntax (`type Int32Or64 = i32 | i64;`), obscure variant names in `match`, and risk silently exceeding `DR-07`'s 16-byte `cx_result_cc` register limit. Instead, `parser.zig:2048` wires cleanly to `InternPool`'s `TypeTag.user_type_group` (emitting `E0427` if a Type Group appears on the error side of `T!Group`), while **`@derive(From)` on a nominal `enum`** (`@derive(From) pub enum AppErr { Io(IoErr), Parse(ParseErr), QuotaExceeded }`) inspects all single-field tuple variants `V(SrcErr)` with distinct `SrcErr` types and synthesizes `impl FromError[SrcErr] for AppErr` automatically during `AST → HIR` lowering (keeping `@from` for disambiguating duplicate payload types) – preserving 100% Signature Firewall Early Cutoff and explicit `≤16 B` niche layout checks.

#### SE-11: PEP 570 Positional-Only and PEP 3102 Keyword-Only Parameter Separators

Universal named call arguments (`SE-07` in `DR-21`) introduced two API hazards well-documented in Python: callers passing `strip(data: buf)` lock internal parameter names into the public SemVer contract, while callers passing boolean flags positionally (`strip(buf, false)`) create unreadable boolean traps. Reusing existing `TokenKind.slash` (`/`) and `TokenKind.star` (`*`) (`0` new `TokenKind`s), `ParamList` partitions non-`self` parameters into three optional zones (`pub fn strip[Data: str | &[u8]](data: Data, /, *, trim_newlines: bool = true) -> Data`): parameters left of `/` are **positional-only** (`E0428` if passed by name, and their names normalize to `_` inside `.cxi` SemVer digests per `DR-20` `D-08`); parameters between `/` and `*` accept positional or named arguments; and parameters right of `*` (both required and defaulted) are **keyword-only** (`E0429` if passed positionally, with `, /` and `, *` invalid in wrong order or empty `*` zone emitting `E0228`). Before `*`, non-defaulted parameters cannot follow defaulted parameters (`E0430`); after `*`, required and defaulted keyword-only parameters may appear in any order. All checks run in `Sema` and lower to flat positional `HIR`/`MIR` calls at zero runtime cost.

### 2.2 Zero-Allocation Formatting, Multiline Strings, Byte Literals, and Numeric Suffixes (SE-12 and SE-13)

#### SE-12: Compile-Time Format Specifiers, Self-Debugging {x=}, {{ and }} Escapes, and Stack FmtArgs

CoreX resolves the Stage-0 `lexer.zig` vs. `type_system.zig` brace-escaping mismatch by locking **`{{`** and **`}}`** as the sole literal brace escapes inside `"…"` and `"""…"""` (retiring `\{` and `\}` with `E0114`), while raw strings (`r"…"`, `r#"…"#`, `r"""…"""`) disable interpolation completely. Each interpolation hole parses `InterpHole = "{" Expr [ "=" ] [ ":" FormatSpec ] "}"`, where `FormatSpec = [ [ FillChar ] ( "<" | "^" | ">" ) ] [ "+" ] [ "#" ] [ "0" ] [ INT_LIT ] [ "." INT_LIT ] [ ( "?" | "x" | "X" | "b" | "o" | "e" | "E" | "f" | "p" ) ]`. Following Python 3.8+ / PEP 701 self-documenting expressions, appending `=` after `Expr` (`"{port=}"` or `"{magic=#010x}"`) folds the exact source slice of `Expr` + `"="` into the preceding static `.rodata` string piece and defaults the format mode to `Debug` (`?`) when no `:FormatSpec` is given.

$$\frac{\forall i \in 1..k.\; \Gamma; \Theta \vdash e_i \Rightarrow \tau_i \quad \text{valid\_fmt}(\tau_i, \text{spec}_i)}{\Gamma; \Theta \vdash \text{"}s_0\{e_1:\text{spec}_1\}s_1\dots\{e_k:\text{spec}_k\}s_k\text{"} \Leftarrow \mathsf{FmtArgs}} \;(\text{FmtArgs}\Leftarrow)$$

Each `FormatSpec` compiles to a packed 8-byte `FmtSpec` value checked against $\tau_i$ at compile time (`E0431` on type/specifier mismatch, such as `"{name:#x}"` on `str`). Whenever an interpolated literal is checked top-down against **`FmtArgs`** – the parameter type of `Write.write_fmt`, `panic`, `assert`, `context.note`, `Arena.fmt`, and `String.fmt` – `AST → HIR` emits static `.rodata` `pieces: &[str; k + 1]` and a **stack-allocated** `[FmtArg; k]` array (`24 B` per arg: `{ data: *opaque, fmt_fn, spec: FmtSpec }`) holding statement-scoped `access.let` temporaries (`Depth(rho_local)` in `MIR` Pass 3 prevents `FmtArgs` from escaping its statement, `E0306`). Formatted streaming I/O, assertions, and panics therefore perform **zero heap allocations** and are **100% legal inside `@no_alloc` functions**. In Synthesis Mode ($\Rightarrow$) with 1 or more holes (`let s = "hi {name}";`), the expression synthesizes `String` via `String.fmt(FmtArgs { … })` (using `String`'s 23-byte inline SSO buffer before touching `context.allocator`), whereas a 0-hole literal `"hi"` synthesizes static `str` (which coerces to `FmtArgs`).

#### SE-13: Closing-Quote Indent-Stripped Multiline Strings, Byte Literals, and Numeric Suffixes

Adopting Swift's multiline string model (`"""…"""`, `r"""…"""`, `r#"""…"""#`, `0` new `TokenKind`s), opening `"""` must be followed immediately by a newline (`E0115`), and closing `"""` must appear on its own line preceded only by spaces $W_{\text{close}}$. Both delimiter newlines are stripped, and $W_{\text{close}}$ is stripped from every non-empty content line at compile time (`E0116` on under-indented lines or mixed leading tabs and spaces, preventing tab-width formatter drift). Unescaped `"` and `""` are valid inside `"""…"""`, and a trailing `\` before `\n` elides the newline for soft line-wrapping.

For wire protocols and parsers, `DR-22` adds `.byte_lit` (`b'A'`, ASCII `0x00..=0x7F` or `\xNN`/`\r`/`\n`/`\t`/`\0`/`\\`/`\'`, `E0117` on non-ASCII, synthesizing **`u8`**) and `.byte_string_lit` (`b"HTTP/1.1\r\n"`, `br#"…"#`, `b"""…"""`, synthesizing `.rodata` **`&[u8; N]`** which coerces to `&[u8]` with interpolation disabled). For numeric literals (`0` new `TokenKind`s), `INT_LIT` accepts `[ _ ](i8|i16|i32|i64|i128|isize|u8|u16|u32|u64|u128|usize|f32|f64)` (`f32`/`f64` on base-10 integers) and `FLOAT_LIT` accepts `[ _ ](f32|f64)`, synthesizing the exact primitive `TypeId` after compile-time range verification (`E0406`). Idiomatic CoreX omits suffixes whenever bidirectional checking ($\Leftarrow$) already knows the target type, uses `_`-separated suffixes (`42_u64`, `1_u64 << shift`, `0.5_f32`, normalized by `corex fmt` from `42u64` → `42_u64`) to disambiguate `let` commit points, and reserves `as` exclusively for converting non-literal expressions (`(i as f32) * 0.5_f32`).

### 2.3 Struct Initialization, Functional Update, Pattern Renaming, and Parallel Assignment (SE-14 and SE-15)

#### SE-14: Mandatory Struct Initialization, Field Defaults, and MVS-Sound Functional Spread

`hir.zig`'s silent zero-initialization of omitted struct fields is removed. Every field lacking a declared `= default_expr` in `StructItem` must be initialized explicitly or supplied by `..base` (`E0432`), and constructing `StructName { … }` or `StructName { .. }` outside a scope where all omitted or private fields are visible (or defaulted) is rejected (`E0433`, protecting private invariants and niche bit-patterns). Writing `Config { .. }` (or `Config { port: 8080, .. }`) evaluates omitted fields' `= default_expr` definitions in declaration order.

In functional struct updates `Config { port: 8080, ..base }` vs. `Config { port: 8080, ..own base }`: if every unmentioned field inherited from `base` is `Copy`, `..base` borrows only those `Copy` fields (`access.let %base.f_k`), leaving `base` completely live in the caller even when an *overridden* field of `base` is `AutoDrop` or `@linear`. Conversely, if any unmentioned inherited field is `~Copy` (`AutoDrop` or `@linear`), the spread requires **`..own base`**: explicit `f_i: e_i` expressions evaluate left-to-right first, unmentioned fields move out (`storage.move %base.f_k`), any *overridden* `AutoDrop` fields of `base` immediately emit `storage.drop %base.f_j`, and overriding an initialized `@linear` field in `..own base` emits `E0304` so linear handles are never silently leaked.

#### SE-15: Struct Pattern Field Renaming and Zero-Unsafe Parallel Destructuring Assignment

In patterns, `FieldPat` supports both shorthand (`let Point { x, var y, &z, &mut w } = p;`) and explicit field renaming or nested sub-patterns (`let Point { x: px, y: 0, .. } = p;`), enforcing field visibility (`E0433`). At statement level, when `lhs = rhs;` has a tuple, array/slice, or struct pattern on the left-hand side (`(a, b) = (b, a);`, `(head, ..) = items;`, `Point { x: a, y: b } = next_pt();`), `Sema` verifies that every non-`_` leaf of `lhs` is a valid mutable place (`E0434` on rvalue expressions like `(a + 1, b) = (1, 2);`, fixing Stage 0's dead-temporary no-op!) and that all `lhs` target paths are pairwise disjoint (`E0305` on `(x, x) = (1, 2);`).

$$\frac{\Gamma; \Theta \vdash e_{\text{rhs}} \Leftarrow \tau_{\text{tup}} \quad \forall i.\; \text{mutable\_place}(\Gamma, p_i) \quad \forall i \neq j.\; p_i \notin \text{Conflict}(p_j)}{\Gamma; \Theta \vdash (p_1, \dots, p_n) = e_{\text{rhs}}; \;\text{valid parallel MVS assignment}} \;(\text{ParAssign})$$

Following Rust `RFC 2909` extended with MVS move-reinitialization (`DR-02` §3.3 Invariant C), `HIR → MIR` lowers `(a.*, b.*) = (b.*, a.*);` in three strict phases: (1) evaluate all `rhs` expressions left-to-right into SSA temporaries (`__r0 = move b.*`, `__r1 = move a.*`); (2) emit `storage.drop` on any `AutoDrop` `lhs` leaf that was *not* moved out during phase (1) (and reject overwriting a live un-moved `@linear` leaf with `E0304`); and (3) store `__r_i` into each `lhs` place (`storage.init`). Generic `swap[T](a: &mut T, b: &mut T)` thus becomes a 1-line safe `(a.*, b.*) = (b.*, a.*);` across `Copy`, `AutoDrop`, and `@linear` types with **zero `unsafe` code**.

### 2.4 First-Class Testing and Fuzzing, Call-Site Locations, and Typed Conditional Compilation (SE-16 through SE-18)

#### SE-16: First-Class test and bench Blocks with DR-18 Fuzz Inputs and O(1) CST Skipping

Replacing `@test fn test_slug()`, CoreX adopts Zig-style prose `test "description" { … }` and `bench "description" (b: &mut Bencher) { … }` declarations, parsed at `Item` level via `LL(2)` contextual `IDENT` `"test"` or `"bench"` (with optional `async` on `test` and leading `@attr` support) immediately preceding `STRING_LIT` (`0` new `TokenKind`s). Test bodies may return `unit` or `unit!E` (allowing direct `?` error propagation). Parameterless `test "…"` blocks run under `corex test` and deterministic `corex test --sim` (`DR-18`), while parameterized `test "…" (frame: PacketFrame)` or `test "…" (raw: &[u8])` blocks automatically register as both structured PRNG property tests and coverage-guided `SanitizerCoverage` fuzz targets under `corex test --fuzz` (`DR-18`). In normal `corex build` and `corex check` invocations (when `--test` / `--bench` is unset), `lowerAst` reads `CstNode.subtree_size` (`DR-12`) and jumps past the entire `TestItem` / `BenchItem` in **O(1) time** with zero AST, `TypeArena`, or `MIR` work.

#### SE-17: Zero-Cloning .rodata Call-Site Location Default (@caller_location)

Modeled on Odin's `#caller_location` and Zig's `@src()`, `core.SourceLoc` is an 8-byte `Copy` descriptor wrapping a static `.rodata` pointer to `{ file: str, fn_name: str, line: u32, col: u32 }` (with inline `.file`, `.fn_name`, `.line`, and `.col` accessors). When `@caller_location()` is written as a parameter's default expression (`pub fn assert(cond: bool, msg: FmtArgs = "", *, loc: SourceLoc = @caller_location())`), `AST → HIR` evaluates `@caller_location()` **at the caller's call-site `Span`**, passing a single 64-bit `.rodata` pointer in a register with **zero generic monomorphization cloning** (unlike Rust's `#[track_caller]` shim duplication) and zero hidden ABI cost on functions that do not request `SourceLoc`.

#### SE-18: Native Statically Typed Boolean Conditional Compilation (@cfg)

`@cfg(expr)` evaluates a standard CoreX boolean expression (`and`, `or`, `not`, `==`, `!=`, `is`) at `comptime` against `core.target` (`os: Os`, `arch: Arch`, `abi: Abi`, `endian: Endian`, `ptr_width: u16`, `cpu_has(CpuFeature)`) and `cfg` (`debug: bool`, `test_mode: bool`, `sim_mode: bool`, `fuzz_mode: bool`, plus `cfg.feature.<ident>` checked against `corex.toml` `[features]`). Unlike Rust's `#[cfg(all(unix, not(...)))]` stringly-typed predicate DSL, `@cfg(target.os is (.Linux | .Macos) and target.ptr_width == 64)` uses CoreX's exact expression grammar, catches misspelled OS/arch variants or undeclared features immediately (`E0408` / `E0435`), formats cleanly in `corex fmt` via `LosslessCstArena`, and skips false items/statements in O(1) via `CstNode.subtree_size`.

### 2.5 Phase 8–13 Seam Completeness and Global Cross-Language Scout (SE-19 through SE-23)

#### SE-19: Three-Tier Callable and Closure Types and Attribute-Prefixed Closures

CoreX cleanly separates three callable representations in `Type` and `Expr`: (1) **`fn(A) -> B`** (8-byte stateless code pointer, `Copy`, `0x0` niche; any non-capturing `|x| expr` coerces $\le_{\text{coerce}} \texttt{fn(A) -> B}$ automatically); (2) **`|A| -> B`** (`||` for zero-arg `unit`, 16-byte stack-bound `@local` non-escaping closure `{ code_ptr, env_ptr }` capturing outer places via `access.let` / `access.inout` and inlining transparently across `.await` per `DR-08` §1.3); and (3) **`own |A| -> B`** (24-byte `AutoDrop` / `@linear` escaping closure `{ code_ptr, env_ptr, drop_fn }` constructed via `own |x| { … }`, capturing outer variables by MVS `storage.move`). `ClosureExpr` accepts leading `{ Attribute } [ "own" ] [ "async" ]` (`@cold |err| …`, `@inline |x| …`).

#### SE-20: async Closures and Single-Inference cx.async.task_group Nurseries

`ClosureExpr` and `ClosureType` support `async` (`async || { … }`, `async |group| { … }`). Streamlining `DR-08`'s verbose 3-parameter `with_task_group[T, E, R]`, **`TaskGroup[E]`** is parameterized solely by the nursery's error type `E` (inferred from the `async |group|` closure's `R!E` return or enclosing `?`), while `group.spawn_local(async { … })` and `group.spawn(own async { … })` return heterogeneous `@linear` **`TaskHandle[T]`** handles (`handle.join().await? -> T`, with `TaskGroup` scope exit canceling and reaping all unjoined handles on early `?` error per `DR-08` §2.1 & `DR-20` `Fix-08B`).

#### SE-21: Formalized MVS subscript / yield Bundles and Multi-Index Expressions

Adding `.kw_subscript` (`"subscript"`) and `.kw_yield` (`"yield"`) (with `"inout"` parsed as a contextual `IDENT` arm introducer inside `subscript { … }`) locks `DR-02`, `DR-06`, and `DR-20` `Fix-06B` coroutine element projections. A `subscript(row: usize, col: usize, /) -> T` bundle defines `let { yield …; }` and optional `inout { yield &mut …; }` arms, each executing **exactly one** `yield` along every non-diverging path. Multi-argument indexing `mat[r, c]` resolves to `subscript`, selecting `inout` on mutable places (`mat[r, c] += 1.0;`, `&mut mat[r, c]`) and `let` on reads, inlining non-recursive subscripts to direct pointer offsets or `bit_field` register extract/writeback `defer` blocks (`DR-20` `Fix-06B`) with zero coroutine frame allocation.

#### SE-22: Scoped @builder Trailing Blocks and @constructor PascalCase UI Structs

In `DR-15` §1.3 (`std::ui`), declaring `pub fn Card(…)` violated `DR-03`'s `snake_case` function rule (`W0201`), while `children: || -> View` lacked a typed mechanism to accumulate multiple child statements `{ Text("a"); Badge("b"); }` without Swift `@resultBuilder`'s deeply nested generic `TupleView` compile-time blowup. CoreX solves both cleanly: marking an associated constructor `@constructor` on `struct Card` (`impl Card { @constructor pub fn init(padding: u16 = 12, …, children: @builder |&mut UiScope|) -> View }`) lets `Card(padding: 16) { … }` invoke `Card.init` with **zero `W0201` casing warnings**. Inside a trailing `{ … }` block checked against `@builder |&mut Scope|`, `Sema` binds an implicit lexical `__builder: &mut Scope` and threads it as argument 0 into every `@builder_item` call (`Text`, `Badge`, `Row`, `Column`, `Button`, emitting `E0436` if called outside an active `Scope` block), appending `ViewNode` descriptors linearly into the frame's 64 KiB `BumpArena` tape (`DR-15` §3.2) while keeping native `if`/`else`, `match`, `for`, and `let` statements 100% ordinary `.cx` code.

#### SE-23: Zig-Inspired Labeled match Finite-State-Machine Dispatch

Scouted from Zig 0.14–0.16's labeled `switch`, `MatchExpr` accepts an optional `IDENT ":"` prefix (`fsm: match State.SkipWs { … }`, parsed at `LL(3)` identically to `SE-06` labeled loops with **zero new `TokenKind`s**). Inside `fsm: match expr`, executing **`continue :fsm next_state`** verifies that `:fsm` targets an enclosing labeled `match` and includes `next_state` (`E0437` otherwise), checking `next_state` top-down against the scrutinee type ($\Leftarrow \tau_{\text{scrut}}$, `E0401` on mismatch):

$$\frac{(\ell_{\text{match}} : \tau_{\text{scrut}}) \in \Gamma_{\text{labels}} \quad \Gamma; \Theta \vdash e_{\text{next}} \Leftarrow \tau_{\text{scrut}} \dashv \Theta'}{\Gamma; \Theta \vdash (\mathsf{continue}\; \text{:}\ell_{\text{match}}\; e_{\text{next}}) \Rightarrow \mathsf{never} \dashv \Theta'} \;(\text{MatchContinue}\Rightarrow)$$

During `MIR` lowering, `continue :fsm .InToken` with a constant constructor jumps directly to `.InToken`'s basic block (zero tag re-dispatch), while a dynamic `continue :fsm next` jumps through an inline dispatch table – giving **Phase 11–12** byte lexers, UTF-8 DFA validators, and HTTP/JSON parsers C computed-`goto` speed with full compile-time `match` exhaustiveness and MVS typestate verification.

pub fn scan_http_token(raw: &[u8], /) -> usize? {

        }
