# Forward-Compatible Phase-7 Hot-Reload Seam, Stateful Live Code Patching, Target-Verified SIMD Contracts, and Multi-Node Simulation Specification for CoreX

To retire the disposable Stage-0 Zig bootstrap compiler (`stage0/corex`) as rapidly as possible at `v0.0.1` (`Phases 6–12`) while unlocking sub-50ms stateful live code patching (`corex run --watch`), hardware-verified SIMD loop contracts (`@must_vectorize`), and multi-node deterministic crash-consistency simulation (`corex test --sim`) in `Phase 13` (`0.x`) with **zero backend or IR rewrites**, CoreX partitions `DR-19` across two strict architectural tiers. First, during `Phase 7`, CoreX embeds a modeled **148-LOC forward-compatible binary and metadata seam** (`< 200 LOC` budget) into `--dev` builds while pruning `DR-20`'s estimated `~22,000 LOC` of disposable Stage-0 Zig native emission and binary-patching code (`Prune-01`) from the pre-`v0.0.1` critical path. In `--dev` mode, all indirect function pointers, closures, coroutine poll tables, and `dyn Trait` vtables route through immutable `.text.cx_thunk` trampolines backed by a writable `.cx_got` jump table; `CompilerDb` emits 32-byte `CxTypeLayoutRecord` descriptors pairing physical `LayoutShapeKey` with a recursive semantic `FieldHash64` (`TypeLayoutHash`); `MIR` loop headers carry an 8-byte `LoopContractMeta` payload; and `std::runtime::poll_reload(&mut app_state)` establishes an MVS-verified quiescent epoch safepoint. In `--release` builds (`-O2`, `-O3`, `-Oz`), every component of this seam is stripped completely, imposing **zero instructions, zero indirect branches, and zero binary-size overhead**.

Second, once Stage-0 Zig is retired in `Phase 12`, `Phase 13` plugs directly into these seams inside the self-hosted `.cx` compiler (`src/compiler/*.cx`). In **`Phase 13.0`**, the self-hosted Tier C single-pass machine-code emitter (`16-byte` `ValueAssignment` TPDE-style lowering, modeled on TPDE's `8x–24x` compilation speedup over `LLVM -O0`) streams ASLR-relocated code patches from the `corex run --watch` supervisor daemon into running `--dev` processes within a modeled **2.55–20.13 ms** end-to-end latency budget across Linux (`mprotect` / `memfd_create` + `membarrier` `SYNC_CORE`), macOS Apple Silicon (`MAP_JIT` + `pthread_jit_write_protect_np` + `sys_icache_invalidate` + `SIGKILL`-safe `UnlinkAndReplace` disk updates), and Windows (`VirtualProtect` + `RtlAddGrowableFunctionTable` dynamic unwind registration without `.exe`/`.pdb` file-lock collisions). Because `poll_reload(&mut app_state)` acquires an exclusive MVS `inout` projection (`access.inout`) at root event-loop boundaries, `DR-06` Pass 2 statically verifies at compile time that zero interior borrows, `subscript`/`yield` projections, or child `TaskGroup` references alias `app_state` during a patch swap – preserving live `AppState`, `BumpArena` slabs, `SlotMap` UI trees, and `@linear` OS handles whenever reachable `FieldHash64` digests match, and executing a zero-dropped-connection restart via inherited listener sockets when layouts change.

In **`Phase 13.2`** and **`Phase 13.3`**, `corex` activates target-parameterized `@must_vectorize` verification and multi-node deterministic simulation without modifying `Phases 0–5` surface grammar. For `@must_vectorize`, a fast Stage-A `MIR` structural pre-check runs in both `--dev` and `--release` (eliminating `--dev` false-positive brittleness while catching non-associative float reductions and loop-carried dependencies immediately), paired in `--release` and `corex lsp` with an in-process C++ `llvm::DiagnosticHandler` in `src/corex_llvm.cpp` that delays pre-vectorization full unrolling (`!llvm.loop.unroll.disable` + `followup_all`) and emits Pentagon-proven `dereferenceable` assumptions to unlock LLVM 21–23 early-exit SIMD across `AVX2`/`AVX-512`, `NEON`/`SVE`, and `wasm32` `SIMD128`. For distributed and storage systems, `SimCluster` multiplexes `N` isolated virtual nodes over Phase 8's `Context.reactor` (`ReactorVTable`) in a modeled `13.38 MiB` of Copy-on-Write RAM (for a 5-node cluster at 15% dirty blocks vs. `80.0 MiB` unshared), pairing an asymmetric packet-fault matrix with a three-layer volatile OS page-cache, parent-directory `fsync`, and `512 B`/`4 KiB` torn-write NVMe simulator governed by TigerBeetle VOPR-style **Safety-to-Frozen-Liveness** transition gates.

### 1.2 Canonical Binary Metadata Records and Recursive FieldHash64 Formulation

A subtle soundness hazard in naive hot-reloading compilers arises when layout equivalence is checked solely using physical ABI shape (`LayoutShapeKey`: total byte size, alignment, padding intervals, and scalar register classes). Suppose a developer refactors `pub struct Vec2 { pub x: f32, pub y: f32 }` into `pub struct Vec2 { pub y: f32, pub x: f32 }`, or replaces `pub user_id: u64` with `pub timestamp_ns: u64`. Because `TypeLayoutResolver` (`DR-09` §1.1) produces the exact same 8-byte physical `ResolvedTypeLayout` before and after the edit, a physical-only hash would permit an in-place code patch while live `AppState` arenas still hold `(x, y)` in the old semantic slot order – silently swapping coordinates or reinterpreting user IDs as timestamps.

CoreX prevents semantic layout confusion by persisting **both** `layout_shape_hash64: u64` (`Wyhash(0)` 64-bit digest over Stage-0's 16-byte `LayoutShapeKey`, shared with `.cxi` ABI records and `Phase 13.2` `D-09` `@fbip` slot reuse) and `field_hash64: u64` (the canonical **`TypeLayoutHash`** for hot-reload state compatibility) inside every 32-byte `CxTypeLayoutRecord`. Using CoreX's deterministic `Wyhash(0)` primitive (`DR-01` §4.1), `FieldHash64` is defined recursively over the `InternPool` type DAG (breaking cycles on pointer or generational-key indirections `OwnPtr[T]` and `SlotKey[T]` via nominal FQN hash so recursive trees terminate in O(1) depth):

$$\text{FieldHash64}(\tau) = \text{Wyhash}_0\!\left(\text{Tag}(\tau) \;\|\; \text{FQN}(\tau) \;\|\; \text{OwnTier}(\tau) \;\|\; \text{LayoutShapeKey}(\tau) \;\|\; \bigoplus_{i=0}^{k-1} \Big(\text{MemberName}_i \;\|\; \text{PhysOffset}_i \;\|\; \text{Discrim}_i \;\|\; \text{FieldHash64}(\tau_i)\Big)\right)$$

Under this formulation, `FieldHash64` remains invariant across edits to function bodies, method implementations, trait `impl` logic, non-capturing or capture-identical closures, loop bodies, and inline string/theme literals, while changing immediately whenever any struct field or enum variant is added, removed, reordered, renamed, re-typed, niche-shifted, `#soa`-transposed, or moved across ownership tiers (`Copy`, `AutoDrop`, `@linear`).

Every record emitted into the `--dev` binary's metadata sections uses explicit fixed-width fields with **zero implicit alignment padding** (`@bitSizeOf(T) == @sizeOf(T) * 8`):

### 1.3 Stable GOT Thunk Indirection and Quiescent Epoch Safepoint Protocol

A recurring failure mode in C/C++ shared-library hot-reloaders (`dlopen`/`LoadLibrary` plugins such as `cr.h`) arises whenever persistent application state stores a function pointer (`fn(&mut AppState)`), an escaping `own` closure, or a `dyn Trait` fat-pointer vtable: if those pointers hold raw `.text` virtual addresses inside an old code module, unloading or replacing that module leaves dangling function pointers inside `AppState` and `SlotMap` widget arenas. CoreX eliminates stale callable pointers structurally at the Phase-7 seam via **Permanent Base-Image Thunk Canonicalization**.

In `--dev` builds, every direct call to a non-`@extern` CoreX function routes through `.cx_got[got_idx]` (`call qword ptr [rip + __cx_got + got_idx * 8]` on `x86_64`, `adrp x16, __cx_got@PAGE; ldr x16, [x16, __cx_got@PAGEOFF + got_idx * 8]; blr x16` on `aarch64`, and `i32.const got_idx; call_indirect` on `wasm32`). Crucially, whenever a function's address is taken as a value (`MirOp.fn_addr`), stored inside a `dyn Trait` vtable, bound to an escaping `own` closure invoke pointer, or indexed in `DR-08`'s `CoroPollDispatchTable` (`TaskHeader.poll_fn_id: u16`), the `--dev` emitter **never** exposes the mutable `Atom`'s `.text` body address. Instead, it materializes the address of a permanent, immutable 8-to-16-byte trampoline stub `__cx_thunk_<got_idx>` placed inside `.text.cx_thunk` of the initial launch binary (`endbr64; jmp qword ptr [rip + __cx_got + got_idx * 8]` on `x86_64`; `bti c; adrp x16, …; ldr x16, …; br x16` on `aarch64`). Because `.text.cx_thunk` never moves for the lifetime of the process, every function pointer, UI button callback in `SlotMap`, and `dyn Trait` object stored inside persistent `AppState` remains permanently valid across unlimited hot-patch epochs while immediately dispatching to updated machine code as soon as `.cx_got[got_idx]` is overwritten.

At runtime, applications and standard event-loop frameworks (`std::ui`, `std::tui`, and `std::http`) invoke `std::runtime::poll_reload(&mut app_state)` once per top-level frame or reactor tick when synchronous call depth above the event loop is zero. Requiring `&mut app_state` (`access.inout` in `DR-06`) lets the compiler's existing Phase-6 SAST pass verify with zero extra rules that no active `&T` or `&mut T` projection into `app_state` survives across the patch boundary.

The Stage-0 Zig implementation of the Phase-7 seam (`stage0/src/codegen_dev_seam.zig`) is specified below, preserving 1-to-1 mechanical translation into `src/compiler/codegen_dev_seam.cx` (`DR-01` §4.2):

```zig
//! CoreX Stage-0 Compiler (`stage0/corex`) – Phase-7 Forward-Compatible Seam
//! Module: `stage0/src/codegen_dev_seam.zig` (< 200 LOC total Phase-7 budget)
//! Emits `.cx_got` metadata, `{TypeId, layout_shape_hash64, field_hash64}` records,
//! `.cx_dev_ctrl` safepoint block, and `LoopContractMeta` for Phase-13 plug-in.

const std = @import("std");
const assert = std.debug.assert;
const mem = @import("mem_foundation.zig");
const query_db = @import("query_db.zig");

/// Re-exported canonical 32-bit `TypeId` handle.
pub const TypeId = mem.TypeId;
/// Re-exported workspace-global 32-bit `DefId` handle.
pub const DefId = query_db.DefId;
/// Re-exported canonical 32-bit `DiagId` handle.
pub const DiagId = mem.DiagId;

// ---------------------------------------- TYPES ----------------------------------------

/// 64-byte header emitted at offset +0 of `.cx_dev_meta` in `--dev` builds only.
pub const CxDevSeamHeader = extern struct {
    magic: [8]u8 = .{ 'C', 'X', 'D', 'E', 'V', '0', '1', 0 },
    seam_version: u16 = 1,
    arch_os_tag: u16,
    seam_flags: u32,
    got_slot_count: u32,
    type_record_count: u32,
    static_root_count: u32,
    loop_contract_count: u32,
    build_id_lo: u64,
    build_id_hi: u64,
    got_rva: u64,
    ctrl_block_rva: u64,
};

/// 24-byte descriptor per indirect `.cx_got[got_idx]` callable / vtable / poll slot.
pub const CxGotSlotMeta = extern struct {
    def_id: DefId,
    got_idx: u32,
    abi_sig_hash64: u64,
    flags: u16,
    slot_kind: SlotKind,
    pad0: u8 = 0,
    atom_alloc_cap: u32 = 0,

    /// Callable category dispatched through `.cx_got[got_idx]`.
    pub const SlotKind = enum(u8) {
        direct_fn = 0,
        closure_invoke = 1,
        trait_vtable_entry = 2,
        coro_poll_fn = 3,
    };
};

/// 32-byte layout equivalence record persisted in `CompilerDb` and `.cx_dev_meta`.
/// Pairs physical `layout_shape_hash64` (ICF/FBIP) with semantic `field_hash64` (hot-reload).
pub const CxTypeLayoutRecord = extern struct {
    type_id: TypeId,
    byte_size: u32,
    align_log2: u8,
    kind_flags: u8,
    fields_len: u16,
    fqn_hash32: u32,
    layout_shape_hash64: u64,
    field_hash64: u64,
};

/// 8-byte SIMD contract payload stored on `MirLoopHeader` (`DR-20` Seam #4).
pub const LoopContractMeta = extern struct {
    contract_flags: Flags = .{},
    target_override_mask: u8 = 0,
    min_lanes: u16 = 0, // 0 = canonical target vector width / sizeof(elem).
    diag_id: DiagId = .none,

    /// Packed boolean flags governing `@must_vectorize` Stage-A and Stage-B checks.
    pub const Flags = packed struct(u8) {
        is_must_vectorize: bool = false,
        has_predicated_early_exit: bool = false,
        is_scalable_allowed: bool = true,
        is_slp_unroll_allowed: bool = true,
        has_reassoc_fp_reduce: bool = false,
        _reserved: u3 = 0,
    };
};

/// 64-byte runtime safepoint control block emitted into `.cx_dev_ctrl` (aligned to 128 B).
pub const CxReloadControlBlock = extern struct {
    pending_patch_gen: u64 = 0,
    applied_patch_gen: u64 = 0,
    ipc_shm_offset: u64 = 0,
    active_workers: u32 = 1,
    arrived_workers: u32 = 0,
    reload_action: u32 = 0,
    status_flags: u32 = 0,
    root_state_addr: u64 = 0,
    root_type_id: u32 = 0xFFFF_FFFF,
    patched_fn_count: u32 = 0,
    root_field_hash64: u64 = 0,
};

// ------------------------------------- PUBLIC API --------------------------------------

/// Deterministic semantic `TypeLayoutHash` (`Wyhash` seed = 0) detecting field renames,
/// swaps, offset shifts, enum discriminant changes, and ownership tier changes.
pub fn computeFieldHash64(
    fqn_bytes: []const u8,
    ownership_tier_flags: u8,
    layout_shape_hash64: u64,
    member_hashes: []const u64,
) u64 {
    var hasher = std.hash.Wyhash.init(0);
    hasher.update(fqn_bytes);
    hasher.update(&[_]u8{ownership_tier_flags});
    hasher.update(std.mem.asBytes(&layout_shape_hash64));
    hasher.update(std.mem.sliceAsBytes(member_hashes));
    return hasher.final();
}

comptime {
    assert(@sizeOf(CxDevSeamHeader) == 64);
    assert(@bitSizeOf(CxDevSeamHeader) == 64 * 8);
    assert(@sizeOf(CxGotSlotMeta) == 24);
    assert(@bitSizeOf(CxGotSlotMeta) == 24 * 8);
    assert(@sizeOf(CxTypeLayoutRecord) == 32);
    assert(@bitSizeOf(CxTypeLayoutRecord) == 32 * 8);
    assert(@sizeOf(LoopContractMeta) == 8);
    assert(@sizeOf(CxReloadControlBlock) == 64);
    assert(@bitSizeOf(CxReloadControlBlock) == 64 * 8);
}
```

## 2. Deliverable 2: Phase-13 Cross-Platform Stateful Live Hot-Reloading Architecture and MVS Soundness Proof

In `Phase 13.0`, live code patching links the resident `corex run --watch` compiler daemon directly to the running `--dev` child process across a shared-memory patch stream, separating immutable base-image call thunks from an append-only 2-epoch `W^X` code slab and enforcing hardware Cross-Modifying Code (CMC) barriers across Linux, macOS Apple Silicon, and Windows.

> **▸ Architectural Summary – Permanent Base-Image Thunks & Epoch Safepoints**
> During `corex run --watch`, function pointers, closures, and trait vtables inside persistent `AppState` and `SlotMap` arenas point exclusively to permanent `.text.cx_thunk` base-image trampolines rather than mutable code addresses. At a quiescent `poll_reload(&mut app_state)` frame boundary, worker threads park at an epoch barrier while Coordinator Thread 0 toggles `W^X` page permissions, writes new machine code into Epoch `E + 1`, flushes split instruction caches, and atomically flips `.cx_got` slots.

### 2.1 Supervisor-to-Target IPC Protocol and Sub-50ms Incremental Patch Pipeline

Invoking `corex run --watch` launches a long-lived **Compiler & Watch Supervisor** process (`CompilerDb`, `InternPool`, fine-grained declaration dependency graph, and Tier C single-pass emitter kept warm in RAM) that spawns the compiled `--dev` target executable as a supervised child process connected via two inherited OS handles. The first handle, `COREX_WATCH_IPC_FD`, is a bidirectional, message-framed local control channel (`socketpair` Unix domain socket on Linux and macOS; overlapped Named Pipe on Windows) modeled on Zig `#20604`'s build-watch communication channel and Dioxus Subsecond's ASLR handshake. The second handle, `COREX_WATCH_SHM_FD`, is a zero-copy shared-memory staging buffer (`memfd_create` on Linux, POSIX `shm_open` on macOS, file-mapping section handle on Windows) through which the supervisor streams compiled machine code, read-only constant islands, `.cx_got` delta pairs `(got_idx, new_vaddr)`, and unwind descriptors without socket buffer copies.

Before invoking `main()`, the `--dev` startup shim `__cx_dev_runtime_init()` reserves a single `64 MiB` virtual **JIT Patch Slab** (`W^X` virtual address region, placed within `±2 GiB` of `__ehdr_start` / `__mh_execute_header` / `__ImageBase` where the OS virtual memory manager permits) and transmits a 48-byte `MsgTargetHello` frame over `COREX_WATCH_IPC_FD` reporting `{ pid, build_id_128, image_base_vaddr, jit_slab_base_vaddr, worker_count }`. Because the supervisor knows the exact runtime virtual addresses of `.cx_got`, `.data`/`.bss` statics, and `jit_slab_base_vaddr` inside the live child process, **Phase 13.0 Tier C emits fully relocated native `x86_64` and `aarch64` instructions directly for their destination address inside `jit_slab_base_vaddr`**, avoiding in-target relocation loops.

Across the modeled **2.55–20.13 ms** end-to-end latency budget for a single-function edit in a 100k-LOC workspace, the supervisor pipeline (Stages 1–5) accounts for **2.30–10.60 ms** prior to target synchronization (`0.20–1.20 ms` for Stage 6 IPC/W^X/I-cache flush and `0.05–8.33 ms` for Stage 7 safepoint arrival at 120 Hz):

1.  **OS File-Watch Delivery (`0.20–1.50 ms`):** `inotify` (Linux), `kqueue` / FSEvents (macOS), or Windows file-change notifications deliver the modified `.cx` path to the warm supervisor daemon.
2.  **Incremental Lex & CST/AST Reparse (`0.30–1.20 ms`):** Reparses only the edited `.cx` file into a flat postorder syntax tree (`DR-01` §2.2); if token and declaration hashes of unchanged items match `CompilerDb`, downstream queries short-circuit via BLAKE3 Early Cutoff.
3.  **Dirty `DefId` Sema & 4-Pass `MIR` SAST (`1.50–6.00 ms`):** Re-runs bidirectional type checking and `DR-06` Passes 1–4 (using `DR-20` `Fix-06A` `Intv`-first filtering + Sparse ABCD demand-sliced Pentagon `MAX_SUB_VARS = 256`) strictly on invalidated functions.
4.  **Reachable `FieldHash64` & `AbiFnRecipe` Diff Classification (`0.10–0.40 ms`):** Compares the new `CxTypeLayoutRecord` table against the running epoch's active type closure: if all reachable `field_hash64` values match, the supervisor selects **`OpApplyInPlace`** (`reload_action = 1`); if root `AppState` and static `field_hash64` values match while an active `async fn` altered its `CoroFrameHash64`, it selects **`OpDrainCorosAndApply`** (`reload_action = 2`); and if any reachable `struct`, `enum`, `#soa` slice, closure environment, `dyn Trait` vtable shape, or `static`/`@thread_local` layout changed `field_hash64`, it selects **`OpCleanRestart`** (`reload_action = 3`) and logs the exact modified `TypeId` and field name.
5.  **Tier C Single-Pass Native Emission (`0.20–1.50 ms`):** Compiles only dirty `MirBody` functions into the shared patch buffer using a 32-byte `IpcPatchHeader`, advances `.cx_dev_ctrl.pending_patch_gen`, and signals `COREX_WATCH_IPC_FD` (registered inside each core's `io_uring` / `kqueue` / `IOCP` completion ring so idle event loops wake in `< 50 µs` without polling timers).

#### Critical Multi-Core Cross-Modifying Code (CMC) Synchronization Sequence

As established in OpenJDK HotSpot's multi-core CMC engineering analysis, updating machine instructions and `.cx_got` pointers from Coordinator Thread 0 while Worker Threads `1 … W - 1` execute on other CPU cores requires both a **CMC-release** on the patching thread and a **CMC-acquire** on every executing thread – particularly on weakly ordered ARM64 processors where speculative instruction prefetching can execute stale pre-barrier pipeline state unless every core executes an Instruction Synchronization Barrier (`isb`). CoreX coordinates multi-core `Thread-Per-Core` reactors (`DR-08` §4.1) via a four-step **Epoch Rendezvous** inside `__cx_reload_safepoint_slow()`:

1.  **Worker Quiescence Arrival:** Each core reactor `worker_idx` in `0 .. worker_count` hits `poll_reload()` at stack depth `0` (between CQE poll batches or UI frames), atomically increments `ctrl.arrived_workers` (`AcqRel`), and parks on `ctrl.applied_patch_gen` for non-coordinator workers (`worker_idx != 0`).
2.  **CMC-Release & Atomic GOT Commit (Coordinator Thread 0):** Once `arrived_workers == active_workers`, Thread 0 writes the new `Atom` machine code and `.rodata.patch` constants into the uncommitted `Epoch E + 1` slice of the `64 MiB` slab (never overwriting `Epoch E` code pages in place while any frame or profiler sample could reference them), restores `R-X` protection (`pthread_jit_write_protect_np(1)` / `mprotect` / `VirtualProtect`), invalidates instruction caches (`sys_icache_invalidate` on macOS; `dc cvau` + `ic ivau` on Linux ARM64), registers sorted dynamic unwind entries (`RtlAddGrowableFunctionTable` on Windows), and updates each modified `.cx_got[got_idx]` slot via atomic 64-bit `Release` stores.
3.  **Global Core Serialization:** On Linux, Thread 0 invokes `membarrier(MEMBARRIER_CMD_PRIVATE_EXPEDITED_SYNC_CORE, 0)`; Thread 0 then stores `ctrl.applied_patch_gen = E + 1` (`Release`) and wakes parked workers.
4.  **Worker CMC-Acquire:** Before returning from `__cx_reload_safepoint_slow()`, every waking worker thread executes an explicit hardware pipeline synchronization barrier (`isb` on `aarch64`; `atomic_thread_fence(seq_cst)` + serializing instruction such as `cpuid` on `x86_64` when kernel `SYNC_CORE` is not active).

### 2.3 Resolution of Live-Patching Hazards and Zero-Downtime Restart Handoff

CoreX resolves all five stateful hot-reloading hazards documented across C++ `Live++`, Rust `Subsecond` / `Blinc`, and Erlang BEAM. First, to eliminate **active stack-frame return hazards**, CoreX combines `poll_reload(&mut app_state)` placement at the top-level event-loop tick (where zero synchronous application callee frames remain on the stack) with Erlang BEAM's two-version (`current` and `old`) code retention discipline: the `64 MiB` JIT slab partitions into **Active (`Epoch E + 1`)** and **Retiring (`Epoch E`)** regions, keeping `Epoch E` mapped `R-X` until `Epoch E + 2` so even asynchronous OS profiler stack walks complete safely.

Second, for **suspended stackless coroutines (`AsyncFrame[F]`)**, `DR-08` stores suspended tasks inside pooled `64 KiB` `BumpArena` slabs indexed by `TaskHeader { state_idx: u16, poll_fn_id: u16, pin_ref_count: u16 }`. `CompilerDb` computes a dedicated `CoroFrameHash64` over `(CoroFrameLayout, [suspend_0 … suspend_{K-1}] live-spill sets)`. Editing any synchronous helper called *between* `.await` points leaves `CoroFrameHash64` unchanged so `.cx_got` patches instantaneously while all suspended connections stay live; if an `async fn` itself is modified across `.await` points (`CoroFrameHash64` changed) while `pin_ref_count > 0`, `OpDrainCorosAndApply` cancels or drains the affected `TaskGroup` using `DR-08`'s **Two-Phase Cancellation Protocol** + `DR-20` `Fix-08B` `CompletionReaper` (running old `CancelDestroy` cleanup blocks and closing any raced `cqe.res >= 0` sockets inside `InFlightOpTable`) before activating the new `poll_fn_id` entry.

Third, **escaping `own` closures and `dyn Trait` vtables** use deterministic `InstanceKey` identity (`(enclosing_fn_fqn, lexical_closure_ordinal)`, analogous to Blinc's caller-keyed stateful widget hooks) routed through `.text.cx_thunk` trampolines. Modifying a UI callback's body without altering its captured variable types updates `.cx_got[closure_got_idx]` in place while preserving widget state inside `SlotMap`; adding or retyping a captured variable changes `ClosureEnv`'s `field_hash64`, triggering a clean restart rather than reading shifted capture offsets.

Fourth, CoreX solves **mutable static and `@thread_local` address instability** – a bug documented in `DioxusLabs/dioxus#5237` (January 2026), where recompiling a Rust crate for hotpatching emitted local `static` variables as defined symbols at new addresses rather than binding to the base image's address. In CoreX, `CompilerDb` pins every existing module-level `Atomic*`, `Shared[Mutex[T]]`, and `@thread_local` variable to its **initial launch-binary RVA or TLS offset**; when Tier C compiles a patch (or mutates imported Wasm globals on `wasm32`), references to existing statics bind directly to `image_base + pinned_rva`, ensuring `(&STATIC_COUNTER) as usize` never drifts across patches. Meanwhile, modified inline string/style literals inside patched functions emit into `.rodata.patch` inside the JIT slab so UI labels, shaders, and TUI styles update live, whereas adding a brand-new `@thread_local` variable or altering an existing static's `FieldHash64` triggers a clean restart (matching `Live++`'s TLS safety boundary).

Fifth, **`@linear` OS handles (`File`, `TcpSocket`, `IoBuf`, `Arena`, GPU surfaces)** remain untouched in memory across every `OpApplyInPlace` swap. When a `FieldHash64` mutation mandates `OpCleanRestart`, `poll_reload` returns `.RestartRequired`, allowing the root scope to execute all lexical `defer` cleanup blocks cleanly (`arena.release()`, `file.close()`). For network servers (`std::http` / `std::net`), the `corex run --watch` supervisor retains bound listener sockets across the restart – using inherited listener file descriptors via the `LISTEN_FDS` socket-activation protocol on Linux and macOS, and `WSADuplicateSocketW` (`WSAPROTOCOL_INFOW` shared socket transfer, paired with `WSA_FLAG_NO_HANDLE_INHERIT` on non-listener sockets so child processes never hang parent `closesocket` calls) on Windows. During the ~15–35 ms process swap, the OS kernel TCP listen queue buffers incoming client `SYN` packets seamlessly with **zero dropped connections**.

The self-hosted `.cx` target runtime patcher (`src/runtime/hot_reload.cx`) implements this safepoint protocol:

```rust
// File: src/runtime/hot_reload.cx (Phase 13.0 Self-Hosted Runtime)
mod hot_reload;

use std::atomic::{AtomicU32, AtomicU64, Ordering, cpu_icache_sync_acquire};
use std::build;

/// Runtime safepoint control block (`64B` on `x86_64`, `128B` on `aarch64-macos` per `D-10A`).
@repr(C)
@cache_aligned
pub struct CxReloadControlBlock {
    pub pending_patch_gen: AtomicU64,
    pub applied_patch_gen: AtomicU64,
    pub ipc_shm_offset: u64,
    pub active_workers: AtomicU32,
    pub arrived_workers: AtomicU32,
    pub reload_action: u32,
    pub status_flags: u32,
    pub root_state_addr: u64,
    pub root_type_id: u32,
    pub patched_fn_count: u32,
    pub root_field_hash64: u64,
}

/// Action returned to the top-level event loop after a `poll_reload` safepoint check.
pub enum ReloadOutcome {
    Unchanged,
    Patched { epoch: u64, fns_updated: u32 },
    RestartRequired { changed_type_id: u32 },
}

/// Checks for a pending `corex run --watch` patch at a quiescent `&mut S` (`access.inout`) boundary.
/// `DR-06` Pass 2 statically guarantees zero interior borrows into `app_state` survive across this call.
@inline(always)
pub fn poll_reload[S](app_state: &mut S) -> ReloadOutcome {
    comptime if !build::IS_DEV_MODE {
        let _ = app_state;
        return .Unchanged; // Compiles to 0 instructions in `--release`.
    }
    unsafe {
        let ctrl = __cx_get_dev_ctrl_block();
        if @likely(ctrl.pending_patch_gen.load(.Acquire) == ctrl.applied_patch_gen.load(.Relaxed)) {
            return .Unchanged;
        }
        return safepoint_apply_slow(ctrl, (app_state as *mut S) as u64);
    }
}

/// Cold multi-worker epoch rendezvous, `W^X` code-slab write, and hardware CMC barrier.
@cold
unsafe fn safepoint_apply_slow(
    ctrl: *mut CxReloadControlBlock,
    state_addr: u64,
) -> ReloadOutcome {
    ctrl.root_state_addr = state_addr;
    let total_workers = ctrl.active_workers.load(.Acquire);
    let ticket = ctrl.arrived_workers.fetch_add(1, .AcqRel) + 1;

    if ticket == total_workers {
        // Coordinator thread; apply `W^X` slab write, I-cache flush, unwind reg, and GOT swap:
        if ctrl.reload_action == 3 {
            ctrl.arrived_workers.store(0, .Release);
            ctrl.applied_patch_gen.store(ctrl.pending_patch_gen.load(.Relaxed), .Release);
            __cx_wake_all_workers(&ctrl.applied_patch_gen);
            return .RestartRequired { changed_type_id: ctrl.root_type_id };
        }
        __cx_os_apply_shm_patch_and_flip_got(ctrl);
        ctrl.arrived_workers.store(0, .Release);
        ctrl.applied_patch_gen.store(ctrl.pending_patch_gen.load(.Relaxed), .Release);
        __cx_wake_all_workers(&ctrl.applied_patch_gen);
    } else {
        let observed_gen = ctrl.applied_patch_gen.load(.Acquire);
        __cx_wait_until_gen_advances(&ctrl.applied_patch_gen, observed_gen);
    }

    // Mandatory Multi-Core CMC-Acquire Barrier (`isb` on ARM64 / core sync on x86_64):
    cpu_icache_sync_acquire();

    if ctrl.reload_action == 3 {
        return .RestartRequired { changed_type_id: ctrl.root_type_id };
    }
    .Patched {
        epoch: ctrl.applied_patch_gen.load(.Relaxed),
        fns_updated: ctrl.patched_fn_count,
    }
}
```

### 2.4 Formal MVS Memory-Safety and Resource-Linearity Soundness Proof

To verify that stateful live hot-code patching in `--dev` mode preserves CoreX's compile-time guarantees against Use-After-Free (`E0301`), Use-After-Move (`E0302`), Double-Free (`E0313`), Uninitialized Reads (`E0303`), `@linear` Resource Leaks (`E0304`), Exclusivity Violations (`E0305`), Dangling Region Escapes (`E0306`), and Out-of-Bounds Overflows (`E0307`) under the zero-GC MVS memory model (`DR-06`), we establish **Theorem 1 (Hot-Patch Epoch Preservation)** up to collision resistance of 64-bit `Wyhash(0)` (`FieldHash64` + `fqn_hash32`):

$$\textbf{Theorem 1 (MVS Epoch Soundness):} \quad \text{If } P_E \vdash_{\text{SAST}} \text{Safe} \;\land\; P_{E+1} \vdash_{\text{SAST}} \text{Safe} \;\land\; \forall \tau \in \mathcal{R}(\Sigma_E),\; \text{FieldHash64}_E(\tau) = \text{FieldHash64}_{E+1}(\tau), \text{ then } (\Sigma_E \xrightarrow{\text{patch}} P_{E+1}) \vdash_{\text{MVS}} \text{Safe}.$$

1.  **Lemma 1 (Quiescent Exclusivity & Absence of Interior Loans at Safepoint):** Let $\Sigma_E$ denote the live process heap, `BumpArena` slabs, static globals, and root `app_state: S` upon entering `poll_reload(&mut app_state)`. Because `poll_reload` requires an exclusive MVS `inout` projection (`%loan = access.inout %app_state`), `DR-06` Pass 2 verifies $(\text{LetLoan}(\ell) \cup \text{InoutLoan}(\ell)) \cap \text{Conflict}(\text{app\_state}) = \emptyset$ (`E0305`), and `DR-08` §3.2 Rule 2 ensures that any child `TaskGroup` holding borrows into `app_state` has already joined prior to `%loan` (`E0309`). Combined with second-class references (`DR-06` §1.1: references cannot be stored inside structs) and `DR-20` `Fix-06B` (all `subscript`/`yield` projections have completed their `defer` writebacks before returning to the event loop), **zero interior pointers into `app_state` or its owned subtrees exist on any thread stack at the patch transition**.
2.  **Lemma 2 (Representation & Typestate Isomorphism Across Epochs):** Let $\mathcal{R}(\Sigma_E)$ be the transitive type closure of `S`, pinned `static`/`@thread_local` slots, live `ClosureEnv` instances, and non-drained `AsyncFrame`s. When $\text{FieldHash64}_E(\tau) = \text{FieldHash64}_{E+1}(\tau)$ for all $\tau \in \mathcal{R}(\Sigma_E)$, matching recursive `Wyhash(0)` digests over `(FQN, OwnTier, LayoutShapeKey, [(MemberName, PhysOffset, Discrim, ChildHash)])` ensure that every initialized memory slot in $\Sigma_E$ ($\mathcal{I}_E[p] = 1, \mathcal{U}_E[p] = 0$) satisfies the exact field byte offsets, natural alignment, niche bit-pattern invariants (`NicheSpec`), `#soa` SIMD column offsets (`ColOffset(f, cap)`), and Pentagon slice-length bounds (`0 <= len <= cap`) assumed by the SAST-verified `MirBody` functions of $P_{E+1}$.
3.  **Lemma 3 (Indirection & Call-ABI Soundness):** Every runtime-dispatched callable in $\Sigma_E$ (`fn` pointer, `own` closure, `dyn Trait` vtable, `CoroPollDispatchTable`) holds the permanent address of `__cx_thunk_<got_idx>`. If an edited target `def_id` alters its `AbiFnRecipe` (`abi_sig_hash64`), `CompilerDb`'s `decl_deps` edge invalidates every caller and type-checked `fn_addr` coercion in $P_{E+1}$; either all callers recompile inside the same atomic `.cx_got` commit batch, or (if a signature change alters a stored `fn` type in $\mathcal{R}(\Sigma_E)$) `FieldHash64` changes and triggers `OpCleanRestart`.
4.  **Lemma 4 (Strict Conservation of `@linear` Resources):** During `OpApplyInPlace`, $\Sigma_E$'s memory bytes are unmodified (`0` drops and `0` duplications, preserving $\mathcal{I}[\text{linear}] = 1$). During `OpDrainCorosAndApply` or `OpCleanRestart`, `poll_reload` executes in-flight `CompletionReaper` drains (`DR-20` `Fix-08B`) and lexical `defer` cleanup chains before process exit, ensuring $\mathcal{I}[\text{linear}] = 0$ on termination (`E0304` leak-freedom preserved) ✓.

### 3.1 Target-Parameterized SIMD Contracts and Two-Stage MIR/LLVM Verification

Relying on implicit C++/Rust auto-vectorization leaves performance-critical kernels (`simdjson` tape scanners, `#soa` physics/ECS integrators, CRC32C/BLAKE3 checksums, audio DSP, and UI glyph rasterizers) vulnerable to **silent scalarization**: a seemingly minor refactor inside a loop body can defeat LLVM's `LoopVectorize` alias or cost-model checks and silently degrade throughput by `4x` to `16x` without a compiler diagnostic. In `Phase 13.2`, CoreX turns auto-vectorization into a **statically verified compile-time contract** via `@must_vectorize`, using existing `@attribute` syntax with zero changes to the `Phases 0–5` EBNF grammar:

```rust
    particles[i].pos_x += particles[i].vel_x * dt;
}

// [2] Target-parameterized contract + associative FP reduction:
@must_vectorize(x86_64: 8, aarch64: 4, wasm32: 4, reassoc: true)
```

#### Canonical Target Lane Widths and Two-Stage Verification Without Dev-Mode Brittleness

To prevent false-positive failures during fast `--dev` builds (where Tier C intentionally emits unvectorized scalar machine code in microseconds) while still giving developers instant structural feedback before `--release` CI runs, CoreX splits `@must_vectorize` verification into two deterministic stages.

In **Stage A (Target-Independent `MIR` Structural Pre-Check, running in BOTH `--dev` and `--release`)**, `MIR` Pass D2/D5 inspects every loop carrying `LoopContractMeta.contract_flags.is_must_vectorize == true` in under `0.1 ms`. It rejects `.await` suspension points (`coro.suspend`), recursive calls, or non-inlined opaque `@extern` calls inside the loop body (`E0522`). Crucially, as documented in LLVM's Vectorizers specification, LLVM refuses to vectorize floating-point reductions (`sum += a[i]` on `f32`/`f64`) unless floating-point reassociation (`-fassociative-math -fno-signed-zeros -fno-trapping-math`) is explicitly permitted (or slower ordered target reductions are used). Stage A detects `f32`/`f64` loop-carried accumulator cycles lacking `reassoc: true` (or `std::simd::reduce_add`) and immediately emits **`E0521 (NonAssociativeFloatReductionInSimdLoop)`** even in `--dev` mode, alongside flagging strided Array-of-Structs (`>= 32 B` stride) field accesses (`E0520`) with a fix-it suggesting `#soa[]T` transposition. Once Stage A passes, `--dev` Tier C compiles the loop as fast scalar code with **zero false-positive remark errors**.

In **Stage B (Exact In-Process LLVM `DiagnosticHandler` Verification, running in `--release`, `corex check --simd`, and `corex lsp`)**, `src/corex_llvm.cpp` installs a C++ `llvm::DiagnosticHandler` subclass (`CxLlvmSimdDiagHandler`) on `LLVMContext` overriding `isPassedOptRemarkEnabled`, `isMissedOptRemarkEnabled`, and `isAnalysisOptRemarkEnabled` for `"loop-vectorize"` and `"slp-vectorizer"`. Each `@must_vectorize` loop's 32-bit `DiagId` (`LoopContractMeta.diag_id`) is encoded into the loop latch's `!DILocation` discriminator so structured `DiagnosticInfoOptimizationBase` arguments (`"VectorizationFactor"` and `"InterleaveCount"`) correlate `1-to-1` back to `MirLoopHeader` without brittle YAML or stderr string parsing.

#### Solving the Constant-Trip Unroll and Early-Exit Fault Traps

As identified in `DR-20` `Audit 3.7` and LLVM's optimization pipeline (`PassBuilderPipelines.cpp`), two LLVM middle-end behaviors break naive `@must_vectorize` verifiers. First, on small constant-trip loops (e.g., `for i in 0..16`), early full loop unrolling (`LoopFullUnrollPass` during function simplification) can completely unroll the loop *before* `LoopVectorizePass` executes, suppressing `loop-vectorize` remarks even when `SLPVectorizerPass` subsequently vectorizes the straight-line instructions (or leaving scalar operations if SLP misses). `src/corex_llvm.cpp` resolves this cleanly by attaching `!{!"llvm.loop.unroll.disable"}` to the initial `@must_vectorize` loop metadata node `!L_pre` paired with `!{!"llvm.loop.vectorize.followup_all", !L_post}` where `!L_post` enables unrolling (`!{!"llvm.loop.unroll.enable"}`). Consequently, `LoopVectorizePass` sees the intact loop, vectorizes it at full hardware width, emits its `VectorizationFactor` remark, and hands the vectorized loop to the post-vectorization `LoopUnrollPass`; in addition, `CxLlvmSimdDiagHandler` accepts `"slp-vectorizer"` passed remarks for ultra-short fixed-width loops (`trip_count == 4`).

Second, in LLVM 21–23's single-early-exit loop vectorizer (`middle.split` ▸ `vector.early.exit`, documented in `llvm-project#159697`), `LoopVectorizer` strictly rejects `find`-style search loops (`for i in 0..buf.len() { if buf[i] == needle { return .Some(i); } }`) unless it can prove there are **no potentially faulty loads** across the speculative vector width. Whereas C++ `std::vector` fails this check due to pointer-difference opacity, CoreX's `BumpArena` and `#soa` allocators pad backing allocations to SIMD register multiples (`32 B` / `64 B`) and `DR-06` Pass 4 Pentagon intervals prove exact byte dereferenceability. `src/corex_llvm.cpp` emits `call void @llvm.assume(i1 true) [ "align"(ptr %base, i64 32), "dereferenceable"(ptr %base, i64 %proven_bytes) ]` in the loop preheader alongside `!{!"llvm.loop.vectorize.predicate.enable", i1 true}`, unlocking early-exit SIMD automatically.

```cpp
// Excerpt from `src/corex_llvm.cpp` (Phase 13.2): In-Process LLVM 20-23 SIMD Contract Verifier
#include "llvm/ADT/SmallString.h"
#include "llvm/IR/DiagnosticHandler.h"
#include "llvm/IR/DiagnosticInfo.h"
#include "llvm/IR/DebugInfoMetadata.h"

struct CxSimdContractResult {
    uint32_t diag_id;
    uint16_t achieved_vf;
    uint16_t interleave_count;
    bool is_scalable;
    bool has_passed_lv_or_slp;
    llvm::SmallString<128> missed_analysis_reason;
};

class CxLlvmSimdDiagHandler final : public llvm::DiagnosticHandler {
public:
    llvm::DenseMap<uint32_t, CxSimdContractResult> *contracts;

    explicit CxLlvmSimdDiagHandler(llvm::DenseMap<uint32_t, CxSimdContractResult> *map)
        : contracts(map) {}

    bool isPassedOptRemarkEnabled(llvm::StringRef pass_name) const override {
        return pass_name == "loop-vectorize" || pass_name == "slp-vectorizer";
    }
    bool isMissedOptRemarkEnabled(llvm::StringRef pass_name) const override {
        return pass_name == "loop-vectorize";
    }
    bool isAnalysisOptRemarkEnabled(llvm::StringRef pass_name) const override {
        return pass_name == "loop-vectorize";
    }

    bool handleDiagnostics(const llvm::DiagnosticInfo &diag_info) override {
        const auto *opt_diag = llvm::dyn_cast<llvm::DiagnosticInfoOptimizationBase>(&diag_info);
        if (!opt_diag || !opt_diag->getLocation().isValid()) return false;

        // Recover Phase-7 `LoopContractMeta.diag_id` encoded in `DILocation` discriminator:
        const llvm::DILocation *debug_loc = opt_diag->getLocation().getAsMDNode();
        if (!debug_loc) return false;
        uint32_t contract_id = debug_loc->getBaseDiscriminator();
        auto entry_it = contracts->find(contract_id);
        if (entry_it == contracts->end()) return false;

        if (opt_diag->isPassed()) {
            entry_it->second.has_passed_lv_or_slp = true;
            for (const llvm::DiagnosticInfoOptimizationBase::Argument &arg : opt_diag->getArgs()) {
                if (arg.Key == "VectorizationFactor") {
                    llvm::StringRef val_str = arg.Val;
                    if (val_str.consume_front("vscale x ")) entry_it->second.is_scalable = true;
                    unsigned vec_factor = 1;
                    val_str.getAsInteger(10, vec_factor);
                    if (vec_factor > entry_it->second.achieved_vf) {
                        entry_it->second.achieved_vf = static_cast<uint16_t>(vec_factor);
                    }
                } else if (arg.Key == "InterleaveCount") {
                    unsigned interleave_cnt = 1;
                    llvm::StringRef(arg.Val).getAsInteger(10, interleave_cnt);
                    entry_it->second.interleave_count = static_cast<uint16_t>(interleave_cnt);
                }
            }
        } else if (opt_diag->isAnalysis() && entry_it->second.missed_analysis_reason.empty()) {
            entry_it->second.missed_analysis_reason = opt_diag->getMsg();
        }
        return true; // Handled in-memory; never spam stderr.
    }
};
```

### 3.2 Multi-Node Deterministic Virtual Network and Three-Layer Crash-Consistency Engine

In `Phase 11`, CoreX ships single-process deterministic simulation (`corex test --sim`) over `DR-20` Seam #5 (`Context.reactor: *const ReactorVTable` providing virtualized `monotonic_ns`, `fill_rng`, and `submit_io`, plus `Fix-18A` `Context.rng`-seeded `Map`/`Set` Wyhash determinism across ASLR runs). In **`Phase 13.3`**, `std::test::sim` extends this seam into **`SimCluster`** – an inside-out, single-threaded multi-node cluster and crash-consistency simulator inspired by FoundationDB and TigerBeetle's VOPR.

#### Single-Thread Multiplexed Virtual Nodes and Copy-on-Write Storage

`SimCluster` instantiates `N` isolated virtual hosts (`SimNode[0 … N - 1]`) inside a single deterministic OS thread driven by a global min-heap priority queue `BinaryHeap[SimEvent]` ordered strictly by `(deliver_at_ns: u64, monotonic_seq_id: u64)`. Each `SimNode` binds its own `Context` (`SimNodeReactor` implementing `ReactorVTable`), its own `SplitMix64(master_seed ^ node_id)` PRNG, its own simulated NTP/PTP wall-clock and monotonic `SimClock` (supporting bounded drift and forward/backward clock jumps), its own `InFlightOpTable` (`IoUserData` 64-bit correlation keys from `DR-08`), and its own `BumpArena` pool. Backing virtual NVMe block devices with a shared zero-page + **4 KiB Copy-on-Write (`CoW`) page table** yields a modeled **`13.38 MiB` host RAM footprint** for a 5-node cluster with `16 MiB` virtual disks per node at a typical 15% dirty-block ratio (compared to `80.0 MiB` unshared if 100% of blocks diverge), enabling CI to execute thousands of multi-hour virtual fault histories per minute.

#### Virtualized Network Fabric: Asymmetric Partitions, Misdirection, and Adversarial TCP

Rather than modeling partitions as coarse node-wide on/off booleans, `SimNetwork` maintains a directed **`N × N` Link Fault Matrix** `LinkProfile[src][dst]` supporting asymmetric partitions (for example, `Node 0 ▸ Node 1` healthy, `Node 1 ▸ Node 2` healthy, and `Node 0 ▸ Node 2` dropping 100% of traffic – the exact topology that induces Raft pre-vote storms and Viewstamped Replication view-change livelocks). For UDP datagrams, each directed link injects configurable drop probabilities, burst duplication, heavy-tailed reordering jitter, bit-flip payload corruption, and **packet misdirection** (delivering a packet sent from `Node 0 ▸ Node 1` into `Node 2`'s receive queue to test protocol recipient-ID verification). For virtualized TCP (`SimTcpStream`), `SimNetwork` preserves per-connection in-order byte delivery while deterministically injecting **adversarial stream segmentation and coalescing** (splitting a `4,096 B` write into `1 B + 17 B + 4,078 B` `ProvidedBuf` reads or coalescing multiple frames), `SYN` blackholes, mid-write `ECONNRESET`, and **silent half-open dead peers** when a remote `SimNode` undergoes an abrupt power-loss crash without transmitting `FIN` or `RST`.

#### Three-Layer OS Page-Cache, Directory-Sync, Linked-SQE, and NVMe Torn-Write Model

Storage engines lose or corrupt committed data on power loss because buffered POSIX writes sit in the volatile OS page cache for `0 ms` to `30 s` (`dirty_expire_centisecs = 3000`), flush to storage **out of submission order**, omit parent-directory `fsync(dir_fd)` after `O_CREAT` or atomic `rename()`, fail to chain `io_uring` writes and flushes, or tear `4 KiB`/`8 KiB` pages across `512 B` physical sectors. `SimStorage` models all three persistence layers explicitly:

| Persistence Layer / Fault Class | Virtualized Data Structure in `SimStorage` | Exact POSIX / `io_uring` / NVMe Crash-Consistency Rule Enforced on `crash_power_loss(node)` |
| :--- | :--- | :--- |
| **Layer 1A: Volatile OS Page Cache (`write` / `pwrite`)** | Per-inode `DirtyWriteLog` + coherent live RAM overlay | Concurrent readers on the *same* node observe dirty writes immediately; on `crash_power_loss`, PRNG selects an **arbitrary out-of-order subset** of un-`fsync`ed writes to discard or persist (catching `write B` surviving while earlier `write A` vanishes!). |
| **Layer 1B: Unsynced Parent Directory Entries (`O_CREAT`, `rename`, `unlink`)** | Separate `DurableDentryMap` vs. `VolatileDentryMap` per directory inode | `fsync(file_fd)` / `fdatasync(file_fd)` flushes *only* file data and inode size/metadata. Unless **`fsync(parent_dir_fd)`** completes after `open(O_CREAT)` or `rename("a.tmp", "a.db")`, `crash_power_loss` reverts the directory entry to `DurableDentryMap` (catching orphaned inodes and lost atomic renames!). |
| **Layer 2: `io_uring` `IOSQE_IO_LINK` Chain Ordering** | Per-ring `SqeChainQueue` inside `SimNodeReactor` | Linked chains (`WRITE` with `IOSQE_IO_LINK` ▸ `IORING_OP_FSYNC`) execute strictly sequentially and cancel downstream SQEs with `-ECANCELED` on upstream `-EIO` (`IOSQE_IO_HARDLINK` continues). Unlinked concurrent `WRITE` + `FSYNC` SQEs intentionally test adversarial `FSYNC`-before-`WRITE` reorderings. |
| **Layer 3A: NVMe Power-Loss Torn Writes (`AWUPF`)** | Configurable `atomic_write_unit_bytes` (`512 B` consumer 512e SSD or `4,096 B` enterprise PLP) | Any in-flight or un-`fsync`ed write spanning multiple `AWUPF` sectors (such as an `8 KiB` B-tree page across sixteen `512 B` sectors) tears deterministically on `crash_power_loss`, persisting a random bitmask of `512 B` sectors while leaving sibling sectors old or zeroed. |
| **Layer 3B: Latent Media Corruption & Misdirected I/O** | Per-LBA fault injection map (`CorruptBit`, `EioSector`, `MisdirectLba`) | Injects single-bit flips (including inside unused struct/sector zero-padding per Jepsen's TigerBeetle `#2681` finding), sector `-EIO` read errors, and misdirected writes/reads to verify per-block copy/LBA checksum headers. |

### 3.3 Two-Phase Safety-to-Frozen-Liveness Protocol and End-to-End Verification Blueprint

As demonstrated by TigerBeetle's VOPR engineering findings (`DR-20` `Audit 3.7`), running uniform probabilistic fault injection and recovery from start to finish (*Safety Mode* alone) misses real-world distributed livelocks: because network partitions eventually heal and stuck nodes get randomly rebooted by the fuzzer, protocol deadlocks and round-robin repair-loop resonance bugs accidentally "self-heal" undetected. `SimCluster` therefore enforces a **Two-Phase (*Safety Mode* ▸ *Frozen-Liveness Mode*) Execution Schedule** on every seed:

1.  **Phase I – Safety Chaos Window (`0 .. T_chaos`):** On every virtual tick, the simulator rolls `context.rng()` to crash healthy nodes via abrupt `crash_power_loss` (wiping RAM, arenas, and sockets without running `defer` or `AutoDrop`), reboot downed nodes from their torn/rolled-back `SimStorage` image, mutate asymmetric `LinkProfile[src][dst]` partitions, skew `SimClock`, and inject single-bit sector corruptions, while asserting inside-out safety invariants after every committed request (including WAL checksum agreement `(commit_a == commit_b) == (checksum_a == checksum_b)`).
2.  **Transition Gate at `T_chaos` (`enter_frozen_liveness_mode`):** `SimCluster` deterministically selects a quorum subset `Q` of size `floor(N / 2) + 1` as the **Core**. Crashed nodes inside `Q` are restarted once; network partitions and local storage `-EIO` faults among Core nodes in `Q` are healed; and **all failures involving non-core nodes outside `Q` are permanently frozen** (crashed non-core nodes never restart, and asymmetric links where a non-core node can send disruptive messages into `Q` without receiving replies remain permanently wedged).
3.  **Phase II – Frozen-Liveness & Physical Convergence Verification (`T_chaos .. T_max`):** With random reboots disabled and non-core faults permanently frozen, `SimCluster` drives a verification workload against `Q` and asserts that (a) every client transaction completes within bounded virtual deadline, (b) local crash recovery without WAL corruption completes locally without requiring cluster-wide coordination, and (c) all caught-up Core replicas in `Q` converge to **byte-for-byte identical physical storage and state digests**.

### 3.4 Master Implementation and Verification Gate Checklist

To operationalize `DR-19` cleanly across `Phase 7` (Pre-`v0.0.1` Seam) and `Phase 13` (`0.x` Self-Hosted Capabilities), the CoreX compiler team enforces five verification gates:

1.  **Zero-Cost `--release` Seam Gate (`Phase 7`):** Verify via binary section inspection in CI that `corex build --release` emits **zero** `.cx_got`, `.cx_dev_ctrl`, or `.cx_dev_meta` sections and lowers `poll_reload` to zero machine instructions, while `--dev` seam code remains strictly `< 200 LOC` (`148 LOC` modeled).
2.  **Semantic `FieldHash64` Differential Fuzzing (`Phase 7` & `Phase 13.0`):** Run schema-mutation tests asserting that swapping two same-typed struct fields (`{x: f32, y: f32}` ▸ `{y: f32, x: f32}`), altering an enum niche range, or adding a closure capture changes `field_hash64` (`OpCleanRestart`), while editing function bodies, inline literals, and non-capturing closures preserves `field_hash64` (`OpApplyInPlace`).
3.  **Cross-OS Live Patch Equivalence & `SIGKILL` Gate (`Phase 13.0`):** Extend `DR-09`'s `incr-check` harness across Linux (`mprotect` + `memfd_create` SELinux mode + `membarrier`), macOS Apple Silicon (`MAP_JIT` + `pthread_jit_write_protect_np` + `sys_icache_invalidate` + `UnlinkAndReplace`), and Windows (`VirtualProtect` + `RtlAddGrowableFunctionTable`), asserting `< 50 ms` patch latency, pinned static addresses, and zero stale vtable/callback dispatches across 1,000 sequential live edits.
4.  **Delayed-Unroll & Early-Exit `@must_vectorize` Matrix (`Phase 13.2`):** Compile the standard `#soa` SIMD test suite across `x86_64-v3` (`AVX2`), `x86_64-v4` (`AVX-512`), `aarch64` (`NEON` and `+sve`), and `wasm32` (`+simd128`), verifying zero false-positive failures in `--dev` mode, exact `VectorizationFactor` verification on constant-trip (`0..16`) loops via `followup_all`, and non-faulting early-exit vectorization via Pentagon `dereferenceable` assumptions.
5.  **Known-Bug Litmus Suite for `SimCluster` (`Phase 13.3`):** Validate `corex test --sim` against seeded litmus faults – omitting `parent_dir.sync()` after `rename`, omitting `IOSQE_IO_LINK` between `WRITE` and `FSYNC`, writing unchecksummed `8 KiB` pages across `512 B` `AWUPF` sectors, flipping single bits inside zero-padding, and injecting asymmetric 3-node view-change livelocks – asserting that every litmus bug is caught deterministically within 100 seeds and replays identically from its printed `--seed` under ASLR.
