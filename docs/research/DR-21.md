# Post-Phase-7 Surface Syntax Elevation, Namespace and Path Ergonomics, and Zero-Cost Expressiveness for CoreX (.cx)

CoreX (`corex-lang/corex`, `.cx`) should execute a single pre-Phase-8 surface syntax elevation that renames the public standard library root namespace from `std` to **`cx`** (transparently re-exporting Stage-1 `core` symbols through `cx.*` and the universal prelude), retires the `::` path separator in favor of **unified `.`** across modules, types, enum variants, associated constants, and `use` import trees (`cx.fs.File.open(path)?`, `Vec[u8].with_capacity(16)`, `Color.Red`, `use cx.fs.{File, BufReader};`), adopts **eight** orthogonal zero-cost surface elevations (`SE-01`–`SE-08`), and prunes **eight** redundant or error-prone constructs. Because `DR-03` already partitions identifiers at lex time into disjoint casing classes (`IDENT` for `snake_case` values/functions/modules, `TYPE_IDENT` for `PascalCase` types/traits/variants, `CONST_IDENT` for `SCREAMING_SNAKE_CASE` constants, and `PRIM_TYPE` for the 19 built-in primitives) alongside square-bracket generics `[T]`, unifying `::` onto `.` preserves **100% stateless, symbol-table-free `LL(k)` + Pratt parsing** across every generic call, array/map index, associated call, contextual `.Variant`, nested tuple `.0.1` projection, and `use` tree. Across four complete domain showcases spanning low-level AVL tree manipulation, streaming wire/log I/O, async HTTP/JSON handlers, and declarative `cx.ui` components, this elevation eliminates all 77 shifted `::` tokens (`-100%`), reduces source line count by **9.8%–18.5%** (`352` to `303` lines overall, `-13.9%`), and trims source byte volume by **7.0%–18.0%** (`-11.4%` overall) with zero hidden heap allocations, zero runtime branch overhead, and zero parser backtracking.

For condition bindings and local declarations, CoreX enforces its **One Canonical Way** invariant by retaining `let` (immutable value root) and `var` (mutable value root) as the sole statement-level local declaration keywords while pairing two strictly non-overlapping condition-header constructs:
1.  **Flow-Sensitive `is` and `is not` Pattern + Guard Chains (`SE-01`):** Written `if reader.next_line()? is .Some(line) and not line.is_empty() { … }`, reusing CoreX's existing `kw_is` token to express refutable enum, `Option`, slice, and range destructuring in left-to-right reading order while retiring Wave-1's right-to-left `if let` and `while let` forms.
2.  **Parenthesized Statically Typed Inline Walrus Bindings (`SE-02`):** Written `while (n := sock.read(&mut buf)?) > 0 { … }` or `if (var rem: usize := frame.len()) >= 4 { … }`, capturing irrefutable values directly inside positive `if` and `while` predicates with mandatory outer parentheses (eliminating Python PEP 572 precedence bugs) and linear-time bidirectional `TypeId` inference. Both `SE-01` and `SE-02` enforce Rust-2024-style **Pre-Else Drop Semantics** on `MIR`: condition temporaries and `AutoDrop` bindings drop in reverse LIFO order on the false CFG edge *before* entering any `else` branch, preventing MVS exclusivity deadlocks (`E0305`).

Across everyday systems, CLI, web backend, and UI engineering, six additional syntactic elevations desugar purely in `AST → HIR` with full Phase-6 `MIR` SAST and Pentagon (`Intv × Sub`) verification: (`SE-03`) infix **`orelse`** (`opt orelse .Member`, `y.left.take() orelse return y`, `opt orelse unreachable`) as the canonical `Option[T]` counterpart to `Result[T, E]`'s `catch`; (`SE-04`) **end-relative `$` slice/array indexing** (`frame[..$-4]`, `frame[$-4..]`, `buf[$-1]`) backed by a Pentagon backward-offset transfer rule that statically elides both subtraction underflow and bounds checks; (`SE-05`) **element-first zero-allocation indexed loops** (`for item, i in slice` and `for &mut p, i in &mut particles`); (`SE-06`) **labeled loops with `T?`-typed value `break` composing directly with `orelse`** (`find: for x, i in items { if pred(x) { break :find i; } } orelse continue`); (`SE-07`) **single-expression `=` functions** and formalized **call-site named + default arguments**; and (`SE-08`) **lexical `with context.field = expr { … }` blocks** that override implicit `Context` slots across `.await` and `?` boundaries without closure wrappers. Conversely, the pruning gate rejects statement-level `:=`, optional chaining `?.`, implicit `x != .None` smart-casting, Swift comma condition lists, Python `for … else`, Scala `_` lambda placeholders, and `??` coalescing.

## 1. Deliverable 1: Architectural Decision Record on Namespace and Path Syntax

### 1.1 Standard Library Root Namespace and Stage-1 Kernel Topology

**ADR-21A (Standard Namespace Selection):** CoreX renames its public standard library root namespace from `std` to **`cx`** (`cx.mem`, `cx.meta`, `cx.col`, `cx.str`, `cx.crypto`, `cx.io`, `cx.async`, `cx.fs`, `cx.net`, `cx.serde`, `cx.cli`, `cx.tui`, `cx.http`, `cx.ui`, `cx.test`, `cx.bench`) and reserves `cx` as a protected root module identifier in the Phase 8/9 resolver (`corex.toml` already mandates `kebab-case` package names without `-cx` suffixes per `DR-03` §4.3, preventing registry collisions).

**ADR-21B (Stage-1 Kernel Relationship):** Stage-1 `core/*.cx` remains the physical compiler-internal bootstrap kernel (`Phase 7`), **transparently re-exported (`pub use`) through `cx.*` submodules and the universal prelude** rather than exposed as a separate `use core.*` or nested `use cx.core.*` user path.

Renaming `std` to `cx` replaces a generic C++ holdover (`std::`) with a concise, two-character brand anchor aligned with the `.cx` file extension, the `cx` / `cx_result_cc` native calling convention (`DR-02`, `DR-07`), and already-established `DR-02` framework references (`cx.ui`). More critically, evaluating the three candidate relationships between `core` and `cx` – (1) Rust-style dual roots (`core.*` vs. `cx.*`), (2) nested `cx.core.*` alongside `cx.mem.*`, or (3) compiler-internal `core` transparently re-exported into `cx.*` – shows why only option (3) upholds CoreX Invariant 2 (**One Canonical Way**).

Rust was forced to expose both `core::` and `std::` to library authors because linking Rust's `std` crate pulls in OS runtime initialization and a global heap allocator, forcing freestanding crates into `#![no_std]` and splitting imports across the ecosystem. CoreX eliminates that architectural divide through three existing Phase 5–8 invariants. First, `DR-15` §1.1 enforces an absolute ban on runtime module `init()` constructors; all lookup tables are evaluated inside `MirVm` at `comptime` and frozen in `.rodata`. Second, Phase 4's signature firewall and Phase 5's reachability-driven monomorphizer never lower unreferenced items in an imported `cx.*` module, stripping unused symbols via `-ffunction-sections -fdata-sections` and `lld --gc-sections`. Third, Phase 6's `DR-17` call-graph capability engine infers an exact `EffectCapabilityMask` (`fs`, `net`, `env`, `process`, `ffi`, `unsafe`, `alloc`, `may_panic`) on every function. Consequently, an `@no_alloc` embedded firmware module or a `1.5–10 KB` freestanding `wasm32` module writes the exact same `use cx.mem.{Arena, Span16};` and `use cx.cmp.Ord;` imports as a Linux HTTP server; only actually calling an `fs`- or `alloc`-tainted symbol triggers a capability diagnostic. Exposing `cx.core.*` would merely add a redundant path hop (`cx.core.simd` vs. `cx.simd`).

### 1.2 Syntactic and Human-Factors Comparison of Double-Colon vs. Unified Dot

**ADR-21C (Path Separator Selection):** CoreX retires `TokenKind.COLONCOLON` (`"::"`) and unifies module paths, type-associated functions and constants, qualified enum variants, associated types, struct fields, method calls, tuple projections, and `use` import trees onto **`.` (`TokenKind.DOT`)**.

In C++ and Rust, `::` is a parser necessity rather than an ergonomic feature: C++ lacks lexical type-vs-value casing, and both C++ and Rust use `< >` for generic parameters, forcing Rust to keep `::` so the turbofish `::<T>` (`Json::parse::<User>(buf)`, `Vec::<u8>::with_capacity(16)`) can disambiguate generic arguments from `<` relational comparisons. Because `DR-03` already selected square-bracket generics `[T]` and contextual dot-variants (`.Ok(v)`, `.None`, `.SpaceBetween`), retaining `::` in Wave-1 `.cx` imposed three concrete costs:
-   **Split Variant Mental Model:** Developers wrote `.Red` when the `Color` type was contextually expected, but had to rewrite `.` to `::` (`Color::Red`) whenever qualifying that exact same variant. Under unified `.`, `.Red` is literally `Color.Red` with the expected type prefix elided, matching Swift (`SE-0287`) and Zig.
-   **Split Generic Placement on Associated Calls:** Wave-1 code permitted two competing styles for generic type constructors – `PoolAllocator::new[AvlNode[K, V]](cap)` (`DR-03` Showcase 3) versus `Vec[u8]::with_capacity(256)` (`DR-06` §2.5). Unifying onto `.` establishes **One Canonical Way**: type parameters belong on the type (`PoolAllocator[AvlNode[K, V]].new(cap)`, `Vec[u8].with_capacity(256)`), and function type parameters belong on the function (`cx.serde.from_json[User](arena, buf)`).
-   **Visual Density & Keystroke Friction:** In Dorn's (2012) empirical readability model (`DR-03` §1.3), lowering visual operator-to-identifier area ratio directly improves human scanning speed. Replacing `std::http::StatusCode::PayloadTooLarge` with `cx.http.StatusCode.PayloadTooLarge` removes six shifted `:` characters in a single expression while keeping `PascalCase` (`StatusCode`, `PayloadTooLarge`) vs. `snake_case` (`cx.http`) visually unmistakable at a glance.

### 1.3 Formal Proof of Stateless `LL(k)` + Pratt Disambiguation Under Unified Dot

In Go (`go/parser`), unifying package paths onto `.` with `[T]` generics creates a true parse-time ambiguity on `a[b](c)` because Go uses uppercase/lowercase for export visibility rather than type-vs-value kind (`b` could be an unexported type `myType` or an unexported variable `myIdx`), forcing Go's parser to emit an ambiguous index node and rewrite the AST during type checking.

By contrast, CoreX's lexer (`DR-03` §4.3 & §5.2) partitions all identifiers and primitive types at scan time into four mutually disjoint token classes without symbol-table access:
1.  `PRIM_TYPE`: the 19 reserved lowercase primitive keywords (`i8`..`i128`, `u8`..`u128`, `isize`, `usize`, `f32`, `f64`, `bool`, `str`, `char`, `unit`, `never`).
2.  `IDENT`: `snake_case` value, function, method, field, and module names (`^_?[a-z][a-z0-9_]*|_[a-z0-9_]+$`).
3.  `TYPE_IDENT`: `PascalCase` nominal types, traits, enum variants, and type parameters (`^[A-Z][a-zA-Z0-9]*$` containing at least one lowercase letter or having length 1, e.g., `T`, `V`, `User`, `AvlNode`).
4.  `CONST_IDENT`: `SCREAMING_SNAKE_CASE` compile-time constants (`^[A-Z][A-Z0-9_]+$` of length ≥ 2 with zero lowercase letters, e.g., `MAX_SLOTS`, `EMPTY`, `PI_2`).

Combined with a 1-byte `prev_sig_kind` register in the stateless O(n) lexer, every construct in CoreX disambiguates deterministically at parse time across all five edge-case families:

#### Edge Case Family 1: Generic Calls (`cx.json.parse[User](buf)`) vs. Array/Map Indexing (`table[cx.limits.MAX_SLOTS]`, `table[ColumnKey.Primary]`)

When the Pratt postfix loop has parsed left-hand operand `lhs` and encounters `LBRACKET` (`[`):
-   **Rule 1A – `lhs` Syntactically Ends in a Type (`k = 1`):** If `lhs` is `TypeIdent` (`Vec`), `SelfType` (`Self`), or `PathType` (a dotted path whose final segment is `TYPE_IDENT`, such as `cx.col.SlotMap`), `lhs` denotes a type or enum variant constructor rather than an indexable container value (runtime values cannot be types; compile-time type reflection uses `@type_info[T]()` per `DR-15` §2.1). Therefore, `[` is **unconditionally `TypeArgs` at `LL(1)` (`k = 1`)**. This resolves `Vec[u8].with_capacity(16)`, `cx.col.SlotMap[K, V].new()`, and const-generic type instantiations like `Simd[f32, 8].splat(0.0)` or `StaticVec[u8, MAX_CAP].new()` without requiring `const` before `8` or `MAX_CAP`.
-   **Rule 1B – `lhs` Ends in a Value/Callable `IDENT` or Expression:** The parser runs the stateless token predicate `isTypeStart(off = 1)` beginning at `peek(1)`:
    1.  `peek(1)` in `{KW_CONST, HASH_SOA, KW_FN}` (`k = 1`), or contextual modifier `peek(1) == IDENT` in `{"dyn", "any"}` with `isTypeStart(2)` (`k = 2`) $\implies$ **`TypeArgs`** (e.g., `align_only[const 64](ptr)`, `alloc[#soa Particle](n)`, `box_new[dyn Reader](r)`).
    2.  `peek(1)` in `{PRIM_TYPE, KW_SELF_TYPE}` (`k = 2`): inspect `peek(2)`. If `peek(2) != DOT` (`alloc[u32](64)`, `read[u64?]()`), `u32` is a type $\implies$ **`TypeArgs`**. If `peek(2) == DOT` (`table[u32.MAX]`, `lut[Self.PRIMARY_KEY]`), `u32.MAX` is an associated constant value expression $\implies$ **`IndexExpr`**.
    3.  `peek(1)` in `{AMP, STAR, KW_OWN, KW_REF}` (plus optional `KW_MUT`): recursively evaluate `isTypeStart` on the target token (`foo[&User](x)` vs. `arr[&idx]`).
    4.  `peek(1) == LBRACKET`: recursively test `isTypeStart(2)` (`read[[u8; 4]]()` vs. `mat[[0, 1]]`). `peek(1) == LPAREN`: `peek(2) == RPAREN` (`[()]`) or `isTypeStart(2)` (`[(u64, i64)]`) $\implies$ **`TypeArgs`**, whereas `arr[(i + 1)]` starts with `IDENT`/`INT_LIT` inside `(` $\implies$ **`IndexExpr`**.
    5.  `peek(1)` is `DOT` (`.Primary`), literal, `$`, `..`, or unary `-`/`!` (`k = 1`) $\implies$ **`IndexExpr`**.
    6.  `peek(1)` in `{IDENT, TYPE_IDENT}`: scan forward across contiguous `(IDENT | TYPE_IDENT | CONST_IDENT)` segments separated by `DOT` (for module depth `m`, bounded lookahead `k = 2m + 3`, typically `3..9` tokens). Because modules are strictly `IDENT` (`snake_case`) and nominal types cannot be declared directly inside `struct`/`enum` bodies (only inside `mod ident` scopes), **every concrete nominal type path `{ mod_ident . } TypeIdent` contains zero or more `IDENT` segments followed by exactly one `TYPE_IDENT`**, immediately followed by `]`, `,`, `?`, or `[`. By contrast: `table[cx.limits.MAX_SLOTS]` ends in `CONST_IDENT` (`0` `TYPE_IDENT`s) $\implies$ **`IndexExpr`**; `table[row.col_idx]` ends in `IDENT` $\implies$ **`IndexExpr`**; and `table[ColumnKey.Primary]` or `table[cx.http.Method.Get]` contains **two `TYPE_IDENT`s** (`ColumnKey` + `Primary`, `Method` + `Get`) $\implies$ **`IndexExpr`** – even when indexing an array of function pointers `handlers[ColumnKey.Primary](req)`! *(In `Type` grammar positions such as `-> Iter.Item` or `Vec[Iter.Item]`, the parser is already inside `parseType()`, so `TYPE_IDENT . TYPE_IDENT` associated types parse directly; in the rare case an unprojected `Iter.Item` is passed explicitly inside an expression call `f[…](x)`, binding `type Item = Iter.Item;` keeps `table[Enum.Variant]` 100% unambiguous.)*

#### Edge Case Family 2: Associated Calls and Constants on Generic and Primitive Types (`Vec[u8].with_capacity(16)`, `u32.MAX`)

In `PrimaryExpr`, `PRIM_TYPE` (`u32`, `f64`, `usize`), `KW_SELF_TYPE` (`Self`), `TYPE_IDENT` (`Vec`, `Span16`), and `IDENT` (`cx`) parse as valid primary nodes. When `lhs` is a static path or instantiated type (`Ident`, `TypeIdent`, `SelfType`, `PrimType`, `PathMember`, `PathType`, or `TypeInst`), postfix `DOT` accepts `.IDENT` (`Vec[u8].with_capacity(16)`), `.TYPE_IDENT` (`cx.http.StatusCode.Ok`), or `.CONST_IDENT` (`u32.MAX`, `Span16.EMPTY`). Phase 4 `Sema` resolves whether `lhs` denotes a module, a `TypeId`, or a local variable in O(1) scope lookup without altering the parse tree.

#### Edge Case Family 3: Contextual `.Variant` vs. Qualified `Result.Ok(v)` vs. Multiline `.map(…)` Chains & Tail Expressions

1.  **Prefix Contextual `.Variant` (`PrimaryExpr`):** Starts with `DOT` followed **strictly by `TYPE_IDENT`** (`.Ok(val)`, `.None`, `.SpaceBetween`). Because methods and fields are `IDENT` (`snake_case`), tuple indices are `INT_LIT`, and `.await` is `KW_AWAIT`, a value projection can never legally start a `PrimaryExpr`.
2.  **Multiline Leading-Dot Method Chains:** Because newlines are pure trivia in CoreX (`DR-03` §3.2), `let ids = users \n .filter(|u| u.active) \n .map(|u| u.id);` has no `;` after `users`, so the Pratt loop consumes `.filter(…)` and `.map(…)` (`DOT` + `IDENT`) seamlessly across line breaks.
3.  **Self-Terminating Block Statement Followed by Tail `.Ok(val)`:** In `DR-03` §3.2, block-bodied statements (`if … { }`, `match … { }`, `for … { }`, `while … { }`, `loop { }`) omit trailing `;`. Consider:

    ```rust
    if bad_header {
        return .Err(.CorruptHeader);
    }
    .Ok(records_written)
    ```

    Because CoreX restricts postfix `.TYPE_IDENT` and `.CONST_IDENT` exclusively to static path/type primaries (`isStaticPath(lhs) == true`, which is `false` for `IfExpr`, `MatchExpr`, `LoopExpr`, and `Block`), the parser sees `peek(0) == DOT` and `peek(1) == TYPE_IDENT` (`Ok`) after `}`, immediately closes the `IfExpr` statement (`k = 2`), and parses `.Ok(records_written)` as the block's `TailExpr`!

#### Edge Case Family 4: Nested Tuple Indexing (`tup.0.1.2`) vs. Float Literals (`0.1`)

In Rust, writing `nested_tuple.0.1` fails with a syntax error because the maximal-munch lexer tokenizes `0.1` as a single `FLOAT_LIT` token unless parenthesized `(nested_tuple.0).1` or split via parser hacks. CoreX's lexer (`stage0/src/lexer.zig`) maintains a 1-byte register `prev_sig_kind: TokenKind` (the kind of the previous non-trivia syntactic token). When scanning decimal digits at offset `i`, the lexer munches `.` + `[0-9]` into `FLOAT_LIT` **if and only if `prev_sig_kind != .dot`** (and `source[i..i+2] != ".."`). Thus `tup.0.1.2` lexes cleanly into `[IDENT("tup"), DOT, INT_LIT("0"), DOT, INT_LIT("1"), DOT, INT_LIT("2")]`, while `0..0.5` lexes into `[INT_LIT("0"), DOTDOT, FLOAT_LIT("0.5")]` and `0.max(x)` lexes into `[INT_LIT("0"), DOT, IDENT("max"), …]`.

#### Edge Case Family 5: Unified Dot `use` Import Trees (`use cx.fs.{self, File, BufReader as Reader};`)

In `UseTree`, after consuming a `ModuleSegment` and `DOT`, the next token is one of `STAR` (`use cx.math.*;`), `LBRACE` (`use cx.fs.{self, File};`), or `ModuleSegment` (`IDENT | TYPE_IDENT | CONST_IDENT`), with optional trailing `KW_AS` (`as`). All three continuations have pairwise-disjoint `FIRST` sets, parsing in strict **`LL(1)` (`k = 1`)** lookahead.

## 2. Deliverable 2: Selected Syntax Elevation Catalog and Pruned Anti-Patterns Matrix

### 2.1 Comparative Evaluation of Condition-Binding and Local Declaration Candidates

Research Objective 2 requires solving a pervasive systems ergonomics gap – binding an intermediate value and testing a guard predicate on it inside the same `if` or `while` header – by evaluating four candidate designs `(A)`–`(D)` across visual readability, `LL(k)` parser simplicity, MVS drop-order soundness, and CoreX's **One Canonical Way** invariant:

| Candidate Design | Representative Syntax | Readability & Dataflow Direction | `LL(k)` Parser Simplicity | MVS & SAST Drop-Order Soundness | CoreX `DR-21` Verdict & Role |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **(A) Parenthesized Statically Typed Inline Walrus (`:=`)** | `while (n := sock.read(&mut b)?) > 0 { … }`<br>`if (var rem: usize := len) >= 4 { … }` | **High for relational predicates:** Binds an irrefutable value inline right inside `> 0` / `!= EOF` checks without splitting the loop into `loop { let n = …; if n == 0 { break; } }`. | **`LL(2)` inside `(`:** Mandatory `(…)` prevents all PEP 572 operator-precedence bugs (`n := a > 0`). | **100% Sound (`ConditionScope`):** Scoped strictly to subsequent `and` conjuncts + `then`/loop body; pre-`else` LIFO drop; forbids `@linear` moves. | **✓ ADOPT (`SE-02`)** strictly for **irrefutable** inline condition bindings. |
| **(B) Flow-Sensitive `is` / `is not` Pattern + Guard Chains** | `while r.next_line()? is .Some(line) and line.len() > 0 { … }` | **Best-in-class for sum types:** Reads strictly left-to-right (`expr` $\rightarrow$ `is` $\rightarrow$ `Pattern` $\rightarrow$ `and` $\rightarrow$ `guard`), unlike Rust's right-to-left `if let Pat = expr`. | **Pratt `(6, 7)`:** Reuses existing `KW_IS` token; `PatternNoStruct` avoids `{` block collision at `LL(1)`. | **100% Sound (`ConditionScope`):** Adopts Rust 2024 `if_let_rescope` (`#124085`) pre-`else` temporary drop. | **✓ ADOPT (`SE-01`)** for **refutable** pattern tests & bindings; **retire `if let` / `while let`**. |
| **(C) Swift-Style Comma Condition Lists** | `if let n = sock.read(&mut b)?, n > 0 { … }` | **Poor Boolean Composability:** Overloads `,` to mean `and`; cannot group `a and (b or c)` cleanly without colliding with tuple syntax `(a, b)`. | **Ambiguous with Tuples:** Forces context-sensitive `,` parsing inside `if`/`while` headers vs. tuple expressions. | Sound if lowered as `and`, but duplicates `and` keyword. | **✗ REJECT** (violates Invariant 2: redundant with `and` chains). |
| **(D) Statement-Level `:=` Declarations** *(Go / Odin / Jai)* | `x := expr;` / `x: Type = expr;` | **Harms MVS Mutability Clarity:** Either makes all locals mutable by default (destroying `DR-02` `let` vs. `var` clarity) or duplicates `let x = expr;`; `x := 1` vs. `x = 1` risks silent shadowing. | Requires lookahead across arbitrary pattern/tuple LHS before seeing `:=` vs. `=`. | Obscures whether root variable permits `access.inout` (`&mut x`) in `DR-06` Pass 2. | **✗ REJECT** (`let` and `var` remain sole statement declarations). |

Crucially, adopting **both `(B)` (`SE-01` `is`) and `(A)` (`SE-02` `(x := expr)`)** while banning bare irrefutable identifier patterns in `is` (`if x is y` is a compile error; write `(y := x)`) satisfies **One Canonical Way** with zero syntactic overlap: `is` exclusively performs **refutable pattern matching/destructuring** (`.Some(x)`, `.Err(e)`, `1..=12`, `[head, ..tail]`), whereas `(x := expr)` exclusively performs **irrefutable value capture inside a relational or boolean expression** (`(n := read()?) > 0`).

### 2.2 Selected Syntax Elevation Catalog (`SE-01` through `SE-08`)

#### `SE-01`: Flow-Sensitive `is` and `is not` Pattern Expressions and Guard Chains

-   **Exact Surface Syntax:**

    ```rust
    // 1. Positive conjunctive pattern + guard chain in `if` and `while` (replaces `if let` / `while let`):
    while reader.next_line()? is .Some(raw_line) and not raw_line.is_empty() {
        out.write_fmt("{raw_line}\n")?;
    }
    if node.left is .Some(ref left_child) and Self.balance_factor(left_child) < 0 { … }

    // 2. General boolean pattern test (allowed in any expression when pattern binds 0 variables):
    let ok_status = resp.status is (.Ok | .Created | .NoContent);
    if user.role is not .Admin { return .Err(.Forbidden); }
    ```

-   **Grammar & Precedence Rules:** `is` and `is not` sit at Pratt Precedence Tier 3 (`(6, 7)`, **non-associative**, identical to `==`, `!=`, `<`, `>`), binding looser than arithmetic, `|>`, and `orelse`/`catch` `(9, 8)` and tighter than `and` `(4, 5)`. Inside `if` and `while` headers (`allow_struct_lit = false`), `is` parses `PatternNoStruct`, which forbids unparenthesized struct-payload braces `{ … }` so `if status is StatusCode.Ok { handle(); }` never mistakes `{ handle(); }` for a struct pattern; struct patterns in `if` headers wrap in parentheses: `if err is (.CorruptHeader { magic, offset }) and magic == 0 { … }`. Bare irrefutable binding patterns (`x is y` without `@` subpattern) emit `E0418` (`use '(y := x)' for irrefutable inline binding`), and legacy `if let` / `while let` are removed from the grammar.
-   **Static Bidirectional Typing (`DR-04` Extension):**
    $$\frac{\Gamma; \Theta \vdash e \Rightarrow \tau_e \dashv \Theta_1 \quad \Gamma; \Theta_1 \vdash P \Leftarrow \tau_e \dashv (\Gamma_P, \Theta_2)}{\Gamma; \Theta \vdash (e \;\mathsf{is}\; P) \Rightarrow \mathsf{bool} \;\text{with true-bindings}\; \Gamma_P \dashv \Theta_2} \;(\text{IsPat}\Rightarrow)$$
    Along a positive conjunctive condition spine $C_1 \;\mathsf{and}\; C_2$, $C_2$ is checked under $\Gamma \cup \Gamma_P(C_1)$, and `then_block` / `while_body` is checked under $\Gamma \cup \bigcup_i \Gamma_P(C_i)$ (rejecting duplicate binding names across conjuncts). Under `is not`, unary `not`/`!`, `or`/`||`, or outside an `if`/`while` condition spine, $\Gamma_P$ **must be empty** ($\Gamma_P = \emptyset$, else `E0214`).
-   **MVS Scoping & Pre-Else `MIR` Drop Semantics (`DR-06` + Rust 2024 `if_let_rescope`):**
    As demonstrated by Rust 2024's `if_let_rescope` stabilization (`#124085`), extending scrutinee temporaries into an `else` branch causes unexpected lock/exclusivity deadlocks when `else` mutates the same state. In CoreX, `HIR → MIR` lowering opens a dedicated `ConditionScope` before evaluating `CondExpr`. All scrutinee temporaries and `AutoDrop` bindings introduced in `CondExpr` remain live through `then_block` (dropping in reverse LIFO order at the end of `then_block`), and along any short-circuit false CFG edge they **drop in reverse LIFO order *prior* to entering `else_block`**. Binding a `@linear` payload inside `is` requires `ref` / `ref mut` (`access.let` / `access.inout`) whenever followed by another `and` conjunct so a false guard can never leak a moved `@linear` handle (`E0304`).

#### `SE-02`: Parenthesized Statically Typed Inline Walrus Condition Bindings (`:=`)

-   **Exact Surface Syntax:**

    ```rust
    while (n := sock.read(&mut chunk)?) > 0 {
        out.write_all(chunk[..n])?;
    }
    if (var rem: usize := packet.len() - HEADER_BYTES) >= 4 and verify_crc(packet[..rem]) {
        rem -= 4;
        consume(packet[..rem]);
    }
    ```

-   **Grammar & Scope Rules:** Syntax is **`"(" [ "var" ] IDENT [ ":" Type ] ":=" Expr ")"`**, recognized inside `PrimaryExpr`'s `(` branch at `LL(2)` (`peek(0) == KW_VAR` or `peek(0) == IDENT and peek(1) in {COLON_EQ, COLON}`). Mandatory parentheses prevent all precedence traps (`(n := read()?) > 0` clearly binds `n` to `usize` before comparing `> 0`). Parser flag `allow_walrus` permits `WalrusCondExpr` **only** along the positive `and`/`&&` spine of `if` and `while` headers; using `:=` as a statement, under `not`/`or`, or in general expressions emits `E0215`.
-   **Static Bidirectional Typing:**
    $$\frac{\Gamma; \Theta \vdash e \Rightarrow \tau_e \dashv \Theta_1 \quad \tau_c = \text{default}(\tau_e) \quad \text{valid\_range}(e, \tau_c)}{\Gamma; \Theta \vdash (\mathsf{var}^?\; x := e) \Rightarrow \tau_c \;\text{with true-binding}\; (x :_{\mathsf{let}/\mathsf{var}} \tau_c) \dashv \Theta_1} \;(\text{Walrus}\Rightarrow)$$
    If explicit `: Type` is provided, $e$ is checked top-down ($\Leftarrow \text{Type}$). For non-`Copy` `AutoDrop` types, the parenthesized expression yields a read-only `access.let` projection of `x` to the surrounding relational/method predicate so `x` itself is not moved before entering `then_block`. `@linear` types are disallowed in `:=` (`E0304`; declare `@linear` resources via block-level `let`/`var` + `defer`).
-   **MVS Drop Semantics:** Shares `SE-01`'s exact `ConditionScope` pre-`else` LIFO drop discipline.

#### `SE-03`: Infix `orelse` Option Coalescing and Control-Flow Divergence

-   **Exact Surface Syntax:**

    ```rust
    let assigned_role = payload.role orelse .Member;               // Lazy value coalescing
    var x = y.left.take() orelse return y;                         // Early-return unwrap (replaces 3-line let..else)
    let left_owned = node.left.take() orelse unreachable;          // Explicit zero-cost invariant assertion
    let host = cli_host orelse env_host() orelse "127.0.0.1";      // Right-associative lazy chain
    ```

-   **Comparison (`orelse` vs. `??` vs. `catch`):** Using `??` collides visually with postfix `?` propagation (`fetch()? ?? default`) and nested option type annotations `bool??` (`DR-04` §4.1), while overloading `catch` onto `Option[T]` (`DR-07` §2.2) blurs operational error handling (`Result[T, E]`) with optional absence (`T?`). Adopting Zig's keyword **`orelse`** (combined with Kotlin's `Nothing` / CoreX's `never` bottom-type coercion) creates a clean 1-to-1 symmetry: **`orelse` is the sole infix recovery/coalescing operator for `T?`**, and **`catch` is the sole infix recovery operator for `Result[T, E]`** (retiring `Option.unwrap_or` and `Option.unwrap`).
-   **Static Bidirectional Typing (`Pratt (9, 8)`, Right-Associative):**
    $$\frac{\Gamma; \Theta \vdash e_1 \Rightarrow \tau? \dashv \Theta_1 \quad \Gamma; \Theta_1 \vdash e_2 \Leftarrow \tau \dashv \Theta_2}{\Gamma; \Theta \vdash (e_1 \;\mathsf{orelse}\; e_2) \Rightarrow \tau \dashv \Theta_2} \;(\text{Orelse}\Rightarrow)$$
    Because `return`, `break`, `continue`, `panic(…)`, and `unreachable` are primary `DivergingExpr`s synthesizing `never`, and `never <=_coerce \tau` holds for every `TypeId` (`DR-04` §1.3D), control-flow divergence checks seamlessly against $\tau$! And because `orelse` is right-associative `(9, 8)`, `a orelse b orelse c` parses as `a orelse (b orelse c)`, typing `(b orelse c) <= T` cleanly.
-   **MVS & `MIR` Lowering:** Lowers directly to `term_branch_try` (`DR-07` §4.3): on `.Some(v)`, control jumps straight to `^orelse_join(%v)` with zero extra copies; on `.None`, control enters the cold `^orelse_none` block to evaluate $e_2$ lazily, running active `defer` / `AutoDrop` chains if $e_2$ diverges (`errdefer` runs iff diverging via `return .Err(…)`).

#### `SE-04`: End-Relative `$` Slice and Array Length Indexing (Pentagon-Integrated)

-   **Exact Surface Syntax:**

    ```rust
    let last_byte = frame[$-1];
    let payload   = frame[..$-4];
    let trailer   = frame[$-4..];
    let inner     = raw_line[1..$-1];
    let nested    = outer_buf[offsets[$-1]..$-2]; // Inner `$` = offsets.len(); outer `$` = outer_buf.len()
    ```

-   **Grammar & Lexical Scope Rules:** Following D's `ArrayLength` specification, `TokenKind.DOLLAR` (`"$"`) is a `PrimaryExpr` valid **strictly inside `[ … ]` index/slice brackets** of an array (`[T; N]`), slice (`[T]`, `&[T]`, `&mut [T]`, `str`), `#soa` slice (`#soa[T]`), or `Vec[T]`. Referencing `$` outside `[ … ]` or when indexing a raw pointer `*T` or `Map[K, V]` emits compile error `E0416`. Simultaneously, `DR-21` enables prefix/postfix open range forms (`..b`, `..=b`, `a..`, `..`) inside `[ … ]` so `chunk[..n]` and `frame[$-4..]` omit redundant `0` and trailing `$` endpoints.
-   **`AST → HIR` Desugaring & Phase-6 Pentagon (`Intv × Sub`) Bounds Elision:**
    `container_expr[idx_expr]` evaluates `container_expr` **exactly once** into a temporary MVS borrow `__base` and binds `let __dollar_len: usize = __base.len();` in that bracket's inner scope (so nested brackets shadow `__dollar_len` without conflict). In Phase 6 (`stage0/src/mir_sast.zig` Pass 4 Pentagon abstract domain, `DR-06` §2.4), we add the exact backward-offset transfer rule for checked unsigned subtraction `%idx = sub_u %len, K` ($K > 0$ integer constant):
    $$\inf(b^*(\%len)) \ge K \implies b'(\%idx) = [\inf(b^*(\%len)) - K,\; \sup(b^*(\%len)) - K] \subseteq [0, +\infty) \;\land\; s'(\%idx) = \{ \%len \} \cup s^*(\%len)$$
    Consequently, after a dominating guard `if frame.len() < 4 { return .Err(.TruncatedTrailer); }`, Pentagon statically proves `0 <= %idx < %len` for both `frame[..$-4]` and `frame[$-4..]`, **erasing both the `$-4` unsigned underflow trap and the slice bounds check** at compile time! Conversely, `arr[$-5]` on `arr: [u8; 4]` is rejected at compile time with `E0307 (StaticBufferOverflow)`.

#### `SE-05`: Element-First Zero-Allocation Indexed Iteration (`for item, i in slice`)

-   **Exact Surface Syntax:**

    ```rust
    for sample, idx in tail {
        Text(value: "#{idx + 1}: {sample.cpu_load}%", size: 12);
    }
    for &mut particle, i in &mut particles {
        particle.pos_x += (i as f32) * 0.5;
    }
    ```

-   **Why Element-First (`item, i`) Beats Index-First (`i, item`):** In Go (`for i, v := range s`), writing a single binding `for x := range s` binds `x` to the integer *index* rather than the element, causing bugs whenever developers add or remove the second variable. Following Odin's usage-priority design and `DR-02` §4.1's `#soa` loop design (`for &v, i in view`), CoreX places the primary element first (`for item in slice` $\rightarrow$ `for item, i in slice`, and for `Map[K, V]`, `for key, val in map`).
-   **Static Typing, MVS & Pentagon Lowering:** On slices, arrays, `Vec[T]`, and `#soa` views, `i` synthesizes immutable `usize` (`let`). `AST → HIR` lowers the loop directly to a hardware counter `%i: usize` over `0..%__len` (with zero `Enumerate` wrapper struct), automatically seeding `%__len` $\in s^*(\%i)$ in Pentagon Pass 4 and projecting `item` via `access.let` (or `access.inout` when `&mut` is written).

#### `SE-06`: Labeled Loops (`label: for/while/loop`) and `T?`-Typed Search-Loop `orelse`

-   **Exact Surface Syntax:**

    ```rust
    let rule_idx: usize = find_rule: for rule, idx in rules {
        if line.contains(rule) {
            break :find_rule idx;
        }
    } orelse continue;
    ```

-   **Grammar & `LL(3)` Disambiguation:** Loop headers accept an optional `IDENT ":"` prefix (`find_rule: for …`, `outer: loop { … }`), recognized in `PrimaryExpr` and `Block` at `LL(3)` (`peek(0) == IDENT`, `peek(1) == COLON`, `peek(2) in {KW_LOOP, KW_FOR, KW_WHILE}`). Jump expressions accept optional `:IDENT` targets (`break :find_rule idx`, `continue :outer`), avoiding Rust's `'label` single-quote token clash with `CHAR_LIT`.
-   **Static Bidirectional Typing:** An unconditional `loop { … }` with `break val` synthesizes `T` (or `never` if no `break` is reachable). A conditional `for` or `while` loop with no value `break` synthesizes `unit`; when one or more `break [:label] val` edges carry a value of type `T`, the `for`/`while` expression synthesizes **`T?` (`Option[T]`)** – yielding `.Some(val)` on `break val` and `.None` when the loop exhausts naturally! Chaining **`orelse fallback_or_diverge`** (`SE-03`) immediately unwraps `T?` to `T`, solving Python's notorious `for … else` readability anti-pattern without adding a special loop-else clause.

#### `SE-07`: Single-Expression `=` Function Shorthand and Call-Site Named/Default Arguments

-   **Exact Surface Syntax:**

    ```rust
    // 1. Single-expression `=` function / method shorthand:
    @inline
    pub fn node_height(node: &OwnPtr[AvlNode[K, V]]?) -> i32 =
        if node is .Some(ref n) { n.height } else { 0 };

    // 2. Named + default arguments on ANY direct function/method/constructor call:
    pub fn connect(addr: SocketAddr, timeout_ms: u64 = 5_000, nodelay: bool = true) -> Result[TcpSocket, IoError];
    let sock = connect(addr, nodelay: false)?; // Skips `timeout_ms` cleanly using its default `5_000`!
    ```

-   **Single-Expression `=` Typing Rules:** `FunctionItem` and `TraitMember` accept `Block | "=" Expr ";" | ";"`. Explicit parameter and `-> ReturnType` annotations remain mandatory (`DR-04` signature firewall); `Expr` is checked top-down ($\Leftarrow \text{ReturnType}$, or $\Leftarrow \mathsf{unit}$ if `-> ReturnType` is omitted).
-   **Named + Default Call-Site Rules & `DR-02` Sequencing:** Building on `DR-03` §5.4 (`FnParam` `= Expr` defaults and `CallArg` `IDENT : Expr`), `DR-21` formalizes named and default arguments across all direct function, method, and variant calls (not just `cx.ui` widgets):
    1.  Positional arguments must precede named arguments; each parameter is supplied at most once, and omitted parameters must declare a default `= Expr` (`E0419` otherwise).
    2.  Default expressions are type-checked **once at the function's definition site** ($\Leftarrow \text{ParamType}$) in pure/module scope (may reference `const` items and earlier parameters by `let` copy, never caller locals).
    3.  During `AST → HIR` lowering, `Sema` maps arguments to declaration slot order while **preserving strict left-to-right source evaluation order (`DR-02` §2.2)**: if named arguments at a call site appear out of declaration order and any argument is impure, `AST → HIR` binds left-to-right `let __arg_i = …;` temporaries before invoking the callee, then evaluates omitted default expressions in parameter order, and finally projects any `&mut self` receiver *post-arguments* (`DR-02` §2.2). Indirect `fn(…)` pointers and `ClosureType` (`|…| -> R`) remain positional-only to keep `TypeId` interning O(1).

#### `SE-08`: Lexical `with context.field = expr` Context Override Blocks

-   **Exact Surface Syntax:**

    ```rust
    with context.allocator = &mut scratch, context.logger = &req_logger {
        let payload = body_bytes |> Json.parse[CreateUserReq]()?;
        persist_user(&payload).await
    }
    ```

-   **Static Typing, `.await` Transparency & Phase-6 Escape Soundness:** `WithExpr = "with" ContextBinding { "," ContextBinding } Block ;` statically validates each `.IDENT` against the 5 slots of `core.Context` (`allocator`, `temp_allocator`, `logger`, `diagnostics`, `cancel_token`). Assigning `&mut arena` (`&mut Arena`) to `allocator` or `temp_allocator` automatically coerces via `arena.as_handle()` (`AllocTag = 1`). Unlike `DR-15`'s `mem::with_arena(&mut arena, || { … })` closure wrapper (which is retired), `with context…` desugars in `AST → HIR` to inline save-and-`defer`-restore statements around `Block`:

    ```rust
    {
        let __saved_alloc = context.allocator;
        context.allocator = scratch.as_handle();
        defer { context.allocator = __saved_alloc; }
        Block
    }
    ```

    Because there is no closure boundary, `.await` suspension points (where the coroutine resumption loop automatically swaps `context` slots on poll entry/exit), `?` propagation, `return`, `break`, and `continue` all work transparently inside `Block`! In Phase 6 (`mir_sast.zig` Pass 3), `Depth(rho_ctx)` inside `Block` is raised to `max_i Depth(rhs_i)` – statically rejecting (`E0306`) any `AutoDrop` container (`Vec`, `String`, `Map`) allocated via `context.allocator` inside `with context.allocator = &mut scratch` from escaping past `scratch`'s lifetime!

```rust
use std::mem::{OwnPtr, PoolAllocator};

pub struct AvlNode[K: Ord, V] {

    pub value: V,

            root: .None,
            pool: PoolAllocator::new[AvlNode[K, V]](cap),
```

#### Showcase (b): Streaming Wire/Log I/O, Inline Walrus, and Slice `$` Verification (`frame_scanner.cx`)

Here `while (n := sock.read(&mut chunk)?) > 0` eliminates the `loop { let n = …; if n == 0 { break; } }` boilerplate, `frame[..$-4]` and `frame[$-4..]` leverage Phase 6's Pentagon verifier (which sees `if frame.len() < 4 { return …; }` and statically erases all underflow and bounds traps), and `find_rule: for rule, rule_idx in rules { … } orelse continue` eliminates mutable `matched_rule: usize?` and manual `rule_idx += 1` state.

##### Before (DR-03 Wave-1 Baseline)

```rust
mod frame_scanner;

use std::fs::{BufReader, File};
use std::hash::crc32;
use std::io::{IoError, Read, Stdout};
use std::mem::Arena;

pub enum ScanError {
    @from Io(IoError),
    TruncatedTrailer,
    BadChecksum { expected: u32, actual: u32 },
}

pub fn verify_wire_stream[R: Read](
    sock: &mut R,
    out: &mut Stdout,
) -> Result[u64, ScanError] {
    var chunk: [u8; 4096] = [0; 4096];
    var total_payload_bytes: u64 = 0;

    loop {
        let n = sock.read(&mut chunk)?;
        if n == 0 {
            break;
        }
        let frame = chunk[0..n];
        if frame.len() < 4 {
            return .Err(.TruncatedTrailer);
        }
        let split_at = frame.len() - 4;
        let payload = frame[0..split_at];
        let trailer = frame[split_at..frame.len()];
        let expected = u32::from_le_bytes(trailer);
        let actual = crc32::compute(payload);
        if actual != expected {
            return .Err(.BadChecksum { expected, actual });
        }
        out.write_all(payload)?;
        total_payload_bytes += payload.len() as u64;
    }

    .Ok(total_payload_bytes)
}

    path: str,
    rules: &[str],
    out: &mut Stdout,

            raw_line[0..raw_line.len() - 1]
        } else {
            raw_line
        };

                if line.contains(rule) {
                    matched_rule = .Some(rule_idx);
                    break;
                }
                rule_idx += 1;
            }
            if let .Some(idx) = matched_rule {
                hits += 1;
                out.write_fmt("[rule #{idx}] {line}\n")?;
            }
        }
    }
```

```rust
    @from Io(IoError),
    TruncatedTrailer,
    BadChecksum { expected: u32, actual: u32 },
}

pub fn verify_wire_stream[R: Read](
    sock: &mut R,
    out: &mut Stdout,
) -> Result[u64, ScanError] {
    var chunk: [u8; 4096] = [0; 4096];
    var total_payload_bytes: u64 = 0;

    while (n := sock.read(&mut chunk)?) > 0 {
        let frame = chunk[..n];
        if frame.len() < 4 {
            return .Err(.TruncatedTrailer);
        }
        let payload = frame[..$-4];
        let expected = u32.from_le_bytes(frame[$-4..]);
        let actual = crc32.compute(payload);
        if actual != expected {
            return .Err(.BadChecksum { expected, actual });
        }
        out.write_all(payload)?;
        total_payload_bytes += payload.len() as u64;
    }

    .Ok(total_payload_bytes)
}
```

```rust
}

@route(method = "POST", path = "/v1/users")
pub async fn create_user(
    req: &mut Request,
    pool: &PgPool,
) -> Result[Json[CreateUserResp], ApiError] {
    var scratch = Arena::with_capacity(65_536);
    defer scratch.release();

    let body_bytes = req.read_body_bounded(MAX_BODY_BYTES).await catch {
        return .Err(ApiError::PayloadTooLarge);
    };

    let payload = mem::with_arena(&mut scratch, || {
        Json::parse[CreateUserReq](body_bytes)
    }) catch |e| {
        return .Err(ApiError::InvalidJson(e.message()));
    };

    if payload.username.len() < 3 or not payload.email.contains("@") {
        return .Err(ApiError::ValidationFailed("invalid username or email"));
    }

    let assigned_role = match payload.role {
        .Some(r) => r,
        .None => UserRole::Member,
    };
    let password_hash = argon2::hash_password(payload.password_raw).await
        catch { return .Err(ApiError::DatabaseError("hash failure")); };

    var tx = pool.begin_tx(TxIsolation::Serializable).await
        catch |e| { return .Err(ApiError::DatabaseError(e.message())); };
    defer tx.rollback_if_uncommitted();

    let (user_id, created_at_unix) = tx.query_one[(u64, i64)](
        "INSERT INTO users (username, email, password_hash, role) VALUES ($1, $2, $3, $4) RETURNING id, created_unix",
        [payload.username, payload.email, password_hash, assigned_role.as_str()],
    ).await catch |e| {
        return .Err(ApiError::ConflictEmail(payload.email));
    };

    tx.commit().await catch |e| {
        return .Err(ApiError::DatabaseError(e.message()));
    };

    .Ok(Json::from(CreateUserResp {
        user_id,
        username: payload.username,
        created_at_unix,
    }))
```
