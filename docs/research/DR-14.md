# Zero-Legacy Automated Source Migration Engine (`corex upgrade`) and Canonical Formatter (`corex fmt`) for CoreX (.cx)

To enforce CoreX's **Zero-Legacy Compiler Philosophy** while guaranteeing that 100% of `.cx` code across the ecosystem is canonically formatted at **2,758,621 lines of code per second (LOC/sec) on a single core** (and **20,413,793 LOC/sec across 8 cores** in quantitative throughput modeling), CoreX (`corex-lang/corex`) unifies its formatting, linting, and version-upgrade tooling directly atop `DR-12`'s contiguous Struct-of-Arrays (SoA) syntax arenas (`TokenBuffer`, `TriviaTable`, `LosslessCstArena`, and `AstArena`). Rather than allocating pointer-heavy recursive Wadler-Lindig `Doc` closures on the heap – which bottleneck traditional formatters via pointer chasing and recursive `fits()` lookahead scans – `corex fmt` lowers `LosslessCstArena` (`10 bytes/node`) into a flat, contiguous **8-byte Instruction Document Arena (`DocArena`, 36.56 KiB per 400-LOC file)**. During a single bottom-up/preorder emission pass (`38.0 µs` per 400-LOC file), `DocArena` precomputes the exact flattened horizontal column width (`flat_width: u16`, saturating at `0xFFFF` on hard newlines) for every `GroupStart` instruction. Consequently, the final rendering pass (`26.0 µs`) resolves every Wadler-Lindig group break decision in **O(1) arithmetic (`col + inst.flat_width <= max_width`)** without backtracking or rescanning tokens, formatting a 400-line file in **145.0 µs cold** (`25.0 µs` lex + `56.0 µs` CST + `38.0 µs` `DocArena` + `26.0 µs` render = **2,758,621 LOC/sec** single-core, or **6,250,000 LOC/sec** on warm CSTs inside `corex lsp`) and formatting an entire 500,000-line workspace from cold disk in **24.49 ms** across 8 threads.

For language evolution, `corex upgrade` ensures that **zero legacy grammar branches, deprecated token kinds, or historical edition flags ever enter the main compiler pipeline (`corex`)**. Every CoreX project declares its target specification in `corex.toml` (`corex = "1.0"`). When a newer toolchain (`v1.1` or `v1.2`) encounters a project or third-party dependency targeting an older specification, `corex` refuses to activate legacy compatibility modes; instead, it invokes the isolated **`corex upgrade` Migration Subsystem (`src/tools/upgrade/`)**. This subsystem executes a deterministic, version-chained Directed Acyclic Graph (DAG) of **Three-Tier Migration Analyzers**: (1) **Lexical & Pre-CST Token-Stream Shims** that normalize retired keywords or punctuation in a transient copy of `TokenBuffer` before main parsing begins; (2) **Declarative CST Structural Rewrite Rules** that transform surface syntax trees while preserving 100% of leading, trailing, and dangling `TriviaPiece` comments; and (3) **Type-Checked Semantic Modernizers & Hazard-Checked Source Inliners** (modeled on Go 1.26's `go fix` analysis framework and `@deprecated(upgrade = ...)` directives) that migrate standard library and user APIs using `CompilerDb` type facts.

Crucially, `corex fmt --fix`, `corex fix`, `corex lsp` (`textDocument/codeAction`), and `corex upgrade` all share a single **Transactional Byte-Patch Engine (`DiagnosticSink` / `TransactionalPatcher`)** modeled on Cargo's transactional `rustfix` and `go fix`'s synergistic fixed-point loop. All candidate `TextEdit` spans emitted by compiler diagnostics or migration analyzers are sorted by byte offset and priority (`100` for structural syntax migrations, `80` for compiler quick-fixes, `50` for semantic API renames, `10` for style/casing lints), filtered via a linear-time disjoint interval sweep to eliminate overlapping edit collisions, and iterated to a synergistic fixed point (`MAX_SYNERGY_PASSES = 4`) before running an in-memory `corex fmt` pass. This guarantees that every automated migration produces conflict-free, syntactically valid, and canonically formatted `.cx` source code in a single atomic operation.

## 1. Deliverable 1: `corex fmt` Document Algebra, Trivia-Attachment & Formatting Rules Specification

### 1.1 Architectural Synthesis: Strict Wadler-Lindig Algebra Meets User-Steered Formatting (`zig fmt`)

Code formatters in systems programming languages traditionally fall into one of two camps, each exhibiting distinct trade-offs. The first camp consists of **Pure Width-Driven Pretty Printers** (`rustfmt`, `prettier`, `biome_formatter`, `ruff_formatter`), built on Philip Wadler's *A Prettier Printer* (1998/2003) and Christian Lindig's strict adaptation *Strictly Pretty* (2000). These formatters lower the syntax tree into an intermediate document algebra (`DocNil`, `DocText`, `DocLine`, `DocNest`, `DocGroup`) and break groups solely when the flattened representation exceeds a global column limit (`max_width = 100`). While width-driven formatting handles deeply nested expressions systematically, pure width-fitting frequently overrides human structural intent – collapsing a purposefully multi-line 3-argument function call onto a single dense line because it happens to be 98 characters wide, or destroying carefully aligned tabular array data. Furthermore, naive strict implementations of Lindig's `fits(w, stack)` predicate repeatedly scan ahead through the document stack at every `DocGroup` boundary, risking quadratic lookahead overhead unless flat widths are precomputed.

The second camp consists of **Author-Steered Formatters** (`zig fmt`, `gofmt`). As analyzed by Alex Kladov (`matklad`) in *Steering Zig Fmt* (May 2026), `zig fmt` ignores screen width entirely and instead selects layout variations by inspecting **structural cues written by the developer** – most notably **trailing commas** and **initial line breaks**. In `zig fmt`, `f(1, 2, 3)` is always formatted flat on one line, whereas adding a trailing comma `f(1, 2, 3,)` forces a multi-line layout with one argument per line. Similarly, inside an array literal with a trailing comma, `zig fmt` inspects the position of the *first* line break (for example, after the 3rd element) and formats the entire array into a 3-column aligned grid. While developers value `zig fmt`'s steerability and predictability, ignoring line width entirely forces programmers to manually break long boolean conditions or method chains.

`corex fmt` unifies both paradigms via a **Hybrid Steerable Wadler-Lindig Architecture**. First, under **Deterministic Width-Driven Breaking (`MAX_LINE_WIDTH = 100`, `INDENT_SPACES = 4`)**, every delimited list, function signature, binary expression, and `|>` / `.` chain is wrapped in a Wadler-Lindig `Group` that formats `Flat` if its precomputed horizontal width fits within the remaining columns of the 100-character line (`col + group.flat_width <= 100`), and switches to `Break` (4-space indentation) if it exceeds 100 columns. Second, under **Authoritative Trailing-Comma & Columnar Steerability (`zig fmt` Cues)**, if a developer explicitly writes a **trailing comma** before the closing delimiter of any comma-separated construct (`CallArgs`, `ParamList`, `TypeParams`, `TypeArgs`, `StructLiteral`, `TuplePat`, or `UseTree` group), `corex fmt` marks the enclosing `GroupStart` with `GroupMode.force_break`, expanding it into a vertical multi-line layout even if it is shorter than 100 columns. Conversely, if a multi-line construct breaks due to the 100-column limit, `corex fmt` automatically inserts the trailing comma (`IfBreak(",", "")`), ensuring that subsequent runs of `corex fmt` preserve the multi-line layout (**100% idempotency**). For homogeneous array literals (`[1, 2, 3, ...]`), if a trailing comma is present and the first newline appears after `K` elements (`2 <= K <= 16`), `corex fmt` formats the array in a `K`-column grid (`GroupMode.columnar_grid`).

### 1.2 The Contiguous 8-Byte `DocArena` Instruction Algebra and O(1) Width Propagation

To eliminate heap allocations and recursive tree traversals, `corex fmt` represents Wadler-Lindig documents as a flat instruction stream (`DocArena`) where every instruction occupies **8 bytes (`u64`)**. Instead of nesting `DocCons(lhs, rhs)` pointer nodes, concatenation is sequential array adjacency (`insts[i]` followed by `insts[i + 1]`), and scoped constructs (`Group`, `Indent`) are represented as matched bracket instruction pairs (`group_start` / `group_end`, `indent_start` / `indent_end`).

| `DocOp` Opcode (`u8`) | Instruction Semantics in `corex fmt` | `mode_or_delta` (`u8`) | `flat_width` (`u16`) | `payload` (`u32`) |
| :--- | :--- | :--- | :--- | :--- |
| **`noop` (`0`)** | Identity element (`DocNil`); skipped in O(1) during rendering. | `0` | `0` | `0` |
| **`text_source` (`1`)** | Zero-copy slice directly into `TokenBuffer.source` (used for identifiers, literals, and comments). | `byte_len_hi: u8` | Column width in UTF-8 code points (`u16`) | `source_byte_offset: u32` |
| **`text_static` (`2`)** | Canonical keyword or punctuation slice from the static compiler string table (`"fn"`, `" -> "`, `", "`, `";"`). | Static token length (`u8`) | Static column width (`u16`) | `static_table_offset: u32` |
| **`space_or_line` (`3`)** | Wadler-Lindig `Line`: emits `" "` (1 space) when enclosing group is `Flat`, or `\n` + indentation when `Break`. | `blank_lines: u2` (`0` = 1 newline, `1` = 1 blank line) | `1` (width when rendered flat as `" "`) | Enclosing `group_id: u32` |
| **`soft_line` (`4`)** | Wadler-Lindig `SoftLine`: emits `""` (0 bytes) when enclosing group is `Flat`, or `\n` + indentation when `Break`. | `blank_lines: u2` | `0` (width when rendered flat as `""`) | Enclosing `group_id: u32` |
| **`hard_line` (`5`)** | Unconditional newline (`\n` + current indentation); poisons enclosing groups' `flat_width` to `0xFFFF` (`INF_WIDTH`). | `blank_lines: u2` (`0` = `\n`, `1` = `\n\n`) | `0xFFFF` (`INF_WIDTH`) | `0` |
| **`if_break` (`6`)** | Conditional token (`IfBreak(break_str, flat_str)`): emits `break_str` (e.g., trailing `","`) if target group breaks, else `flat_str`. | `break_len: u4`, `flat_len: u4` | `flat_len` (`u16`) | Enclosing `group_id: u32` |
| **`line_suffix` (`7`)** | Buffers trailing inline comments (`// note`) in a side queue and flushes them immediately before the next physical `\n`. | `has_leading_space: u1` | `0xFFFF` (forces parent group to break if suffix is followed by tokens) | `trivia_piece_index: u32` in `TriviaTable` |
| **`group_start` (`8`)** | Opens a Wadler-Lindig layout group $G$; decides `Flat` vs `Break` in O(1) via `col + flat_width <= MAX_LINE_WIDTH`. | `GroupMode`: `auto_fit (0)`, `force_break (1)`, `columnar_grid (2)` | **Total flat width** from `group_start` to `group_end` (`0xFFFF` if broken) | `group_id: u32` |
| **`group_end` (`9`)** | Closes layout group $G$. | `0` | `0` | `group_id: u32` |
| **`indent_start` (`10`)** | Increments active indentation depth by `delta` spaces (`4` spaces standard; `4` spaces for `\|>` / `.` chains) when broken. | `delta_spaces: u8` (default `4`) | `0` | Enclosing `group_id: u32` (`0` = unconditional) |
| **`indent_end` (`11`)** | Decrements active indentation depth by `delta_spaces` upon leaving the indented construct. | `delta_spaces: u8` (default `4`) | `0` | Enclosing `group_id: u32` |

#### The O(1) Flat-Width Backpatching Invariant

In Lindig's original *Strictly Pretty* algorithm, deciding whether `Group(d)` fits on the current line requires calling `fits(w, stack)`, which walks the document nodes inside `d` until either `w` characters are consumed, a newline is encountered, or the group ends. When groups are deeply nested (`fn_sig` containing `param_list` containing `type_args` containing `tuple_type`), scanning ahead at every group boundary visits the inner tokens multiple times.

`corex fmt` eliminates lookahead scanning during rendering by maintaining an explicit **Open-Group Stack (`open_groups: [64]OpenGroupFrame`)** during the single-pass `LosslessCstArena` to `DocArena` builder:
1.  Every time a leaf instruction (`text_source`, `text_static`, `space_or_line`, `soft_line`, `if_break`) is appended to `DocArena`, its flat horizontal width (from `0` to `65,534`) is added to a running cumulative counter `cumulative_flat_cols: u64`.
2.  When `beginGroup(mode)` is called, the builder pushes `{ group_id, inst_idx, start_flat_cols: cumulative_flat_cols, poisoned: (mode == .force_break) }` onto `open_groups`.
3.  If a `hard_line` or a multi-line comment/string literal is emitted, or if a `line_suffix` (trailing `//` comment) is emitted inside the group, the builder sets `poisoned = true` on all currently open groups on the stack.
4.  When `endGroup()` is called, the builder pops the top `OpenGroupFrame`. If `frame.poisoned` is `true` or `cumulative_flat_cols - frame.start_flat_cols >= 0xFFFF`, it backpatches `doc_insts[frame.inst_idx].flat_width = 0xFFFF` (`INF_WIDTH`). Otherwise, it backpatches the exact integer difference:
    $$\text{flat\_width}(G) = \min\big(\text{0xFFFF},\; \text{cumulative\_flat\_cols} - \text{start\_flat\_cols}(G)\big)$$
5.  During the final `render` linear scan (`0 .. doc.insts.len`), encountering `group_start` at current column `current_col` resolves the group mode in **O(1) time**:
    $$\text{Mode}(G) = \begin{cases} \text{Flat} & \text{if } \text{inst.mode\_or\_delta} = \text{auto\_fit} \;\land\; \text{inst.flat\_width} < \text{0xFFFF} \;\land\; (\text{current\_col} + \text{inst.flat\_width} \le 100) \\ \text{Break} & \text{otherwise} \end{cases}$$

### 1.3 Lossless Trivia-Attachment (`Leading`, `Trailing`, `Dangling`) & Blank-Line Preservation

As established in Biome (`biome_formatter`) and Ruff (`ruff_formatter`), dropping, duplicating, or misplacing a source comment during formatting is unrecoverable data loss. Recall from `DR-12` Section 1.2 that the CoreX lexer partitions 100% of the source buffer into syntactic tokens (`TokenBuffer`) and an 8-byte-per-record `TriviaTable` (`TriviaPiece`), binding comments to tokens via `trivia_spans[tok]: PackedTriviaSpan` (`start_index: u24`, `count: u8`) with `meta.is_trailing: bool` and `meta.blank_lines_before: u2`.

To handle all structural boundaries – before the first child, between children, after the last child, and inside empty containers `{ /* empty */ }` – `corex fmt` classifies every `TriviaPiece` into one of **three structural attachment roles** (`Leading`, `Trailing`, `Dangling`) during CST-to-`DocArena` lowering:

| Comment Attachment Role | Ownership & Trigger Condition in `TokenBuffer` / `LosslessCstArena` | `DocArena` Lowering & Indentation Normalization Protocol |
| :--- | :--- | :--- |
| **1. Leading Trivia** (`meta.is_trailing == false`) | Any line comment (`//`), outer doc comment (`///`), module doc comment (`//!`), shebang (`#!`), or block comment (`/* ... */`) starting on a new line before Token `i`. | Emitted immediately *before* Token `i`'s `text_source` / `text_static` instruction. If `piece.meta.blank_lines_before >= 1` (and Token `i` is not immediately after `{`, `(`, or `[`), emits `hard_line(blank_lines = 1)`, clamping 2+ blank lines to at most 1 blank line. Multi-line `/* ... */` comments re-indent continuation lines by `current_indent - piece.indent_cols`. |
| **2. Trailing Trivia** (`meta.is_trailing == true`) | Any comment starting on the **same physical line** after Token `i - 1` (up to that line's `\n`). | If `piece.meta.has_newline_after == true` (`//`, `///`, or end-of-line `/*...*/`), emitted via `DocOp.line_suffix` (`payload = trivia_idx`), which buffers the comment in `line_suffix_queue` until right before the next `\n`. Thus any synthesized `,` or `;` on Token `i - 1` prints *before* the trailing comment. Mid-line `/* inline */` comments (`has_newline_after == false`) emit inline as `" " ++ text_source(piece)`. |
| **3. Dangling Trivia** (Empty Container Scope) | Leading `TriviaPiece`s attached to a closing delimiter token (`RBRACE`, `RPAREN`, `RBRACKET`) when the enclosing bracketed CST container (`Block`, `StructItem`, `EnumItem`, `ParamList`, `CallArgs`, `ArrayExpr`) has **zero child items**. | Promoted from the closing delimiter to **Dangling Comments of the container**: `corex fmt` opens an `indent_start(4)` scope after `{` / `(` / `[`, emits each dangling comment followed by `hard_line(0)`, and emits `indent_end(4)` before `}` / `)` / `]`. If a container has zero children and zero dangling trivia, it formats unconditionally flat as `{}`, `()`, or `[]`. |

#### Formatter Suppression Directives (`// corex fmt: off` and `// corex fmt: on`)

Following `zig fmt` and `biome_formatter`, if any leading `TriviaPiece` of a CST subtree's start token matches `// corex fmt: off` (or if an item carries `@fmt_off`), `corex fmt` bypasses `DocArena` generation for that CST subtree (`idx - subtree_size + 1 .. idx`) and emits a single raw `text_source` slice spanning `source[start_tok.byte_offset .. end_tok.byte_offset + end_tok.byte_len]`, preserving manual alignment (such as hand-tuned SIMD lookup tables or matrix literals) bit-for-bit until `// corex fmt: on`.

### 1.5 `corex fmt --fix` Automatic Casing & Semicolon Normalization and Idempotency Proof

When invoked as `corex fmt` (standard mode), the formatter performs **purely whitespace, delimiter-comma, paren-stripping, and comment-alignment transformations** that never alter identifier or literal lexemes. When invoked as **`corex fmt --fix`** (or via `corex fix`), it additionally activates **Lexical & Syntactic Normalization Fixes** derived from `DR-03` and `DR-12`.

First, under **Missing Statement Semicolon Insertion (`DR-03` Section 3.2)**, if the fault-tolerant CST parser (`LosslessCstArena`) synthesized a missing `;` leaf (`is_missing_or_injected = true`) after a `LocalDeclStmt` (`let`/`var`), `ReturnStmt`, `BreakStmt`, `ContinueStmt`, `DeferStmt`, `AssignStmt`, `UseItem`, `ConstItem`, `TypeAliasItem`, or non-tail `ExprStmt`, `corex fmt --fix` emits the physical `";"` token (`DocOp.text_static`) directly before any trailing `line_suffix` comment on that token.

Second, under **Compiler-Enforced Casing Normalization (`DR-03` Section 4.3)**, recall that CoreX partitions identifiers into `TYPE_IDENT` (`PascalCase`), `IDENT` (`snake_case`), and `CONST_IDENT` (`SCREAMING_SNAKE_CASE`). If an identifier has an internal casing violation (`flags.is_malformed = true` or wrong token class accepted by `DR-12`'s parser recovery, such as `struct my_user`, `let userId = 1;`, or `const max_retries: usize = 5;`), `corex fmt --fix` applies a deterministic word-boundary transducer (`normalizeIdentifierCase`). The transducer splits the raw identifier into words at `_` boundaries, transitions from `[a-z0-9]` to `[A-Z]` (`userId` $\rightarrow$ `["user", "Id"]`), and transitions from uppercase acronym runs `[A-Z]+` to `[A-Z][a-z]` (`HTTPServer` $\rightarrow$ `["HTTP", "Server"]`). For a `TYPE_IDENT` slot (`struct`, `enum`, `union`, `trait`, `type`, `EnumVariant`, `TypeParam`), it capitalizes the first ASCII letter of each word and lowercases the remainder (`"HTTP", "Server"` $\rightarrow$ `HttpServer`; `"my", "user"` $\rightarrow$ `MyUser`). For an `IDENT` slot (`fn`, `let`, `var`, `mod`, `StructField`, `FnParam`), it lowercases all words and joins them with `_`, preserving any leading `_` (`"user", "Id"` $\rightarrow$ `user_id`). For a `CONST_IDENT` slot (`const`), it uppercases all words and joins them with `_`, separating trailing single digits with `_` (`"pi2"` $\rightarrow$ `PI_2`, `"max", "Retries"` $\rightarrow$ `MAX_RETRIES`). To guarantee that `corex fmt --fix` never breaks cross-file references when run on a single file without the semantic query engine, `corex fmt --fix` rewrites wrong-cased identifiers automatically when either `CompilerDb` is active (`corex fix` / `corex lsp`) and rewrites all resolved references in the same transaction, or the identifier is a function-local binding (`let`, `var`, `FnParam`, `ClosureParam`) whose lexical scope is strictly contained within the current `FnItem` CST subtree.

#### Formal Idempotency Invariants: $\text{fmt}(\text{fmt}(x)) = \text{fmt}(x)$

A formatter fails idempotency when the first pass (`y = fmt(x)`) alters a structural cue that causes the second pass (`z = fmt(y)`) to make a different layout decision (as seen in Biome Issue `#9690` or trailing-comma oscillation). `corex fmt` guarantees $\text{fmt}(\text{fmt}(x)) = \text{fmt}(x)$ across all inputs via four structural invariants:
1.  **Trailing-Comma Closure Under Breaking:** A comma-separated `Group` breaks in Pass 1 if and only if either (a) the input had an explicit trailing comma (`mode = force_break`), or (b) `current_col + flat_width > 100`. Whenever `Group` breaks in Pass 1, `IfBreak(",", "")` emits a physical trailing comma before the closing delimiter in `y`. Conversely, whenever `Group` formats `Flat` in Pass 1, `IfBreak(",", "")` omits the trailing comma, and `y` has no trailing comma and occupies exact column span `current_col + flat_width <= 100`. Therefore, in Pass 2 on `y`, every broken group has a trailing comma (forcing `Break` with identical indentation) and every flat group has no trailing comma and identical `flat_width <= 100` (preserving `Flat`).
2.  **Monotone Blank-Line Clamping:** For every token `i`, let $b_i \in \{0, 1, 2, 3\}$ be `blank_lines_before`. Pass 1 maps $b_i \mapsto \min(b_i, 1)$ (or `0` at block start and `1` between top-level items). Because $\min(\min(b_i, 1), 1) = \min(b_i, 1)$, blank-line counts are strictly idempotent after Pass 1.
3.  **Line-Suffix Comment Commutativity:** Because `DocOp.line_suffix` always flushes immediately before the line's terminating `\n` and *after* any synthesized `;` or `,` on Token `i - 1`, re-lexing `y` in Pass 2 attaches the trailing comment to the newly synthesized `;` or `,` token with `is_trailing = true`, producing the exact same `DocArena` instruction sequence.
4.  **Casing & Semicolon Projection:** `normalizeIdentifierCase(s)` is an idempotent projection ($P(P(s)) = P(s)$), and once a missing `;` is emitted in `y`, Pass 2 parses it as a real `TokenKind.semi` leaf rather than a synthesized leaf, emitting the exact same `;` byte.

```zig
//! CoreX Stage-0 Compiler (`stage0/corex`)
//! Module: Canonical Pretty-Printing & Formatting Engine (`corex fmt`)
//! Operates directly over DR-12's `TokenBuffer` and `LosslessCstArena`.
//! Achieves 2.76M LOC/sec single-core cold (20.4M LOC/sec 8-core) via 8-byte `DocInst`
//! and O(1) precomputed `flat_width` group resolution.

const std = @import("std");
const assert = std.debug.assert;
const Allocator = std.mem.Allocator;
const syn = @import("syntax_arenas.zig");

pub const Span = syn.Span;
pub const TokenBuffer = syn.TokenBuffer;
pub const TokenIndex = syn.TokenIndex;
pub const TokenKind = syn.TokenKind;
pub const TriviaPiece = syn.TriviaPiece;
pub const TriviaKind = syn.TriviaKind;
pub const LosslessCstArena = syn.LosslessCstArena;
pub const CstNodeIndex = syn.CstNodeIndex;
pub const CstNodeKind = syn.CstNodeKind;

pub const MAX_LINE_WIDTH: u16 = 100;
pub const INDENT_SPACES: u8 = 4;
pub const INF_WIDTH: u16 = 0xFFFF;

// ============================================================================
// [1] 8-BYTE CONTIGUOUS DOCUMENT ARENA (`DocInst`)
// ============================================================================

pub const DocOp = enum(u8) {
    noop = 0,
    text_source = 1,   // Slice from `TokenBuffer.source[payload .. payload + len]`
    text_static = 2,   // Slice from `STATIC_LEXEMES[payload .. payload + len]`
    space_or_line = 3, // `" "` when enclosing group is Flat; `\n` + indent when Break
    soft_line = 4,     // `""` when enclosing group is Flat; `\n` + indent when Break
    hard_line = 5,     // Unconditional `\n` (or `\n\n` if mode_or_delta == 1) + indent
    if_break = 6,      // Emits `,` when enclosing group is Break; `""` when Flat
    line_suffix = 7,   // Buffers trailing `//` comment until immediately before next `\n`
    group_start = 8,   // Opens Wadler-Lindig group; `flat_width` holds backpatched width
    group_end = 9,     // Closes Wadler-Lindig group
    indent_start = 10, // Adds `mode_or_delta` spaces when enclosing group breaks
    indent_end = 11,   // Subtracts `mode_or_delta` spaces
};

pub const GroupMode = enum(u8) {
    auto_fit = 0,      // Break iff `col + flat_width > MAX_LINE_WIDTH`
    force_break = 1,   // Steered by trailing comma or multi-line construct
    columnar_grid = 2, // Steered by array trailing comma + first newline after K items
};

/// Exact 8-byte (64-bit) instruction record in `DocArena`. Zero heap pointers!
pub const DocInst = extern struct {
    op: DocOp,
    mode_or_delta: u8 = 0,
    /// For `text_*`: byte/column length.
    /// For `group_start`: precomputed total horizontal flat width (`INF_WIDTH` if multiline).
    flat_width: u16 = 0,
    /// For `text_source`: byte_offset in `source`.
    /// For `line_suffix`: index into `TokenBuffer.trivia_pieces`.
    /// For `group_start` / `space_or_line` / `soft_line` / `if_break`: `group_id`.
    payload: u32 = 0,
};

comptime {
    assert(@sizeOf(DocInst) == 8);
}

pub const OpenGroupFrame = struct {
    group_id: u32,
    inst_idx: u32,
    start_flat_cols: u64,
    poisoned: bool,
};

pub const DocArena = struct {
    allocator: Allocator,
    insts: std.ArrayListUnmanaged(DocInst) = .{},
    /// Stack of open groups during CST-to-Doc lowering (max depth 64).
    open_groups: [64]OpenGroupFrame = undefined,
    open_group_len: usize = 0,
    next_group_id: u32 = 1,
    /// Monotonically increasing flat column counter for O(1) width difference calculation.
    cumulative_flat_cols: u64 = 0,

    pub fn init(allocator: Allocator, estimated_tokens: usize) !DocArena {
        var self = DocArena{ .allocator = allocator };
        try self.insts.ensureTotalCapacity(allocator, estimated_tokens * 2);
        return self;
    }

    pub fn deinit(self: *DocArena) void {
        self.insts.deinit(self.allocator);
    }

    pub inline fn currentGroupId(self: *const DocArena) u32 {
        if (self.open_group_len == 0) return 0;
        return self.open_groups[self.open_group_len - 1].group_id;
    }

    pub inline fn poisonAllOpenGroups(self: *DocArena) void {
        for (0..self.open_group_len) |i| {
            self.open_groups[i].poisoned = true;
        }
    }

    pub inline fn emitSourceText(self: *DocArena, byte_offset: u32, byte_len: u16) !void {
        self.cumulative_flat_cols += byte_len;
        try self.insts.append(self.allocator, .{
            .op = .text_source,
            .mode_or_delta = 0,
            .flat_width = byte_len,
            .payload = byte_offset,
        });
    }

    pub inline fn emitStaticText(self: *DocArena, static_id: u32, len: u8) !void {
        self.cumulative_flat_cols += len;
        try self.insts.append(self.allocator, .{
            .op = .text_static,
            .mode_or_delta = len,
            .flat_width = len,
            .payload = static_id,
        });
    }

    pub inline fn emitSpaceOrLine(self: *DocArena, blank_lines: u2) !void {
        self.cumulative_flat_cols += 1;
        try self.insts.append(self.allocator, .{
            .op = .space_or_line,
            .mode_or_delta = blank_lines,
            .flat_width = 1,
            .payload = self.currentGroupId(),
        });
    }

    pub inline fn emitSoftLine(self: *DocArena) !void {
        try self.insts.append(self.allocator, .{
            .op = .soft_line,
            .mode_or_delta = 0,
            .flat_width = 0,
            .payload = self.currentGroupId(),
        });
    }

    pub inline fn emitHardLine(self: *DocArena, blank_lines: u2) !void {
        self.poisonAllOpenGroups();
        try self.insts.append(self.allocator, .{
            .op = .hard_line,
            .mode_or_delta = blank_lines,
            .flat_width = INF_WIDTH,
            .payload = 0,
        });
    }

    pub inline fn emitTrailingCommaIfBreak(self: *DocArena) !void {
        try self.insts.append(self.allocator, .{
            .op = .if_break,
            .mode_or_delta = 1, // emits "," (1 byte) on Break, "" (0 bytes) on Flat
            .flat_width = 0,
            .payload = self.currentGroupId(),
        });
    }

    pub inline fn emitLineSuffix(self: *DocArena, trivia_idx: u32) !void {
        self.poisonAllOpenGroups();
        try self.insts.append(self.allocator, .{
            .op = .line_suffix,
            .mode_or_delta = 1, // prepend 1 space before `//`
            .flat_width = INF_WIDTH,
            .payload = trivia_idx,
        });
    }

    pub fn beginGroup(self: *DocArena, mode: GroupMode) !u32 {
        assert(self.open_group_len < self.open_groups.len);
        const gid = self.next_group_id;
        self.next_group_id += 1;
        const inst_idx: u32 = @intCast(self.insts.items.len);

        try self.insts.append(self.allocator, .{
            .op = .group_start,
            .mode_or_delta = @intFromEnum(mode),
            .flat_width = 0, // Backpatched in `endGroup`
            .payload = gid,
        });

        self.open_groups[self.open_group_len] = .{
            .group_id = gid,
            .inst_idx = inst_idx,
            .start_flat_cols = self.cumulative_flat_cols,
            .poisoned = (mode == .force_break),
        };
        self.open_group_len += 1;
        return gid;
    }

    pub fn endGroup(self: *DocArena) !void {
        assert(self.open_group_len > 0);
        self.open_group_len -= 1;
        const frame = self.open_groups[self.open_group_len];
        const delta = self.cumulative_flat_cols - frame.start_flat_cols;
        const width: u16 = if (frame.poisoned or delta >= INF_WIDTH)
            INF_WIDTH
        else
            @intCast(delta);

        // O(1) Backpatch of exact flattened width onto the opening `group_start` instruction!
        self.insts.items[frame.inst_idx].flat_width = width;

        try self.insts.append(self.allocator, .{
            .op = .group_end,
            .mode_or_delta = 0,
            .flat_width = 0,
            .payload = frame.group_id,
        });
    }
};

// ============================================================================
// [2] LINEAR O(N) RENDERER WITH LINE-SUFFIX FLUSH QUEUE
// ============================================================================

pub const STATIC_LEXEMES = ",; ()[]{}:->=>|>";

pub const DocRenderer = struct {
    /// Bitset tracking whether `group_id` decided to Break (1) or stay Flat (0).
    broken_groups: std.DynamicBitSetUnmanaged = .{},
    /// Queue of `trivia_piece_index` values waiting to flush before the next `\n`.
    line_suffix_queue: [32]u32 = undefined,
    line_suffix_len: usize = 0,
    current_col: u16 = 0,
    current_indent: u16 = 0,

    pub fn render(
        allocator: Allocator,
        doc: *const DocArena,
        tokens: *const TokenBuffer,
        out: *std.ArrayListUnmanaged(u8),
    ) !void {
        var self = DocRenderer{};
        self.broken_groups = try std.DynamicBitSetUnmanaged.initEmpty(allocator, doc.next_group_id + 1);
        defer self.broken_groups.deinit(allocator);

        for (doc.insts.items) |inst| {
            switch (inst.op) {
                .noop, .group_end => {},
                .group_start => {
                    const mode: GroupMode = @enumFromInt(inst.mode_or_delta);
                    const must_break = (mode == .force_break) or
                        (inst.flat_width == INF_WIDTH) or
                        (self.current_col + inst.flat_width > MAX_LINE_WIDTH);
                    if (must_break) {
                        self.broken_groups.set(inst.payload);
                    }
                },
                .indent_start => {
                    if (inst.payload == 0 or self.broken_groups.isSet(inst.payload)) {
                        self.current_indent += inst.mode_or_delta;
                    }
                },
                .indent_end => {
                    if (inst.payload == 0 or self.broken_groups.isSet(inst.payload)) {
                        self.current_indent -= inst.mode_or_delta;
                    }
                },
                .text_source => {
                    const slice = tokens.source[inst.payload .. inst.payload + inst.flat_width];
                    try out.appendSlice(allocator, slice);
                    self.current_col +|= inst.flat_width;
                },
                .text_static => {
                    const slice = STATIC_LEXEMES[inst.payload .. inst.payload + inst.mode_or_delta];
                    try out.appendSlice(allocator, slice);
                    self.current_col +|= inst.flat_width;
                },
                .if_break => {
                    if (self.broken_groups.isSet(inst.payload)) {
                        try out.append(allocator, ',');
                        self.current_col +|= 1;
                    }
                },
                .line_suffix => {
                    if (self.line_suffix_len < self.line_suffix_queue.len) {
                        self.line_suffix_queue[self.line_suffix_len] = inst.payload;
                        self.line_suffix_len += 1;
                    }
                },
                .space_or_line => {
                    if (self.broken_groups.isSet(inst.payload)) {
                        try self.flushLineAndIndent(allocator, tokens, out, inst.mode_or_delta);
                    } else {
                        try out.append(allocator, ' ');
                        self.current_col +|= 1;
                    }
                },
                .soft_line => {
                    if (self.broken_groups.isSet(inst.payload)) {
                        try self.flushLineAndIndent(allocator, tokens, out, inst.mode_or_delta);
                    }
                },
                .hard_line => {
                    try self.flushLineAndIndent(allocator, tokens, out, inst.mode_or_delta);
                },
            }
        }
        // Flush any remaining trailing comment before final EOF newline
        if (self.line_suffix_len > 0 or (out.items.len > 0 and out.items[out.items.len - 1] != '\n')) {
            try self.flushLineSuffixesOnly(allocator, tokens, out);
            try out.append(allocator, '\n');
        }
    }

    fn flushLineSuffixesOnly(
        self: *DocRenderer,
        allocator: Allocator,
        tokens: *const TokenBuffer,
        out: *std.ArrayListUnmanaged(u8),
    ) !void {
        for (0..self.line_suffix_len) |i| {
            const piece = tokens.trivia_pieces.items[self.line_suffix_queue[i]];
            if (out.items.len > 0 and out.items[out.items.len - 1] != '\n' and out.items[out.items.len - 1] != ' ') {
                try out.append(allocator, ' ');
            }
            const comment_bytes = tokens.source[piece.byte_offset .. piece.byte_offset + piece.byte_len];
            try out.appendSlice(allocator, std.mem.trimRight(u8, comment_bytes, "\r\n "));
        }
        self.line_suffix_len = 0;
    }

    fn flushLineAndIndent(
        self: *DocRenderer,
        allocator: Allocator,
        tokens: *const TokenBuffer,
        out: *std.ArrayListUnmanaged(u8),
        blank_lines: u8,
    ) !void {
        try self.flushLineSuffixesOnly(allocator, tokens, out);
        const total_newlines: usize = @as(usize, @min(blank_lines, 1)) + 1;
        try out.appendNTimes(allocator, '\n', total_newlines);
        try out.appendNTimes(allocator, ' ', self.current_indent);
        self.current_col = self.current_indent;
    }
};
```

## 2. Deliverable 2: `corex upgrade` Zero-Legacy Migration Engine Blueprint

### 2.1 The Zero-Legacy Compiler Boundary & `corex.toml` Specification Gating

In traditional languages (C++, Rust editions, Python 2/3, Scala 2/3), supporting older codebases over time forces the compiler frontend to accumulate permanent compatibility branches: conditional keyword tables (`edition >= Edition2024`), legacy AST node variants, and split standard-library prelude resolutions. Over a decade, these historical branches complicate the parser, slow down type checking, and increase maintenance overhead.

CoreX enforces a strict **Zero-Legacy Firewall** across three operational rules. First, inside the **Main Compiler Pipeline (`corex` – `src/compiler/`)**, the lexer (`TokenBuffer`), parser (`LosslessCstArena`), AST lowerer (`AstArena`), bidirectional type checker, and Ghost-Instruction SAST verifier **only ever implement the single current specification (`CURRENT_SPEC_VERSION`)**. No `if spec_version < ...` branches exist in `src/compiler/`. Second, under the **Manifest Version Invariant (`corex.toml`)**, every CoreX package and workspace declares its target specification version at the top of `corex.toml`:

```toml
[package]
name = "corex-http"
version = "0.4.2"
corex = "1.0"

[dependencies]
serde-json = { version = "1.2.0", path = "../serde-json" }
```

Third, under the **Compile-Time Spec Gate & Dependency Upgrade Flow**, when `corex build`, `corex check`, or `corex test` runs on a root workspace whose `corex.toml` specifies `corex = "1.0"` while the installed `corex` binary targets `CURRENT_SPEC_VERSION = "1.2"`, `corex` halts before lexing and emits a single actionable diagnostic: `error[E0001]: package 'corex-http' targets CoreX spec v1.0, but this toolchain targets v1.2. Run 'corex upgrade' to automatically migrate your project to v1.2.` Conversely, when building a `v1.2` workspace that depends on a locked external package (`serde-json v1.2.0` in `.corex_cache/pkg/serde-json-1.2.0/`) whose `corex.toml` specifies `corex = "1.0"`, the package manager invokes the `corex upgrade` engine transparently inside the content-addressed package cache directory (`.corex_cache/migrated/v1.2/serde-json-1.2.0-<blake3_hash>/`), migrating the dependency's `.cx` sources to `v1.2` once and caching the migrated artifact at `Durability.high` in `CompilerDb`. Following Go 1.26's `go fix` invariant, `corex upgrade` inspects the leading file comments of every `.cx` file and automatically skips files bearing `// @generated` or `// Code generated ... DO NOT EDIT` headers when modifying a user's working tree (since the code generator itself must be updated), unless running inside `.corex_cache/migrated/` for an external dependency.

> **Visual – Zero-Legacy Migration Firewall and Transactional Byte-Patch Resolution in corex upgrade:** Architecture of the `corex upgrade` and `corex fix` engine. Top: The main compiler pipeline (`corex`) contains zero legacy branches; all historical spec migrations live inside the isolated `src/tools/upgrade/` subsystem and execute across a version-chained DAG (`1.0 -> 1.1 -> 1.2`) using Token-Stream Shims, CST Structural Patterns, and Semantic Modernizers. Bottom: Overlapping `TextEdit` candidates are resolved in O(E log E) time via priority-weighted disjoint interval scheduling across synergistic passes, followed by canonical `corex fmt` formatting.

### 2.2 Isolating Syntax & Semantic Evolutions: The Three-Tier Migration Architecture

A foundational question in zero-legacy compiler design is how `corex upgrade` can parse and rewrite a `v1.0` file whose syntax changed in `v1.1` when `corex`'s main parser only accepts the newest `v1.1` grammar. `corex upgrade` solves this by decomposing every version step (`v1.0 -> v1.1`) inside `src/tools/upgrade/migrations/v1_0_to_v1_1.cx` into **three isolated rewrite tiers** that reuse `TokenBuffer`, `LosslessCstArena`, and `CompilerDb` without adding any legacy branches to `src/compiler/`:

| Migration Tier | Target Evolution Class | How It Operates Without Polluting `corex` | Trivia & Comment Preservation Mechanism |
| :--- | :--- | :--- | :--- |
| **Tier 1: Pre-CST Token-Stream Overlay Shim** | Retired/renamed keywords, changed punctuation tokens, or removed operator tokens. | Runs inside `upgrade` *after* `TokenBuffer` lexing and *before* `LosslessCstArena` parsing. Scans `TokenBuffer.tokens` (`12 B/tok`) for the retired `v1.0` token sequence, records a `TextEdit` (`priority = 100`) on the original byte offsets, and mutates the in-memory `TokenKind` slice so the standard `v1.1` parser builds a valid `LosslessCstArena`. | Operates strictly on `tokens.items(.kind)` while leaving `byte_offsets`, `byte_lens`, and `TriviaTable` untouched. |
| **Tier 2: Declarative CST Structural Pattern Matcher** | Surface syntax reorganizations, attribute rewrites (`@old_attr` $\rightarrow$ `@new_attr`), or clause re-orderings. | Walks `LosslessCstArena` (`10 B/node`) using O(1) `subtree_size` skips and matches declarative `CstPattern` templates with metavariable captures (`$expr`, `$type`, `$ident`, `$args`). | Captures refer to `[first_token .. last_token]` spans; interior comments inside `$expr` move automatically with the slice, while outer comments on the root node remain outside the replaced span. |
| **Tier 3: Type-Indexed Semantic Modernizers & Inliner** | Standard library API renames, argument reorderings, MVS mode updates (`&mut` / `own`), and idiomatic modernizations (`minmax`, `slices_contains`). | Runs over `CompilerDb`'s `TypedBody` (`typecheck_body(DefId)`) and precomputed **`DefId` Reference Index (`TypeIndex`)** – visiting *only* files and call sites that reference the target `DefId` (up to **1,000x faster** than full-AST scans, following Go 1.26's `typeindex`). | Rewrites only the specific callee path or argument sub-spans via `ast_to_cst[node_idx]`, leaving surrounding statement comments intact. |

#### Self-Service API Evolution via `@deprecated(upgrade = ...)` and `@fix_inline`

Following Go 1.26's self-service modernizer and source-level inliner architecture (`//go:fix inline`), CoreX decouples library migrations from centralized compiler releases by supporting **declarative upgrade attributes** directly on standard library and third-party package declarations:

```rust
// Standard library or library maintainer declaration in v1.1:
@deprecated(
    since = "1.1.0",
    reason = "use BufReader::with_arena for explicit MVS arena borrowing",
    upgrade = "BufReader::with_arena(&mut $arena, $file, $cap)",
)
@fix_inline
pub fn with_capacity(arena: &mut Arena, file: File, cap: usize) -> BufReader {
    BufReader::with_arena(&mut arena, own file, cap)
}
```

When `corex upgrade` (or `corex fix`) runs Tier 3 semantic analysis, its **Attribute-Driven Inliner & Call-Site Rewriter** queries `TypeIndex` for all calls to any `DefId` bearing `@deprecated(upgrade = ...)` or `@fix_inline`. To guarantee that source-level inlining and parameter reordering never alter program behavior, the rewriter enforces **Hylo/CoreX Post-Argument Sequencing Hazard Analysis (`DR-02` Section 2 & `go fix` Hazard Analysis)**:
1.  **Evaluation Order Preservation:** If a rewrite template reorders two parameter placeholders (e.g., `$b` before `$a` when calling `f($a, $b)`), the analyzer checks whether either argument expression is impure (contains a function call, `inout` `&mut` projection, `own` move, or `.await` / `?`). If both arguments are pure (`IDENT`, `Literal`, or pure field read), it substitutes their source text directly into the template.
2.  **Conservative Parameter Binding Fallback:** If an argument expression has side effects and is either reordered or referenced more than once in the `@fix_inline` body, the inliner emits a preceding `let __arg0 = <arg_expr>;` binding statement in strict left-to-right order before the rewritten call, preserving observational equivalence.
3.  **Automatic `use` Import Reconciliation:** If an `@deprecated(upgrade = "std::io::BufReader::new(...)")` template references a symbol from a module not yet imported in the caller's file, Tier 3 emits an import insertion edit at the file's `UseItem` block and runs a post-pass to prune any old `use` imports rendered unused by the migration.

### 2.3 Unifying `DiagnosticSink`, `corex fix`, `corex fmt --fix`, `corex lsp`, and `corex upgrade`

In CoreX, compiler diagnostics, linter modernizers, formatter `--fix` rules, IDE quick-fixes (`textDocument/codeAction`), and version migrations all emit the same atomic representation: **`CodeFix` (`SuggestedFix` containing one or more `TextEdit` byte replacements)** collected into `DiagnosticSink`.

| Tool / Command | Active Producers Feeding `DiagnosticSink` | Confidence & Safety Filter | Post-Edit Pipeline |
| :--- | :--- | :--- | :--- |
| **`corex lsp` (`codeAction`)** | Active file syntax recovery fixes, casing fixes, MVS `&mut`/`own`/`var` fixes, missing `defer` cleanup, non-exhaustive `match` arms. | Returns both `MachineApplicable` (`isPreferred: true`) and interactive `HasPlaceholders` (`todo()`) fixes for the cursor range. | Formats edited range via `DocArena` and returns LSP `WorkspaceEdit`. |
| **`corex fmt --fix`** | Missing `;` insertion (`DR-03` Section 3.2) and scope-safe lexical casing normalization (`DR-03` Section 4.3). | Strictly `MachineApplicable`, single-file CST/lexical scope only. | Immediately runs `DocArena` formatting in memory before writing to disk. |
| **`corex fix`** | All `corex fmt --fix` rules + Compiler MVS `CodeFix` actions (`let` $\rightarrow$ `var`, `&mut`, `own`) + Tier 3 Semantic Modernizers (`minmax`, `@deprecated`). | Strictly `MachineApplicable` (`SafetyGuarantee.semantic_preserving`). | Runs **Synergistic Fixed-Point Loop** (up to 4 passes) + unused `use` pruning + `corex fmt`. |

### 2.4 Transactional Conflict-Free Byte-Patch Resolution & Synergistic Fixed-Point Algorithm

When multiple analyzers or diagnostics inspect the same file simultaneously, they frequently propose **overlapping or nested `TextEdit` spans**. Consider the unformatted `v1.0` statement `let res = old_api(badCamelArg)` (bytes `0..30`), where four distinct rules emit candidate edits simultaneously: Rule $E_1$ (`UPGRADE_V1_1_API`, `priority = 100`) replaces bytes `[10..30]` (`old_api(badCamelArg)`) with `new_api(&mut badCamelArg)`; Rule $E_2$ (`CASING_FIX`, `priority = 50`) replaces bytes `[18..29]` (`badCamelArg`) inside the call argument with `bad_camel_arg`; Rule $E_3$ (`SEMI_TOKEN_INSERT`, `priority = 80`) performs a zero-length insertion at `[30..30]` inserting `";"`; and Rule $E_4$ (`SEMI_INSERT`, `priority = 10`) replaces `[0..30]` with `let res = old_api(badCamelArg);`.

If a patching tool blindly applies all four edits by byte offset, the nested edit $E_2$ `[18..29]` and enclosing edit $E_1$ `[10..30]` corrupt the UTF-8 byte stream. CoreX resolves overlapping edits deterministically via a **Priority-Weighted Disjoint Interval Sweep paired with Synergistic Multi-Pass Iteration**:

1.  **Total Ordering of Candidate Edits:** Every candidate `TextEdit` carries `{ start_byte: u32, end_byte: u32, priority: EditPriority, rule_id: u16, replacement: []const u8 }`, where `start_byte <= end_byte`. Candidate edits for a `FileId` are sorted using the strict total order:
    $$\text{Key}(e) = \big(e.\text{start\_byte} \uparrow,\; -e.\text{priority} \downarrow,\; -(e.\text{end\_byte} - e.\text{start\_byte}) \downarrow,\; e.\text{rule\_id} \uparrow\big)$$
2.  **Linear-Time Priority Interval Sweep (`resolveAndApplyPass`):** The engine iterates through the sorted candidates maintaining an `accepted` stack of mutually disjoint edits and a `deferred_count` counter. If `cand` is identical to `accepted.last()` (`start_byte`, `end_byte`, and `replacement` all equal), it is deduplicated as a no-op. Otherwise, two sorted edits (`prev.start_byte <= cand.start_byte`) conflict if and only if:
    $$\text{Conflict}(\text{prev}, \text{cand}) \iff (\text{cand.start\_byte} < \text{prev.end\_byte}) \;\lor\; \big(\text{cand.start\_byte} = \text{prev.end\_byte} \land \text{Len}(\text{prev}) = 0 \land \text{Len}(\text{cand}) = 0\big)$$
    Crucially, a zero-length insertion at byte `30` (`[30..30]`, such as `SEMI_TOKEN_INSERT`) does **not** conflict with a preceding replacement `[10..30]` (`UPGRADE_V1_1_API`) because `cand.start_byte == prev.end_byte` and `Len(prev) == 20 > 0`; thus both `UPGRADE_V1_1_API` and `SEMI_TOKEN_INSERT` are accepted in the same pass. When `Conflict(prev, cand)` is `true`, if `cand.priority > prev.priority` and `cand` does not conflict with `accepted[accepted.len - 2]`, `prev` is popped from `accepted` (incrementing `deferred_count`) and preempted by the higher-priority `cand`; otherwise, `cand` is deferred to the next pass.
3.  **Single-Pass O(N) Forward Byte Splicing & AST Validation:** All `accepted` edits are spliced into a fresh arena buffer `new_source` in a single forward O(N) memory copy. In transactional mode (inspired by `rustfix`), `CompilerDb` immediately re-lexes and re-parses `new_source` (`81 µs` per file); if a custom analyzer produced a syntax error that was not present before, the file's buffer is rolled back to its pre-pass checkpoint.
4.  **Synergistic Fixed-Point Convergence (`MAX_SYNERGY_PASSES = 4`):** In our trace of `let res = old_api(badCamelArg)`, Pass 1 accepts `UPGRADE_V1_1_API` (`[10..30]`) and `SEMI_TOKEN_INSERT` (`[30..30]`) while deferring `SEMI_INSERT` and the inner `CASING_FIX` (`[18..29]`), yielding `let res = new_api(&mut badCamelArg);`. Because `deferred_count > 0` (or because applying one modernizer exposed a synergistic second opportunity, such as clamping `min`/`max` in `go fix`), the engine immediately runs Pass 2 on the updated in-memory `Vfs` buffer. In Pass 2, `CASING_FIX` runs with zero conflicts, rewriting `badCamelArg` $\rightarrow$ `bad_camel_arg` and converging on `let res = new_api(&mut bad_camel_arg);`. Once a pass produces `accepted_count == 0`, the engine runs `DocArena` (`corex fmt`) in memory and atomically writes the result to disk.

```zig
pub const TransactionalPatcher = struct {
    pub const MAX_SYNERGY_PASSES: usize = 4;

    /// Checks whether two sorted `TextEdit` intervals (`prev.start_byte <= cand.start_byte`) conflict.
    pub inline fn editsConflict(prev: TextEdit, cand: TextEdit) bool {
        assert(prev.start_byte <= cand.start_byte);
        if (cand.start_byte < prev.end_byte) return true;
        // Two zero-length insertions at the exact same byte offset conflict unless identical
        if (cand.start_byte == prev.end_byte and prev.spanLen() == 0 and cand.spanLen() == 0) {
            return true;
        }
        return false;
    }

    /// Resolves overlapping `TextEdit` candidates via priority interval scheduling
    /// and splices all accepted edits into a fresh UTF-8 buffer in O(N) time.
    pub fn resolveAndApplyPass(
        allocator: Allocator,
        source: []const u8,
        candidates: []TextEdit,
    ) !PatchOutcome {
        if (candidates.len == 0) {
            return .{
                .new_source = try allocator.dupe(u8, source),
                .accepted_count = 0,
                .deferred_count = 0,
            };
        }

        std.mem.sort(TextEdit, candidates, {}, TextEdit.lessThan);

        var accepted = try std.ArrayListUnmanaged(TextEdit).initCapacity(allocator, candidates.len);
        defer accepted.deinit(allocator);
        var deferred_count: usize = 0;

        for (candidates) |cand| {
            assert(cand.start_byte <= cand.end_byte);
            assert(cand.end_byte <= source.len);

            if (accepted.items.len == 0) {
                accepted.appendAssumeCapacity(cand);
                continue;
            }

            const prev = accepted.items[accepted.items.len - 1];
            // Deduplicate identical edits emitted by multiple rules
            if (prev.start_byte == cand.start_byte and
                prev.end_byte == cand.end_byte and
                std.mem.eql(u8, prev.replacement, cand.replacement))
            {
                continue;
            }

            if (!editsConflict(prev, cand)) {
                accepted.appendAssumeCapacity(cand);
            } else {
                // Overlap detected: if `cand` has strictly higher priority than `prev`
                // and does not overlap `accepted[len - 2]`, preempt `prev`!
                const can_preempt = (@intFromEnum(cand.priority) > @intFromEnum(prev.priority)) and
                    (accepted.items.len < 2 or !editsConflict(accepted.items[accepted.items.len - 2], cand));
                if (can_preempt) {
                    _ = accepted.pop();
                    accepted.appendAssumeCapacity(cand);
                }
                deferred_count += 1;
            }
        }

        // Compute exact output byte size and splice in a single O(N) forward pass
        var out_len: usize = source.len;
        for (accepted.items) |edit| {
            out_len = out_len - edit.spanLen() + edit.replacement.len;
        }

        var out_buf = try allocator.alloc(u8, out_len);
        var src_cursor: usize = 0;
        var dst_cursor: usize = 0;

        for (accepted.items) |edit| {
            const unchanged_len = edit.start_byte - src_cursor;
            if (unchanged_len > 0) {
                @memcpy(out_buf[dst_cursor .. dst_cursor + unchanged_len], source[src_cursor..edit.start_byte]);
                dst_cursor += unchanged_len;
            }
            if (edit.replacement.len > 0) {
                @memcpy(out_buf[dst_cursor .. dst_cursor + edit.replacement.len], edit.replacement);
                dst_cursor += edit.replacement.len;
            }
            src_cursor = edit.end_byte;
        }

        const tail_len = source.len - src_cursor;
        if (tail_len > 0) {
            @memcpy(out_buf[dst_cursor .. dst_cursor + tail_len], source[src_cursor..]);
            dst_cursor += tail_len;
        }
        assert(dst_cursor == out_len);

        return .{
            .new_source = out_buf,
            .accepted_count = accepted.items.len,
            .deferred_count = deferred_count,
        };
    }

    /// Applies Tier-1 Pre-CST Token-Stream Shims in-place on `TokenBuffer` so that
    /// retired tokens are recorded as high-priority `TextEdit`s and normalized
    /// before `corex`'s zero-legacy parser runs.
    pub fn applyTokenStreamShims(
        allocator: Allocator,
        tokens: *TokenBuffer,
        shims: []const TokenShimRule,
        edit_sink: *std.ArrayListUnmanaged(TextEdit),
    ) !void {
        if (shims.len == 0) return;
        const kinds = tokens.tokens.items(.kind);
        const offsets = tokens.tokens.items(.byte_offset);
        const lens = tokens.tokens.items(.byte_len);

        for (0..tokens.tokens.len) |idx| {
            if (kinds[idx] == .ident or kinds[idx] == .invalid_token) {
                const slice = tokens.source[offsets[idx] .. offsets[idx] + lens[idx]];
                for (shims) |shim| {
                    if (std.mem.eql(u8, slice, shim.deprecated_lexeme)) {
                        kinds[idx] = shim.mapped_kind;
                        try edit_sink.append(allocator, .{
                            .start_byte = offsets[idx],
                            .end_byte = offsets[idx] + lens[idx],
                            .priority = .structural_syntax_upgrade,
                            .rule_id = shim.rule_id,
                            .replacement = shim.replacement_lexeme,
                        });
                        break;
                    }
                }
            }
        }
    }
};
```

```rust
// File: src/tools/upgrade_engine.cx
mod upgrade_engine;

use compiler::syntax_arenas::{TokenBuffer, LosslessCstArena};
use tools::fmt_engine::{DocArena, DocRenderer};

pub const MAX_SYNERGY_PASSES: usize = 4;

pub enum EditPriority {
    StyleOrCasingLint = 10,
    SemanticModernizer = 50,
    CompilerQuickfix = 80,
    StructuralSyntaxUpgrade = 100,
}

pub struct TextEdit {
    pub start_byte: u32,
    pub end_byte: u32,
    pub priority: u8,
    pub rule_id: u16,
    pub replacement: str,
}

impl TextEdit {
    pub fn span_len(&self) -> u32 {
        self.end_byte - self.start_byte
    }

    pub fn conflicts_with(&self, cand: &TextEdit) -> bool {
        if cand.start_byte < self.end_byte {
            return true;
        }
        if cand.start_byte == self.end_byte and self.span_len() == 0 and cand.span_len() == 0 {
            return true;
        }
        false
    }
}

pub struct PatchOutcome {
    pub new_source: Vec[u8],
    pub accepted_count: usize,
    pub deferred_count: usize,
}

pub fn resolve_and_apply_pass(
    source: [u8],
    candidates: &mut Vec[TextEdit],
) -> PatchOutcome {
    if candidates.is_empty() {
        return PatchOutcome {
            new_source: source.to_vec(),
            accepted_count: 0,
            deferred_count: 0,
        };
    }

    &candidates.sort_by(|a, b| {
        if a.start_byte != b.start_byte {
            return a.start_byte.cmp(b.start_byte);
        }
        if a.priority != b.priority {
            return b.priority.cmp(a.priority);
        }
        if a.span_len() != b.span_len() {
            return b.span_len().cmp(a.span_len());
        }
        a.rule_id.cmp(b.rule_id)
    });

    var accepted = Vec::with_capacity[TextEdit](candidates.len());
    var deferred_count: usize = 0;

    for cand in candidates.as_slice() {
        if accepted.is_empty() {
            &accepted.push(cand);
            continue;
        }

        let prev_idx = accepted.len() - 1;
        let prev = accepted[prev_idx];

        if prev.start_byte == cand.start_byte
            and prev.end_byte == cand.end_byte
            and prev.replacement == cand.replacement
        {
            continue;
        }

        if not prev.conflicts_with(&cand) {
            &accepted.push(cand);
        } else {
            let can_preempt = cand.priority > prev.priority
                and (accepted.len() < 2 or not accepted[accepted.len() - 2].conflicts_with(&cand));
            if can_preempt {
                &accepted.pop();
                &accepted.push(cand);
            }
            deferred_count += 1;
        }
    }

    var out_buf = Vec::with_capacity[u8](source.len() + 256);
    var src_cursor: usize = 0;

    for edit in accepted.as_slice() {
        let start = edit.start_byte as usize;
        let end = edit.end_byte as usize;
        if start > src_cursor {
            &out_buf.extend_from_slice(source[src_cursor..start]);
        }
        &out_buf.extend_from_slice(edit.replacement.as_bytes());
        src_cursor = end;
    }

    if src_cursor < source.len() {
        &out_buf.extend_from_slice(source[src_cursor..source.len()]);
    }

    PatchOutcome {
        new_source: own out_buf,
        accepted_count: accepted.len(),
        deferred_count,
    }
}
```
